# PROMPT 00 — Контекст и ограничения эксперимента

Ты работаешь в репозитории Quantor. Твоя задача — не перепроектировать существующий продукт, а подготовить изолированный эксперимент MEP P→RD→ВОР.

Сначала полностью изучи репозиторий и найди реальные точки переиспользования. Не придумывай пути и классы. В переданном AI-контуре уже есть идеи/компоненты, которые нужно сохранить: EvidenceGraph, source-space geometry, обратимые transforms, whole-sheet context + high-res views, typed primitives POINT/LINE/AREA, разделение raw/source-supported/unresolved, project-heldout split, provenance и строгие JSON contracts.

Гипотеза:
1) загрузить стадию П и выбрать один план этажа;
2) распознать геометрию/текст/якоря инженерной системы;
3) построить RD-подобную сеть на основе обученного prior по РД и детерминированных ограничений;
4) получить полный ВОР по этой сети;
5) отдельно расценить ВОР моделью/модулем, обученным на исторических ВОР/КП.

Первый scope: ВК, горизонтальная разводка типового жилого этажа. Не подключай одновременно ОВ/ЭОМ/СС.

Обязательные правила:
- feature flag `mep_rd_hypothesis_v1`;
- существующие production-флоу не менять;
- не обучать и не запускать тяжёлые GPU jobs без отдельной явной команды;
- не писать в Revit в первом MVP;
- ни одна inferred величина не маскируется под observed;
- unknown != negative;
- П и РД одного проекта не могут оказаться в разных folds;
- reference RD на blind test скрыт от inference и показывается только после фиксации результата;
- при неизвестном масштабе метрические quantities запрещены.

Сделай короткий `MEP_EXPERIMENT_STATE.md`: цель, scope, найденные точки интеграции, риски, неизменяемые файлы/модули, следующий шаг. Никаких продуктовых изменений в этом промте.
