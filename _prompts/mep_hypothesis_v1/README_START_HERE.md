# Quantor — MEP P→RD→ВОР hypothesis prompt pack v1

Цель пакета: безопасно проверить в портале Quantor гипотезу:

**стадия П одного этажа → структурированное распознавание → RD-подобная инженерная сеть → ВОР → расценивание.**

Рекомендуемый первый узкий контур: **ВК / горизонтальная разводка типового жилого этажа**. Не расширять первый опыт одновременно на ОВ, ЭОМ и СС.

## Принципы, которые нельзя нарушать

1. Не генерировать «красивую картинку РД» как источник истины. Истина — структурированный MEP Network Graph + provenance.
2. Переиспользовать существующие контракты Quantor: source-space coordinates, EvidenceGraph, full-sheet context + high-res views, POINT/LINE/AREA primitives, raw/source-supported/unresolved, project-heldout split.
3. Для MEP добавить отдельный `MepNetworkGraph`; не запихивать сеть в `FloorGraph` как набор линий.
4. Любое поле должно иметь происхождение: `observed`, `rd_prior_inferred`, `rule_derived`, `retrieved`, `human_confirmed`, `unresolved`.
5. Никакого leakage: split только по проектам; П и РД одного проекта всегда в одном fold.
6. Первый end-to-end тест — только на заранее отложенном проекте/этаже, который не использовался ни в обучении, ни в калибровке.
7. В первом MVP не писать автоматически в Revit. Достаточно overlay + JSON + quantities. Revit/IFC подключать после topology/quantity gate.
8. Модель расценивания отделена от модели количества. Количество не должно зависеть от цены.
9. Никаких догадок при неизвестном масштабе, диаметре, материале, уровне или принадлежности системы: `unresolved`/review.
10. Не делать массовые рефакторинги существующего монолит/кладка/двери контура.

## Рекомендуемый порядок запуска промтов

00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11.

Промт 06 (обучаемая P→RD модель) запускать только после того, как 04–05 доказали качество парных данных и baseline.
