# Трек «ИИ-петля обводки и ВОР» — план и решения

Промт-документ для новой сессии Claude. Состояние на 2026-11-25. Основание — [ADR-0055](../../docs/adr/0055-ii-petlya-obvodki-i-zapolnenie-vor.md)
(статус «черновик», в main с a924d75; утверждает владелец). Дополняет `CLAUDE.md` проекта; при конфликте приоритет у него.
Остальные треки — только если владелец скажет явно; приоритет — CAD.

## 1. Цель трека

Пайплайн проекта (тендера) без ручных шагов, кроме прямого вопроса человеку:

```text
загрузка → автопайплайн (паспорта листов, вопросы к документации, CAD на планах)
→ движок рисует → Claude Opus правит (находки = замечания с рамкой + правки свойств)
→ перестроение движком по замечаниям → круги (≤3)
→ верификация Claude (Codex — для сравнения)
→ ручная приёмка с петлёй замечаний
→ заполнение копии ВОР Заказчика + строки «нет в ВОР»
```

- Объём: конструктив, двери, отделка МОП.
- Этапность — на уровне ПРОЕКТА (счётчики по листам: «Проверка Claude: 7 из 12 листов, круг 2»); внутри этапа —
  все листы. Пошаговая шкала листа — только детализация.
- Человек — только прямой вопрос во всплывашке (масштаб CAD, вопрос к документации); отдельного экрана нет.
- Пилот: «341. Капельский (СОЮЗ) (тест)», `65583d09-c28a-44da-85a1-052189cc68cc`, малый объём (2 плана).

## 2. Решения владельца (2026-11-25)

- Движок и модель скрещиваются: модель находит, движок строит. Находка = тип замечания CAD + рамка + id + доказательство.
- Правщик и проверщик — оба Claude Opus (`claude-opus-5-5`), проверщик в чистом контексте; Codex — позже, для сравнения.
- Петля одна для модели и для человека: замечание человека -> правка -> проверка.
- ВОР Заказчика с самого начала — перечень «что искать» (`vor_check`); в конце — копия xlsx с колонкой «Quantor»
  и строками «нет в ВОР». Оригинал не меняется.
- Типовые этажи умножаются (`SheetSource.floors`, x(to-from+1)).
- Промты ИИ — версионированные записи с автором, датой, активной версией и статистикой для доработки и обучения.
- Ускорить сборку выкладки: статичное (deps, venv движка, ssh, архив) отделено от меняющегося.
- После каждого ответа владельцу писать «Выполнено N/17» (выполнено = принято).
- Пилотные настройки — только на suvpn, закрыты флагом пилота и на сервере, и в интерфейсе (ADR-0023).

## 3. Принципы и границы

- Модель не рисует геометрию и не выдаёт физических величин: метры, м² и м³ считает только детерминированный движок.
- Рамка находки — только область поиска; геометрию строит движок из примитивов PDF внутри рамки.
- Масштаб — только движок (ADR-0045); модель масштаб не определяет.
- Количества — только от движка; в выгрузку ВОР — только после одобрения человеком (кандидат модели — не факт).
- Цен, расценок, валюты и стоимости нет; флаг `reports` не включается.
- Оригинал ВОР Заказчика не изменяется; выгрузка — копия.
- `max_iterations` — жёсткий лимит (3); модель вызывается только по кнопке или в петле пилота.
- Клиентские чертежи, ВОР, документы и данные PlanSwift в git не попадают; только синтетические fixtures.
- Передача клиентских данных внешней модели — только для пилотного проекта (ADR-0055 п.6); остальные не передаются.
- `BLOCKED` не записывается как `PASS`.

## 5. Как устроено

**Задания.** `cad_ai_review` — правщик и проверщик (роль выбирается, лимит кругов у каждой роли свой; замечания
пишутся на задание convert, `cad_job_id`; автор замечаний ИИ — нулевой UUID). `cad_ai_vor_map` — сопоставление
позиций ВОР с конструкциями, дверями и отделкой МОП (S4-B). Результат вида — кандидат до одобрения человеком.

**Шлюз на `kg_claude`.** Вызов: `claude -p --model claude-opus-5-5 --setting-sources "" --strict-mcp-config
--json-schema … --output-format json`, ответ — поле `structured_output` (`--bare` не работает: нет входа).
SSH suvpn -> kg_claude, ключ ограничен `command=…/quantor-outline-review/pilot.py`; ветки шлюза:
`AI_COMMAND_SHA` -> `ai_review.py`, `AI_VOR_COMMAND_SHA` -> `ai_vor_map.py`. Файл шлюза —
`~/.local/share/quantor-outline-review/pilot.py`, генератор — `/home/usrr/quantor-ai/tools/make_ai_gate.py`.
**Перезапускать генератор после ЛЮБОЙ правки REMOTE** (иначе «Pilot key: command refused»). Sha промта шлюз не
проверяет (лимит пакета 64 КиБ): новые версии промтов проходят без пересборки. Источники для модели —
только `/home/usrr/quantor-ai/341-test/sources/*.md` (vor, explanatory_note, architecture_note,
terms_of_reference, mop_design).

**Пилотные настройки на suvpn** — `/opt/portals/quantor/compose.pilot.ui.yml` (бэкапы `.bak-*` рядом):
`CAD_AI_LOOP` (JSON: `project_id`, `model`, `max_iterations`, `sources{role: path}`) — у `api` и `cad-worker`;
`PIPELINE_AUTO` (`project_ids`, `max_cad_sheets_per_project=3`) — у `api` и `worker` (job_runner и паспорта
исполняет worker); `CAD_REVIEW_PILOT` — у `api`. `ship-local.sh` возвращает overlay для api, worker, cad-worker.

**Подсказки движку.**
- `cad_walls --hints` (v1.26, контракт `quantor.cad_walls_hints.v1`): `missing_wall`, `false_wall`, `missing_door`,
  `bbox_mm` в кадре вида; портал переводит pt -> мм кадра (`bbox_pt_to_view_mm`); отчёт `hints_applied` в `walls.json`.
- `operator_convert_hints` в преобразовании PDF->DXF (контракт `quantor.cad_convert_hints.v1`, `bbox_pt` — в
  координатах отображаемой страницы с `/Rotate`); отчёт — в `checks.json`.
- Движок 2026.11.25+a34437736054, ветка CAD_engine `ai-hints-2026.11.25` (запушена, 01907a5).
- Пороги «нет стены»: рамка <=6 м и <=12 м² (иначе `too_large`); больше 6 кандидатов — `ambiguous`; толщина
  по номиналам +-12 мм; только «стеновые» линии. Константы — `hints.py` движка. Не сделано: дверь по разрыву без
  дуги, окна; `missing_wall`-повтор без `concrete_strokes` не переводит кладку со штриховкой ж/б в монолит.
- Ограничение `cad_walls`: видит только заливки DXF движка; стены «линиями без штриховки» и двери без блока —
  только подсказками преобразования.

**Промты.** Таблица `ai_prompt_versions` (роль, текст, версия, автор, дата, активная); роли `corrector`,
`verifier`, `vor_mapper` (последняя на веб-доске пока не показана — хвост). Страница `/ai-prompts` (ссылка в
`/settings`), статистика: прогоны, стоимость, вердикты, находки по типам, судьба замечаний. У каждого прогона —
`prompt_version_id` + `prompt_sha256`. Активный промт правщика — v2 (узкие рамки).
