# PROMPT 02 — Manual Takeoff Ready for Work (ручной обмер готов к работе)

**Модель:** Opus 5  
**Режим мышления:** высокий  
**Цель:** после этого этапа инженер уже должен уметь работать в Quantor с реальным PDF вручную, даже без MEP-автоматизации.

## 1. Scope (объём)

Используй уже существующий `takeoff.manual`. Не переписывай его.

Нужно доказать и при необходимости исправить сквозную цепочку на raw PDF:

```text
PDF
→ открыть workspace
→ выбрать лист
→ калибровать масштаб
→ создать строку обмера
→ Count / Line / Polyline / Polygon
→ сохранить
→ перезагрузить страницу
→ отредактировать
→ удалить/архивировать по существующим правилам
→ увидеть server-side quantity (расчёт на сервере)
```

## 2. Доступ

- `takeoff.manual` остаётся default OFF.
- Включается только для pilot workspace (пилотного пространства) через существующую админку/feature override.
- При OFF клиент не должен отправлять takeoff requests (запросы обмера), сервер должен отказать.
- Не включай флаг глобально.

## 3. Проверь реальные UX-косяки

Проведи browser smoke test (быстрый браузерный тест) и исправь только то, что реально мешает инженеру:

- невозможно понять, какой инструмент активен;
- инструмент не завершается/не отменяется;
- ошибка калибровки непонятна;
- после reload пропадают измерения;
- изменение вершины не сохраняется;
- optimistic conflict (конфликт версий) отображается как непонятная ошибка;
- количество/длина/площадь показываются неверной единицей;
- лист без масштаба выдаёт ноль вместо unavailable (недоступно);
- pan/zoom конфликтует с drawing tools (инструментами рисования);
- переключение листов оставляет чужую selection (выбор) или geometry draft (черновик геометрии).

Не добавляй новые типы геометрии.

## 4. Минимальный экспорт ручного обмера

Для начала реальной работы нужен способ забрать результат наружу.

Добавь простой экспорт **CSV** (UTF-8) для выбранного листа или проекта — выбери минимальный вариант, который естественно ложится на текущий API.

Минимальные поля:

- project/document/revision/sheet;
- takeoff item (строка обмера);
- geometry type (тип геометрии);
- quantity;
- unit;
- measurement count;
- unavailable count;
- rule key/version;
- calibration id/fingerprint, где применимо.

Не делай Excel-движок, шаблоны смет или отчётность Stage 2. Простой CSV достаточно.

CSV должен строиться по серверным quantity results (результатам количеств), а не пересчитываться на фронтенде.

## 5. Acceptance (приёмка)

Добавь один E2E/smoke сценарий или подробный USER_RUN, если браузерная автоматизация среды не может безопасно создать PDF:

- raw PDF;
- ручная калибровка;
- 2 Count;
- одна Polyline;
- один Polygon;
- reload;
- величины те же;
- CSV совпадает с UI/сервером.

## 6. Не делать

- MEP ontology;
- MEP detector;
- P→RD;
- fitting rules;
- pricing;
- новый reports module (модуль отчётов);
- изменения MOCK MEP.

## 7. Проверки и ZIP

Запусти полный доступный набор `lint/typecheck/test/build` и релевантный browser test.

Создай `review/QUANTOR_FASTSTART_P02_REVIEW.zip`.

В конце дай вердикт:

`MANUAL_TAKEOFF_USABLE = YES/NO`.

Если YES — отдельно напиши 5 шагов, как инженер уже может начать пользоваться порталом.

После отчёта остановись.
