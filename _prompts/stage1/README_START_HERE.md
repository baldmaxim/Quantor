# QTO Portal — Stage 1 prompt pack for Claude Code / Opus 5 (1M)

Этот пакет предназначен **только для первого этапа разработки: фундамент и оболочка портала** автоматизированного подсчёта строительных объёмов.

## Что должно получиться после Stage 1

Рабочий web-портал, в который можно создать проект, загрузить уже распознанный пакет документации текущего формата, открыть проект и быстро просматривать PDF с базовой навигацией и отладочным overlay распознанных блоков. Архитектура должна быть готова к будущим AI/CV/QTO-модулям, но **никаких реальных алгоритмов подсчёта объёмов, распознавания элементов или вызовов моделей в Stage 1 не реализуется**.

## Как использовать

1. Распакуйте эту папку в репозиторий, например в `_prompts/stage1/`.
2. Положите тестовый архив распознавалки в `fixtures/legacy/` (исходный пример пользователя: `01-03-00-01-12_ПД-00260560-АР.zip`). Не коммитьте крупный PDF/ZIP в git, если репозиторий для этого не предназначен.
3. В Claude Code используйте **Opus 5 / 1M context**.
4. Выполняйте файлы из `prompts/` строго по порядку. Не отправляйте все промты одной командой.
5. После каждого промта просматривайте `git diff`, запускайте указанные тесты и только затем переходите дальше.
6. Если Claude Code обнаружит уже существующую архитектуру, он обязан адаптировать план к ней, а не уничтожать её ради этого шаблона.

## Порядок

- `00_MASTER_CONTEXT.md` — дать Claude общий контекст и постоянные правила.
- `01_REPO_AUDIT_AND_ARCHITECTURE.md` — аудит репозитория и ADR; минимум кода.
- `02_FOUNDATION_BOOTSTRAP.md` — monorepo/backend/frontend/infra foundation.
- `03_DOMAIN_STORAGE_API_SHELL.md` — минимальная модель данных, storage и API.
- `04_FRONTEND_DESIGN_SYSTEM_APP_SHELL.md` — визуальная оболочка портала.
- `05_PROJECTS_AND_UPLOAD_FLOW.md` — проекты и поток загрузки.
- `06_LEGACY_RECOGNIZED_PACKAGE_IMPORT.md` — тонкий импорт текущего ZIP-формата.
- `07_PROJECT_WORKSPACE_VIEWER_SHELL.md` — быстрый PDF viewer + debug overlay.
- `08_FUTURE_AI_ORCHESTRATION_BOUNDARIES.md` — только контракты будущих AI/CV/QTO сервисов.
- `09_PERFORMANCE_SECURITY_OBSERVABILITY.md` — hardening и тесты.
- `10_STAGE1_ACCEPTANCE_AUDIT.md` — финальная проверка границ и готовности Stage 1.

## Важное правило Stage 1

Не начинать «внутренности» QTO. В Stage 1 **запрещено** реализовывать:

- распознавание стен/дверей/окон/инженерных систем;
- Auto Measure / Auto Count;
- вычисление длин, площадей, объёмов как бизнес-функцию;
- LLM/VLM/CV inference;
- обучение моделей;
- BIM extraction из RVT/NWD/NWC;
- сметный движок;
- отчёты ВОР/Excel как рабочий расчёт;
- сложный агентный runtime.

Допустимы только интерфейсы, data contracts, placeholder UI и минимальный legacy importer, необходимый для открытия уже распознанного пакета.

## Почему такая граница

Главный риск проекта — смешать viewer, распознавание, вычисления и агентный runtime в один сервис. Тогда каждое изменение модели начнёт ломать UI и наоборот. Stage 1 должен создать стабильные границы, чтобы Stage 2 можно было развивать модульно.
