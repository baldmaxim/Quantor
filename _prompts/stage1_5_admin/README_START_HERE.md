# QTO Portal — Stage 1.5: Admin / Control Plane

Этот пакет выполняется **после Stage 1 и до Stage 2 (QTO/AI)**.

Цель Stage 1.5 — превратить базовую оболочку портала в управляемую платформу:

- настоящая аутентификация;
- workspace/tenant isolation;
- роли и разрешения;
- отдельное административное приложение (Control Plane);
- централизованные типизированные настройки;
- управление feature flags;
- безопасная диагностика интеграции TenderHUB;
- заготовка управления AI/model providers без реализации QTO;
- эксплуатационная диагностика storage/jobs/workers;
- audit log всех административных изменений.

## Важно

Пакет составлен по отчёту Stage 1 от 2026-09-07. Переданный одновременно архив `LocalAI-main.zip` НЕ совпадает с описанным QTO-репозиторием: в нём `apps/rag-api`, `apps/rag-ui`, `apps/mcp-server`, а в отчёте QTO указаны `apps/api`, `apps/web`, `packages/api-client`, `docs/adr`, корневой `CLAUDE.md`.

Поэтому первый промт содержит обязательный repository identity gate: Claude Code должен сначала убедиться, что открыт именно репозиторий QTO Portal. Если структура не совпадает — он не имеет права импровизировать или переносить изменения в другой проект.

## Как выполнять

Использовать Claude Code, модель Opus 5 (1M).

Запускать промты строго по порядку. После каждого промта проверить отчёт Claude и состояние тестов. Claude **не должен сам переходить к следующему промту**.

Начать:

```text
Прочитай полностью и выполни:
_prompts/stage1_5_admin/prompts/00_MASTER_STAGE1_5_CONTEXT.md

Не переходи к следующему промту самостоятельно.
```

Рекомендуемое размещение пакета в QTO-репозитории:

```text
_prompts/stage1_5_admin/
```

## Что НЕ входит в Stage 1.5

- ручные измерения;
- AI Auto Count / Auto Measure;
- ScaleResolver;
- CV/VLM распознавание;
- Model Gateway runtime;
- правила расчёта объёмов;
- ProjectGraph;
- BIM/Revit/Navisworks ingestion;
- сравнение ревизий чертежей;
- отчёт ВОР.

Для них будет отдельный Stage 2.
