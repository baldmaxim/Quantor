# ОБЩИЙ КОНТЕКСТ ДЛЯ ВСЕХ ПРОМТОВ

Мы добавляем в расчётный контур `calc` Quantor вторую систему после ВК — пожаротушение — и
автоматическое построение геометрии и трасс по планам АР. Пакет идёт параллельно основному пакету
`_prompts/calc_portal_stage_p/` и не ждёт гейта ВК.

Источник знаний — навык Claude `raschet-pozharotusheniya` владельца:
`/home/usrr/Пожаротушение/Расчет пожаротушения/` (вне git, **только чтение**). Главное в нём:

- `SKILL.md` — порядок работы и результаты;
- `references/lessons.md` — 54 урока эталонного объекта (ошибки и исправления);
- `references/norms_and_pd.md` — где что в ПД, формулы гидрорасчёта, цитаты СП 486 / 1.13130 / 477;
- `references/sheets.md` — чек-лист топологии этажа, правила разводки и трассировки, автостоянка;
- `references/example_339.md` — эталонные цифры объекта 339 (в git не переносятся);
- `scripts/build/pipes_template.py`, `scripts/build/build_svod.py` — формулы надземки и свода;
- `scripts/calc/branch_hydraulics.py` — гидравлика веток;
- `scripts/ar/measure_corridors.py` — замер коридоров (растр — только как описание идеи);
- `scripts/draw/floor_example.py`, `floor_trade.py`, `floor_retail.py`, `parking.py` — разводка этажа,
  торговля, 1-й этаж, трассировка автостоянки.

ВАЖНО:

1. Принципы навыка обязательны:
   - схема ВК даёт топологию (стояки, ветки, СПЖ, затворы, ПК), а не количество; оросители
     считаются двумя способами — по схеме и по АР, в объём идёт АР;
   - каждый отрезок внеквартирного коридора питается от своей шахты «ПТ»; лишние против схемы
     стояки и СПЖ — вопрос проектировщику, а не труба через холл;
   - красный флаг (Ду больше гидрорасчёта ПД, труба через холл, ПБЗ, лестницу или квартиру,
     подводка длиннее отрезка, шахт «ПТ» больше групп стояков) — смена топологии и вопрос, а не
     увеличение диаметра;
   - у каждой величины есть источник или явное допущение; «не посчитано» никогда не 0;
   - расхождения «схема ↔ АР» и ошибки гидрорасчётов ПД — отдельные разделы паспорта.
2. Все ограничения ADR-0030 действуют: цены, ставки, валюта — нет; число от модели — нет; ВОР
   Заказчика как вход — нет; запись в таблицы обмера, MEP и `Region` — нет; замороженные
   компоненты не меняются.
3. Автоматическая геометрия и трассы (ADR-0034) строятся **генератором в исполнителе заданий**
   (`python -m app.worker`), отдельно от `calc`:
   - только векторная геометрия PDF через pypdf: пути, заливки, текст с координатами; растр
     страницы, OCR, PyMuPDF, OpenCV, Shapely, pypdfium2 — нет; скан — «автоматически не построено»;
   - масштаб — только калибровка листа человеком; автоопределение масштаба запрещено; генератор
     проверяет калибровку по площадям помещений против экспликации;
   - результат генератора — кандидат; в расчёт идёт только после принятия человеком;
   - инженерные числа генератора — только из утверждённых правил и фактов; веса алгоритма (цена
     стены, поворота, вес глубины) — часть версии алгоритма с отпечатком;
   - процесс API и `calc` модуль генератора не импортируют; `calc` читает только факты.
4. Скрипты навыка в git не копируются: алгоритмы переписываются на векторной геометрии. Данные
   объекта 339 и любые клиентские П, схемы, планы, своды — вне git и вне внешних API; в репозитории —
   только синтетика, в том числе синтетические векторные PDF.
5. Инженерное число в калькуляторе — только параметр утверждённой версии правила. Код ничего не
   утверждает. Факты проекта (шаг и отступ оросителей, марки, материалы, Ду по зонам, напоры) — из
   документации; норма — резерв со ссылкой на пункт и редакцию.
6. Правила старого портала (48 записей FIRE, `docs/calc/legacy/fire.md`) — только карантин и
   регрессия случая B; идея — новым черновиком через `create_from_legacy`.
7. Раздел — `CalcDiscipline.APT` («Пожаротушение»). Поведение ВК не меняется: golden-тесты ВК
   зелёные на каждом промте. Общие места обобщаются по разделу, а не копируются.
8. Флаги: `calc.portal` закрыт и не включается; генератор и калибровка — дополнительно за
   `takeoff.manual`; проверка и в интерфейсе, и на сервере.
9. После изменений — `pnpm lint`, `pnpm typecheck`, `pnpm test` релевантных частей; при новых
   маршрутах — регенерация `packages/api-client` вручную (см. память о Linux-окружении).
10. Не продолжать следующий промт автоматически. В конце — отчёт в `docs/calc/fire/` и STOP.
    `BLOCKED` не записывается как `PASS`.
