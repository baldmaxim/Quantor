# model_package — выгрузка модели в пакет QMP v1 и привязка листа к осям

Конвертер IFC → пакет QMP v1 по контракту
[docs/building-model/07-model-package-qmp-v1.md](../../docs/building-model/07-model-package-qmp-v1.md),
самопроверка пакета по разделу 9 и привязка листа PDF к модели по подписям осей.
Портал читает только пакет; IFC и PDF разбираются здесь, офлайн.

## Установка

Python 3.12+:

```bash
cd tools/model_package
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` — точные версии ifcopenshell, trimesh, numpy, shapely, PyMuPDF и pytest.
Самопроверка `model_package/qmp_check.py` зависимостей не требует: файл можно скопировать отдельно и
запускать как `python qmp_check.py КАТАЛОГ`.

## Команды

Все команды — из каталога `tools/model_package`.

```bash
# Сборка: один или несколько IFC, дисциплина — по суффиксу имени (…_ARCH.ifc, …_PL.ifc,
# …_ARCH_1 (20260901).ifc), иначе из «:КОД», иначе UNK
python -m model_package build --ifc KPLSK_UD_PD_R22_ARCH_1.ifc --ifc KPLSK_UD_PD_R22_PL.ifc --out qmp_341
python -m model_package build --ifc model.ifc:STR --out qmp_str --only-storey "3_этаж"

# Самопроверка (код выхода 0 — ошибок нет, 1 — есть)
python -m model_package check qmp_341

# Привязка одной страницы (индекс с нуля) и картинка проверки
python -m model_package register --grids qmp_341/grids.json --pdf AR2.pdf --page 8 \
    --out placement_p8.json --png overlay_p8.png --footprint qmp_341/footprints/<этаж>.json

# Все планы PDF: этаж по отметке из заголовка «План … на отм.±N.NNN», привязка по осям
python -m model_package register-all --package qmp_341 --pdf AR2.pdf --out registrations.json
```

Пример для Капельского (ARCH, 12 этажей):

```bash
python -m model_package build --ifc ARCH.ifc --out probe_341/qmp_arch
python -m model_package check probe_341/qmp_arch
python -m model_package register-all --package probe_341/qmp_arch --pdf AR2.pdf
```

Ключи `build`: `--part-limit-mb` (предел части GLB, по умолчанию 60 МиБ — запас к 64 МиБ на неточность
оценки), `--threads` (потоки триангуляции, по умолчанию 1). Каталог `--out` должен быть пустым или
содержать только прежнюю выгрузку (её части удаляются); посторонние файлы — отказ.

## Что делает сборка

1. Входы с одинаковым sha256 — один раз (предупреждение).
2. Единица длины — только из `IfcUnitAssignment`; нет — ошибка.
3. Смещение `frame.origin_offset_mm`: X, Y — перенос `IfcBuilding` (вместе с участком); Z — мировая Z этажа
   минус его `Elevation` (медиана), то есть ноль проекта. Для Капельского `[0, 0, 159400]`.
4. Этажи: отметка — `IfcBuildingStorey.Elevation`; ключ — GlobalId с заменой `$` на `-`; здание — ближайшее
   `IfcBuilding` над этажом. Здания файлов сводятся: тот же GlobalId, иначе то же имя, иначе (в файле и в пакете
   по одному зданию) — одно здание. Этажи следующих файлов привязываются к известным этажам того же здания: тот же
   GlobalId, иначе отметка в пределах 20 мм (при нескольких — то же имя, затем ближайший). Одинаковые отметки
   внутри здания тоже сводятся: отметки этажей здания различны. Если зданий с этажами два и больше (объект 346:
   корпуса, стилобат, подземная часть), этажи пишутся по зданиям с `building_key`/`building_name`, высота — до
   следующего этажа того же здания; одно здание — как раньше, без этих полей.
5. Оси всех `IfcGrid` сводятся по `(tag, dir)`; `dir` — по геометрии (U — вдоль Y), расхождение > 10 мм —
   предупреждение.
6. Элементы: `IfcElement` без проёмов (`IfcFeatureElement`) и `IfcVirtualElement`; вхождение в этаж (или в
   помещение этажа) главнее, затем части агрегатов, вложенные и заполнения проёмов получают этаж родителя
   (части витражей — отдельными строками). Элементы без геометрии остаются в списке с `part: null`.
7. Категории — таблица `categories.py` (версия в `generator.category_table`), для IFC2X3 трубы, воздуховоды и
   лотки — по классу типа.
8. Свойства — только Pset-ы: сначала `Pset_*`, затем прочие в порядке источника; ≤ 24 ключей, строки ≤ 120.
9. Геометрия — ifcopenshell.geom (мировые координаты минус смещение), GLB на этаж и дисциплину: узел на элемент,
   имя узла = id, материал `cat:<category>`, метры, Y вверх; без нормалей и расширений. Части > предела делятся
   на `…__ARCH.1.glb`, `…__ARCH.2.glb`. Элемент, у которого проёмы заданы сетками больше 3000 граней в сумме,
   считается без вычитания проёмов (предупреждение с его id): булева операция над такими проёмами идёт часами
   (в Капельском две плиты отделки паркинга с «швами» на 53–85 тыс. граней — 74 мин из 75).
10. Разрез +1200 мм от отметки: стены (`walls`), колонны (`columns`), витражи и их части (`curtain`).
11. `manifest.json` пишется последним; `manifest_sha256` — без `manifest_sha256` и `generated_at`. Повторная
    сборка тех же файлов даёт те же байты всех частей и тот же хеш (проверяется тестом).

## Привязка листа

`register` ищет подписи осей среди слов текста PDF и коротких аннотаций (в том числе «AutoCAD SHX Text»);
латинские двойники кириллицы приводятся к кириллице. Для каждого направления сетки строятся гипотезы
`лист = a·модель + b` по парам подписей, считаются совпадения (≤ 1 pt), лучшие уточняются МНК. Перебираются
повороты листа 0/90/180/270°. Подгонка принимается, если масштабы по U и V совпали в пределах 0,5 %, на каждое
направление совпало не меньше 5 осей и невязка каждой подписи не больше 1 pt.

Результат (`placement.json`):

```json
{
  "pdf": "AR2.pdf",
  "page": 8,
  "method": "grid_labels",
  "sx": [0.028345, 405.89],
  "sy": [-0.028347, 890.08],
  "scale_ratio": 100.0,
  "matched_u": ["1", "3", "…"],
  "matched_v": ["А", "…"],
  "resid_mm_max": 3.32,
  "resid_mm_rms": 1.48,
  "orientation": 0,
  "ok": true,
  "reasons": [],
  "affine": [
    [0.028345, 0.0, 405.89],
    [0.0, -0.028347, 890.08]
  ],
  "page_size_pt": [2383.9, 1683.7]
}
```

- `лист_pt = a · модель_мм + b`: `sx` — для X модели, `sy` — для Y. При повороте 0/180° X ложится на
  горизонталь листа, Y — на вертикаль; при 90/270° наоборот. Однозначная запись для любого поворота —
  `affine`: `[u, v] = affine · [x_мм, y_мм, 1]`.
- Координаты листа — пространство неповёрнутой страницы PDF (как отдаёт PyMuPDF: начало сверху слева, ось
  вниз), не зависят от `/Rotate` страницы.

`register-all` сопоставляет отметку заголовка с `elevation_mm` этажей: допуск 300 мм, расхождение > 20 мм —
предупреждение, два кандидата и больше — «неоднозначно», этаж не выбирается. Лист с несколькими отметками
(«План типовых этажей … на отм. +14.620, +18.700») относится ко всем найденным этажам.

## Самопроверка

`check` повторяет раздел 9 спецификации и правила серверного модуля `apps/api/app/services/model_package.py`:
схема и поля, пути, повторы, размеры и sha256 частей, `manifest_sha256`, заголовок и JSON-блок GLB, узлы для
элементов, этажи элементов, возрастание отметок, счётчики; предупреждения — высота и габарит этажа, нет сетки,
`other` больше половины, файлы каталога вне манифеста, тот же источник, что у прежней версии
(`--previous manifest.json`). Неизвестные поля — предупреждение, не ошибка (раздел 10 спецификации).

## Нагрузка

Триангуляция — один поток (`--threads 1`); IFC открывается целиком в память (Капельский, 172 МБ: около
20 с, пик ~1,8 ГБ ОЗУ, вся сборка ~5,5 мин). Файлы обрабатываются по одному.

## Тесты

```bash
python -m pytest -q
```

Синтетический IFC (`tests/synth_ifc.py`: 2 этажа, сетка 3×2, стены, колонна, витраж из частей, проём,
второй файл PL с этажами в пределах 20 мм, вариант IFC2X3) и синтетический лист
(`tests/synth_pdf.py`: марки осей, штриховка, экспликация, «ложный ряд» цифр в масштабе 1:200, разбросанные
номера помещений, четыре поворота листа).
