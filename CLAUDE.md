# CLAUDE.md — Quantor / QTO Portal

Дополняет `Odintsov/CLAUDE.md`. При конфликте приоритет у этого файла.

Портал автоматизированного подсчёта строительных объёмов по проектной документации.
Работа ведётся по пакету промтов `_prompts/stage1/` строго по порядку.

## Стек

Отступление от общего стека каталога зафиксировано в [ADR-0000](docs/adr/0000-otstuplenie-ot-obshchego-steka.md).

- `apps/web` — Next.js (App Router) + React + TypeScript strict, Tailwind, TanStack Query, Zustand, Zod
- `apps/api` — Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2 async + Alembic
- `packages/api-client` — TypeScript-клиент, **генерируется** из OpenAPI, руками не правится
- `infra` — PostgreSQL/PostGIS и MinIO в docker compose

## Команды

```bash
pnpm install && pnpm run setup   # node- и python-зависимости
pnpm infra:up                    # postgres + minio
pnpm dev                         # api :8000 + web :3000
pnpm lint                        # ruff + eslint
pnpm typecheck                   # mypy + tsc
pnpm test                        # pytest + vitest
pnpm build                       # генерация клиента + сборка web
pnpm db:migrate                  # alembic upgrade head
pnpm api-client:generate         # FastAPI -> openapi.json -> TS
```

## Границы этапа

Stage 1 — фундамент и оболочка. Реально работают: проекты, загрузка и импорт распознанного
пакета, просмотр PDF с отладочным слоем распознанных областей.

**Запрещено реализовывать на Stage 1:**

- распознавание элементов (стены, двери, окна, инженерные системы);
- Auto Measure / Auto Count;
- вычисление длин, площадей и объёмов как бизнес-функцию;
- определение масштаба чертежа;
- инференс CV/LLM/VLM и любые вызовы моделей;
- извлечение данных из BIM (RVT/NWD/NWC/IFC) — файлы только хранятся;
- сметный движок и отчёты ВОР как рабочий расчёт;
- агентный runtime.

Допустимы интерфейсы, контракты данных, выключенные заглушки интерфейса и импортёр legacy-пакета.

## Архитектурные правила

- Бинарные файлы — только в объектном хранилище, никогда в PostgreSQL ([ADR-0002](docs/adr/0002-hranenie-binarnyh-fajlov.md)).
- Загрузка и выгрузка потоковые, с ограниченной памятью. Никакого base64 в JSON.
- `DocumentRevision` неизменяем; повторная загрузка создаёт новую ревизию ([ADR-0003](docs/adr/0003-neizmenyaemye-revizii.md)).
- `Region` ≠ `Measurement` ≠ `Quantity` — три разные сущности, не переиспользовать ([ADR-0008](docs/adr/0008-koordinaty-i-proishozhdenie.md)).
- Координаты хранятся нормализованными от левого верхнего угла; перевод — только при отрисовке.
- Пользовательские архивы недоверенные: защита от path traversal и zip-бомб обязательна.
- `crop_url` из legacy-пакета сервер **не загружает** никогда.
- Контракт API один — OpenAPI. Ручные TypeScript-DTO запрещены.
- Тяжёлые зависимости просмотрщика (`pdfjs-dist`, WebGL) грузятся только на маршруте рабочей области.
- Панорамирование и зум не проходят через состояние React ([ADR-0004](docs/adr/0004-arhitektura-prosmotrshchika.md)).
- Бизнес-логика не зависит от имени конкретной модели ([ADR-0006](docs/adr/0006-shlyuz-modelej.md)).
- Claude Code и Cursor — инструменты разработки, не часть продукта.

## Правила работы

- Сначала читать, потом менять. Репозиторий не считать пустым.
- Строгая типизация. `any`, `# type: ignore`, отключение правил линтера — запрещены,
  ошибка чинится кодом.
- Не удалять полезную существующую архитектуру ради шаблона; расхождение оформлять новым ADR.
- После изменений прогонять lint / typecheck / test релевантных частей.
- `git commit`, `push`, `merge` — только по явной команде пользователя.
- `.env` не изменять; ключи и адреса пользователь добавляет сам.
- Не копировать бренд и оформление Kreo — только рабочие сценарии как ориентир.
- Не начинать следующий промт этапа самостоятельно.
