# CLAUDE.md — Quantor / QTO Portal

Дополняет `Odintsov/CLAUDE.md`. При конфликте приоритет у этого файла.

Портал автоматизированного подсчёта строительных объёмов по проектной документации.
Работа ведётся по пакету промтов `_prompts/stage2b_ai_geometry_qwen/` строго по порядку,
по одному промту за раз.

## Стек

Отступление от общего стека каталога зафиксировано в [ADR-0000](docs/adr/0000-otstuplenie-ot-obshchego-steka.md).

- `apps/web` — Next.js (App Router) + React + TypeScript strict, Tailwind, TanStack Query, Zustand, Zod
- `apps/api` — Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2 async + Alembic
- `packages/api-client` — TypeScript-клиент, **генерируется** из OpenAPI, руками не правится
- `infra` — PostgreSQL/PostGIS и MinIO в docker compose

## Команды

```bash
pnpm install && pnpm run setup   # node- и python-зависимости
pnpm infra:up                    # postgres + minio
pnpm dev                         # api :8000 + web :3000
pnpm lint                        # ruff + eslint
pnpm typecheck                   # mypy + tsc
pnpm test                        # pytest + vitest
pnpm build                       # генерация клиента + сборка web
pnpm db:migrate                  # alembic upgrade head
pnpm api-client:generate         # FastAPI -> openapi.json -> TS
pnpm benchmark:measurement       # замер точности и стоимости измерительного ядра
pnpm benchmark:viewer            # замер просмотрщика: холсты, память, отрисовка, панорама (ADR-0024)
```

## Границы этапа

Stage 1, 1.5 и 2A закрыты: фундамент, оболочка, импорт распознанного пакета, просмотр PDF,
аутентификация, рабочие пространства, админ-контур и **ручное измерительное ядро** — каноническая
геометрия PDF, калибровка масштаба, `TakeoffItem` и `Measurement`, инструменты Count / Line /
Polyline / Polygon, детерминированный расчёт `count.v1` / `length.v1` / `area.v1`. Итог
Stage 2A — PASS 15 / FAIL 0 ([16-acceptance](docs/stage2a/16-acceptance.md)).

**Stage 2B — AI Geometry Lab** ([ADR-0020](docs/adr/0020-napravlenie-stage-2b-ai-geometry-lab.md)).
Задача этапа: на PlanSwift ground truth честно сравнить архитектуры, которые строят геометрию, и
только прошедшую гейт интегрировать в портал. Пилоты — площадь плиты с отверстиями и осевые линии
кладки.

```text
PlanSwift GT → малая сегментация / SAM 2 / Qwen3-VL + Unsloth / Qwen→SAM
→ маска или вектор → Mask→Vector → кандидат → проверка человеком
→ Measurement(source=ai) → существующий Quantity Engine
```

**Разрешено на Stage 2B:**

- масштабируемый просмотрщик: слои размером с область просмотра, пространственный индекс, по замеру —
  отрисовка PDF по видимой части;
- валидность геометрии и отверстия многоугольника;
- частный офлайн-импорт PlanSwift и сборка датасета — вне git и вне производственного API;
- отдельный ML-контур `vision/`: обучение, оценка, векторизация, бенчмарк ([ADR-0021](docs/adr/0021-oflajn-eksperiment-ne-proizvodstvennaya-vozmozhnost.md));
- модели и веса только с записью в матрице лицензий: SAM 2, MobileSAM, официальные Qwen3-VL
  2B / 4B / 8B Instruct, Unsloth core в изолированном окружении обучения;
- после PASS Prompt 18 и утверждения владельцем конкретных pipeline и checkpoint — домен
  кандидатов, доверенный исполнитель инференса, проверка человеком, AI-интерфейс за флагом
  `takeoff.ai`.

**По-прежнему запрещено:**

- выдавать моделью физическую величину — метры и м² считает только детерминированный движок;
- автоматическое определение масштаба, в том числе чтение надписи `М 1:100`;
- автоматическое распознавание размерных линий;
- семантические строительные правила и вычитание проёмов;
- объём, масса, стоимость;
- извлечение данных из BIM (RVT/NWD/NWC/IFC) — файлы только хранятся;
- генерация Revit/IFC, ProjectGraph и агентный runtime;
- сметный движок и ВОР как рабочий отчёт;
- сравнение ревизий чертежа;
- клиентские чертежи и данные PlanSwift во внешних API без отдельного решения владельца;
- Ultralytics без решения владельца о коммерческой лицензии; Unsloth Studio внутри Quantor;
- torch, SAM, OpenCV, Transformers и Unsloth в процессе `apps/api`;
- менять test-разбиение по результатам модели;
- промты 19–24 без PASS Prompt 18 и утверждения владельцем.

Флаг `takeoff.manual` — пилотная возможность: готов, выключен по умолчанию, включается на
пространство через админку и закрывает возможность и в интерфейсе, и на сервере
([ADR-0023](docs/adr/0023-pilotnyj-flag-zakryvaet-vozmozhnost-na-servere.md)). `takeoff.ai` и
`models.gateway` выключены и из админки не включаются, пока не пройдены гейты производственной
интеграции.

## Архитектурные правила

- Бинарные файлы — только в объектном хранилище, никогда в PostgreSQL ([ADR-0002](docs/adr/0002-hranenie-binarnyh-fajlov.md)).
  Маски, веса и датасеты — тоже: в базе только ключи и хеши.
- Загрузка и выгрузка потоковые, с ограниченной памятью. Никакого base64 в JSON.
- `DocumentRevision` неизменяем; повторная загрузка создаёт новую ревизию ([ADR-0003](docs/adr/0003-neizmenyaemye-revizii.md)).
- `Region` ≠ `PredictionCandidate` ≠ `Measurement` ≠ `Quantity` — разные сущности, не
  переиспользовать ([ADR-0008](docs/adr/0008-koordinaty-i-proishozhdenie.md), [ADR-0022](docs/adr/0022-kandidat-predskazaniya-otdelyon-ot-izmereniya.md)).
- Непроверенное предсказание не входит в рабочий итог: принятие создаёт обычный
  `Measurement(source=ai)` доверенным сервисом. Ручной HTTP-эндпоинт `source` не принимает.
- Происхождение модели обязательно: хеши весов, входа и выхода, версии конфигураций.
- Координаты хранятся нормализованными от левого верхнего угла; перевод — только при отрисовке.
  Истина координаты не зависит от разрешения растра.
- Поворот страницы к нормализованным координатам legacy-v1 повторно не применяется: отрисовщик
  уже применил его сам ([ADR-0008](docs/adr/0008-koordinaty-i-proishozhdenie.md)).
- `Sheet.width_px/height_px` — размер растра распознавалки, а не геометрия документа. В расчёте
  физических величин не участвует никогда.
- Физические длины и площади считаются только через каноническую геометрию PDF и явную
  калибровку; результат клиента не является источником правды.
- Слои наложения — Canvas2D; WebGL только после замера ([ADR-0015](docs/adr/0015-sloi-nalozheniya-na-canvas2d.md)).
- У задания есть явная область видимости: `workspace_id` пуст только у общесистемного,
  и такое задание не видно ни одному рабочему пространству.
- Пользовательские архивы недоверенные: защита от path traversal и zip-бомб обязательна.
- `crop_url` из legacy-пакета сервер **не загружает** никогда.
- Контракт API один — OpenAPI. Ручные TypeScript-DTO запрещены.
- Тяжёлые зависимости просмотрщика (`pdfjs-dist`, WebGL) грузятся только на маршруте рабочей области.
- Панорамирование и зум не проходят через состояние React ([ADR-0004](docs/adr/0004-arhitektura-prosmotrshchika.md)).
- Бизнес-логика не зависит от имени конкретной модели ([ADR-0006](docs/adr/0006-shlyuz-modelej.md)).
- Флаг пилотной возможности проверяется и интерфейсом, и сервером ([ADR-0023](docs/adr/0023-pilotnyj-flag-zakryvaet-vozmozhnost-na-servere.md)).
- Claude Code и Cursor — инструменты разработки, не часть продукта.

## Правила работы

- Сначала читать, потом менять. Репозиторий не считать пустым.
- Строгая типизация. `any`, `# type: ignore`, отключение правил линтера — запрещены,
  ошибка чинится кодом.
- Не удалять полезную существующую архитектуру ради шаблона; расхождение оформлять новым ADR.
- После изменений прогонять lint / typecheck / test релевантных частей.
- `git commit`, `push`, `merge` — только по явной команде пользователя.
- `.env` не изменять; ключи и адреса пользователь добавляет сам.
- Не копировать бренд и оформление Kreo — только рабочие сценарии как ориентир.
- Не начинать следующий промт этапа самостоятельно.
- Частные данные PlanSwift, растры, датасеты и веса в git не попадают; в репозитории — только
  синтетические fixtures.
- `BLOCKED` не записывается как `PASS`: невыполнимый в среде шаг помечается честно.
