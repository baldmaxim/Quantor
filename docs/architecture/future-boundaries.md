# Границы будущих сервисов

Документ описывает, куда именно подключится Stage 2, чтобы подключение не потребовало
переделки оболочки. Реализаций у описанного нет: на Stage 1 это типы, правила и точки
расширения.

Код контрактов: [`apps/api/app/contracts/`](../../apps/api/app/contracts/).
Проверка границ: `apps/api/tests/test_contracts.py`.

## 1. Шлюз моделей

Между бизнес-логикой и моделями всегда стоит шлюз ([ADR-0006](../adr/0006-shlyuz-modelej.md)).
Модуль формулирует требование в терминах **возможностей**, а не имён:

```python
requirement = ModelRequirement(
    modalities=frozenset({Modality.VISION}),
    structured_output=True,
    must_run_locally=True,   # документация не покидает периметр заказчика
)
```

Паспорт модели (`ModelCapabilities`) описывает: поставщика и модель, модальности,
структурированный вывод, вызов инструментов, размер контекста, ограничения на изображения,
допустимую параллельность, класс задержки и стоимости, признак локального исполнения.

Правила, которые нельзя нарушать:

- ветвление `if provider == "..."` в бизнес-коде запрещено;
- `provider_id` и `model_id` попадают в происхождение результата — без них результат
  необъясним;
- ключи не хранятся в базе открытым текстом и не редактируются через интерфейс;
- на Stage 1 в зависимостях нет ни одного SDK моделей.

Ожидаемые адаптеры: локальные OpenAI-совместимые серверы (vLLM, SGLang, llama.cpp),
удалённые OpenAI-совместимые сервисы, Anthropic, OpenAI, собственные VLM-сервисы.

## 2. Конвейер обработки

```text
ingest → sheet_parse → ocr_layout → vector_extract → symbol_detect
       → semantic_link → measure → quantity_calculate → verify → export
```

Каждый шаг — отдельное задание со своим состоянием, входными и выходными артефактами.
Таблица `STAGE_CONTRACTS` фиксирует для каждого: идемпотентность, повторяемость,
отменяемость, возобновляемость и обращение к моделям.

Отдельно закреплено: **`quantity_calculate` не обращается к моделям**. Величина обязана
воспроизводиться при повторном расчёте, поэтому её считает детерминированный сервис по
правилу с версией.

Выбор исполнителя и пороги перехода — [ADR-0010](../adr/0010-orkestrator-buduschego-konvejera.md).

## 3. Область подсчёта объёмов

Три понятия, которые нельзя смешивать ([ADR-0008](../adr/0008-koordinaty-i-proishozhdenie.md)):

| Понятие       | Что это                                       | Кто создаёт              |
| ------------- | --------------------------------------------- | ------------------------ |
| `Region`      | что увидела распознавалка — свидетельство     | импорт, распознавание    |
| `Measurement` | геометрия, созданная для подсчёта — намерение | человек или ИИ           |
| `Quantity`    | вычисленная величина с указанием правила      | детерминированный сервис |

`Region` не превращается в `Measurement`: из него можно только создать новый объект,
сославшись на него как на свидетельство. Смешение этих понятий означает, что правка разметки
молча меняет посчитанный объём, — защитить такой результат перед заказчиком нечем.

Таблиц для `Measurement` и `Quantity` на Stage 1 нет намеренно: пока нет реальных расчётов,
любая схема окажется неверной.

## 4. Масштаб чертежа

`ScaleCalibration` объявлен типом, но не вычисляется. Интерфейс честно пишет «Масштаб
чертежа: Не задан». Тип нужен заранее, чтобы измерения сразу проектировались с оглядкой на
калибровку: единицы, источник (вручную, по распознанному размеру, из импорта), точки
проверки и признак подтверждения человеком.

## 5. Флаги возможностей

`app/core/features.py` отдаёт набор флагов, а `/api/v1/meta` — их значения. Интерфейс берёт
список оттуда и не хранит свою копию.

Выключены по умолчанию: `takeoff.manual`, `takeoff.ai`, `models.gateway`, `reports`,
`bim.import`, `drawing.compare`.

Флаги переопределяются переменной `FEATURE_FLAGS` (`takeoff.ai=true,reports=true`) — для
демонстраций и отладки. Включение флага не создаёт функциональность, оно лишь перестаёт её
прятать.

## 6. Инструменты разработки не являются частью продукта

Claude Code и Cursor — инструменты разработки. Ни одна функция портала не может зависеть от
запущенного агента в IDE, и ни один сценарий работы пользователя не проходит через них.
Оркестрация во время работы продукта живёт на сервере и переживает перезапуск.

Это ограничение проверяемо: в зависимостях портала нет ни одного пакета, связанного
с агентами разработки.
