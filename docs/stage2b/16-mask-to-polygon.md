## 1. Что взято из SU10

Разбор передачи SU10 (2026-09-14) показал, что у коллеги этот шаг уже есть в чистом виде:
`area_candidate_geometry_v001.py` — обход пиксельных рёбер без потерь, отверстия по вложенности.
Взяты алгоритм обхода (поворот к своей клетке на диагональном касании) и привязка отверстия к
наименьшему охватывающему кольцу; код переписан без numpy и типизирован. Добавлено то, чего у SU10 нет
и без чего кандидат не пройдёт портал:

- **разведение перетяжек:** вершина, через которую граница проходит дважды, сдвигается на
  `pinch_nudge_px` внутрь своей клетки — касание в промте 05 — пересечение, а не валидный контур;
- **упрощение с ограничением площади:** Дуглас — Пекер с откатом допуска вдвое, пока изменение
  нетто-площади ≤ `max_area_change_ratio` и контур валиден; последний вариант — без упрощения;
- **проверка валидности портала:** `vector/validity.py` — копия `apps/api/.../geometry/validity.py`;
  тест сверяет текст построчно (кроме импорта) и значения кодов с `GeometryIssueCode`;
- **сшивка тайлов голосованием** и **метрики против векторной разметки**.

## 2. Конвейер

```text
маски тайлов <run>/predictions/<split>/*.png    (SHA-256 сверяется с <split>-predictions.jsonl)
→ сшивка листа: доля покрывающих тайлов с плитой ≥ vote_threshold (0,5; ничья — плита)
→ морфология: нет (польза на val не проверена)
→ рёбра пикселей → кольца → углы               площадь кольца = число пикселей, точно
→ отверстие → наименьшее охватывающее внешнее кольцо
→ отверстия < min_hole_px заливаются, области < min_component_px отбрасываются — со счётчиками
→ разведение перетяжек → упрощение с откатом → нормализованные координаты листа
→ валидность промта 05: недействительный — status=invalid с кодом, площади не даёт
```

Связность: плита 4-связна, фон 8-связен. Пустой пиксель, касающийся наружного фона углом, — не
отверстие, а перетяжка внешнего кольца.

Координаты: рабочий пиксель (x, y) → `x · downsample / source_width` (как `TileTransform` промта 08),
отсчёт от левого верхнего угла листа. Масштаба и метров здесь нет.

## 3. Настройка — `vectorize_polygon_v1`

| Ключ                    | По умолчанию | Смысл                                                         |
| ----------------------- | -----------: | ------------------------------------------------------------- |
| `vote_threshold`        |          0,5 | доля тайлов с плитой для пикселя в перекрытии                 |
| `min_component_px`      |          256 | меньше — обрывок (16×16 рабочих px = 32×32 px TIFF)           |
| `min_hole_px`           |           64 | меньше — шум, заливается                                      |
| `simplify_tolerance_px` |          1,5 | стартовый допуск упрощения                                    |
| `min_tolerance_px`      |         0,25 | ниже — без упрощения                                          |
| `max_area_change_ratio` |         0,01 | предел изменения нетто-площади многоугольника упрощением      |
| `pinch_nudge_px`        |         0,05 | сдвиг вершины перетяжки                                       |
| `edge_budget`           |    4 000 000 | больше рёбер на листе — `too_complex`, не зависание           |
| `metric_stride_px`      |            2 | шаг растеризации метрик покрытия                              |
| `boundary_tolerance_px` |            3 | допуск Boundary F1 (6 px TIFF)                                |
| `coverage_to_recall`    |          0,5 | доля покрытия, чтобы плита или отверстие считались найденными |

Значения объявлены до val. Меняются только `--set` на val; хеш настройки — имя каталога результатов.
Test принимает только настройку, у которой уже есть val-метрики, и только один раз.

## 4. Метрики против разметки PlanSwift

| Метрика                        | Как считается                                                               |
| ------------------------------ | --------------------------------------------------------------------------- |
| ошибка нетто-площади листа     | Σ(внешнее − отверстия) годных многоугольников против той же суммы разметки  |
| ложная площадь листа без плиты | площадь прогноза / площадь листа — закрывает пробел метрики промта 11       |
| полнота плит                   | плита разметки покрыта прогнозом ≥ 0,5 её площади                           |
| точность многоугольников       | многоугольник прогноза лежит в плитах разметки ≥ 0,5 своей площади          |
| полнота отверстий              | отверстие найденной плиты оставлено пустым ≥ 0,5 его площади                |
| граница                        | точки через 1 px вдоль колец; F1 при допуске 3 px; медиана и p90 расстояния |
| недействительные               | доля и коды промта 05                                                       |
| вершины                        | углы решётки → вершины после упрощения, коэффициент сжатия                  |

Разметка читается из `planswift-gt-v1` (`annotations.jsonl`) с отбором и снятием дублей, как у
сборщика промта 08; перекрывающиеся плиты разметки в сумме площади считаются дважды — так же, как
их посчитал бы `area_with_holes.v1` по отдельным измерениям.

## 5. Артефакты и происхождение

```text
<run>/vector/<config12>/config.json            настройка и SHA-256
<run>/vector/<config12>/<split>/<page>.json    многоугольники, коды, хеши масок-источников, digest
<run>/vector/<config12>/<split>-metrics.json   сводка, листы, хеши манифеста прогнозов, tiles и разметки
```

Маска остаётся доказательством; вектор — производный артефакт с версией, хешем настройки и хешами
масок. Изменённая после прогноза маска — отказ.

## 7. Ограничения

- Контур — пиксельная ступенька рабочего растра, упрощённая с ограничением площади: это не
  «родная» линия чертежа. Точность границы ограничена разрешением прогноза (1 рабочий px = 2 px TIFF).
- Полнота плит и отверстий — по покрытию площади, а не по сопоставлению объектов; сопоставление
  (минимальная стоимость, как `prepared_min_cost_matching.py` SU10) нужно, когда появятся экземпляры.
- Ошибка площади листа суммирует разметку без объединения перекрытий.
- Скорость — чистый Python на обходе границы: лист с шумным прогнозом упирается в `edge_budget`.
