# Решения владельца Stage 2B

Журнал решений, принятых после промтов 01–09. Каждое — с датой, основанием и тем, что изменено в
репозитории. Открытые вопросы — в конце.

## 2026-09-14

### Р-1. Прямой полигон от Qwen не поддерживается

- **Решение:** `qwen_slab_polygon_v0` — неподдерживаемый вид. Путь для плит — `qwen_slab_localization_v1`
  → SAM → mask→vector (промт 14).
- **Основание:** при тайле 1 024 ни один тайл не содержал все плиты целиком — 0 положительных
  примеров; окна вокруг разметки чинят только train, а в val/test это утечка (промт 08, § 5).
- **Изменено:** сборщик больше не пишет вид; причина — в `build.json → unsupported_views`; настройки
  `qwen_polygon_max_vertices` и `qwen_simplify_tolerance_px` удалены из конфига; тест проверяет, что
  файла вида нет.

### Р-2. Unsloth разрешён для локального обучения — с условиями

- **Решение:** обучение Qwen можно вести на Unsloth в локальном окружении владельца.
- **Условия** (следуют из аудита, `vision/licenses/decisions.json`): wheel `unsloth 2026.9.4` несёт
  AGPL-3.0 — `studio/` и `unsloth/kernels/moe`; `unsloth-zoo 2026.9.3` объявлен LGPL-3.0, но 41 файл
  с заголовком AGPL-3.0. Поэтому:
  - только окружение обучения на GPU-машине владельца; не в `apps/api` и не в производственном образе;
  - окружение, образ или архив с файлами Unsloth не распространяются;
  - Unsloth Studio не запускается и не встраивается;
  - checkpoint сохраняется стандартным safetensors / PEFT-адаптером и загружается без Unsloth —
    инференс (промт 20) Unsloth не требует;
  - версии `unsloth`, `unsloth-zoo` и SHA-256 их wheel пишутся в `run.json` каждого прогона.
- **Изменено:** решения `unsloth` и `unsloth-zoo` — `conditional`; extra `vision[qwen-unsloth]`;
  формулировка в `CLAUDE.md`; матрица лицензий. Apache-стек `transformers + peft + trl` остаётся
  запасным путём и путём инференса.
- **Открыто:** размер модели — см. О-2.

### Р-3. «Плита» — нетто, как в разметке сметчика

- **Решение владельца:** подтверждено. Класс «плита» — плиты перекрытия и фундаментная плита;
  маска — тело плиты с вычтенными отверстиями, включая отверстия под термовкладыши и капители.
- **Основание:** 481 из 482 термовкладышей и 21 из 23 капителей лежат в отверстиях плит — сметчик
  считал площадь плиты нетто; цель совпадает с числом `area_with_holes.v1` по той же разметке.
- **Изменено:** ничего — так собрана сборка промта 08. Несостыковки (2 капители без отверстия,
  1 термовкладыш вне плит, 3 плиты в папке «Балки») остаются замечанием для ручного QA.

### Р-4. Обучение — локально на машине владельца, RTX 5050

- **Решение владельца:** всё обучение и оценку владелец выполняет у себя; от разработки —
  инструкции и код, проверенный на синтетике без GPU. Инструкция — [gpu-runbook](gpu-runbook.md).
- **Следствия RTX 5050 (Blackwell, 8 ГБ):** PyTorch под CUDA 12.8+; Qwen3-VL-4B — только 4-битным
  (QLoRA); BF16-замер без дообучения — для 2B, для 4B BLOCKED по памяти; 8B — не рассматривается.
  Малая сегментация и SAM 2 small помещаются.
- **Обмен:** в чат — только текст (`run.json`, `metrics.json`, логи); изображения, тайлы и веса — нет.

## 2026-09-15

### Р-5. Малый U-Net — нижняя граница; дальше SAM

- **Решение владельца:** `slab-tinyunet-b16-v1` оценён на test один раз, порог 0,5 из `run.json`
  без подбора; U-Net v2 не делается; следующий шаг — промт 11 (SAM 2 / MobileSAM).
- **Основание:** val IoU 0,272, Boundary F1 0,021, ошибка нетто-площади по листу — медиана 21 %,
  максимум 388 %; test IoU 0,135, ошибка единственного листа с плитой 85 %. Порог не рычаг (плато
  IoU при 0,50–0,60), модель не держит контур и отверстия; train — 77 тайлов одного проекта.
- **Изменено:** результаты — [10, § 7](10-slab-small-baseline.md); число test — нижняя граница для
  сравнения в промте 18.

### Р-6. SAM: test обеих политик по одному разу; дальше промт 12

- **Решение владельца:** `sam-coarse-small-v1` и `sam-auto-small-v1` оценены на test по одному разу с
  настройками по умолчанию, объявленными до val; MobileSAM не выполняется; дообучение SAM не начинается;
  следующий шаг — промт 12 (промт 14 опирается на обученный Qwen промта 13).
- **Основание:** test IoU — U-Net 0,135, `coarse` 0,154, `auto` 0,054; ошибка площади единственного
  test-листа — 85,5 %, 65,5 %, 287,6 %. SAM уточняет подсказку, но не находит пропущенное; без подсказки
  заливает всё замкнутое.
- **Изменено:** результаты — [11, § 8](11-sam-baselines.md); три строки — нижние границы для промта 18.

### Р-7. Берём лучшее из SU10; промт 16 — раньше 13–15

- **Решение владельца:** проект SU10 другого участника (передача 2026-09-14, конечная цель — модель
  Revit) — источник проверенных решений: забирать у него лучшее, не повторять уже сделанное. SU10
  внедряется в Quantor позже. SU10 ограничен ресурсами и использует малые модели; Quantor может брать
  модели крупнее. Проектов PlanSwift у владельца много — загружены пока не все. Промт 16 выполняется
  до промтов 13–15.
- **Основание:** разбор SU10 — у коллеги уже измерены и закрыты: U-Net с нуля на ФП (IoU 0,07, хуже
  априорного прогноза), DINO → SAM 2.1 (границы не улучшаются, IoU ≈ 0,41), Qwen как визуальный
  ранжировщик (≈ 0,5); лучший сигнал по плитам — замороженный DINOv3 как грубый локатор (OOF IoU 0,58).
  Это совпадает с промтами 10–11 Quantor. Весов и данных в передаче нет.
- **Изменено:**
  - промт 16 построен на обходе контуров SU10 (`area_candidate_geometry_v001.py`) с доработками
    под валидность портала — [16](16-mask-to-polygon.md);
  - к правилам данных добавляются правила SU10 для следующих сборок: неразмеченное — «неизвестно», а
    не фон; отложенные проекты вместо отложенных листов одного проекта; контроли (априорный прогноз,
    подмена изображения); худший проект в отчёте; критерии остановки — до прогона;
  - лицензии кода и весов SU10 при переносе проходят гейт `vision/licenses`: ultralytics и PyMuPDF
    (AGPL), веса DINOv3 (лицензия Meta), C-RADIO (лицензия NVIDIA) — без решения не используются.
- **Открыто:** О-5 (данные) и О-6 (крупнее модели) ниже.

### Р-8. Следующая модель плит — замороженный DINOv2 ViT-L с лёгкой головой

- **Решение владельца:** одобрено предложение по О-6.
- **Основание:** лучший измеренный сигнал SU10 по плитам — замороженный DINOv3 как грубый локатор
  (OOF IoU 0,58 на отложенных компонентах); U-Net с нуля и SAM не держат плиту (промты 10, 11, 16).
  DINOv2 — тот же класс энкодера, но веса под Apache-2.0; DINOv3 — только после решения по лицензии Meta.
- **Изменено:** `vision train slab --arch dinov2-probe` — энкодер `facebook/dinov2-large` закреплён
  ревизией и SHA-256, заморожен, признаки val считаются один раз; обучается голова ≈ 0,85 млн
  параметров, в `best.pt` — только она. Оценка — тем же `vision evaluate slab`, test один раз; маски
  идут в векторизацию промта 16. Строки весов — в матрице лицензий.
- **Ограничение:** шаг патча 14 px — модель локализует плиту, границу и отверстия уточняют SAM или
  векторизация. Сравнение с U-Net и SAM честное только на той же сборке v1; после сборки v2 (О-5) —
  все три заново.
