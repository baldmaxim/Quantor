# Промт 08 — тайлы, цели, разбиение и утечка

Дата: 2026-09-14. Сборщик — `pnpm planswift build` (`tools/planswift_gt`), вход — `planswift-gt-v1`
([06](06-planswift-import.md), [07](07-ground-truth-validation.md)).

> **Контрольная точка владельца перед обучением.** Разбиение заморожено, но ни одна модель на нём не
> обучалась. Решения ниже — определение класса «плита», доли разбиения, отказ от полигонального вида
> Qwen v0 — на ревью владельца до промтов 10–15.

## Итог

- **Сборка воспроизводима и без зависимостей:** `build.json`, `split.json` с SHA-256, `tiles.jsonl`,
  тайлы, маски, цели осевой и три вида Qwen; повторная сборка — те же хеши (проверено тестом).
- **Все четыре проверки утечки — true** на реальной сборке: оценочные тайлы только из сетки, лист не
  попадает в две части, инструкции постоянные, имена файлов непрозрачные.
- **Бенчмарк честно называется `within-project grouped holdout`** — по одному проекту на домен.
- **Класс «плита» уточнён по данным:** из 602 контуров Мосфильмовской 482 — термовкладыши и 23 —
  капители; цель плиты — 94 контура плит перекрытия и фундаментной плиты с их 835 отверстиями.
- **Маска сохраняет отверстия:** площадь каждой маски совпадает с «контур − Σ отверстий» до 0,09 %.
- **`qwen_slab_polygon_v0` не жизнеспособен** при тайле 1 024: ни одного тайла, где все контуры
  плит целиком внутри. Вид собран пустым по положительным примерам и так и помечен.
- **Разбиение Stories перекошено по объективной причине:** 11 из 16 листов — один кластер типовых
  этажей; 84 / 6 / 11 % аннотаций.

## 1. Цели

### Плита / фундаментная плита — маска с отверстиями

- Растровая цель — маска 0/255 рабочего растра: внешний контур минус отверстия по правилу чёт-нечет
  по центрам пикселей. Морфологии нет — отверстие не заплывает.
- Главная истина оценки — векторная разметка `planswift-gt-v1`; маска — только для обучения.
- Какие контуры — плиты, задаётся метками позиций PlanSwift в частном конфиге, а не догадкой кода.
  Разбор меток Мосфильмовской:

| Позиция PlanSwift (папка)                  | Контуров | В цели «плита»          |
| ------------------------------------------ | -------: | ----------------------- |
| Термовкладыш (Плиты перекрытий)            |      482 | нет — вкладыш, не плита |
| Плита перекрытия (Плиты перекрытий, Балки) |       62 | да                      |
| Фундаментная плита                         |       35 | да                      |
| Капитель (Плиты перекрытий)                |       23 | нет — отдельный элемент |

Все 835 отверстий принадлежат плитам. Дубли геометрии из промта 07 входят в цель один раз.

Проверка маски на 10 листах с плитами: объединённая маска против аналитической площади — до 0,08 %
на девяти листах; на одном 10,1 %, и там сумма отдельных масок совпадает с аналитикой до 0,09 % —
разница целиком перекрытие контуров (объединение считает общую часть один раз).

### Кладка — цель осевой по расстоянию

- GT — осевая полилиния. Цель — «шапка» расстояния: 255 на линии, линейный спад до 0 на
  `radius_px = 6` рабочих пикселей (12 исходных), максимум по линиям.
- Почему расстояние, а не линия фиксированной толщины: толщина стен на листах разная, и узкая
  бинарная линия штрафует модель за смещение в пару пикселей так же, как за промах; спад даёт
  градиент к оси. Оценка по-прежнему векторная — осевая и длина (промты 15, 17, 18).

## 2. Тайлы

| Параметр          | Значение                                                           |
| ----------------- | ------------------------------------------------------------------ |
| рабочий растр     | исходный с целым шагом 2, пиксель — самый тёмный из отсчётов блока |
| тайл / перекрытие | 1 024 / 128 рабочих px (2 048 / 256 исходных)                      |
| заливка           | белым (255) справа и снизу, размер записан в `padding`             |
| преобразование    | в каждой строке `tiles.jsonl`: размеры, начало окна, формулы       |

```text
page_norm  x_n = (x0 + u) · downsample / source_width
tile px    u   = x_n · source_width / downsample − x0
qwen       q   = round(u / tile_px · 1000),  u = q / 1000 · tile_px
```

В памяти — одна рабочая копия листа (13 МиБ при 8 608 × 6 081 и шаге 2): листы PlanSwift записаны
одной полосой TIFF, и полоса разжимается целиком; полный растр в пикселях не собирается.

**Отбор:**

| Часть          | Тайлы                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| val, test      | вся сетка листа; сетка строится только из размера листа — разметку функция не принимает                                         |
| train          | положительные тайлы сетки + до 8 окон вокруг разметки на лист со сдвигом от seed (`gt_positive`) + негативы                     |
| негативы train | `ceil(0,3 × положительных)`; сначала «трудные» с долей чернил ≥ 2 % (текст, размеры, штампы, похожие конструкции), затем пустые |

Тайл положительный, если доля цели ≥ 0,001 (плита) или ≥ 0,0005 (осевая).

## 3. Разбиение

1. Лист — неделимая единица; pHash 64 бит по уменьшенному листу.
2. Кластер — листы одного проекта с расстоянием Хэмминга ≤ 10 или одинаковым растром.
3. Кластер целиком уходит в часть с наибольшим недобором веса аннотаций (от тяжёлых к лёгким,
   равные — по хешу от seed `20260914`); листы без целевой разметки — по кругу.
4. `split.json` замораживается с SHA-256; сборка поверх другого разбиения без `--refreeze` падает.

**Перезаморозка до обучения.** Первая редакция распределения заполняла пустые части первыми
кластерами и отдала в val лист с третью контуров. Это найдено при разборе сборки, до какого-либо
обучения; алгоритм заменён, разбиение пересобрано с `--refreeze`. Действующее — `ecb3498034b30def…`.

| Проект            | Кластеров (многолистовых) | Листы train / val / test | Аннотации цели train / val / test       |
| ----------------- | ------------------------: | ------------------------ | --------------------------------------- |
| `mosfilm31a`      |             30 (три по 2) | 18 / 9 / 5               | 65 / 12 / 20 контуров (67 / 12 / 21 %)  |
| `stories_masonry` |            5 (один на 11) | 12 / 2 / 2               | 2 128 / 142 / 270 линий (84 / 6 / 11 %) |

Stories: 11 листов — один кластер типовых этажей, и по правилу он не делится. Тест на двух листах
оценивает кладку на тех же типах планировок, что и обучение, — именно within-project holdout.

## 5. Виды для Qwen — тот же разбиение, без второго split

Строка вида: `tile_id`, `split`, путь и SHA-256 изображения, размер, `coordinate_range: 1000`,
`crop_policy`, постоянная инструкция и `target` — строгий JSON с целыми 0..1000 относительно ровно
этого тайла (с заливкой). Преобразование обратно — в `tiles.jsonl` по `tile_id`, формулы в § 2.

| Вид                         | Строк train / val / test | С объектами   | Вывод                                                                         |
| --------------------------- | ------------------------ | ------------- | ----------------------------------------------------------------------------- |
| `qwen_slab_localization_v1` | 77 / 150 / 56            | 57 / 55 / 12  | годен: bbox плиты, обрезанный тайлом, и seed-точка внутри плиты вне отверстий |
| `qwen_slab_polygon_v0`      | 20 / 95 / 44             | 0 / 0 / 0     | **не жизнеспособен** при этих настройках                                      |
| `qwen_masonry_roi_v0`       | 179 / 24 / 24            | 132 / 12 / 24 | годен: есть ли кладка, ROI, до 8 опорных точек на осях                        |

**Почему полигональный вид пуст.** Условие вида — в тайле все контуры плит целиком и суммарно не
больше 64 вершин после упрощения на 2 px; иначе цель неполная и учит модель пропускать плиты. Плиты
Мосфильмовской — крупные контуры (медиана 28 вершин, до 289 с дугами), пересекающие границы тайлов,
поэтому ни один из 124 тайлов с плитами условие не прошёл. Окна вокруг контура решили бы это только в
train; в val/test выбор окна по разметке — утечка. Путь дальше — решение владельца: тайл крупнее при
большем шаге уменьшения или отказ от прямого полигона в пользу `localization → SAM` (промт 14).

Негативы Qwen — тайлы без цели: для плиты это листы и зоны с текстом, размерами, штампами, осями и
термовкладышами; счётчиков и меток в инструкциях нет.

## 6. Конфиг

Пример без частных путей — [`tools/planswift_gt/configs/dataset-build.example.json`](../../tools/planswift_gt/configs/dataset-build.example.json):
пути через `${QUANTOR_DATASET_ROOT}`, метки плит пустые. Действующий конфиг с метками позиций лежит
рядом с данными (`QuantorData\planswift\build-v1.json`): метки — названия позиций клиентского
проекта. Разбиение зависит от seed, датасетов, долей, порога pHash и шага уменьшения; смена размера
тайла его не меняет.

## 7. Проверки

| Команда                              | Результат                            |
| ------------------------------------ | ------------------------------------ |
| `pnpm test:planswift`                | ruff, mypy strict — чисто; 61 passed |
| `planswift build` на реальных данных | код 0, четыре проверки утечки true   |
| площадь масок против аналитики       | ≤ 0,09 % по отдельным контурам       |

Тесты сборщика: маска с отверстием и её площадь, спад цели осевой, seed-точка вне отверстия,
упрощение, покрытие листа сеткой, преобразование туда-обратно и заливка, обрезка с заливкой,
кластеры только внутри проекта, кластер не пересекает части и test не пуст, заморозка и
`--refreeze`, pHash, оценочная часть — ровно сетка, bbox и отверстие в координатах Qwen, повторная
сборка с теми же хешами и отказ при смене разбиения, train с окнами вокруг разметки, выбор трудных
негативов.

## 8. Ограничения и решения владельца

- Один проект на домен: test — within-project grouped holdout, не обобщение на новые объекты.
- Stories: val и test по два листа; в test Stories нет тайлов-негативов (оба листа плотно размечены).
- Класс «плита» = плита перекрытия + фундаментная плита; капители и термовкладыши исключены — на
  подтверждение владельца.
- `qwen_slab_polygon_v0` — нужен выбор настройки или отказ (§ 5).
- Ручной просмотр оверлеев промта 07 не выполнен (BLOCKED за владельцем) — сборка на него не опирается,
  но обучение до его PASS начинать не стоит.
