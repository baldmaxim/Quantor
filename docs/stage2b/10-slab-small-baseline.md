## Итог

- **Малый U-Net — слабая нижняя граница:** test IoU 0,135, Dice 0,238, Boundary F1 0,001; ошибка
  нетто-площади единственного test-листа с плитой — 85 %. Гейт требует медиану ≤ 5 % и p90 ≤ 10 %.
- **Порог не главный рычаг:** на val IoU растёт до плато 0,272 при 0,50–0,60 и падает при низких
  порогах — модель при «смелости» рисует лишнее, а границы и отверстия не держит.
- **Причина по данным:** внутренность плиты на плане — та же белая бумага, что снаружи; окно
  рецептивного поля (~140 px) много меньше контуров плит; 77 тайлов train из одного проекта.
- **Решения владельца** ([журнал](owner-decisions.md), Р-5): test v1 один раз без подбора; U-Net v2
  не делается; следующий шаг — SAM 2 / MobileSAM (промт 11).

Числа ниже — из присланных владельцем `metrics.json`, `val-metrics.json` и `test-metrics.json`;
маски прогнозов и веса остаются на его машине.

## 1. Модель

- **Малый U-Net с нуля** (`TinyUNet`, базовая ширина 16, 4 уровня, ≈ 1,9 млн параметров): свёртки
  3×3 + BatchNorm + ReLU, транспонированные свёртки, сквозные связи. Никаких предобученных весов —
  нет и отдельной строки лицензии веса; стек — `torch` / `torchvision` (BSD-3, `allow`).
- Одна задача: плита / фон с сохранением отверстий. Шести классов монолита нет.
- `segmentation_models.pytorch` не используется: его энкодеры потребовали бы аудита каждого веса.

## 2. Данные

- Тайлы плиты из `tiles.jsonl` по полю `split` — ровно так, как их заморозил сборщик; разбиение не
  пересчитывается (`split_sha256` пишется в `run.json` и сверяется при оценке).
- Вход — тайл 1 024 px рабочего растра, яркость / 255; цель — маска 0/1; **заливка за краем листа
  исключена** и из потери, и из метрик.
- Кэш в памяти (~2 МиБ на тайл); батчи собираются детерминированно по seed, без процессов-загрузчиков.
- Аугментации: поворот на 90°·k и горизонтальное отражение — одинаково для изображения, маски и
  допустимой области; топология не меняется, отверстие остаётся отверстием.

Объём части с плитами: train — 77 тайлов (55 сетки + 22 окна вокруг разметки), val — 150, test — 56.

## 3. Обучение

| Параметр          | Значение по умолчанию                                                              |
| ----------------- | ---------------------------------------------------------------------------------- |
| оптимизатор       | AdamW, lr 2·10⁻³, weight decay 10⁻⁴, косинусное затухание                          |
| эпохи / остановка | до 60, ранняя остановка через 10 эпох без роста val IoU                            |
| батч              | 4 тайла 1 024 px                                                                   |
| точность          | bf16 autocast на GPU (Blackwell поддерживает), float32 на CPU                      |
| потеря            | BCE с `pos_weight = фон / плита` (≤ 20) + мягкий Dice                              |
| seed              | 20260914; `cudnn.benchmark = False`, детерминированные алгоритмы с предупреждением |

**Дисбаланс** учтён явно: доля пикселей плиты в train считается до обучения и задаёт `pos_weight`;
Dice не даёт модели выиграть на пустом фоне.

**Выбор без утечки:**

1. каждую эпоху — IoU на val при пороге 0,5; сохраняется лучшая эпоха (`best.pt`);
2. после обучения порог перебирается на val (0,20…0,80 шагом 0,05) по лучшей эпохе и
   **замораживается** в `run.json`;
3. test оценивается отдельной командой, **один раз**: порог и веса берутся из `run.json`, SHA-256
   весов и сборки сверяются, повторная оценка test тем же прогоном — отказ.

## 4. Метрики

| Метрика                           | Как считается                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| IoU, Dice                         | суммарно по всем тайлам части, а не среднее по тайлам                                                   |
| Boundary F1                       | границы маски (эрозия 3×3), допуск 2 px рабочего растра (4 исходных)                                    |
| ошибка площади по тайлу           | модуль разности площадей прогноза и истины, делённый на истину, для тайлов с плитой; медиана и p90      |
| **ошибка нетто-площади по листу** | вероятности окон сшиваются в лист (среднее по перекрытию), порог — замороженный; медиана, p90, максимум |
| задержка                          | мс на тайл, медиана и p90, с синхронизацией CUDA                                                        |
| память                            | пик `torch.cuda.max_memory_allocated`                                                                   |
| прогнозы                          | маска каждого тайла в `predictions/<split>/<tile_id>.png`, SHA-256 в `<split>-predictions.jsonl`        |

Ошибка площади — в пикселях рабочего растра: на одном листе масштаб общий, поэтому доля ошибки
совпадает с долей ошибки физической площади. В метры и м² модель ничего не переводит.

Метрики QTO из `BENCHMARK_GATES.md` (outer contour recall, hole recall, invalid topology) требуют
маски → вектора и считаются в промтах 16 и 18.

| оценка того же прогона на **val** (150 тайлов, CPU)                | 3 мин 15 с; сшивка покрыла все пиксели 5 листов с плитами (`uncovered_pixels: 0`) |

Числа дымового прогона — проверка того, что конвейер проходит, а не качество модели. Test в дымовом
прогоне не трогался.

Тесты на синтетике: PNG с фильтрами 0 и 2, U-Net сохраняет разрешение и мал, идеальный прогноз даёт
1, залитое отверстие штрафуется по IoU, Boundary F1 и площади, заливка исключена, граница квадрата,
ошибка площади листа, допустимая область, аугментация двигает изображение, маску и область вместе,
обучение → замороженный порог → однократная оценка test, отказ при другой сборке и изменённых весах.

## 6. Запуск на RTX 5050

В `vision\` окружении `.venv-train` (раздел 5а [инструкции](gpu-runbook.md)). `$B` — сборка:

```powershell
cd vision
$B = "$env:QUANTOR_DATASET_ROOT\planswift\build\planswift-build-v1"
```

**Шаг 1 — дымовой прогон на GPU** (≈ минута): проверяет CUDA, bf16 и память.

```powershell
.\.venv-train\Scripts\python -m quantor_vision train slab --build $B --run-id smoke-gpu --epochs 1 --limit-tiles 4
```

Прислать напечатанный JSON.

**Шаг 2 — обучение baseline:**

```powershell
.\.venv-train\Scripts\python -m quantor_vision train slab --build $B --run-id slab-tinyunet-b16-v1
```

Результат — в `$env:QUANTOR_DATASET_ROOT\runs\slab-tinyunet-b16-v1\`. Прислать `metrics.json`,
`run.json` и последние 10 строк `train.log`. Если не хватит памяти — повторить с `--batch-size 2`
и новым `--run-id`.

**Шаг 3 — test, один раз** — только после того, как val-метрики обсуждены и конфигурация
зафиксирована; подбирать что-либо по test нельзя:

```powershell
.\.venv-train\Scripts\python -m quantor_vision evaluate slab --build $B --run "$env:QUANTOR_DATASET_ROOT\runs\slab-tinyunet-b16-v1"
```

Прислать `test-metrics.json`. Маски прогнозов остаются на машине.

### Разбор

- Test хуже val вдвое по IoU. На test всего 12 тайлов с плитой и один лист: разброс большой, и
  одно число по листу — не распределение. Гейт это не меняет: до 5 % далеко на обеих частях.
- Boundary F1 около нуля: почти все границы истины — сотни отверстий термовкладышей ≈ 9×7 px,
  которые четыре уровня пулинга не различают; внешние грани плиты модель тоже не держит.
- Ошибка по листу val 388 % на худшем листе — ложная «плита» на больших белых зонах.
- Подбирать U-Net дальше на 77 тайлах бессмысленно: задача «залить внутренность контура» требует
  контекста всего контура или подсказки — это то, что проверяют SAM (промт 11) и Qwen → SAM (промт 14).

## 8. Ограничения

- Датасет мал (77 тайлов train) и из одного проекта: результат — within-project proof of
  feasibility, не точность на новых объектах.
- Термовкладыши на рабочем растре ≈ 9×7 px; четыре уровня пулинга U-Net сжимают их до долей
  пикселя — ожидаемо трудный класс отверстий. Hole recall посчитает промт 16/18.
- Детерминизм на GPU — «с предупреждением»: часть ядер CUDA недетерминирована, повторный прогон может
  отличаться в последних знаках; seed и все параметры записаны.
