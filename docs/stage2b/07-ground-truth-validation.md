## 1. Что проверяет `validate`

Ошибки (делают датасет негодным, код возврата 1):

| Требование промта       | Проверка                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| координаты внутри листа | `points_normalized` ∈ [0, 1]; исходные пиксели ≤ размера растра                                          |
| NaN / inf / заглушки    | JSON пишется с `allow_nan=False`; исходные координаты конечны и не отрицательны                          |
| нормализация честная    | `points_normalized = points_source_px / размер` с допуском 1e-12 — ловит подмену с пересчитанными хешами |
| ссылки `PageGUID`       | лист аннотации есть в `pages.jsonl`, хеш и размер растра совпадают                                       |
| нет «сирот»-отверстий   | у `polygon_hole` есть родитель `polygon` на том же листе; у остальных родителя нет                       |
| число точек             | линия ≥ 2, контур и отверстие ≥ 3, счёт ≥ 1; `object_count` = число точек только у счёта                 |
| дубли                   | повтор `id` — ошибка                                                                                     |
| стабильность растров    | `--source`: SHA-256 каждого TIFF пересчитывается                                                         |
| детерминизм разбора     | `--reparse`: проект разбирается заново во временный каталог, `dataset_fingerprint` сравнивается          |
| целостность файлов      | SHA-256 трёх JSONL и `dataset_fingerprint` сверяются с `manifest.json`                                   |

Замечания (видимы, но датасет не бракуют — ремонта геометрии нет по ADR-0026): группы одинаковой
геометрии под разными `id` и повторы соседних вершин.

Отпечатки в `manifest.json`:

- `dataset_fingerprint` — SHA-256 от формата и хешей трёх JSONL: два прогона на тех же данных дают
  один отпечаток;
- `source_fingerprint` — SHA-256 от путей и хешей всех прочитанных `Data.xml` и растров листов:
  повторный разбор с другим отпечатком источника сообщает «источник изменился».

## 3. Совмещение с растром

Вдоль рёбер каждой аннотации берутся точки через 8 px (до 4 000 на лист, без счёта); для сдвигов
−48…+48 px шагом 12 по обеим осям считается доля точек, рядом с которыми (крест радиуса 2 px) есть
тёмный пиксель. Совмещённый лист: лучший сдвиг в пределах 12 px от нуля и доля в нуле ≥ 1,5 × медианы
по всем сдвигам. Проверка — свидетельство о координатах (масштаб, ось, лист), а не о смысле разметки.

| Датасет           | Листов с разметкой | Пик в нуле | Мин. доля в нуле | Макс. фон (медиана по сдвигам) |
| ----------------- | -----------------: | ---------: | ---------------: | -----------------------------: |
| `stories_masonry` |                 13 |         13 |             0,82 |                           0,36 |
| `mosfilm31a`      |                 17 |         16 |             0,54 |                           0,41 |

На листах с контурами и отверстиями доля в нуле 0,97–0,999 при фоне 0,05–0,18 — координаты
PlanSwift совпадают с пикселями TIFF без сдвига, масштаба и переворота.

**Лист 6 Мосфильмовской** (68 линий, 67 из 69 отрезков — короткие горизонтальные, медиана 108 px):
доля в нуле 0,54, лучший сдвиг на уточнённой сетке с шагом 2 px — (−18, −22) с долей 0,80 при фоне
0,42. Пик размыт, а отрезки короткие и однонаправленные: так ведут себя линии, проведённые между
параллельными линиями чертежа (ось балки между гранями), — а не сдвиг координат листа, иначе он
проявился бы и на остальных 16 листах того же проекта. Вывод без просмотра глазами не делается:
лист первым в чек-листе владельца.

Время: QA Stories — 1 мин 26 с, Мосфильмовская — 2 мин 43 с (растр 4 бита PackBits декодируется
стандартной библиотекой, без Pillow).

## 4. Оверлеи и карточка

`pnpm planswift qa <датасет> --source <проект> --out <каталог> --debug-pages 3`:

- `page-NNN.png` — каждый лист: уменьшенный до 2 400 px по длинной стороне растр (пиксель — самый
  тёмный из четырёх отсчётов блока, чтобы тонкие линии не пропадали), осветлённый; контуры — синие,
  отверстия — красный штрих, осевые — зелёные, точки счёта — пурпурные кресты;
- `page-NNN-debug.png` — первые три листа по GUID: плюс номер аннотации у первой точки, легенда
  «номер → id» в `qa-report.json`;
- `qa-report.json` — совмещение по листам.

Оверлеи детерминированы (тот же вход — те же байты PNG) и пишутся только вне git-репозитория:
48 листов, 11,7 МиБ в `C:\Users\Usrr\QuantorData\planswift\qa\`.

`pnpm planswift card <датасет> --qa-report …/qa-report.json --out card.md` — карточка без изображений,
без имён листов и названия проекта: ключ, формат и версия инструмента, объём по видам, метки с числом
аннотаций, отказы по причинам, кодировки, замечания качества, совмещение, отпечатки, известные
ограничения. Карточки лежат рядом с датасетами (`gt/<ключ>/card.md`); метки позиций в них —
рабочие названия строк PlanSwift, поэтому в git карточки не копируются.
