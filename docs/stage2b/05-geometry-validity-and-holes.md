# Промт 05 — валидность многоугольника и отверстия

Дата: 2026-09-14. Решение — [ADR-0026](../adr/0026-validnost-mnogougolnika-i-otverstiya.md).

> **Контрольная точка владельца.** Пакет требует остановки после промта 05. Работа продолжена по
> прямому указанию владельца «до конца, пуш после каждого промта»; решения ниже — на его ревью.

## Итог

- **Самопересекающийся многоугольник недействителен: площади нет, никогда не 0 м².** Запись
  отвергает его `422 GEOMETRY_INVALID` с кодом дефекта, кольцом и рёбрами; строка, попавшая в базу
  мимо сервиса, получает в величинах `invalid_geometry` и пустое значение.
- **Валидатор детерминированный, без зависимостей:** точные предикаты ориентации (фильтр по double и
  `Fraction`), сетка для крупных контуров, отказ `too_complex` вместо времени без предела. Shapely/GEOS
  не добавлены — ADR лицензии не нужен, в браузер ничего не уходит.
- **Отверстия — колонка `holes` рядом с `points`**, миграция `0011_measurement_holes` с `[]` по
  умолчанию и CHECK формы. Прежний контракт `points` не тронут ни у одного типа.
- **`area.v1` не изменился:** многоугольник без отверстий даёт прежнее число и прежний отпечаток входа
  (тест собирает отпечаток по старой формуле вручную). С отверстиями — `area_with_holes.v1`.
- **Просмотрщик показывает отверстия:** заливка чёт-нечет, обводка колец, клик в отверстие фигуру не
  выбирает. Рисование отверстий вручную не делалось — это UX проверки кандидатов (промты 21–22).
- Замер: аналитические случаи 10/10 и датасет `measurement_v2` 19/19; стоимость — ниже.

## 1. Политика и валидатор

`apps/api/app/services/geometry/validity.py`, `validate_polygon(outer, holes) -> GeometryIssue | None`.

Порядок проверок фиксирован, первый дефект и возвращается:

1. устройство каждого кольца: число вершин → совпадающие соседние вершины (включая замыкание) →
   вырожденность в линию;
2. внутри кольца: разворот ребра назад (наложение соседних рёбер) → пересечение или касание
   несоседних рёбер;
3. между кольцами: пересечение или касание;
4. каждое отверстие внутри внешнего контура; ни одно не внутри другого.

| ----------------------------------------- | ---------------------------------------- | --------------------------------------------------------- |
| бантик                                    | `self_intersection`                      | `test_bow_tie_is_a_self_intersection`                     |
| повтор соседней вершины                   | `duplicate_vertex`                       | `test_duplicate_consecutive_vertex`                       |
| ребро нулевой длины (замыкание повтором)  | `duplicate_vertex`                       | `test_zero_length_closing_edge`                           |

перебор находят одну и ту же первую пару рёбер на контурах 12…1 500 вершин.

## 2. Данные и контракт

- `Measurement.holes: jsonb not null default '[]'` — кольца `[[x, y], …]`, нормализованные, без
  повтора первой точки.
- CHECK `ck_measurements_holes_match_geometry`: массив; не пуст только у `polygon`; каждый элемент —
  массив минимум из трёх. Режим jsonpath `strict` обязателен: в нестрогом кольцо разворачивается до
  точек, и условие «меньше трёх» срабатывало на любой паре координат.
- `MeasurementCreate.holes` (по умолчанию `[]`), `MeasurementUpdate.holes` (`null` — оставить
  прежние: перетаскивание вершины контура отверстия не теряет, но новый контур проверяется вместе с
  ними), `MeasurementRead.holes`.
- Пределы: 200 отверстий, 10 000 вершин в них суммарно; координаты в [0, 1] и конечны, как у `points`.
- Ошибка: `ErrorCode.GEOMETRY_INVALID` (422), `detail.issue = {code, ring, vertex, edge, other_ring, other_edge}`.
- Величины: `MeasurementQuantityRead.geometry_issue`, `TakeoffItemQuantityRead.invalid_count`;
  `rule_key` итога — все правила строки через `+`.
- Журнал: `point_count`, `hole_count`, `geometry_digest` (отверстия входят в отпечаток только когда есть).
- OpenAPI и `packages/api-client` перегенерированы.

## 3. Правило величины

```text
area.v1             POLYGON без отверстий   |контур|                     — как в Stage 2A
area_with_holes.v1  POLYGON с отверстиями   |контур| − Σ |отверстие_i|   — порядок хранения
```

Обе площади — формула шнурков по точкам PDF (`display` размеры страницы), затем `mm_per_pt²`
сохранённой калибровки, без промежуточного округления.

## 4. Просмотрщик

- `OverlayMeasurement.holes` — необязательное поле; отверстия лежат внутри охвата контура, поэтому
  отсечение и пространственный индекс промта 04 не меняются.
- Отрисовка: кольца отверстий — подпути того же пути, `fill('evenodd')`, одна обводка на фигуру.
  Без отверстий заливка прежняя (`nonzero`).
- Попадание: внутри отверстия фигуры нет (клик достаётся тому, что под отверстием), кромка отверстия —
  край фигуры; с индексом ответ тот же.
- Инспектор: «контур недействителен» с причиной и подсказкой перерисовать; число отверстий.
- Отказ записи показывает причину словами (`lib/geometry-issues.ts`).

### Датасет измерительного ядра — `measurement_v2`

`benchmarks/datasets/measurement_v2.json` = v1 + политика ADR-0026: бантик ожидает `invalid_geometry`,
добавлены два многоугольника с отверстиями (93,75 и 87,5 м², допуск ноль — доли 0,25/0,5/0,625/0,875
точны в двоичной записи) и отверстие вне контура. Умолчание `measurement_bench` — v2; v1 оставлен.

Прогон `benchmarks.measurement_bench` на v2: **19 / 19**, повторяемость у всех случаев, API-раздел `ok`,
N+1 нет. Результат — [benchmarks/05-measurement-v2.json](benchmarks/05-measurement-v2.json).
На v1 прежний код падает ровно на одном случае — `polygon.bowtie_self_intersecting` (заложен в v1
именно для того, чтобы смена поведения была заметна).

Сравнение со Stage 2A по времени **не прямое**: отчёт 2A снят на другой машине (Windows 11, AMD
Family 25). Случаи без многоугольника здесь в 5,4–7,5 раза медленнее — это разница машин;
многоугольники — в 6,9–10,5 раза, то есть валидатор добавляет к расчёту малого многоугольника порядка
трети времени. Многоугольник с отверстиями — 0,23–0,31 мс против 0,11–0,15 мс без них.

`docs/stage2a/benchmark-*` не перезаписывались: `pnpm benchmark:measurement` пишет туда, и перезапуск
на другой машине подменил бы отчёт закрытого этапа.

## 7. Ограничения и открытое

- **Стоимость чтения.** Валидатор работает на каждом расчёте величин листа. Для ручных контуров
  (десятки вершин) это доли миллисекунды; контур модели на тысячи вершин — десятки миллисекунд за
  фигуру. Если лист с сотнями таких контуров станет медленным — кэш результата по отпечатку геометрии
  (ADR-0026, последствия), а не отключение проверки.
- **Рисование отверстий вручную** в интерфейсе отсутствует: API и путь чтения готовы.
- **`too_complex`** на честных, но очень плотных контурах возможен: предел сетки выбран по гребёнке;
  PlanSwift-контуры проверит промт 07.
- Живая проверка в браузере на стенде владельца не выполнялась — только vitest и замер.
