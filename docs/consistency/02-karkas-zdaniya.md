# Этап С2: каркас здания и комплектность

Основание: [ADR-0043](../adr/0043-soglasovannost-komplekta-i-svyaz-ar-ios.md), [план](00-plan.md). Флаг
`project.consistency`. Дата: 2026-11-14.

## Решения владельца (2026-11-14)

1. **Каркас привязан к проекту**, а не к версии тендера. Собирается из подтверждённых паспортов последних
   ревизий PDF. Привязка к версии тендера (ADR-0035) — отдельным шагом позже.
2. **Факты ПЗ берутся из вопросов к документации.** В каталог `consistency.doc_questions.v1` добавлены три
   вопроса: этажность, количество этажей с подземными, высота типового этажа. Они проходят тот же путь:
   кандидат с цитатой, подтверждение человеком, область — корпус или секция.
3. **«Ведомость листов ↔ листы» — подэтапом С2.** Сделано: раздел
   [«Подэтап: ведомость ↔ листы»](#подэтап-ведомость--листы) ниже.

## Что сделано

```text
подтверждённые паспорта планов (последние ревизии)
→ сборка кандидатов: корпус → секция → уровень (+ отметка, если источники согласны)
→ подтверждение человеком (пачкой, по узлу) и ручная правка или добавление уровня
→ проверки по подтверждённому: каркас + паспорта + ответы ПЗ
```

| Часть | Где |
|---|---|
| Таблица `frame_nodes` (вид, родитель, корпус, секция, код уровня, номер, отметка, высота, статус, происхождение, доказательства) | `models/frame_node.py`, миграция `0036_frame_nodes` |
| Сборка из паспортов, без БД: `consistency.frame.v1` | `services/consistency/building_frame.py` |
| Каталог проверок `consistency.checks.frame.v1`, без БД | `services/consistency/frame_checks.py` |
| Сервис: пересборка, правка, пачка статусов, ручной узел, удаление ручного | `services/building_frame.py` |
| API: `GET /frame`, `POST /frame/rebuild`, `POST /frame/nodes`, `PATCH`/`DELETE /frame/nodes/{id}`, `POST /frame/bulk-status` | `api/v1/building_frame.py` |
| Экран `projects/[id]/frame`: сборка, проверки, дерево каркаса, правка и добавление уровня | `components/consistency/Frame*.tsx` |
| Вопросы `storeys`, `floors_total`, `floor_height`; вид значения `count` и его извлечение | `doc_questions.py`, `doc_search.py`, `doc_answers.py`, форма ответа в вебе |

### Правила сборки

- В сборку идут только **подтверждённые** паспорта с типом «план этажа». Разрез, фасад и схема уровней не дают.
- Типовой план «2-17 этаж» даёт все уровни диапазона. Нулевого этажа нет: −1 и 1 — соседи.
- Корпус или секция не указаны на листе — узел «корпус (секция) не указан». Догадки нет.
- Отметка привязывается к уровню, только если план покрывает **один** уровень. Если отметки источников
  расходятся больше чем на 0,5 мм, значение остаётся пустым, а все отметки с листами лежат в доказательствах.
  Выбирает человек.
- Высота «пол — пол» **не хранится**: она выводится при чтении из отметки следующего номерного уровня той же
  секции. Ручная высота, если её ввёл человек, главнее.
- Пересборка не трогает подтверждённые и отклонённые узлы и поля, правленные человеком. Кандидат из паспортов,
  которого больше нет в паспортах, удаляется, если под ним не остаётся узлов и в нём нет правок человека.

### Каталог проверок v1

Входы — только подтверждённые уровни, у которых не отклонены ни секция, ни корпус, а также подтверждённые
паспорта и ответы к документации из документа или ручного ввода. Итог — `match` / `mismatch` / `not_run`
с причиной. Результат не хранится, а считается при каждом чтении.

| Код | Что проверяет | Допуск |
|---|---|---|
| `ar_plan_per_level` | У уровня есть подтверждённый план АР своего корпуса и секции (лист без корпуса подходит любому) | — |
| `level_sequence` | Номерные надземные уровни секции идут с 1 до верхнего без пропусков | — |
| `level_elevations` | Отметка уровня однозначна, и отметки растут снизу вверх | — |
| `scheme_per_system` | У раздела ИОС с планами есть схемы; у каждой системы из заголовков планов (В1, Т3, К1…) есть схема с этой системой | — |
| `pz_storeys` | Этажность по ПЗ = верхний номер надземного уровня (или он же + цоколь и техэтаж) | точное |
| `pz_floors_total` | Количество этажей по ПЗ = надземные + подземные (или они же + цоколь и техэтаж) | точное |
| `pz_floor_height` | Высота типового этажа по ПЗ = самая частая высота уровней области | 10 мм |

Счёт с цоколем и техэтажом принимается как совпадение, потому что нормы по-разному включают их в число этажей.
Какой из двух счётов совпал, видно в сообщении проверки.

## Подэтап: ведомость ↔ листы

Дата: 2026-11-14.

```text
текст страниц последних ревизий PDF (сохранён разбором паспортов, В1)
→ задание sheet_register_extract: разбор таблиц ведомостей consistency.sheet_register.v1
→ кандидат-ведомость (строки «номер листа — наименование», страницы, повторы номеров)
→ подтверждение человеком: ведомость целиком
→ проверки consistency.checks.register.v1 по подтверждённой ведомости и паспортам того же документа
```

| Часть | Где |
|---|---|
| Разборщик ведомости по тексту страницы, без БД | `services/consistency/sheet_register.py` |
| Проверки «ведомость ↔ листы», без БД | `services/consistency/register_checks.py` |
| Таблица `sheet_registers` (ревизия, страница, страницы-продолжения, строки JSONB, повторы, статус) | `models/sheet_register.py`, миграция `0037_sheet_registers` |
| Задание `sheet_register_extract` в основном исполнителе, выдача, пачка статусов | `services/sheet_registers.py`, `worker/registry.py` |
| API: `POST /sheet-registers/extract`, `GET /sheet-registers`, `POST /sheet-registers/bulk-status`; проверки — в `GET /frame` | `api/v1/sheet_registers.py`, `services/building_frame.py` |
| Панель «Ведомости листов» на экране каркаса: разбор, строки, подтверждение | `components/consistency/FrameRegistersPanel.tsx` |

### Правила разбора

- Ведомость листов — заголовок «Ведомость (рабочих / основных) чертежей / листов», «Перечень листов (чертежей)»,
  «Перечень / состав / содержание графической части». Ведомости ссылочных документов, спецификаций и отделки — не
  ведомость листов. «Содержание тома» перечисляет документы, а не листы, и в v1 не разбирается.
- Строка — номер листа и наименование: «5 План 3 этажа» (номер слева, форма ГОСТ Р 21.101) или «План 3 этажа 5»
  (номер справа). Вид строк ведомости выбирается большинством.
- Наименование, перенесённое на следующую строку, склеивается: не больше двух строк продолжения. Конец ведомости —
  следующий раздел листа («Ведомость ссылочных…», «Общие указания») или штамп. Три шумовые строки подряд тоже
  заканчивают ведомость.
- Меньше двух строк — не ведомость. Повтор номера внутри ведомости записывается и даёт расхождение.
- Страница с заголовком «(продолжение)» сразу после страницы с ведомостью дописывается к этой ведомости.
- Повторный разбор заменяет кандидатов. Подтверждённые и отклонённые ведомости он не трогает.

### Каталог проверок `consistency.checks.register.v1`

Ведомость описывает листы своего документа, поэтому сравнение идёт только внутри ревизии. Листы текстовой части
(тип «текст») не сравниваются: у них своя нумерация страниц. Без подтверждённой ведомости все три проверки
получают `not_run` с причиной.

| Код | Что проверяет | Итог |
|---|---|---|
| `register_sheets` | У каждой строки ведомости ровно один подтверждённый лист документа с этим номером | `mismatch`: нет листа, номер на нескольких листах, повтор в ведомости. `not_run`: паспорт с номером ещё кандидат |
| `sheets_in_register` | Каждый подтверждённый лист документа с номером есть в ведомости | `mismatch`: лист не в ведомости. Листы без номера перечисляются как непроверенные |
| `register_titles` | Наименование в ведомости совпадает с наименованием подтверждённого листа | По словам, без адреса «Корпус N. Секция M»: совпадение — не меньше 60 % слов меньшего наименования |

Итог по ведомости — одна строка проверки: номера перечислены в сообщении, ссылки ведут на страницу ведомости и
листы с расхождением (до 20).
