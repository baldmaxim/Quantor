# Шаг 2: вопросы к документации (черновик плана, ждёт решений владельца)

Основание — [ADR-0043](../adr/0043-soglasovannost-komplekta-i-svyaz-ar-ios.md), [план](00-plan.md). Флаг
`project.consistency`. Приоритет владельца 2026-11-12: ответы для трасс CAD берутся из документации проекта, а
не из допущений движка.

## Задача

На любом загруженном проекте (приёмка — 328, 314; регрессия — 342) по каталогу инженерных вопросов найти в тексте
листов кандидаты ответа с цитатой и ссылкой «файл / страница / лист», дать человеку подтвердить и отдать
подтверждённые ответы трассам CAD. Нет ответа в проекте — так и показать, и предложить норматив как допущение с
пунктом СП, а не молчаливое умолчание.

```text
паспорт листа (раздел, тип, корпус, секция, уровень) + текст страниц
→ каталог вопросов v1 (где искать, шаблоны, извлечение значения)
→ задание поиска в исполнителе → кандидаты (значение, цитата, страница, оценка)
→ подтверждение человеком → ответ проекта (с областью: корпус / секция / уровень)
→ API для CAD-трасс (только подтверждённые)
```

## Что есть

- Паспорт листа на 328 (127/128 файлов) и 314 (114/114) на бою; раздел ≈ 100 %, тип листа ≈ 76–79 %.
- Текст страниц после разбора выбрасывается: в базе только короткие цитаты-доказательства паспорта.
- Трассы CAD берут из проекта только высоту в свету (разрезы / плита проекта / допущение) и толщину плиты.
  Отметка подвесного потолка, пирог пола, сечения ДУ/ДП и лотков, тип оросителей и их зазор — нигде.
- Ручной прогон на 342 (5 вопросов) показал, где лежат ответы: потолок — Договор / ПЗ АР / разрезы; пол — АР
  (экспликация полов); плита — КР; ДУ/ДП — ИОС4.2; лотки — ИОС1 (сечений нет); оросители — ИОС2.2 ПЗ;
  зазор «горячее над холодным» — в проекте нет, только норматив.

## Этапы

| # | Этап | Результат | Гейт |
|---|---|---|---|
| В1 | Текст страниц | Разбор паспорта сохраняет текст страниц ревизии (сжатый JSON в MinIO, ключ — ревизия + версия разборщика); доразбор 328/314 без повторного паспорта | Текст есть у всех разобранных ревизий; занятое место ≤ 300 МБ на оба проекта |
| В2 | Каталог вопросов v1 | Версионированный каталог в коде (как словари): код вопроса, параметр-получатель, единица, где искать (разделы, типы листов), шаблоны поиска, извлечение значения, норматив-допущение | Каталог покрывает 5 вопросов 342 + сечения ДУ/ДП и лотков; тесты на синтетике |
| В3 | Поиск и кандидаты | Задание `doc_questions_search` в исполнителе; таблица кандидатов (значение, цитата, ревизия, страница, область, оценка, версии); детерминированное извлечение чисел из текста, без модели | На 328/314/342: где ответ есть, верная цитата в первых 3 кандидатах ≥ 90 %; где ответа нет — «не найдено», не ноль |
| В4 | Подтверждение и экран | Экран «Вопросы к документации» в проекте: вопрос → кандидаты с цитатой и переходом на лист → принять / отклонить / ввести вручную / «нет в проекте, принять норматив» | Владелец проходит 328 за один сеанс; 360 px без горизонтального скролла |
| В5 | Ответы для CAD | `GET /projects/{id}/doc-answers` (только подтверждённые, с происхождением); запуск трасс показывает источник «документация» рядом с разрезами и плитой проекта | Трассы 342 получают потолок, пол и плиту из подтверждённых ответов; источник виден в задании |

STOP после каждого этапа. В5 трогает запуск трасс CAD — по согласованию с сессией трасс.

## Ограничения

- Модель чисел не выдаёт; LLM и внешние API не используются. Извлечение — шаблоны и словари с версией.
- Кандидат — не ответ: в CAD идёт только подтверждённое человеком; «нет в проекте» не превращается в 0.
- Не пишем в обмер, MEP, `Region`, calc, ВОР; Facts Registry calc — только через мост С6 отдельным решением.
- Разбор PDF — только в исполнителе (подпроцесс с лимитом памяти), не в процессе API; без OCR и растра —
  листы без текстового слоя честно помечаются «нет текста».
- ВОР и Договор Заказчика — данные объекта, в git только синтетика.

## Решения владельца (2026-11-12)

1. Текст страниц — в MinIO, сжатый JSON на ревизию; поиск — в исполнителе. Без полнотекстового индекса в базе.
2. Ответы — свой реестр контура `consistency`; объединение с вопросами calc — позже.
3. Каталог v1: 5 вопросов 342 (потолок коридора, пирог пола, плита, оросители и зазор до перекрытия,
   «горячее над холодным») + сечения ДУ/ДП и лотков.
4. В5: новый источник высоты трасс «документация»; порядок: разрезы → документация → плита проекта → допущение.
5. Договор и ТЗ Заказчика грузятся в проект как документы и ищутся наравне с листами (в git — нет).

## В5 реализован (2026-11-12)

- Источник высоты трасс `doc_answer` стоит между разрезами и плитой проекта (`cad_sections.resolve_route_levels`);
  работает только при флаге `project.consistency` пространства.
- Берутся подтверждённые ответы `document` и `manual` на `clear_height` (→ `clear_height_mm`), иначе на
  `slab_thickness` (→ `slab_thickness_mm`); `not_in_project` и `norm_assumption` не используются.
- Область: корпус+секция паспорта листа > корпус > секция > весь проект; расхождение на самом точном уровне —
  `doc_answer_ambiguous`, значение вне пределов (1500–6000 / 100–600) — `doc_answer_out_of_range`, дальше плита проекта.
  При расхождении разрезов документация не подставляется (как и плита).
- Происхождение — `levels_doc_answer` в задании и `CadJobRead`; `answer_id` входит в ключ идемпотентности.
- Потолок коридора, пирог пола, оросители и прочие вопросы движок трасс пока не принимает.
