# Gate 06-B — профиль объекта и чек-лист документов первого реального гейта

Дата: 2026-09-28. Решения инженера — [gate-06-engineer-review.md](gate-06-engineer-review.md);
калькулятор — [06-vk-stage-p-calculator.md](06-vk-stage-p-calculator.md).

Объект выбирает владелец. Quantor объект не выбирает, а данные объекта в git не попадают:
документы загружаются в проект среды гейта, в репозитории — только этот чек-лист и протокол без
названий, адресов и значений объекта. Флаг `calc.portal` для пользователей остаётся выключенным;
гейт проводится в изолированной среде разработки.

## Профиль объекта

- жилой многоквартирный корпус или секция, ориентировочно 15–30 этажей, типовые жилые этажи;
- стадия П; РД не требуется, BIM не используется;
- документы — распознанный пакет (текст и таблицы блоков). Сведения только на изображениях
  (разрезы-картинки) не читаются: нового OCR нет, их вводит инженер вручную с основанием;
- ВОР Заказчика допускается только как будущий объект сверки (PROMPT 09): в расчёт и в оценку
  гейта не входит.

## Чек-лист перед прогоном

Обязательные факты — найдены в документах или введены инженером с основанием:

- [ ] этажность корпуса или секции (`building.floors_above_ground`);
- [ ] квартиры на **каждом** надземном этаже, включая 0 на нежилых и технических
      (`floor.apartments_count`). Отсутствие данных нулём не считается;
- [ ] высоты этажей 1…(верхний жилой − 1) или отметки 1-го и верхнего жилого этажа
      (`floor.height`, `floor.elevation`);
- [ ] назначение каждой системы по легенде или записке (`system.function`);
- [ ] область гейта: корпус целиком или секция (у секций свои этажи и квартиры).

Желательные — повышают долю определённого:

- [ ] число стояков по схемам (`system.risers_count`) — иначе решения 8–11;
- [ ] зоны (`system.zones_count`) — иначе решение 12;
- [ ] длина магистрали по схеме или обмеру (`system.main_length`);
- [ ] диаметры стояков и магистрали, материал труб (`system.riser_diameter`,
      `system.main_diameter`, `system.pipe_material`).

Решения инженера по разделу «Сводка» пакета 06-A приняты и внесены утверждёнными версиями правил.

Опыт пробного прогона PROMPT 06 на пакете АР: без легенды ВК все системы BLOCKED; этажности и высот
этажей в тексте АР не было; у трёх этажей не было экспликаций квартир. После 4 + 1 + 3 ручных фактов
квартирография определилась автоматически, а пролёт остался «не определено» — нужны высоты.

## Особая проверка Т3 / Т4

По документации объекта проверить:

1. Что называют обозначения Т3 и Т4 в легенде и записке — подающий и циркуляционный трубопроводы
   горячей воды или иное.
2. Связаны ли они в одну систему: циркуляционный стояк при каждом стояке Т3, секционные узлы,
   кольцевание верхней разводкой, полотенцесушители на Т3 или на Т4.

Исходы:

- **назначение не подтверждено или другое** — паспорта Т3 и Т4 BLOCKED с вопросом; это корректное
  поведение, а не ошибка;
- **подтверждены связанные подающий и циркуляционный контуры** — ограничение PROMPT 06 «Т4 не
  связан с числом стояков Т3» выносится на гейт вопросом В-1 пакета 06-A. Предположением оно не
  исправляется: после ответа инженера решается, нужно ли менять калькулятор Т4 до реального прогона.

## Порядок гейта

1. Владелец выбирает объект по профилю; документы загружаются распознанным пакетом в проект среды
   гейта.
2. Сбор фактов PROMPT 02; готовность ВК: назначение систем, обязательные данные, правила.
3. Инженер принимает решения пакета 06-A; утверждённые версии правил вносятся вторым человеком.
4. Расчёт комплекта ВК; фиксируются идентификаторы и отпечатки паспортов (`passport_sha256`).
5. Независимый инженерный расчёт по тем же документам П — без РД и без ВОР.
6. Протокол: метрики ниже, каждое расхождение с причиной и классом, итог по метрике.

## Метрики гейта

Только для этого гейта; в продукт как универсальные пороги не вносятся.

| Метрика                          | Критерий                                                                                                                     |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Критичные явные факты документов | 100 % корректности: этажность, квартиры по этажам, высоты или отметки, назначение систем, стояки и зоны, если они взяты из П |
| UNKNOWN и конфликты              | 0 скрытых подстановок: ни одно «не определено» или конфликт не превращено в число молча                                      |
| Арифметика                       | 0 необъяснимых ошибок: каждое число раскрывается цепочкой до факта и правила                                                 |
| Вертикальные длины               | совпадение с независимым инженерным расчётом в пределах правил округления                                                    |
| Количество стояков               | точное значение Quantor совпадает с утверждённым решением инженера; при диапазоне решение инженера входит в диапазон         |
| EXPECTED общая длина труб        | если документация позволяет сопоставимый независимый расчёт: до ±12 % — PASS; 12–20 % — REVIEW; более 20 % — разбор причины  |
| Разбивка по диаметрам            | ориентир ±20 % — только там, где утверждена методика выбора диаметров; сейчас методики нет, метрика не применяется           |

Правила оценки:

- отсутствие достаточных данных стадии П само по себе не является ошибкой продукта, если Quantor
  честно показал «не определено» и причину;
- точное значение без доказанного основания — ошибка;
- сравнивается сопоставимое: если общая длина Quantor — PARTIAL (подтверждаемая часть), сравниваются
  только определённые составляющие (вертикаль, подключения), а не итог с неизвестной магистралью.

## Вопросы владельцу до гейта

1. **Общая длина труб диапазоном.** Как считать отклонение, если Quantor выдал диапазон, а не
   число? Предложение: независимый расчёт внутри диапазона — PASS; вне — отклонение от ближайшей
   границы. Середина диапазона не используется.
2. **Область гейта.** Какие системы проверять: все четыре или В1 и К1 первыми.
