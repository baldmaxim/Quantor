# PROMPT 06 — готовность инженерных правил ВК, пакет для инженера, готовность к гейту

Дата: 2026-09-28. Калькулятор — [06-vk-stage-p-calculator.md](06-vk-stage-p-calculator.md).
Решение — [ADR-0030](../adr/0030-raschyotnyj-kontur-stadii-p.md), раздел «Решения PROMPT 06».

Ни одно правило не утверждено кодом и не создано от имени инженера. Проверенного нормативного
или методического источника в репозитории нет, память модели источником не считается. Поэтому
у каждого решения статус SOURCE_REQUIRED (или IMPLEMENTATION_REQUIRED, если методики нет в коде),
а в пространстве — то, что вычисляет реестр: READY, DRAFT (блокер гейта), SOURCE_REQUIRED.

Вычислительные примитивы (этажность, квартирография, сумма высот, итог квартир, итог приборов,
шахты) правилами не являются и здесь не перечислены — они в `engine/primitives.py`.

## Пакет для инженера ВК

Как утвердить: создать версию правила по контракту (шаблон — `systems/vk/rule_templates.py`,
заявка видна в `GET /calc/vk/calculators`), указать источник (NORMATIVE — документ, редакция,
пункт, дата; ENGINEERING — методика с автором и ограничениями; TENDER_ASSUMPTION — решение
владельца или проверяющего и влияние), значения параметров и утвердить вторым человеком.
Примеры ниже — синтетические, только для понимания арифметики.

### `vk.b1.risers.count_range` — нужно для гейта

- **Решение:** Число стояков В1 по квартирам на этаже. Слой B структура; системы В1.
- **Формула/логика:** стояков = ⌈квартир на этаже / квартир на стояк⌉ для обеих границ. Реализация `vk.risers.count_range.v1`.
- **Входы:** `apartments_per_floor` (apartment) — Наибольшее число квартир на обслуживаемом этаже (примитив квартирографии).
- **Параметры версии (задаёт инженер):** `per_riser_min` (apartment) — Квартир на один стояк — нижняя граница; `per_riser_max` (apartment) — Квартир на один стояк — верхняя граница.
- **Источник:** не найден в репозитории — нужен документ (ENGINEERING).
- **Применимость:** стадия П, жилые здания; ограничения задаёт версия.
- **Пример:** 8 кв. на этаже, 2–3 кв. на стояк → 3–4 стояка (синтетика).
- **Что изменит в объёмах:** `pipe.riser`, `pipe.connection`, `penetration.slab`, `valve.riser_shutoff`; без версии — число стояков, вертикальные трубы, проходки, арматура стояков, этажные подключения.
- **Статус:** SOURCE_REQUIRED.

### `vk.water.riser.end_segments` — нужно для гейта

- **Решение:** Участки стояка водопровода ниже 1-го этажа и выше верхнего. Слой D количества; системы В1, Т3, Т4.
- **Формула/логика:** длина стояка = межэтажный пролёт + нижний участок + верхний участок. Реализация `vk.riser.end_segments.v1`.
- **Входы:** —.
- **Параметры версии (задаёт инженер):** `bottom_length` (m) — Участок стояка ниже уровня 1-го этажа — до магистрали; `top_length` (m) — Участок выше уровня верхнего этажа — до верхнего подключения.
- **Источник:** не найден в репозитории — нужен документ (GEOMETRY / ENGINEERING).
- **Применимость:** стадия П, жилые здания; ограничения задаёт версия.
- **Пример:** 1,5 м ниже 1-го этажа и 0,5 м выше верхнего (синтетика).
- **Что изменит в объёмах:** `pipe.riser`; без версии — полная длина стояка: без правила подтверждается только межэтажная часть.
- **Статус:** SOURCE_REQUIRED.

### Правила

Утверждено: 0. Черновиков: 0. Ждут источника и инженера: 22 (из них нужны для гейта — все
правила числа стояков, схем, концевых участков, длины подключений и зонирования: 12).
Методики без реализации: 2.

### Какие количества вычисляются, какие остаются диапазоном, какие не определяются

- **вычисляются без правил:** этажная структура, квартирография, межэтажный пролёт, проходки и
  оконечные элементы при известных стояках (из документа), магистраль при известной длине,
  оборудование из документа;
- **диапазоном:** всё, что зависит от числа стояков-диапазона и диапазона длины подключений —
  пока стояки не указаны в П или не выбраны инженером;
- **не определяются до правил и данных:** участки стояков ниже 1-го и выше верхнего этажа,
  магистраль без длины, выпуски, изоляция, крепления, гильзы и огнезащита, фитинги трассы,
  переходы без диаметров, расходы (контроль).

Пробный прогон на реальном пакете АР (подробно — раздел AD калькулятора): без легенды ВК и без
текстовой этажности паспорта BLOCKED; после 4 + 1 + 3 фактов человека — квартирография определена
автоматически, пролёт «не определено» (высот этажей в тексте нет).

## Технический профиль объекта для гейта

Объект выбирает владелец. Подходит:

- жилой корпус 15–30 этажей, 1–3 секции, типовые жилые этажи;
- распознанный пакет АР стадии П с экспликациями квартир по этажам;
- текстовые высоты или отметки этажей: разрез с отметками, ведомость, ПЗ или названия планов;
- частичная ВК стадии П: легенда систем, принципиальные схемы В1/Т3/Т4/К1 с числом стояков,
  по возможности — ПЗ ВК с расходами;
- ВОР Заказчика — только для будущей проверки (PROMPT 09), в расчёт не входит;
- РД не требуется; MEP semantic не требуется.

Перед гейтом инженер ВК утверждает правила из пакета выше (как минимум нужные для гейта) со
своими источниками и значениями.

## Метрики будущего гейта (только для отчёта)

Методика PASS/FAIL утверждается отдельно после PROMPT 06; в продукт метрики не зашиты.
