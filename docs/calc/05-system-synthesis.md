# PROMPT 05 — синтез структуры инженерной системы стадии П (System Synthesis)

Дата: 2026-09-28. Пакет — [`_prompts/calc_portal_stage_p/`](../../_prompts/calc_portal_stage_p/Quantor_Opus_5.5_Prompts_Calculation_Portal.md),
задание PROMPT 05 в редакции владельца от 2026-09-28. Решение — [ADR-0030](../adr/0030-raschyotnyj-kontur-stadii-p.md),
раздел «Решения PROMPT 05». Предыдущий шаг — [04-calculation-engine.md](04-calculation-engine.md).

```text
Facts Registry → Calculation Engine (запуск, результаты, снимок)
             └─(доп. факты для структуры, тот же строгий допуск)─┐
Rule Registry (утверждённые версии: топология, выбор, допущение) ─┤
                                                                   ▼
                          System Synthesis → SystemGraph (логическая структура, диапазоны,
                          варианты, что неизвестно) → PROMPT 06: ожидаемые количества
```

Реальных синтезаторов В1, Т3, Т4, К1 нет. Есть инфраструктура и демонстрационный синтезатор
`test.riser_structure@1` на синтетике, скрытый из пользовательских списков.

## A. Цель и границы

Синтез после расчёта строит правдоподобную, полностью объяснимую логическую структуру системы,
достаточную для оценки объёмов стадии П. Он не читает документы, не распознаёт, не создаёт и не
меняет факты, не меняет правила и запуски расчёта, не использует LLM, ВОР Заказчика и правила
старого портала. Отдельный пакет `app/services/calc/synthesis/`, свои таблицы и API.

## B. Почему это не РД

Граф — расчётная гипотеза: кто с кем связан и сколько элементов, с происхождением каждого. В нём
нет координат, которых нет в источнике, нет трасс и нет выбора, которого не сделали правило или
инженер. «Стояков 4–5» остаётся диапазоном; «две шахты» не превращаются в размещение стояков;
неизвестная трасса магистрали — открытый вопрос, а не нарисованная линия.

## C. Связь расчёт → синтез

Порядок один: факты → расчёт → синтез.

- Числовые требования считает ядро PROMPT 04: для демо — калькулятор `test.riser_demand@1`
  («⌈квартир / вместимость⌉» дважды → диапазон стояков). Синтезатор их не пересчитывает.
- Синтезатор принимает только успешный запуск своего калькулятора и своего проекта; сценарий
  синтеза — сценарий запуска расчёта. Иначе — BLOCKED `CALCULATION_NOT_USABLE`.
- Дополнительные факты для структуры (ввод, этажность, шахты — не участвовали в арифметике) —
  собственный неизменяемый снимок синтеза с тем же строгим допуском, что у ядра.
- Для демо понадобилась отдельная величина — диапазон числа стояков — и она посчитана в ядре,
  а не внутри синтезатора.

Изменения ядра PROMPT 04 (обоснованы необходимостью, обратно совместимы):

- округление внутри обработчика, записываемое в шаг (`HandlerResult.roundings`) — в PROMPT 04
  обещано, но механизма не было; и деление с явным округлением (`divide_rounded`);
- демо-калькуляторы скрыты из `GET /calc/calculators` по умолчанию (`include_demo=true` —
  отладка), по решению владельца;
- в `CalcBlockCode` добавлены `CALCULATION_NOT_USABLE` и `CALCULATION_RESULT_MISSING`.

## D. Каталог синтезаторов

`SynthesizerDef` — код: `synthesizer_id`, версия, название, вид (DEMO/ENGINEERING), раздел,
системы, стадия, сценарии, тип графа, нужный калькулятор с версией и его результаты,
дополнительные факты (тип, поля области, обязателен ли), правила по ролям (TOPOLOGY, SELECTION,
ASSUMPTION — ключ, допустимые типы, входы из результатов, выходы), детерминированный алгоритм и
контрольные примеры. Каталог `SYNTHESIZERS` статический; `eval`, `exec`, кода из базы и программ
из JSON нет (проверяется разбором AST). Отпечатки: определения (`synthesizer_sha256`) и
реализации (`implementation_sha256` — определение и отпечатки графов контрольных примеров).

## E. Граф системы

`CalcSystemGraph`: тип графа, раздел, система, область, сценарий, синтезатор с версией, узлы,
связи, нерешённое, допущения, предупреждения. Граф проверяется после построения
(`graph_problems`); ошибка графа — ошибка синтезатора, запуск FAILED, а не сохранённый граф.

## F. Узлы и связи

Узел (`CalcSystemNode`) и связь (`CalcSystemEdge`): стабильный идентификатор внутри запуска,
смысловой тип (строка по шаблону — типы добавляются с синтезаторами, закрытого списка нет),
название, происхождение, основания (результат расчёта, факт, решение инженера), ссылки на версии
правил, количественные атрибуты, геометрия, множители, «почему элемент нужен». У узла ещё область,
кратность, повторяемость, оценка сценария; у связи — концы. Демо использует шесть типов узлов и
три типа связей.

## G. Происхождение

| Режим         | Смысл                                         | Обязательное основание                |
| ------------- | --------------------------------------------- | ------------------------------------- |
| `OBSERVED`    | подтверждено документацией                    | факт объекта (→ свидетельство)        |
| `CALCULATED`  | необходимость следует из расчёта              | результат запуска расчёта             |
| `SYNTHESIZED` | структура предложена по утверждённому правилу | утверждённая версия правила синтеза   |
| `ASSUMED`     | только из-за тендерного допущения             | утверждённая версия TENDER_ASSUMPTION |

Без режима элемент не хранится (обязательное поле); без основания своего вида граф не проходит
проверку. Синтезированное никогда не помечается наблюдённым. Кратность, выбранная правилом или
инженером, происхождения элемента не меняет: стояки остаются «рассчитанными», у выбора — своё
основание.

## H. Состояние геометрии

`NONE`, `ANCHOR_ONLY` (зона или элемент привязки), `RANGE`, `ESTIMATED` (по утверждённому правилу),
`OBSERVED` (из источника) — отдельно от происхождения. Контракт не даёт выдумать координаты:
рамка — только `OBSERVED` со ссылкой на факт-источник; `ESTIMATED` — только с правилом; длина
трассы — только при состоянии, которое её допускает. Точек нет вовсе. В демо геометрия всех
элементов `NONE`: архитектурная геометрия существующих артефактов (блоки распознавания) — не
контуры помещений и шахт, и её пригодность тестом не доказана, поэтому она не используется.

## I. Логическая и физическая топология

Связи — логические: ввод → стояки → этажная ветвь, типовой этаж → ветвь. Физическая трасса
отсутствует и явно записана открытым вопросом `ROUTE` («трасса магистрали не определена»), который
не делает запуск неполным. Грубый маршрут и длина-диапазон предусмотрены контрактом
(`CalcGeometry.length`, `anchor`) и допускаются только по утверждённому правилу; демо их не строит.
«Прямая × 1,2» без утверждённого правила невозможна — такого пути в коде нет.

Фитинги в PROMPT 06 выводятся из топологии, а не «метры × коэффициент»: связь
`BRANCH_CONNECTION` имеет множитель «этажная ветвь», и число узлов присоединения — это число
экземпляров связи (демо: 96–120).

## J. Диапазоны

Кратность `CalcCardinality`: `min`, `max`, `selected` и основание выбора. Без утверждённого
правила выбора или решения инженера диапазон остаётся диапазоном: ни середины, ни границы, ни
значения с «высокой уверенностью». Совпавшим границам выбор не нужен. Открытый диапазон —
нерешённое `COUNT_RANGE`, структурное.

## K. Варианты

Если кратность — диапазон, синтезатор перечисляет допустимые варианты (`risers_4`, `risers_5`):
выбор для каждого узла, почему вариант допустим, какие вопросы в нём остаются. Вероятностей и
процентов нет — статистической модели нет. Вариант — выбор поверх одного графа, а не копия графа.
Больше пяти значений не перечисляются (предел показа, не инженерия) — остаётся диапазон с
предупреждением.

## L. MINIMUM

Только неизбежная структура: правило выбора кратности не применяется. Нижняя граница
диапазона — `estimate` со смыслом `LOWER_BOUND` и пометкой «нижняя оценка, а не проектное
решение»; `selected` пуст, вариантов нет, диапазон остаётся открытым.

## M. EXPECTED

Разрешены утверждённые инженерные правила синтеза. Выбор кратности — только утверждённым правилом
роли SELECTION или решением инженера; иначе — диапазон и варианты. Тендерного запаса нет.

## N. TENDER_SAFE

Начинается от EXPECTED. Утверждённое применимое тендерное допущение добавляет элементы
`ASSUMED` (демо — резервные стояки и магистраль к ним) и запись допущения: правило и версия,
почему разрешено, влияние, пометка «это не норматив». Без допущения TENDER_SAFE = EXPECTED с
предупреждением. Обычная роль не примет версию типа TENDER_ASSUMPTION (`RULE_TYPE_NOT_ALLOWED`).

## O. Кратность и двойное умножение

- `cardinality` — экземпляров на «родителя»;
- `multiplicity` — повторяемость группы (типовой этаж ×24);
- `multipliers` — узлы, число экземпляров которых умножает кратность («на стояк и на этаж»).

Число экземпляров считает `instances()`: демо — ветвей 1 × (4–5 стояков) × (1 × 24 этажа) =
96–120. Количественный атрибут всегда несёт `basis`: `TOTAL` не умножается никогда (уже итог),
`PER_INSTANCE` умножается ровно один раз на число экземпляров (`attribute_total`). «Длина уже на
20 этажей × 20» невыразима. Проверяются повторы и циклы множителей.

## P. Типовые группы

Типовой этаж — один узел `TYPICAL_FLOOR_GROUP` с `multiplicity = 24`, а не 24 копии подграфа.
Происхождение группы — наблюдено (этажность из документации). Типовая квартира, повторяемая
ветвь и узел задаются так же — повторяемостью и множителями; демо использует этаж.

## Q. Ограничения

Синтезатор работает через явные ограничения: результаты расчёта (диапазон стояков), наблюдённые
факты (ввод, этажность, шахты), утверждённые правила по ролям. Ни одного «если квартир больше
100 — 5 стояков» в коде: пороги и константы — только параметры утверждённых версий правил.
Две шахты без правила размещения — открытый вопрос `PLACEMENT`, стояки по шахтам не
распределяются (сценарий C).

## R. Правила

Правило синтеза — обычная версия реестра правил PROMPT 03, исполняемая той же реализацией из
того же реестра обработчиков PROMPT 04 с тем же отпечатком семантики. Выбор версии — как у ядра:
только утверждённая, действующая на дату, применимая к системе и стадии. Недоступное правило — не
ошибка: топологии нет — узлы есть, связей нет, запуск PARTIAL; правила выбора нет — диапазон;
допущения нет — TENDER_SAFE = EXPECTED. Несовпадение контракта или типа — блокировка. Черновики,
отклонённые и правила старого портала (включая черновик по мотивам старого) не используются.

Каждое структурное решение ссылается на результат расчёта, утверждённую версию правила или
допущение — «обычно так делают» невыразимо: у синтезированного элемента без правила граф не
проходит проверку.

## S. Запуск синтеза

`CalcSynthesisRun` фиксирует пространство, проект, исходный запуск расчёта и отпечаток его
результата, синтезатор с версией и отпечатками, сценарий, область, версии ядра, снимок
дополнительных фактов, точные версии правил с содержанием и недоступные правила с причинами,
решения инженера на входе и применённые из них, граф, варианты, нерешённое, допущения,
предупреждения, причины блокировки, ошибку, отпечатки, ключ идемпотентности.

| Статус      | Смысл                                                                                                            |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `BLOCKED`   | осмысленную структуру построить нельзя: нет результата расчёта, обязательного факта, неподходящий запуск         |
| `PARTIAL`   | полезная структура есть, но открыто структурное решение: диапазон, размещение, нет правила топологии — не ошибка |
| `SUCCEEDED` | структурных вопросов нет; неизвестная трасса допустима                                                           |
| `FAILED`    | ошибка алгоритма или реализации правила                                                                          |

Запуск синхронный, одной транзакцией, записывается сразу итогом (CREATED снаружи не наблюдаем).

## T. Воспроизводимость

Одинаковые запуск расчёта, снимок, версии правил, решения, синтезатор, сценарий → одинаковый
отпечаток графа (T01, T02). `POST /calc/synthesis-runs/{id}/replay` пересчитывает граф из
собственного снимка, привязок, недоступных правил и решений запуска и результатов исходного
запуска расчёта — текущие реестры не читаются. Изменилась реализация синтезатора (отпечаток) или
обработчика правила, пропала версия правила — повтор честно отказывает.

## U. Объяснение

`GET /calc/synthesis-runs/{id}/trace?element_id=…`:

- рассчитанное: элемент → результат расчёта → цепочка ядра целиком (шаг → версия правила → факт →
  свидетельство);
- наблюдённое: элемент → факт → свидетельство;
- синтезированное: элемент → решение (выбор) → утверждённая версия правила;
- принятое допущением: элемент → тендерное допущение → версия правила → решение ответственного лица.

Текст — из структуры, без модели. Живой пример:
`Стояки (следует из расчёта). Необходимость стояков следует из расчёта: 4–5 ст.; кратность 4–5 — не выбрано`
→ `Стояков не меньше (демо) = 4 ст. 96 кв. / 24 кв. на стояк = 4 → 4 ст.; 96 кв. / 20 кв. на стояк = 4,8 → 5 ст.`

## V. Хранение

| Таблица                    | Зачем                                                                       |
| -------------------------- | --------------------------------------------------------------------------- |
| `calc_synthesis_runs`      | запуск и граф целиком (JSONB по контракту), варианты, нерешённое, отпечатки |
| `calc_synthesis_decisions` | решение инженера по варианту запуска — вход следующего запуска              |

Почему граф в JSONB запуска, а не таблицы узлов и связей: граф читается, проверяется,
воспроизводится и сравнивается целиком; у элементов стабильные идентификаторы, и PROMPT 06
сошлётся на элемент парой (запуск, идентификатор); PROMPT 09 сверяет позиции паспорта, а не
узлы графа; ожидаемые графы стадии П — десятки элементов. Нормализация понадобится, если
появятся запросы по элементам многих запусков — тогда отдельным решением.

## W. Неизменяемость

Обе таблицы только дописываются: триггер той же функции `calc_runs_append_only` (PROMPT 04)
запрещает UPDATE и DELETE любым путём, кроме каскада при удалении проекта. Ограничения согласуют
статус с содержимым: граф есть ровно у SUCCEEDED и PARTIAL, причины — у BLOCKED, ошибка — у FAILED;
отсутствие графа пишется SQL NULL. Изменить решение — новый запуск; изменить старый запуск нельзя
ни через API (маршрутов нет), ни прямым SQL (T25).

## X. Решение инженера

Выбор из вариантов — `POST /calc/synthesis-runs/{id}/decisions` (право проверки): узел, выбранная
кратность внутри диапазона этого запуска, вариант, комментарий; сохраняются автор, дата и
альтернативы. Запуск не меняется. Решение — вход нового запуска (`decision_ids`); в новом графе
кратность `selected` с основанием `HUMAN_DECISION`, элемент остаётся «рассчитанным». Решение вне
нового диапазона не применяется — с предупреждением. В MINIMUM решение не применяется к нижней
оценке.

Почему не `ManualOverride` реестра фактов: тот выбирает утверждение о факте объекта при
расхождении источников, а здесь — гипотеза системы. Решение не пишется в реестр фактов, гипотеза
и расчётное значение тоже (T29): направление данных одно — факты → расчёт → синтез.

## AF. Готовность к PROMPT 06
