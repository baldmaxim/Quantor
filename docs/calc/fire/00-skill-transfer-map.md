### C3. Ограничение контракта: квалификатор — закрытый перечень

`CalcFactTypeDef.qualifier_options` — закрытый список: квалификатор «стояк 1В2.2-3» или «отрезок
левый верхний» в нынешний контракт не ложится. Варианты для F01:

1. **Слоты** (рекомендуется): перечни `R01…R40` для стояков, `S1…S8` для отрезков этажа,
   `Z1…Z5` для зон, `ROW01…ROW40` для рядов ЭМ; подпись из проекта («1В2.2-3») — отдельный TEXT-факт
   того же слота. Контракт субъекта не меняется.
2. Открытый квалификатор для отдельных типов — меняет проверку субъекта и ключ факта для всего
   реестра; без отдельного решения не делать.
3. Код стояка в `system_code` — смешивает систему со стояком; не рекомендуется.

Вид элемента по схеме — естественный закрытый перечень: ПК, клапан сухотруба, СПЖ, затвор отвода,
ороситель по схеме, ШПК, ГМ-80.

Типовые этажи: факт на каждый этаж (журнал F02 пишет диапазон этажей пачкой обычных фактов). Сорок
девять этажей по четыре отрезка — около двухсот фактов на корпус; «этаж в разрыве схемы принят
типовым» — видимое допущение в основании факта.

## D. Карта формул надземной части

Обозначения: E — этажей в группе; J — стояков в строке; n — оросителей в отрезке; l — длина отрезка;
Z(n) — отметка пола этажа n. «Факт» — значение реестра; «примитив» — арифметика ядра без параметров
(`engine/primitives.py`); «правило» — заявка на решение инженера (раздел F); «допущение» —
`TENDER_ASSUMPTION`, только TENDER_SAFE.

### D1. Стояки (лист «Стояки»)

| Величина                       | Формула навыка                                                            | Вид в портале                                                                 |
| ------------------------------ | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Отметка пола                   | Z(n) = 0 при n ≤ 1, иначе Z2 + (n − 2)·H                                  | факт `floor.elevation`; без него — примитив `vertical_span` по высотам этажей |
| Низ стояка                     | ZB (ВПВ, АУП), ZD (сухотруб)                                              | правило `apt.riser.end_segments`                                              |
| Верх стояка                    | Z(этаж по) + HPK (тупиковый ВПВ, сухотруб); Z(этаж по) + HC (кольцо, АУП) | HPK — факт ИОС2.2 (диапазон); HC — правило `apt.riser.end_segments`           |
| Длина стояка                   | верх − низ; все стояки, в том числе транзитные, идут от низа              | примитив                                                                      |
| Перемычки кольца               | J / 2 · (LRT + LRB)                                                       | правило `apt.vpv.ring_jumpers`                                                |
| Горизонталь сухотруба          | J · LDH                                                                   | факт обмера; без него — правило-резерв `apt.dry.horizontal`                   |
| Труба Ду стояка                | J · длина + перемычки + горизонтали                                       | примитив                                                                      |
| ПК, клапаны сухотрубов         | J · (этаж по − этаж с + 1)                                                | факты элементов по схеме на этаж; формула — контроль                          |
| Подводки Ду50 к ПК             | ПК · LPK                                                                  | правило `apt.vpv.hydrant_connection`                                          |
| Отвод сухотруба к клапану Ду65 | клапанов · LDV                                                            | правило `apt.dry.valve_connection`                                            |
| Перекрытий (гильз)             | J · этаж по; у сухотруба J · (этаж по − 1)                                | примитив по фактам; перекрытий — счётчик `slab` (как у ВК)                    |
| Креплений стояка               | J · (этаж по − [1 у сухотруба] + 1) · SHV                                 | правило `apt.supports`                                                        |
| Материал                       | ГОСТ 3262 при Ду ≤ 50, иначе ГОСТ 10704                                   | факт ИОС2.2 (материал и порог); атрибут позиции, не количество                |

### D2. АУП внеквартирных коридоров (лист «Коридоры АУП»)

Навык считает строку «крыло × группа этажей» с H отрезками. Формулы свода (а не промежуточного
шаблона — см. L4):

| Величина                                        | Формула навыка                                                                    | Вид в портале                                                                                         |
| ----------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Оросителей в отрезке                            | n = ⌈l / S⌉                                                                       | правило `apt.aup.corridor_row` по фактам l, S, A (см. ниже)                                           |
| Фактический шаг                                 | L = Σl / Σn — среднее по крылу                                                    | s = l / n по каждому отрезку (точнее; при равных отрезках совпадает)                                  |
| Ду40 на этаж                                    | L / 2, если D40 = 1, FEED = 1 и ⌈K / H / 2⌉ ≥ 4                                   | правило `apt.aup.branch_dn40`                                                                         |
| Ду32 на этаж                                    | Σl − H·L + (FEED = 1 ? 0 : LC + L / 2) − Ду40 + (своя шахта у отрезков ? LK2 : 0) | по отрезку: l − s + подключение по виду подачи − Ду40; подключения — правило `apt.aup.row_connection` |
| Ду50 на этаж                                    | L50 · (своя шахта ? H : 1)                                                        | факт «а-б» × этажных отводов                                                                          |
| Тройник 32×15                                   | своя шахта ? K − H − 1 : (FEED = 1 ? K − 2 : K − 1)                               | по отрезку: в середину n − 2, с торца n − 1 — правило `apt.aup.row_fittings`                          |
| Тройник 32×32 (развилка)                        | своя шахта ? 1 : (FEED = 1 ? 1 : 0)                                               | по отрезку: в середину 1, с торца 0                                                                   |
| Концевые узлы                                   | своя шахта ? H + 1 : (FEED = 1 ? 2 : 1)                                           | по отрезку: в середину 2, с торца 1                                                                   |
| Переход 40×32                                   | 1, если Ду40 > 0                                                                  | правило `apt.aup.branch_dn40`                                                                         |
| Этажных отводов                                 | E · (своя шахта ? H : 1)                                                          | по отрезкам, у которых подача не «от соседнего отрезка»                                               |
| СПЖ, затвор Ду50, тройник 100×50, переход 50×32 | по 1 на этажный отвод                                                             | правило `apt.aup.floor_branch`                                                                        |

Формулы навыка для раздельной подачи (`K − H − 1`, `H + 1`, `LK2` на пару) верны только для
топологии эталонного корпуса: один отрезок пары подан с торца, второй — сбоку с развилкой. В портале
вид подачи — факт **каждого отрезка**, и формулы считаются по отрезку; эталонный случай получается
как частный.

**Расстановка в отрезке.** Навык считает n = ⌈l / S⌉ и не проверяет отступ от торцевых стен A. Это
верно, пока A ≥ S / 2. Правило `apt.aup.corridor_row` должно давать
n = max(⌈l / S⌉, ⌈(l − 2A) / S⌉ + 1) и требовать один ряд по оси только при ширине коридора не больше
2A; шире — вопрос, а не молчаливый один ряд. Ширина W в навыке объявлена, но в формулах не
используется.

Синтетика (S = 3,5 м, A = 1,75 м, подача в середину):

| l, м | n   | s, м   | Ветки | Ду40, м | Ду32, м | Тройники 32×15 | Развилка | Концевые |
| ---- | --- | ------ | ----- | ------- | ------- | -------------- | -------- | -------- |
| 19,0 | 6   | 3,1667 | 3 + 3 | 0       | 15,8333 | 4              | 1        | 2        |

### D7. Диафрагмы ПК

Напор у ПК этажа n = Hст − (Z(n) − Z(нижнего ПК)). Последний этаж с напором выше порога:
J = min(верхний этаж зоны с ПК; ⌊2 + (Z(нижнего) + Hст − THR − Z2) / H − ε⌋). Диафрагм =
max(0; J − max(нижний; 2) + 1) · ПК на этаж + ПК 1-го этажа, если нижний ПК на 1-м этаже и Hст > THR.

- Hст и нижний ПК зоны — факты гидрорасчёта; порог — факт ИОС2.2 или правило
  `apt.vpv.diaphragms` (NORMATIVE с пунктом нормы).
- Навык честно называет результат минимумом: таблицы ПД считают напор только от насоса ВПВ, а насос
  общий с АУП. Это вопрос проектировщику; в портале MINIMUM = по таблицам ПД, EXPECTED — так же,
  пока инженер не утвердит иное.
- Формулу с отметками нужно переписать через факты `floor.elevation`, без Z2 и H навыка.

### D8. Окраска

Площадь = π · Dн · L по каждому Ду (L без запаса); работы — м² площади, без умножения на слои;
грунт, кг = площадь · NG · PG; эмаль, кг = площадь · NE · PE. Dн — таблица ГОСТ (правило
`apt.pipes.dimensions`), слои и расход — правило `apt.coating`. Нужна размерность массы `kg`
(в каталоге единиц её нет — F01).

### D9. Крепления

Хомуты стояков — раздел D1; опоры горизонтальных Ду32–40 = ⌈L / SHH⌉; опоры Ду50 = ПК + этажные
отводы. Правило `apt.supports`; у ВК — `vk.supports.spacing` (решить в F05, общее правило или своё).

### D10. ПНР

По корпусу четыре работы — промывка, гидравлическое испытание, опробование, сдача; количество =
длина трубопроводов корпуса, м (так в образцах ВОР владельца). Правило `apt.commissioning.scope`
(состав работ). Включать ли работы в паспорт системы — вопрос O3.

## G. Гидравлика веток (F09)

`branch(segs, dn)`: участки от концевого оросителя к развилке; P = P диктующего,
Q = 10 · K · √P; на каждом участке P += (1 + местные) · A(Ду) · L · Q² / 100, скорость
v = Q / (π · d² / 4) по внутреннему диаметру; перед следующим участком Q += 10 · K · √P.
`fork(b1, b2)`: вторая ветка приводится к давлению развилки: Q2' = √(Q2² · P1 / P2).

В портале это **проверки**, а не позиции объёма: скорость и давление в развилке против таблиц ПД,
подтверждение правила Ду40, расход зоны по АР против числа оросителей в гидрорасчёте, раздел
«Гидрорасчёты ПД — ошибки» (сумма потерь против давления в узле, пересчёт потерь ВПВ, скорость по
расходу). Таблица A и внутренние диаметры — параметры правил; K и P диктующего — факты ИОС2.2.
Квадратный корень в ядре даёт неточный `Decimal`: округление — именованным шагом с записанной
точностью (ADR-0030, «Числа и единицы»).

## H. Торговля и 1-й этаж (F10)

**Торговля** (`floor_trade.py`): в каждом зале nx = ⌈W/S⌉, ny = ⌈H/S⌉, оросители в центрах ячеек,
без точек в исключённых помещениях (ПУИ, санузлы); тот же счёт при втором шаге; рядки Ду40
перпендикулярно стороне к магистрали — тройников n − 1, концевой 1 на рядок; коллектор Ду50 вдоль
стены от первого до последнего рядка; подвод Ду65 от коллектора к магистрали; магистраль Ду100 —
длина ломаной; коридор — один ряд ⌈L/S⌉. В портале (ADR-0034): контуры залов и исключения — принятая
геометрия F04; сетка по контуру, рядки, коллекторы, подводы и магистраль строит генератор F10 по
правилам `apt.trade.*`; резерв без геометрии — факты ручного ввода и обмера; шаг из гидрорасчёта —
второй вариант трассы в TENDER_SAFE.

**1-й этаж** (`floor_retail.py`): арендные блоки — заливки плана (класс B), в портале — факт
`floor.commercial_units_count` по экспликации; ШПК по схеме против блоков — разница только в
TENDER_SAFE (`apt.tender.retail_cabinets`); горизонтали сухотрубов — трасса генератора от шахты до
наружной стены (место фасадной головки подтверждает человек), резерв — обмер.

## I. Автостоянка (F11)

Что делает навык (`parking.py`): маски залов по цвету заливки, стены по растру, сетка распылителей S × S
с одним в каждой кладовой и ПУИ, рядки до 4, дерево сети поиском пути с весом глубины, замыкание
тупиков в кольца, диаметры по числу распылителей за участком (до 2 — 28 × 1,5; до 4 — 35 × 1,5; иначе
50,8 × 2,0; подвод от узла управления, пока за ним ≥ 60 % распылителей, — 60,3 × 2,0), переходы и
тройники по смене диаметра и ветвлению, завесы ЭМ (дренчеров = ⌈периметр / 0,762⌉ при 1 л/с на 1 м по

Что переносится (после ADR-0034 — с трассировкой генератором F11 на векторной геометрии):

## J. «Ведомость объёмов» навыка → позиции паспорта

## K. Сценарии

| Сценарий    | Что входит                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| MINIMUM     | подтверждённые элементы схемы и АР, нижние границы диапазонов правил и фактов (например, нижняя граница высоты ПК); диафрагмы — по таблицам ПД |
| EXPECTED    | расчёт по АР по утверждённым правилам, как «в объём» навыка: оросители по отрезкам, Ду40 по правилу, этажность по АР                           |
| TENDER_SAFE | EXPECTED + `apt.tender.material_reserve`, `apt.tender.retail_cabinets`, `apt.tender.trade_spacing` — резервы раздельно от базы                 |

Счёт оросителей по схеме — не сценарий: раздел паспорта «Схема ↔ АР» по группам этажей с пометкой
«по АР меньше — сообщить». Инварианты MIN ≤ EXP ≤ TS проверяются по каждой позиции; если по АР
оросителей меньше, чем по схеме, это вопрос, а не нарушение инварианта (схема в сценарии не входит).

## Q. Решения владельца после F00 (2026-10-19)

1. **O1 — слоты.** Квалификаторы: `R01…R40` — стояки, `S1…S8` — отрезки коридора этажа, `Z1…Z5` —
   зоны, `ROW01…ROW40` — ряды мест ЭМ; подпись из проекта — отдельный TEXT-факт того же слота.
2. **O2 — окраска.** Размерность массы и единица `kg`; категория позиций `COATING`.
3. **Трассы — автоматически, как в навыке**
   ([ADR-0034](../../adr/0034-avtomaticheskaya-trassirovka-pozharotusheniya.md)): генератор в
   исполнителе заданий строит кандидатов геометрии и трасс по векторной геометрии PDF; человек
   принимает; принятое — факты; `calc` считает по фактам.
4. **Масштаб — калибровка листа человеком** с автопроверкой по площадям помещений против
   экспликации; автоопределение масштаба остаётся запрещённым.
5. **Значки схем ИОС2.2 — позже**, промтом F13 после гейта; до него — журнал F02.

Пакет перестроен: F03 — векторная геометрия листа, F04 — принятие геометрии и адаптер обмеров,
F08 — автоматическая трасса этажа, F10 и F11 — с трассами, F12 — гейт, F13 — значки. Соответствие
прежним номерам — в ADR-0034.
