# Старый расчётный портал — разбор

Разбор к PROMPT 00 пакета [`_prompts/calc_portal_stage_p/`](../../_prompts/calc_portal_stage_p/Quantor_Opus_5.5_Prompts_Calculation_Portal.md),
2026-09-26. Архитектура нового контура — в [00-audit-and-architecture.md](00-audit-and-architecture.md),
решение — в [ADR-0030](../adr/0030-raschyotnyj-kontur-stadii-p.md).

Старый портал — источник формул, идей и контрольных сценариев только для чтения. Его архитектура
и код в Quantor не переносятся, коэффициенты не считаются подтверждёнными.

## 1. Коротко

- В пяти калькуляторах найдено **365 правил**. Нормативных среди них **ни одного**: ГОСТ встречается
  только в названиях изделий, три ссылки «по СНиП/ГОСТ» в комментариях вентиляции не проверены.
- Физическое ядро — единичные формулы: A = L / (3600·v), площадь поверхности = периметр × длина,
  окраска по наружному диаметру, геометрия зон и транзитная длина стояка. Остальное — инженерные
  эвристики (181), правила неизвестного происхождения (54), потенциально ошибочные (52) и тендерные
  коэффициенты (26).
- Расчёт живёт внутри отрисовки и продублирован в 2–4 местах с разными константами: один и тот же
  корпус даёт 803,4 м или 717,6 м трубы К1, 12 или 32 компенсатора Т3/Т4 — в зависимости от
  вкладки.
- Типовые ошибки — двойное умножение, смешение единиц, молчаливые умолчания и частичное выпадение
  данных. Вентиляция умножает фитинги «по системам» на комнаты (1200 клапанов вместо ~300), VRF
  умножает квартирографию корпуса на секции дважды, гильзы К2 растут квадратично от этажности.
- Сохранённые в базе проекты не годятся как инженерный эталон: зоны и DN туда попадают из гонки
  подстановки умолчаний. Пригодна только квартирография — как частная входная фикстура вне git.

## 3. Архитектура

- **Родительский портал и iframe.** Разделы: управление проектами, сравнение проектов,
  водоснабжение, водоотведение, вентиляция, отопление (заглушка «будет доступен в ближайших
  обновлениях»), пожаротушение, кондиционирование. Калькуляторы открыты во iframe и обмениваются с
  порталом через `postMessage` (`load-project-data`, `auto-save`, `estimate-totals`,
  `sync-underground-area`, `theme-change`, `iframe-ready`) с адресатом `'*'` и без проверки
  источника.
- **Квартирография.** Excel → `building_stats`:
  `{name, num, height, totalApts, totalBath, totalKitchens, floors: [{floor, apts, bath, kitchens}]}`.
  Читается первый лист; «Корпус N» ищется в первых 10 строках; высота — первое число рядом с ячейкой
  «высота»; этажи 1…200, подвалы отбрасываются. Колонки санузлов и кухонь не проверяются. Если у
  проекта нет своей квартирографии, портал молча подставляет квартирографию другого проекта.
- **Хранение.** Supabase — основное; SQLite — запасное при любой ошибке, без сверки (возможен
  раскол данных); localStorage — кеши, справочник цен и **коллизия ключа** проектов между порталом и
  калькулятором ВК, из-за которой в расчёт подставляется состояние по умолчанию. Один расчёт ВК
  пишут три писателя; «Сохранить» ищет проект по **названию** и стирает расчёты других систем.
- **Расчёт в отрисовке.** Правила считаются в функциях, строящих HTML, и продублированы для
  интерфейса, спецификации, сметы, письма поставщику и схемы SVG. Часть блоков результата в обёртке
  отсутствует и не видна; «Экспорт в Excel» калькулятора ВК падает.
- **Цены.** Проектные цены, глобальный справочник в localStorage, цены по умолчанию в коде, импорт
  цен из счетов PDF/Excel, аналитика ₽/м² с зашитыми порогами. В новом контуре цены не считаются.
- **Запрос КП.** Письмо поставщикам через `/send-mail` без авторизации с произвольными адресатами.
  Реквизиты компании и адреса поставщиков зашиты в код — в документы Quantor не переносятся.

## 4. Легенда

Классы — восемь из PROMPT 00; основной класс один, вторичный — в скобках.

| Код    | Класс                       | Смысл                                                     |
| ------ | --------------------------- | --------------------------------------------------------- |
| физ    | физическая / математическая | следует из физики или арифметики без выбора параметров    |
| норм   | нормативная                 | источник назван и проверен — в старом портале таких нет   |
| произв | правило производителя       | зависит от конкретной продукции или марки                 |
| геом   | геометрическая              | длины, площади, этажи из геометрии здания                 |
| эвр    | инженерная эвристика        | правдоподобное правило «как обычно делают», без источника |
| тенд   | тендерный коэффициент       | резерв, запас, группировка расценок                       |
| неизв  | неизвестного происхождения  | число без объяснения                                      |
| ошиб   | потенциально ошибочная      | противоречит другим правилам, физике или единицам         |

| Действие    | Что значит для нового контура                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| UL          | кандидат в Rule Registry со статусом `UNVERIFIED_LEGACY`: только объявленный fallback, с предупреждением, не в сценарии MINIMUM      |
| ЗАМЕНА      | заменить нормативным или физическим методом после проверки инженером                                                                 |
| ВВОД        | сделать явным входом; значение старого портала можно показать как помеченное умолчание                                               |
| ОТКАЗ       | не переносить; правила класса «ошиб» остаются в каталоге как `REJECTED_LEGACY` — для классификации различий `LEGACY_BUG` в PROMPT 12 |
| вне контура | цены, НДС, импорт счетов, аналитика — в расчётный контур не входят                                                                   |

Формулировка «возможно связано с …, требует проверки инженером» — гипотеза о возможной основе
правила, а не нормативный источник.

## 7. Сквозные скрытые допущения

- **Высоты этажей** разные в каждом калькуляторе: 4,0 и 3,3 м (ВК), H / n (К1, ВПВ), 3,0 м (ОВ),
  3,3 м при выводе этажности из высоты (ОВ, VRF, ВПВ), 3 м (АУПТ). Смысл «высоты» в квартирографии
  (до кровли, парапета, перекрытия) не определён нигде.
- **1-й этаж** нежилой в ВК (квартиры отбрасываются) и жилой в VRF — несогласованно.
- **Секции**: в ВК корпус = секция; ОВ ставит одну секцию при загрузке квартирографии; VRF
  умножает квартирографию корпуса на секции; в ВПВ секции множат шкафы, но не стояки.
- **Молчаливые умолчания**: 9 этажей (ОВ), 2 стояка DN 32 (ВК), 4 квартиры на этаже и 30 м коридора
  (VRF, АУПТ), МОП 30 м (ВК), граница зон 17 этажей (ВПВ), буферные блоки включены (VRF).
- **Каждая система — стояк от 1-го этажа** до верха; подвал, лежаки, выпуски, вводы, вентстояки
  над кровлей и наружные сети не считаются.
- **Чужая квартирография** подставляется в проект без своей.
- **Тендерные коэффициенты** применяются скрыто: обрезь 1,07 / 1,10 / 1,15, изоляция ×1,2,
  облицовка 200 м² на секцию.
- **Марки** используются как обобщённые позиции.

## 8. Сквозные классы ошибок

1. **Дубли правил с разными константами** — компенсаторы (12/10/8 м против 25/30/35 м), коллекторы
   (четыре алгоритма), два движка К1, два пути записи сметы ОВ.
2. **Двойное умножение** — фитинги «по системам» × на комнаты (ОВ), квартирография корпуса × секции
   и кровельные трассы × секции дважды (VRF), аварийные гильзы = квартиры × этажи (К2).
3. **Единицы** — «компл.» × м² (подземная часть ВК), метры в поле «число стояков» (К2), периметр как
   «поверхность» (ОВ), «усл. ед.» (ПНР ВК), «Дн» вместо наружного диаметра (изоляция ВК).
4. **Молчаливые ограничения** — Ø500 и 1200×1200 без предупреждения (ОВ), DN 32 при импорте (ВК).
5. **Частичное выпадение** — этажи выше последней зоны (ВК), квартиры 1-го этажа (ВК), системы ДВ
   без клапанов (ОВ), стояк мусорокамеры без трубы (К1).
6. **Порядок событий и кеши** — смета ОВ зависит от последнего обработчика, таблицы арматуры
   устаревают, выбор производителя коллектора сбрасывается и меняет количество вдвое.
7. **Смешение систем** — ДУ, ПД и паркинг считаются вместе с общеобменной вентиляцией.
8. **Материалы** — PP-R и PE-X под одним названием, сталь «оцинкованная» и «ВГП» одновременно.
9. **Мёртвый код и невидимые блоки** — BOM КУУ, таблицы вычета длин фитингов, неработающий экспорт.
10. **Безопасность** — открытая отправка писем, `postMessage` без проверки источника, pdf.js 3.11.174
    (CVE-2024-4367), SheetJS 0.18.5 (CVE-2023-30533, CVE-2024-22363), CDN без проверки целостности.

## 9. Риски прямого переноса

Архитектурные:

- логика в отрисовке — нет чистого ядра, которое можно тестировать и воспроизводить;
- состояние интерфейса — источник истины; три хранилища и гонки между ними;
- нет происхождения величин, версий правил и тестов; классы позиций определяются регулярными
  выражениями по названиям;
- цены и количества перемешаны; ключи привязаны к номеру корпуса в массиве.

Инженерные:

- нет гидравлики и аэродинамики — DN и сечения задаются вручную или эвристикой;
- эвристики стояков (стояк на санузел), зон (по числу этажей), фитингов «на метр»;
- неполный охват — подвал, выпуски, вводы, вентстояки над кровлей, наружные сети;
- тендерные коэффициенты без зарегистрированного правила — по сути «TENDER_SAFE = +10 %», что пакет
  прямо запрещает;
- высоты и секции трактуются по-разному в разных калькуляторах.

Продуктовые:

- совпадение со старым порталом не означает правильности — критерий PROMPT 12 — объяснимость;
- при сравнении путь старого портала (спецификация, смета, письмо) для каждого количества нужно
  выбирать явно — они расходятся.

## 10. Что берём и что нет

Берём как кандидаты `UNVERIFIED_LEGACY` с явными входами или как идеи:

- **ВК** — последовательные зоны; средняя длина до квартиры в МОП; распределение квартир по
  коллекторам; учёт по квартирам, аренде, ПУИ; гильза на два типоразмера больше (проверить).
- **К1** — транзитная длина стояка (накопленный максимум сверху вниз); ревизии по этажам и
  противопожарные муфты на пластике (проверить норму); сценарии кухонь — как диапазон синтеза.
- **ОВ** — A = L / (3600·v); стояк с поэтажным нарастанием расхода; настраиваемые ряды размеров
  (проверить); площадь поверхности = периметр × длина.
- **ВПВ** — окраска по наружному диаметру; транзит зоны II.
- **Сверка** — идея «Книги 3»: раздельные «Кол-во заказчика» и «Кол-во ГП».
- **Квартирография** — формат (этажи с квартирами, санузлами, кухнями; высота) как ориентир для
  адаптера.

Не берём: код, архитектуру, хранение, цены, импорт счетов, письма поставщикам, аналитику; правила
класса «ошиб»; молчаливые умолчания; скрытые коэффициенты (только как явные `TENDER_ASSUMPTION`
после решения владельца); марки как обобщённые позиции.

## 11. Контрольные данные

- **Синтетические случаи поведения** старого портала — в каталогах: S1/S2/S4a/S4b (ВК), A и C
  (канализация), CC1–CC7 (вентиляция), A1 (VRF), B (пожаротушение). Это регрессия старого поведения
  для сравнения в PROMPT 06 и 12, а не эталон правильности. Синтетические входы можно хранить в git
  как фикстуры.
- **Частные данные** — квартирография двух объектов из базы старого портала — входная фикстура вне
  git. Сохранённые там зоны, DN и стояки эталоном не являются.
- **Инженерный эталон** появляется только на гейте после PROMPT 06: реальный объект стадии П,
  протокол и метрики объявляются до запуска.
