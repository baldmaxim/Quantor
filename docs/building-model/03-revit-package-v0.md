# Формат `quantor.revit_package.v0`: для автора плагина Revit

Дата: 2026-11-02. Основание: [ADR-0035](../adr/0035-model-zdaniya-i-versiya-tendera.md), план
[00-plan.md](00-plan.md), разделы 5–7. Код — `tools/building_model/building_model/revit.py` и `revit_format.py`.

**Формат черновой** (`"draft_format": true`). Образца JSON от автора плагина Revit и описания сборщика у нас
нет, поэтому поля выбраны по каноническому формату модели Quantor и по тому, что нужно Revit для
построения стен, проёмов, плит, помещений. Сборщик, который читает этот файл, ещё не написан, в Revit пакет
не открывался. Когда придёт образец, меняется только адаптер (`revit.py`), каноническая модель остаётся.

Схема: [revit-package-v0.schema.json](revit-package-v0.schema.json) (JSON Schema, порождается кодом, тест
следит, чтобы файл совпадал с моделью). Пример: [revit-package-v0.example.json](revit-package-v0.example.json)
(полностью синтетический, порождается тестовой фикстурой `tools/building_model/tests/revit_fixture.py`).
Пакет **на здание** (несколько листов в одной системе координат) — отдельный формат
`quantor.revit_building_package.v0`, собирается из пакетов листов: [05-revit-building-package-v0.md](05-revit-building-package-v0.md).

## Как получается пакет

```text
PDF → plangeom → модель листа (quantor.building_model.v1) → разметка (PNG + index.html)
→ подтверждение человеком (quantor.model_approval.v1) → пакет (quantor.revit_package.v0)
```

Пакет строится на один лист (один файл модели). Адаптер — чистая функция:
`BuildingModel + подтверждение | null + sha256 файла модели → RevitPackage`. Те же входы дают те же байты;
в файле нет времени запуска, единственное время — `manifest.approval.at` из подтверждения. Версия
адаптера — константа `0.1.0` (`manifest.adapter.version`).

Пакет не строится (отказ с перечнем причин), если:

- `sha256` файла модели не совпал с `approval.model_sha256` или номер страницы не совпал;
- в модели есть блокеры, кроме `scale_needs_human` и `scale_not_confirmed` (их снимает только подтверждение
  человека; при `--unapproved-test` пакет строится, но помечен как кандидат) и, при явном принятии в акте,
  `openings_noise` (см. ниже);
- у какого-либо уровня нет отметки (`elevation_mm` пуст).

### Шумный лист: `openings_noise` и `accepted_blockers`

Блокер `openings_noise` ставит нормализатор (версия 0.2.0), когда проёмов без хозяина (`host = null`, все виды
проёмов) на листе не меньше `noise_unhosted_min` = 100 **и** их доля среди всех проёмов листа не меньше
`noise_unhosted_share` = 0,5. Так выглядит лист, на котором plangeom нашёл тысячи «пустых проёмов» (на реальном
комплекте из 50 планов их 5). В данных замечания — `unhosted` и `openings_total`. Пороги — параметры прототипа,
по эталону не подбирались.

Блокер сам по себе не снимается масштабом. Его может принять **только человек**, и только после просмотра
разметки: `approve --accept-noise` кладёт код в поле акта `accepted_blockers` (отсортированный список,
по умолчанию пустой; допустимо единственное значение `openings_noise`, любое другое — ошибка проверки акта).
Без флага `approve` на шумном листе отказывает с подсказкой. Адаптер листа не считает блокером ровно тот
`openings_noise`, который перечислен в `approval.accepted_blockers`; все остальные блокеры акт не снимает.
Без акта (`--unapproved-test`) шумный лист — отказ, как любой другой блокер. В `index.html` у такой строки
вместо обычной команды стоит пометка «шумный лист: сначала проверьте» и команда с `--accept-noise`.

Без подтверждения и без флага `--unapproved-test` команда `revit` отказывает. Пакет с `approval = null`
годится только для проверки сборщика и в проект не загружается.

## Система координат и единицы

- Все длины — миллиметры (`units = "mm"`), площади помещений — м².
- Плоскость плана: ось X вправо, ось Y **вверх**. Начало — пересечение двух осей сетки
  (`manifest.origin.axes` — их метки). Если пары осей нет, был бы блокер `no_axes_origin` и пакета не будет.
- Отметки уровней (`levels[].elevation_mm`) — по высоте, мм, в системе отметок чертежа.
- Точка — массив `[x, y]`. Контур — массив точек, замкнутый неявно (последняя точка не повторяет первую),
  против часовой стрелки, начало — наименьшая вершина.

## Состав файла

`schema` (`"quantor.revit_package.v0"`), `draft_format`, `manifest`, `levels`, `wall_types`, `walls`,
`openings`, `floors`, `columns`, `stacks`, `rooms`, `not_exported`. Списки отсортированы по `id`
(уровни — по отметке, типы стен — по толщине, `not_exported` — по виду и ключу), поэтому порядок устойчив.

### manifest

| Поле | Смысл |
|---|---|
| `tender` | `number`, `version`, `manifest_sha256` версии тендера; до этапа версий тендера — `null` |
| `reader` | `name`, `version` читателя PDF (`plangeom`, `0.1.0a2`) и версия нормализатора (`0.2.0`) |
| `adapter` | `name`, `version` адаптера (`0.1.0`) |
| `model_sha256` | sha256 байтов файла модели, из которого собран пакет |
| `page` | номер страницы листа в комплекте (с нуля) |
| `approval` | акт подтверждения человеком целиком (`page`, `model_sha256`, `mm_per_pt`, `by`, `at`, `note`, `accepted_blockers`) или `null` |
| `scale_status` | `human` — масштаб и модель подтвердил человек; `candidate` — не подтверждены, пакет тестовый |
| `units`, `origin` | `mm`; `origin.axes` (метки осей), `origin.source` (`axes`), `origin.y` (`up`) |
| `coverage` | по видам (`walls`, `openings`, `floors`, `floor_holes`, `columns`, `stacks`, `rooms`): `total`, `exported`, `not_exported`. Всегда `exported + not_exported = total` |
| `review_summary` | `blocker`, `warning`, `info`: код замечания → число. Это замечания модели как есть: `scale_needs_human` останется в списке и у подтверждённого пакета, подтверждение лежит в `approval` |
| `assumptions` | `params` — значения параметров прототипа (`door_height_mm`, `window_sill_mm`, `window_head_mm`, `slab_thickness_mm`, `level_height_mm`); `assumed_elements` — сколько выгруженных элементов каждого вида имеет `QTO_Status = assumed` (и сколько уровней с допущенной отметкой или высотой) |

### levels

`id`, `floor`, `elevation_mm`, `height_mm`, `status` (`elevation_mm`, `height_mm`: `observed`/`derived`/`assumed`),
`instance_of`.

**Геометрия лежит только на базовом уровне** (у него `instance_of = null`), и все `level` у стен, плит,
помещений ссылаются на него. Уровень с `instance_of = "L5"` — экземпляр того же типового этажа: сборщик
повторяет на нём геометрию уровня `L5` (с отметкой этого уровня), копий геометрии в файле нет. Высота
этажа `height_mm` уходит в высоту стен и колонн.

### wall_types, walls

`wall_types[]`: `id` = `QTO-W-<толщина, округлённая до 10 мм>`, `thickness_mm`, `count` (сколько выгруженных
стен). **Это заглушка до каталога типов шаблона (этап M6):** сопоставление с реальными типами стен проекта
Revit пока не делается, типов получается много (на реальном листе несколько десятков). Сборщик сам
сопоставляет `QTO-W-*` с типами шаблона по `thickness_mm`.

`walls[]`: `id` (= устойчивый ключ `QTO_Key`), `level`, `start`, `end` (концы оси стены; направление
каноническое, но от него зависят `offset_mm` и `swing`), `height_mm`, `type`, `thickness_mm` (фактическая),
`structural` (`true` для ролей plangeom `outer wall`, `bearing wall`, `thick wall`; роль — эвристика по
положению и толщине, а не данные КР), `params`.

### openings

`id`, `kind` (`door`/`window`/`opening` — пустой проём без заполнения), `host` (`id` стены), `offset_mm`,
`width_mm`, `height_mm`, `sill_mm`, `swing`, `at`, `params`.

- **`offset_mm`** — расстояние вдоль оси стены от её **начала `start`** до **центра проёма** (проекция центра
  проёма на ось, мм). Проём занимает отрезок `[offset_mm − width_mm/2, offset_mm + width_mm/2]` от `start`.
  Центр проёма: для окна и пустого проёма — середина двух точек plangeom по торцам разрыва; для одиночной
  двери — середина между петлёй и закрытым концом полотна; для двойной двери — середина между петлями.
- `width_mm` — ширина проёма в свету, прочитана с чертежа (`observed`): для двери раскрытие полотна или пары,
  для окна — расстояние между торцами стены. Она может отличаться от разрыва в стене; такие двери модель
  помечает замечанием `door_leaf_vs_gap`, пакет их выгружает.
- `height_mm`, `sill_mm` — **допущения** (`assumed`): у двери высота 2100, `sill_mm = null` (порог на уровне);
  у окна и пустого проёма высота `window_head_mm − window_sill_mm` и подоконник `window_sill_mm`. Разрезы и
  фасады не читаются, поэтому реальных высот нет.
- `at` — центр проёма в плане (контрольная точка; для установки используйте `host` + `offset_mm`). Она может
  отстоять от оси стены не более чем на половину толщины плюс 150 мм.
- **`swing`** — только у дверей, иначе `null`. Список полотен (одно или два у двойной двери). У каждого
  `hinge_at` — у какого конца оси стены петля: `a` — ближе к `start`, `b` — ближе к `end`; `opens_to` — на какую
  сторону от оси открывается полотно, если смотреть вдоль оси от `start` к `end` при Y вверх: `left` — налево,
  `right` — направо. «Внутрь» или «наружу» вывести нельзя (контура здания в модели нет), поэтому поле
  выражено относительно оси.

### floors, columns, stacks, rooms

- `floors[]`: `id`, `level`, `boundary`, `holes[]` (`kind` = `stair`/`shaft`, `boundary`), `thickness_mm`
  (допущение), `params`. Отверстия принадлежат плите, внутри которой лежит их центр.
- `columns[]`: `id`, `level`, `outline`, `height_mm`, `params` — контур колонны, без семейства.
- `stacks[]`: `id`, `level`, `kind` (`stair`/`lift`/`possible_lift`), `outline`, `slab_opening`
  (контур отверстия в плите или `null`), `params` — только контуры лестниц и лифтов, семейств нет.
  `possible_lift` — лифт, в котором читатель не уверен (статус `assumed`).
- `rooms[]`: `id`, `level`, `tag` (номер помещения с чертежа), `type` (тип по экспликации или геометрии),
  `area_m2`, `boundary`, `point`, `params`. **`point` лежит гарантированно внутри контура:** центроид, если он
  внутри; иначе середина самого длинного внутреннего отрезка горизонтальной прямой. Для вогнутых контуров
  (П-образных, гребёнкой) центроид обычно снаружи, поэтому ставить помещение нужно именно по `point`.

### params

У каждого элемента:

- `QTO_Key` — устойчивый ключ (равен `id`); хеш типа, уровня и геометрии относительно осей, не зависит от
  порядка записей чтения;
- `QTO_Status` — `observed` (прочитано с чертежа), `derived` (выведено из прочитанного), `assumed`
  (параметр прототипа), `human` (решение человека; пока не встречается). Для составных значений —
  **самый слабый** статус составляющих (`observed` > `derived` > `assumed`; `human` сильнее `observed`).
  Например, у любого проёма статус `assumed`, потому что его высота — допущение; у плиты — `assumed` из-за
  толщины. `assumed` не выдаётся за `observed`;
- `QTO_Source` — происхождение строкой: `p<страница>:<id plangeom через запятую>`, несколько записей через
  `|` (`p51:W12,W13`);
- у стен дополнительно `QTO_Role` — роль plangeom (эвристика, статус `derived`).

Сборщик должен записать эти параметры в экземпляр элемента Revit (общие параметры проекта); статус нельзя
терять, он нужен человеку при проверке модели.

### not_exported

`key`, `kind` (`wall`/`opening`/`floor`/`floor_hole`/`column`/`stack`/`room`), `reason`, `at` (точка или
`null`). Ничего не пропадает молча. Причины:

| `reason` | Когда |
|---|---|
| `no_host` | у проёма нет стены-хозяина (или хозяин сам не выгружен); у отверстия нет выгруженной плиты |
| `ambiguous_host` | хозяин проёма неоднозначен (две равноценные стены), модель его не угадывает |
| `offset_outside_host` | проём выходит за пределы стены-хозяина больше чем на 50 мм |
| `wider_than_host` | проём шире стены-хозяина (с запасом 50 мм) |
| `zero_length_wall` | стена короче 1 мм |
| `degenerate_polygon` | контур с числом вершин меньше 3 или с нулевой площадью |

Запасы 50 мм и 1 мм — параметры адаптера (`OFFSET_TOLERANCE_MM`, `ZERO_LENGTH_MM` в `revit.py`), не измерения.

## Что требуется от сборщика

1. Проверить `schema`, `draft_format`, `manifest.scale_status`. Пакет с `scale_status = candidate` в проект
   не грузить.
2. Создать уровни по `levels` (отметки), затем элементы на базовом уровне и их экземпляры на уровнях с
   `instance_of`.
3. Стены — по оси `start → end` на уровне `level` с высотой `height_mm`. Типы сопоставлять по `thickness_mm`
   (заглушка `QTO-W-*`). **Стены между собой не соединять** (правило из спецификации SU10: соединения —
   только с явного разрешения).
4. Проёмы — в стену `host` на расстоянии `offset_mm` от `start`; высота, подоконник, ширина из полей; руку
   двери выставить по `swing`.
5. Плиты — по `boundary` с отверстиями, толщина `thickness_mm`; помещения — по `point`; колонны и лестницы с
   лифтами — только контурами (`outline`, `slab_opening`), семейств нет; что сборщик с ними сделает
   (линии, формы, пропуск), решает он и пишет в квитанцию.
6. Записать `QTO_Key`, `QTO_Status`, `QTO_Source` в параметры каждого элемента.
7. Вернуть квитанцию.

## Квитанция (предложение, не согласовано)

Формата квитанции в плане нет, это предложение для обсуждения с автором плагина. Квитанция — JSON рядом с
пакетом:

```json
{
  "package_sha256": "…sha256 байтов пакета…",
  "model_sha256": "…manifest.model_sha256…",
  "elements": [{ "id": "w_042fde73", "element_id": 123456 }],
  "refusals": [{ "id": "o_640fa226", "reason": "host_not_created", "detail": "…" }]
}
```

Каждый `id` пакета (уровни, стены, проёмы, плиты, колонны, стеки, помещения) должен встретиться ровно один раз
либо в `elements` (с `ElementId` Revit), либо в `refusals` (с кодом причины и пояснением сборщика). По
квитанции Quantor считает покрытие: «выгружен» — пакет отдан, «построен» — только после квитанции. Элементы
из `not_exported` в квитанцию не входят, они уже отклонены адаптером.

## Чего в формате нет

Типов Revit по каталогу шаблона (этап M6), семейств дверей, окон, колонн, лестниц, лифтов, соединений стен,
отделки, видов и листов, высот проёмов с чертежей (только допущения), IFC. Образца от плагина нет, поэтому
формат может измениться целиком.
