# Пакет модели QMP v1 (Quantor Model Package)

Дата: 2026-11-16. Статус: черновик к ADR-0053. Это контракт между выгрузчиком модели (конвертер из IFC,
плагин Navisworks, любой следующий источник) и порталом. Портал читает только QMP: ни IFC, ни NWD, ни RVT
он не разбирает.

## 1. Что в пакете

Пакет — набор файлов с общим корнем. Передаётся порталу по одному файлу (`PUT` части), состав и контрольные
суммы объявляет `manifest.json`.

```text
manifest.json                       состав, источник, система координат, счётчики, sha256 частей
storeys.json                        этажи
grids.json                          оси (может отсутствовать)
elements/<этаж>.jsonl               элементы этажа, по строке JSON на элемент
geometry/<этаж>__<дисциплина>.glb   геометрия этажа одной дисциплины
footprints/<этаж>.json              горизонтальный разрез этажа для привязки чертежа
```

`<этаж>` — ключ этажа `storey_key` (раздел 3). `<дисциплина>` — код дисциплины (раздел 2).

## 2. manifest.json

```json
{
  "schema": "quantor.model_package.v1",
  "generated_at": "2026-11-16T09:12:00Z",
  "generator": { "name": "quantor-model-package", "version": "0.1.0" },
  "source": {
    "kind": "ifc",
    "authoring": "Autodesk Revit 26.0.10.8 (RUS) - IFC 26.0.10.8",
    "ifc_schema": "IFC2X3",
    "files": [
      {
        "name": "KPLSK_UD_PD_R22_ARCH_1 (20260901).ifc",
        "bytes": 180994048,
        "sha256": "…",
        "discipline": "ARCH"
      }
    ]
  },
  "units": { "length": "mm" },
  "frame": {
    "axes": "X на восток, Y на север, Z вверх",
    "origin_offset_mm": [0, 0, 159400]
  },
  "disciplines": [{ "code": "ARCH", "name": "Архитектура", "elements": 7106 }],
  "parts": [
    { "path": "storeys.json", "kind": "storeys", "bytes": 1200, "sha256": "…" },
    {
      "path": "geometry/3k9Jx…__ARCH.glb",
      "kind": "geometry",
      "storey_key": "3k9Jx…",
      "discipline": "ARCH",
      "bytes": 1490000,
      "sha256": "…"
    }
  ],
  "counts": { "storeys": 12, "elements": 7106, "triangles": 410000, "parts": 38 },
  "manifest_sha256": "…"
}
```

- `source.kind`: `ifc`, `navisworks`, `revit`, `other`. Файлы источника — для людей и для поиска повторов, портал
  их не читает.
- `disciplines[].code`: латиница и цифры, до 16 знаков, верхний регистр (`ARCH`, `STR`, `EL`, `LC`, `PL`, `VAC`, `H`,
  `FF`, `BMS`, `TMS`, `GL`, …). Соответствие разделам портала (АР, КР, ЭОМ, СС, ВК, ОВ…) — настройка проекта.
- `parts[].kind`: `storeys`, `grids`, `elements`, `geometry`, `footprint`. У `elements`, `geometry`, `footprint`
  обязателен `storey_key`, у `geometry` ещё `discipline`.
- `manifest_sha256` — sha256 от канонического JSON манифеста без полей `manifest_sha256` и `generated_at` (ключи по
  алфавиту, разделители `,` и `:` без пробелов, UTF-8, не-ASCII без экранирования). Время выгрузки в хеш не
  входит, поэтому повторная выгрузка тех же данных даёт тот же хеш. Он же ключ идемпотентности: тот же манифест
  повторно не создаёт новую версию модели.
- Все пути относительные, без `..`, без абсолютных, только `[A-Za-z0-9._-]`, `/` как разделитель, до 160 знаков.

## 3. Система координат и единицы

- В JSON все длины в миллиметрах, координаты в системе здания: X на восток, Y на север, Z вверх.
- Начало Z — нулевая отметка проекта (в Капельском отметка `+0.000` первого этажа). Выгрузчик вычитает из мировых
  координат источника смещение участка и здания и пишет его в `frame.origin_offset_mm` (для Капельского 159 400 мм).
  Брать нужно `Elevation` этажа источника, не абсолютную Z.
- GLB: единицы метры, ось Y вверх (стандарт glTF). Пересчёт из системы здания: `(x, y, z)_мм → (x/1000, z/1000, −y/1000)`.
  Обратно: `X = x·1000`, `Y = −z·1000`, `Z = y·1000`.
- Единицы источника читаются явно (IFC: `IfcUnitAssignment`, Navisworks: единицы документа). Предположения запрещены.

## 4. storeys.json

```json
[
  {
    "storey_key": "3k9Jx…",
    "name": "C00_3_этаж_основной",
    "elevation_mm": 10540.0,
    "height_mm": 4080.0,
    "elevation_source": "ifc_storey_elevation",
    "bbox_mm": [-6000, -3400, 52000, 28400]
  }
]
```

- `storey_key` — устойчивый ключ этажа: IfcGlobalId этажа с заменой `$` на `-` (алфавит GlobalId содержит `$`,
  а ключ входит в путь части), для других источников — строка из `[A-Za-z0-9_-]`, до 64 знаков, которая не
  меняется при повторной выгрузке той же модели.
- `elevation_mm` — отметка относительно нулевой отметки проекта; `height_mm` — до следующего этажа, `null` для
  верхнего. `elevation_source`: `ifc_storey_elevation`, `slab_top`, `level`, `manual`.
- `bbox_mm` — `[minX, minY, maxX, maxY]` элементов этажа или `null`.
- Упорядочены по отметке, отметки различны.

## 5. grids.json

```json
{
  "source": "IfcGrid",
  "axes": [
    { "tag": "1", "dir": "U", "p0": [300.0, -3360.0], "p1": [300.0, 27900.0] },
    { "tag": "А", "dir": "V", "p0": [-5690.0, 0.0], "p1": [51770.0, 0.0] }
  ]
}
```

`dir`: `U` — оси, идущие вдоль Y (имеют постоянную X), `V` — вдоль X. Повторяющиеся по этажам сетки сводятся в одну по
паре `(tag, dir)`; расхождения концов больше 10 мм — предупреждение. Подписи сохраняются как в источнике.

## 6. elements/<этаж>.jsonl

Строка — один элемент:

```json
{
  "id": "2Fk…",
  "category": "wall",
  "ifc_class": "IfcWallStandardCase",
  "name": "Стена_200",
  "type": "Монолит 200",
  "discipline": "ARCH",
  "storey_key": "3k9Jx…",
  "bbox_mm": [0, 0, 10540, 6000, 200, 13540],
  "part": "geometry/3k9Jx…__ARCH.glb",
  "props": { "Pset_WallCommon.FireRating": "EI60" }
}
```

- `id` — устойчивый ключ элемента (IfcGlobalId как есть, `$` допустим; иначе Revit UniqueId; иначе `файл:ElementId`;
  путь в дереве Navisworks недопустим), алфавит `[A-Za-z0-9_$.:-]`, до 64 знаков. Уникален в пакете. Он же имя
  узла в GLB.
- `part` — путь части GLB с геометрией элемента или `null`, если геометрии нет (элемент остаётся в списке).
- `category` — нейтральная: `wall`, `slab`, `column`, `beam`, `door`, `window`, `curtain_wall`, `plate`, `member`,
  `railing`, `stair`, `covering`, `roof`, `furniture`, `equipment`, `pipe`, `duct`, `cable_carrier`, `other`.
  Исходный класс — в `ifc_class` (необязательно). Таблица соответствия — часть выгрузчика, её версия пишется в
  `generator`.
- `props` — плоский словарь «набор.параметр → значение», значения строка до 120 знаков, число или логическое;
  не больше 24 ключей. Исходные свойства, которых нет в словаре, портал не хранит.
- Составные элементы (части витража) — отдельными строками, у них своя категория (`plate`, `member`).

## 7. geometry/<этаж>__<дисциплина>.glb

- glTF 2.0 binary, без текстур, без анимаций, без камер и источников света, без расширений кроме
  `KHR_materials_unlit`, `KHR_mesh_quantization` (если нужно).
- Один узел верхнего уровня на элемент, `name` узла равно `elements[].id`; у узла один меш. Узлы без вершин не пишутся.
- Материалы: один плоский материал на категорию, имя материала `cat:<category>`.
- Размер части не больше 64 МБ. Этаж с дисциплиной больше этого предела делится на части `…__ARCH.1.glb`, `…__ARCH.2.glb`
  (поле `part` у элементов указывает на нужную).

## 8. footprints/<этаж>.json

```json
{"storey_key": "3k9Jx…", "z_cut_mm": 11740.0,
 "polygons": {"walls": [[[x, y], …]], "columns": [[[x, y], …]], "curtain": [[[x, y], …]]}}
```

Разрез на высоте +1200 мм от отметки этажа; контуры внешних колец в мм, замкнутые (первая точка не повторяется).
Служит только для привязки чертежа; не заменяет геометрию. Группы пустые — ключ отсутствует.

## 9. Проверка на портале

Ошибка отклоняет пакет, предупреждение сохраняется в версии.

Ошибки:

- схема, лишние и пропущенные поля, пути, повторы;
- размер части, число частей (не больше 2 000), элементов (не больше 500 000), общий размер (не больше 1 ГиБ);
- sha256 и размер каждой части не совпали с манифестом; `manifest_sha256` не совпал;
- GLB: нет заголовка `glTF`, версия не 2, JSON-блок не читается, у части нет имён узлов, указанных в `elements`;
- у элемента неизвестный этаж или часть; `id` повторяется;
- отметки этажей не возрастают.

Предупреждения:

- высота этажа вне 1,5–12 м; габарит этажа вне 5 м–2 км;
- сетка осей отсутствует или оси расходятся между этажами больше 10 мм;
- элементов без категории `other` больше половины;
- пакет с теми же `source.files[].sha256`, что у существующей версии (возможный повтор).

## 10. Версии и совместимость

`schema` меняется только при несовместимых изменениях. Добавление необязательных полей — та же версия. Портал
игнорирует неизвестные необязательные поля, но не теряет их при чтении манифеста.
