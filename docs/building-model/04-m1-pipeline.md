# M1. Офлайн-цепочка PDF → модель → разметка → подтверждение → JSON для Revit: отчёт

Дата: 2026-11-02. Основание: [ADR-0035](../adr/0035-model-zdaniya-i-versiya-tendera.md), план
[00-plan.md](00-plan.md), отчёт нормализатора [01-m1-offline-normalizer.md](01-m1-offline-normalizer.md),
формат пакета [03-revit-package-v0.md](03-revit-package-v0.md). Код — `tools/building_model/`, вне `apps/`,
`packages/` и боевого образа.

Это продолжение M1: к нормализатору добавлены чтение PDF, разметка для человека, акт подтверждения и
адаптер в черновой JSON для Revit. Нормализатор и его байтовый вывод не менялись (отличие одно, во входе: он
теперь принимает и одиночный лист, см. ниже). **Дополнение от 2026-11-03:** версия нормализатора 0.2.0 — добавлен
блокер шумного листа `openings_noise` (модели перестроены), а к цепочке — пакет здания (`revit-building`,
раздел «Пакет здания» ниже; формат — [05-revit-building-package-v0.md](05-revit-building-package-v0.md)). Эталона нет, поэтому это **не гейт G1**, и ни одно число ниже не
является отклонением от правды: это счётчики работы цепочки.

## Цепочка и команды

```text
PDF ──parse──▶ set.json ──markup──▶ model_<N>.json + overlay_<N>.png + index.html
                                         │
                      человек смотрит index.html и PNG
                                         ▼
                        approve ──▶ approval_<N>.json        (акт человека, код его не создаёт)
                                         ▼
                        revit ──▶ package_<N>.json            (quantor.revit_package.v0)
                        revit-building ──▶ building_<G>.json  (quantor.revit_building_package.v0, листы здания)
```

Окружения: `parse`, `markup` с картинками, `overlay` и `check-binding` — из `.venv-reader`; остальное — из
основного окружения (`apps/api/.venv-linux`), где нет plangeom, pypdfium2 и Pillow.

```bash
cd tools/building_model
./setup_reader_env.sh                                # .venv-reader: plangeom==0.1.0a2, pydantic, pypdfium2, pillow
R="env PYTHONPATH=. .venv-reader/bin/python -m building_model"
PY=../../apps/api/.venv-linux/bin/python

$R parse   --pdf @out/input/pdfpath.txt --out out/X/set.json [--pages 51,33] [--workers 1]
$R markup  --input out/X/set.json --pdf @out/input/pdfpath.txt --out-dir out/X [--pages 51,33]
$R run     --pdf @out/input/pdfpath.txt --out-dir out/X [--pages 51] [--input out/X/set.json] [--workers 1]
$PY -m building_model approve --input out/X/set.json --model out/X/model_51.json --page 51 \
      --by "Имя Фамилия" --out out/X/approval_51.json [--note "…"] [--accept-noise]
$PY -m building_model revit --model out/X/model_51.json --approval out/X/approval_51.json --out out/X/package_51.json
$PY -m building_model revit --model out/X/model_51.json --unapproved-test --out out/X/package_51_test.json
$PY -m building_model revit-schema --out ../../docs/building-model/revit-package-v0.schema.json
$PY -m building_model revit-building --input out/X/set.json --models-dir out/X --building 0 \
      [--add-page P] [--exclude-page P] (--approvals-dir out/X | --unapproved-test) --out out/X/building_0.json
$PY -m building_model revit-building-schema --out ../../docs/building-model/revit-building-package-v0.schema.json
```

`--pdf @файл` — путь к PDF читается из текстового файла, в командной строке и выводе он не появляется. Тексты
ошибок не печатают пути: ошибки ввода-вывода и сбои plangeom сообщают только вид (`OSError`, `RuntimeError`),
ошибки разбора Pydantic — только число несоответствий.

## Что сделано

- **Окружение** `setup_reader_env.sh`: создаёт `.venv-reader` и ставит `plangeom==0.1.0a2 pydantic pypdfium2
  pillow`. plangeom нет ни в `pyproject.toml`, ни в зависимостях. `.venv-*/` уже в корневом `.gitignore`
  (проверено `git check-ignore`). Скрипт выполнен на системном Python 3.14.4, сборок под 3.12 не понадобилось.
- **`parse`** (`parse_pdf.py`): единственный модуль, который подключает plangeom, через
  `importlib.import_module` внутри функции; нет модуля — `ValueError` с подсказкой про `setup_reader_env.sh`.
  Пишет результат `parse_document` как UTF-8 JSON, печатает время, число листов, вердикты.
- **Одиночный лист** (`reader.py`): `load_document` принимает и выход `parse_page` (без `sheets`, без
  верхнего `page`, номер в `source.page`). Гейт версии прежний, строгий. То же для `binding.read_raw_sheet`,
  которым пользуются `overlay` и `check-binding`.
- **Разметка** (`markup.py`, `overlay.py`): к слоям наложения добавлены контуры помещений (бирюзовая тонкая
  линия) и проёмы без хозяина (пурпурные, с крестиком). Прежние цвета не менялись. `index.html`: таблица
  листов, ссылка на PNG, легенда, готовая команда подтверждения; без внешних файлов, скриптов и сети, с
  `meta viewport`, светлой и тёмной темой, таблицей в контейнере с горизонтальной прокруткой, `html.escape`
  для всех значений. Без `--pdf` страница строится без картинок.
- **Подтверждение** (`approval.py`): акт `quantor.model_approval.v1` — `page`, `model_sha256` (sha256 байтов
  файла модели), `mm_per_pt` (из листа), `by`, `at` (UTC), `note`. Пустое имя — ошибка. Команда проверяет, что
  модель построена для этой страницы и что у листа есть масштаб. Подтверждений на реальных данных ни код, ни
  тесты не создавали.
- **Адаптер** (`revit.py`, `revit_format.py`): `BuildingModel + подтверждение | null + sha256 → RevitPackage`.
  Отказы, формат, причины `not_exported` — в [03-revit-package-v0.md](03-revit-package-v0.md). Схема —
  [revit-package-v0.schema.json](revit-package-v0.schema.json), пример —
  [revit-package-v0.example.json](revit-package-v0.example.json).
- **`run`** (`runner.py`): parse (при готовом `--input` пропускается) → markup, модели `model_<N>.json` для
  каждого листа-плана. Пакеты не строит; в конце печатает агрегаты и следующий шаг.

Новые модули: `parse_pdf`, `markup`, `approval`, `revit`, `revit_format`, `runner`; изменены `reader`,
`binding`, `overlay`, `geometry` (точка внутри контура), `cli`.

Дополнение от 2026-11-03:

- **Блокер `openings_noise`** (`pipeline.py`, `params.py`): проёмов без хозяина не меньше 100 и не меньше 0,5 от
  всех проёмов листа. Версия нормализатора `0.1.0` → `0.2.0`. Акт получил поле `accepted_blockers` (единственное
  допустимое значение — `openings_noise`), команда `approve` — флаг `--accept-noise`; адаптер листа и `index.html`
  учитывают это (подробно: [03-revit-package-v0.md](03-revit-package-v0.md)).
- **Пакет здания** (`revit_building.py`, `revit_building_run.py`, команды `revit-building`,
  `revit-building-schema`): пакеты листов группы здания, сдвинутые в общую систему координат по пересечениям осей,
  в одном файле. Из `coords.py` публичными стали `intersection` и `angle_between_deg`.

Все модули короче 500 строк (самый длинный `revit.py`, 456).

## Выводы и слабые места

1. Заглушка типов по толщине с шагом 10 мм даёт 48 типов стен на листе 51 и 79 на листе 33: слишком много
   для сопоставления с шаблоном. Каталог (M6) должен сворачивать толщины в немногие типы; пока список типов —
   перечень толщин, а не рекомендация.
2. Роль `structural` берётся из эвристики plangeom, и 391 стена из 571 на листе 51 «несущая» по ней; это не
