# M1. Офлайн-прототип нормализатора: отчёт этапа

Дата: 2026-11-02. Основание: [ADR-0035](../adr/0035-model-zdaniya-i-versiya-tendera.md), план
[00-plan.md](00-plan.md), разделы 2, 5, 6, 8. Код — `tools/building_model/`, вне `apps/api`, `apps/web` и
`packages`, вне боевого образа.

Это прототип. Инженерные константы ниже — параметры прототипа, а не установленные факты; по реальному
комплекту они не подбирались. Сравнения с эталоном не было, поэтому это **не гейт G1** и ни один показатель
плана (раздел 8) здесь не подтверждён.

## Что сделано

- Нормализатор `выход plangeom 0.1.0a2 → quantor.building_model.v1` для одного листа-плана: система
  координат по осям, стены (колонны отдельно, фильтр, склейка с учётом проёмов), проёмы с хозяином, поиск
  стороны открывания, уровни и экземпляры типового этажа, плиты с отверстиями, помещения, контуры лестниц и
  лифтов, устойчивые ключи, review (блокеры, предупреждения, служебные записи). Для стен plangeom без осевых
  линий — правило «ось по контуру» (отдельный раздел ниже).
- Команды `build`, `survey` (агрегаты по всему комплекту), `check-binding` (поворот и привязка к PDF),
  `overlay` (растр для проверки человеком).
- 85 синтетических тестов; реальные данные и `plangeom_example_*.json` в тестах не используются.
- plangeom не импортируется, не вендорится и не указан в зависимостях: нормализатор читает только его
  выходной JSON. Исходники plangeom не читались, заново он не запускался. Зависимости нормализатора —
  стандартная библиотека и Pydantic v2 (без Shapely, numpy, OpenCV). `check-binding` и `overlay` используют
  pypdfium2 и Pillow из временного окружения оценки и Pydantic не импортируют.

Модули (каждый короче 500 строк): `reader` (строгие модели входа, гейт версии), `params`, `coords`, `walls`,
`openings`, `outline` (ось по контуру), `floors`, `keys`, `canonical` (формат выхода), `pipeline`, `modelstats`, `survey`, `binding`,
`overlay`, `cli`.

## Команды

```bash
cd tools/building_model
PY=../../apps/api/.venv-linux/bin/python
$PY -m building_model build  --input out/input/set.json --page N --out out/model.json
$PY -m building_model survey --input out/input/set.json --out out/survey.json
# check-binding и overlay — из окружения оценки (pypdfium2, Pillow); Pydantic им не нужен
PYTHONPATH=. <venv-plangeom>/bin/python -m building_model check-binding --input … --page N --pdf @out/input/pdfpath.txt
PYTHONPATH=. <venv-plangeom>/bin/python -m building_model overlay --input … --model … --page N --pdf @… --out out/overlay.png
$PY -m ruff check . && $PY -m ruff format --check . && $PY -m mypy && $PY -m pytest
```

`build` принимает `--tender-number`, `--tender-version`, `--manifest-sha256`; без них в `tender` стоит null (в
M1 версий тендера нет). `--pdf @файл` читает путь к PDF из текстового файла, чтобы не печатать его. Входные
данные, `survey.json`, модель и overlay лежат в `tools/building_model/out/` (в git не попадает).

## Правило «ось по контуру»

Для стен plangeom с пустым `segments` и ролью не `column` (решение владельца, доработка M1). Контур из четырёх
вершин с углами в пределах 5° от 90° даёт среднюю линию вдоль длинной стороны L и толщину T (короткая
сторона). Если L/T меньше 1,5, контур компактный: в стены не идёт, в колонны не переносится (это не
наблюдение), площадь считается отдельно. Дальше ось идёт тем же путём, что обычные участки: фильтры толщины и
длины, склейка, висячие концы, поиск хозяина. Ось, у которой не меньше половины длины лежит в пределах t/2 от
оси уже имеющейся стены того же направления (угол в пределах `angle_tol_deg`), — дубль и в стены не идёт;
сравнивается только с осями из настоящих `segments` (после их фильтров), поэтому порядок входа на итог не влияет.
У стены есть поле `axis_source` (`segments` / `outline` / `mixed`); стена с участием контура имеет
`status = derived` и `thickness_status = derived`. Коды review (все `info`): `wall_no_axis` (не прямоугольник),
`wall_no_axis_compact`, `wall_axis_duplicate`.

Судьба 6 006 стен без осевых линий по комплекту (площадь — площадь контура plangeom):

## Что показали окна и лишние стены

**Окна.** Нормализация число окон не меняет: оно целиком из `windows` plangeom. Среди 22 планов группы 0 с
площадью стен в пределах ±10 % от медианы (после правила медиана изменилась, состав на два листа иной) окон: 2,
24, 30, 30, 32, 33, 33, 33, 33, 33, 35, 36, 38, 38, 38, 71, 73, 74, 75, 75, 75, 77. Это два плотных скопления
(около 33 при 30 дверях и около 73–77 при 38–45 дверях) и выбросы (2, 24). Гипотеза: скопления — разные типы
этажей, выбросы — сбой чтения; по чертежам не проверялось. Прежний разброс «73, 73, 23, 77, 75, 35, 74» из плана
выглядит так же. Для 10 из 75 окон страницы 51 хозяин неоднозначен: у каждого два кандидата с толщинами 152 и 182
мм на расстоянии около 110 мм от точки окна. Гипотеза: двухслойная фасадная стена, которую plangeom отдаёт двумя
параллельными полосами. Правило «не угадывать» оставляет такие окна без хозяина.

**Пустые проёмы** (`openings` plangeom): 16 220, из них 14 613 (90 %) — на пяти листах (страницы 40, 41, 71, 75,
76); хозяин найден у 8,3 %. Гипотеза: на этих листах «пустым проёмом» стали обычные разрывы линий. На типовых
листах их 15–18 (лист 51) и 70 (лист 33).

**Лишние стены.** Тонкие участки — 19,6 % всех участков, на листе 51 193 из 847. Отсечённые участки красные на
overlay; слои фасада и штриховка это или перегородки, решит владелец по overlay, я его не видел. Склейка вслепую завышала длину
на 13 % (проба из плана); склейка только через проёмы добавляет 8,9 % длины (6 009 м), каждый такой разрыв
подтверждён проёмом в нём.

## Выводы и слабые места

1. Пробел «стены без осевой линии» правило закрыло в основном. Было вне модели 7 551,6 м² (36,6 % площади стен
   plangeom). Вернулось 4 917,4 м² (23,9 %) осями длиной 7 343,3 м (после склейки в модели 5 689,3 м, +9,2 % к
   длине комплекта). Ещё 1 704,6 м² (8,3 %) — дубли, они покрыты имеющимися стенами. Осталось вне модели 929,5 м²
   (4,5 %): 1 314 компактных контуров (560,8 м²: короткие простенки или колоннообразные участки, гипотеза) и 110
   не прямоугольников (368,7 м²: контуры не из четырёх вершин или с косыми углами, гипотеза — Г-образные участки и
   срезы). Эти 929,5 м² правило не восстанавливает по замыслу. Возвращённая длина не подтверждена эталоном, у 638
   осей (около 2 000 м) есть частичное наложение на имеющиеся стены, поэтому завышение возможно, особенно на листе
   33. Для G1 «длина стен по классам толщин» классу «от 400 мм» это важнее всего: на листе 33 он вырос с 173,4 до
   621,6 м.
2. Допуск висячего конца 50 мм, по-видимому, слишком мал для того, как plangeom ставит оси: 27,7 % висячих концов
   стоят в пределах 100 мм от грани соседней стены, 45,9 % — в пределах 200 мм. Стены намеренно не стыкуются; нужно
   решение, нужен ли отдельный шаг стыковки и с каким допуском, либо это допуск к пересмотру на G1.
3. Двухслойные фасады дают неоднозначного хозяина окна. Нужен шаг, объединяющий слои одной стены, либо правило
   выбора, либо вопрос человеку; сейчас — вопрос (`opening_ambiguous_host`).
4. Пустые проёмы plangeom на части листов — шум (90 % на пяти листах). До M4 нужен фильтр или явное исключение

6. Склейка использует жадную кластеризацию с началом группы (толщина, угол, расстояние осей): две стены ровно на

   одном проёме.

   вдоль стены (20°) мои; на комплекте непарных полотен нет (`door_pair_missing` = 0), но правильность пар не

9. Высота этажа по соседней отметке берётся из ближайшей большей отметки того же здания в комплекте; в 8

## Отклонения от ТЗ

- Пара осей: при равенстве числа кружков порядок задают метка и смещение оси, а не «id/индекс»: у осей нет id,
  а индекс зависел бы от порядка входа и ломал бы побайтное равенство.
- В `review` добавлен счётчик `info`: отсечённые стены, стены без оси и висячие концы у проёмов — служебные
  записи. Код `wall_dangling_end` сохранён; у проёмов он получает severity `info`.
- Лишние поля выхода: `origin.sheet_mm`, `origin.source`, `levels[].floor`, `walls[].pieces`,
  `walls[].bridged_openings`, `walls[].role_status`, `walls[].axis_source`, `walls[].thickness_status`,
  `openings[].at`, `openings[].span`, `review.items[].a/b` (для overlay), блок `stats`.
- `swing` — список полотен вида `{hinge_at: a|b, opens_to: left|right}` относительно оси стены a→b: «внутрь/наружу»
  из плана вывести без контура здания нельзя.
- Выбор типового листа встроен в `survey` (`typical_candidate`), отдельной команды нет. Группы берутся из
  `buildings` plangeom, а не пересчитываются.
- Отметка уровня берётся из штампа, затем с плана; сам `floor_level` важнее не считался.
- Ось по контуру: дубль ищется среди настоящих осей, прошедших фильтры толщины и длины; отсев тонких и коротких
  осей по контуру учитывается отдельно (`outline_axis.filtered`) и не входит в `rejected_thin`/`rejected_short`
  настоящих участков. Код review «стена без оси» переименован из `wall_no_centerline` в `wall_no_axis`.
