## 2. Контракт заданий Quantor (подтверждено кодом)

- Задание — строка `jobs`: `job_type`, `status` (`queued → running → succeeded | failed | cancelled`), `stage`,
  `progress` 0..1, `idempotency_key` (уникален), `error_code`, `error_message` (≤ 500), `payload` JSONB,
  `attempt`/`max_attempts`, аренда — `apps/api/app/models/job.py:39-100`, ADR-0005, ADR-0014.
- `job_type` хранится как VARCHAR(32) без CHECK (`native_enum=False`, `apps/api/app/models/mixins.py:25-40`,
  `alembic/versions/20260904_0001_domain_stage1.py:57`): новое значение `JobType` миграции не требует — так уже
  был добавлен `pdf_geometry_extract` (`apps/api/app/domain.py:403-413`).
- Исполнитель берёт **только свои типы**: `claim(..., job_types=registry.supported_types())`
  (`apps/api/app/worker/runner.py:131-136`, SQL `job_type = any(:job_types)` — `apps/api/app/services/jobs.py:302-325`).
  Отдельный процесс с отдельным реестром заберёт новый тип, а основной `quantor-worker` его не тронет.
- Постановка: `jobs_service.enqueue(job_type, workspace_id, project_id, idempotency_key, payload)` — повтор с тем же
  ключом возвращает существующее задание (`apps/api/app/services/jobs.py:68-121`); образец — `schedule_extract`
  (`apps/api/app/services/geometry/schedule.py:19-38`), ключ включает версию парсера.
- Ход: `start(stage=…)`, `report_progress(progress, stage)`, `succeed(payload)`, `fail(error_code, message)`
  (`apps/api/app/services/jobs.py:221-284`).
- Повтор: только для кодов из `RETRYABLE_ERROR_CODES` (`apps/api/app/services/jobs.py:43-61`), возвращает **то же**
  задание в очередь, очищая ошибку, стадию и прогресс (`jobs.py:449-473`). Остальное — `JOB_NOT_RETRYABLE` (409).
- Чужое задание не видно: `GET /api/v1/jobs/{id}` ищет по `workspace.tenant` и отвечает 404
  (`apps/api/app/api/v1/jobs.py:24-28`).
- Режимы: `JOB_EXECUTOR=worker` (по умолчанию, `apps/api/app/core/config.py:109`) и `inline`. **Inline
  исполняет только `legacy_import`** (`apps/api/app/services/job_runner.py:56-64`); тесты вызывают тело задания
  напрямую (`execute_pdf_geometry_extract`, `job_runner.py:207-282`). Для CAD inline не нужен и не делается:
  движок не должен работать в процессе API.
- Падение тела задания гасится исполнителем и пишется как `IMPORT_FAILED` с именем класса
  (`apps/api/app/worker/runner.py:187-216`). Для CAD нужны свои коды (раздел 5), иначе отказ неотличим от импорта.
- Хранилище: ключи только из UUID, `revisions/{revision_id}/source.pdf` и `revisions/{revision_id}/artifacts/…`
  (`apps/api/app/storage/keys.py:27-38`); бинарное — только в объектном хранилище (ADR-0002).
- Боевая выкладка: один образ `deploy/Dockerfile.api` (python:3.12-slim, linux/amd64 в CI `publish.yml`),
  `quantor-worker` с `mem_limit: 768m` и томом `/tmp` (`deploy/docker-compose.yml:150-165`). Сервер — два ядра и
  4 ГБ на весь стек (`deploy/Dockerfile.api:5`).

## 3. Минимальная точка интеграции

**Новый тип задания `cad_pdf_convert`, исполняемый отдельным процессом `python -m app.cad_worker` в отдельном
образе `quantor-cad-worker`; движок вызывается подпроцессом через CLI-контракт (раздел 4).**

Почему так:

1. Схема `jobs` не меняется, миграция не нужна (раздел 2).
2. Основной образ и `apps/api` остаются без PyMuPDF/Shapely/ezdxf/numpy — это требование `CLAUDE.md:185`,
   ADR-0034 и ADR-0035 п. 5. Импорт движка разрешён только в `app/cad_worker/`, это проверяет страж-тест
   (как запланировано для `plangeom` в `00-plan.md`, раздел 6).
3. Подпроцесс даёт таймаут, предел памяти, убийство по аренде и изоляцию каталога без доверия к коду движка.
4. Это тот же слот, что `PLAN_PARSE`/M3 в `00-plan.md`, и кандидат на «читателя для боевого контура», которого
   требует условие 1 ADR-0035 после отказа от `plangeom`. Решение об этом — за владельцем (раздел 8).

Что придётся изменить в коде (после получения исходников):

| Файл | Изменение | Объём |
|---|---|---|
| `apps/api/app/domain.py` | `JobType.CAD_PDF_CONVERT = "cad_pdf_convert"` | 1 строка |
| `apps/api/app/errors.py` | коды `CAD_*` (раздел 5), сообщения, HTTP-статусы | ~20 строк |
| `apps/api/app/services/jobs.py:43` | `CAD_ENGINE_TIMEOUT` не добавлять; повторяемы уже `STORAGE_UNAVAILABLE`, `JOB_LEASE_LOST`, `JOB_TIMEOUT` | 0 |
| `apps/api/app/worker/runner.py` | `Worker` принимает реестр параметром вместо модульного `registry` (строки 94, 101, 134, 173) | малое, затрагивает общий код |
| `apps/api/app/cad_worker/` (новый) | `__main__`, реестр из одного типа, обработчик: скачать PDF → каталог задания → подпроцесс → проверка выходов → загрузка → `succeed`/`fail` | основной объём |

## 4. Контракт движка (CLI, который должен предоставить пакет)

Обработчик Quantor вызывает движок так — без сети, без секретов в окружении, `-I`:

```text
python -I -m <пакет_движка> run \
  --input   <job_dir>/in/source.pdf \
  --params  <job_dir>/in/params.json \
  --out     <job_dir>/out \
  --progress <job_dir>/progress.jsonl
```

Каталог задания: `${CAD_WORK_ROOT:-/tmp/quantor-cad}/<job_id>/<attempt>/`, права 0700, создаётся заново на каждую
попытку и удаляется после загрузки результатов (при отказе — тоже; диагностика остаётся в журнале и отчёте).
Движок не пишет за пределы `<job_dir>`, не читает ничего, кроме `in/`.

### Вход

- `in/source.pdf` — исходный PDF ревизии из хранилища, как загружен пользователем. **Никакой готовый CAD,
  геометрия пилота или ранее полученный DXF входом не являются.**
- `in/params.json`:

```json
{
  "schema": "quantor.cad_engine.params.v1",
  "mode": "architecture",
  "pages": null,
  "finishes": false,
  "schedules": false,
  "limits": { "max_pages": 200, "page_timeout_s": 300, "total_timeout_s": 3600 }
}
```

`mode` — только `architecture` (режим `architecture_transfer.py`). `finishes` и `schedules` обязаны быть `false`:
`true` — отказ `CAD_PARAMS_INVALID` ещё в API, до постановки. `pages` — `null` (все) или список индексов с 0.
Пределы задаёт Quantor; точные числа — после замера движка (раздел 9).

### Прогресс

`progress.jsonl`, одна строка на событие, дописывается и сбрасывается на диск:

```json
{"stage": "intake|pages|assemble|export|report", "done": 3, "total": 12}
```

Обработчик читает хвост раз в несколько секунд и вызывает `report_progress(done/total, stage)`. Отсутствие файла —
не ошибка, прогресс просто не меняется.

### Выход

| Файл | Обязателен | Содержание |
|---|---|---|
| `out/model.dxf` | при `completed*` | CAD-результат; версия DXF — указать в пакете |
| `out/report.json` | всегда, если процесс не убит | схема ниже |
| `out/manifest.json` | всегда, если процесс не убит | sha256 и размер каждого файла `out/`, версия движка, sha256 входа и параметров |

```json
{
  "schema": "quantor.cad_engine.report.v1",
  "engine": { "name": "…", "version": "X.Y.Z", "source_sha256": "…" },
  "input": { "sha256": "…", "pages": 12, "vector_pages": 11, "scanned_pages": 1 },
  "params_sha256": "…",
  "status": "completed | completed_requires_review | failed",
  "error": null,
  "pages": [
    { "index": 0, "status": "completed_requires_review", "scale": { "value": 100, "basis": "…" },
      "checks": [], "doubts": [ { "code": "…", "message": "…" } ] }
  ],
  "disabled": ["finishes", "schedules"],
  "timings_s": { "total": 0.0 }
}
```

Коды возврата: `0` — `completed` или `completed_requires_review`; `2` — некорректный вход (не PDF, зашифрован,
0 страниц, только сканы); `3` — некорректные параметры; `4` — превышен предел; `1` — внутренняя ошибка движка.
`report.json.error.code` дублирует причину машинным кодом без содержимого PDF.

### Смысл `completed_requires_review`

Задание Quantor при этом — `succeeded` (работа выполнена), а в `payload.result_status` остаётся
`completed_requires_review`. Интерфейс показывает «требует проверки инженером», а не «готово». Статус не
повышается ни Quantor, ни повтором; `completed` без проверки инженером в портал не выдаётся как принятый результат.

## 5. Ошибки, повтор, доступ

| Причина | Код Quantor | Повтор |
|---|---|---|
| Не PDF, битый, зашифрован, 0 страниц, все страницы — сканы | `CAD_INPUT_INVALID` | нет |
| Параметры вне контракта (`finishes`/`schedules` = true, неизвестный режим) | `CAD_PARAMS_INVALID` (422 в API) | нет |
| Превышены страницы или размер | `CAD_INPUT_LIMIT_EXCEEDED` | нет |
| Превышен общий таймаут подпроцесса | `JOB_TIMEOUT` | да (уже в списке) |
| Код 1, нет `report.json`/`manifest.json`, хеш файла не совпал с манифестом | `CAD_ENGINE_FAILED` | нет: ошибка движка детерминирована |
| Хранилище недоступно при скачивании/загрузке | `STORAGE_UNAVAILABLE` | да |
| Потеря аренды (пульс вернул «не наша») | подпроцесс убивается, результаты не загружаются | `JOB_LEASE_LOST`, да |

- Идемпотентность: `cad:{revision_id}:{engine_version}:{params_sha256}`. Тот же PDF, движок и параметры — то же
  задание; новая версия движка — новое задание (как ключ геометрии с версией парсера).
- Повтор — новая попытка в новом каталоге `<attempt>`. Артефакты загружаются **только после** успешной проверки
  манифеста, поэтому неудачная попытка ничего не оставляет в хранилище.
- Ключи артефактов: `revisions/{revision_id}/cad/{job_id}/{model.dxf|report.json|manifest.json}`; в `payload` —
  ключи, sha256, размеры, `engine_version`, `result_status`. Отдельная таблица не нужна до экранов проверки.
- Доступ: скачивание идёт только через API, который находит задание по `workspace.tenant` и `project_id`, как
  `jobs.py:24-28`; чужое — 404. Ключи хранилища и presigned-адреса наружу не отдаются без этой проверки.
- В журнал — коды, номера страниц и время; содержимое и имена из PDF — нет (как `job_runner.py:251-253`).

## 6. Блокеры

1. **PyMuPDF (AGPL-3.0) запрещён** в портале: ADR-0016 (`docs/adr/0016-…:152-154`, :187), ADR-0034,
   `CLAUDE.md:185`. Отдельный образ этого не снимает — портал отдаётся по сети, AGPL §13 действует для сервиса
   целиком. Варианты: (а) коммерческая лицензия Artifex; (б) перенос чтения PDF движка на pypdf (BSD-3, уже в
   `apps/api`) или pypdfium2 (`conditional`); (в) ADR о выполнении AGPL для отдельного сервиса с публикацией его
   исходников. **Нужно решение владельца до сборки образа.**
2. **Shapely** — `conditional`: «в производственный образ — только после ADR о способе распространения GEOS»
   (`vision/licenses/decisions.json:71-77`). ezdxf (MIT) и numpy — `allow`, но с областью `vision[mep-dxf]`; нужна
   запись области `cad_worker`. Pillow в матрице для боевого образа не проверялся.
3. **Генерация CAD** вне контура модели в `CLAUDE.md` не разрешена; контур `model.auto` закрыт до условий
   ADR-0035. Нужен ADR: CAD-выгрузка — часть модели здания или отдельная возможность со своим флагом.
4. **Ресурсы сервера:** 2 ядра и 4 ГБ на весь стек; `plangeom` на реальном комплекте брал до 2,5 ГБ на лист
   (`00-plan.md`, раздел 2). Профиль памяти движка неизвестен — без замера предел контейнера не назначить.
5. **Исходников нет** в ветке — запрос ниже.

## 7. Запрос на минимальный санитизированный пакет

Передать одним архивом (tar.gz или zip) с sha256 в сопроводительном сообщении. Только код и синтетика.

| Что | Откуда (Windows) | Зачем |
|---|---|---|
| `pdf_job_monitor/run.py`, `worker.py`, `intake_profile.py` | `АР_Обработка/90_Пайплайн/pdf_job_monitor/` | Маршрут произвольного PDF — основа CLI |
| `monitor_http.py` | там же | Только чтобы понять контракт прогресса и статусов; HTTP-сервер в Quantor не переносится |
| `architecture_transfer.py` | `АР_Обработка/90_Пайплайн/` | Архитектурный режим |
| `full_corpus.py` | там же | Только если `worker.py` его импортирует; иначе не нужен |
| все модули, которые транзитивно импортируют файлы выше | `90_Пайплайн/` | Полнота сборки |
| `requirements.txt` с **точными** версиями (`==`) | `90_Пайплайн/` | Воспроизводимая сборка |
| `pip freeze` рабочего окружения и `python --version` | рабочая машина | Сверка транзитивных версий |
| строка из истории VCS (коммит или дата) этой версии | — | Номер версии пакета |

**Не передавать:** рабочие PDF, DXF/DWG, геометрию и результаты принятого пилота, пользовательские замечания,
журналы с путями объектов, `.env`, ключи, токены, конфиги с адресами, старый санитизированный архив.

Перед отправкой проверить: в архиве нет файлов `*.pdf`, `*.dxf`, `*.dwg`, `*.json` с геометрией, нет абсолютных путей
к объектам и нет имён заказчиков в коде и комментариях. Если код жёстко ссылается на каталоги Windows или на
готовый CAD как вход — перечислить эти места, Quantor заменит их параметрами CLI.

| С чем | Где пересекается | Что согласовать |
