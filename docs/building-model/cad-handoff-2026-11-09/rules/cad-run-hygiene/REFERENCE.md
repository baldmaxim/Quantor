# Чистое завершение CAD-прогона

Применять правила текущего `AGENTS.md`. Итог — доступный актуальный результат,
целые исходники и зависимости, сохранённые полезные процедуры и отсутствие
разбросанных проб. Этот skill сам по себе не запускает фонового уборщика.

## Выбрать, что необходимо оставить

Определить актуальный результат по указателю последнего проверенного прогона.
Проверить HTML/JS-ресурсы, CAD, геометрию, сертификаты масштаба, пользовательские
замечания и данные повторно использованных видов. Ссылка на старый каталог
может быть рабочей зависимостью. Финализировать новый результат в отдельном
временном каталоге; публиковать указатель после проверки.

Для особенностей проекта читать [references/project.md](references/project.md).
Не переносить работающий движок в skills. В skill сохранять процедуру; рабочую
реализацию предметного алгоритма поддерживать в исходном коде проекта.

## Удалить временное

Свои временные каталоги создавать через `tempfile.TemporaryDirectory` или
отдельную папку в системном TEMP. В существующем проекте не считать всю папку
`_work` временной без анализа её использования.

Для накопленных данных сначала составить явный список файлов, проверив
зависимости. Оригиналы документов сохранять. Историю, для которой больше не
нужны распакованные копии, можно свернуть в один архив с возможностью отката.
Сомнительные данные сохранять до выяснения их роли.

Не включать в очистку файлы другой активной задачи. Если за время уборки
изменился движок или указатель результата, проверить влияние новых правок
на выбранные зависимости. Не откатывать параллельную работу ради совпадения
с контрольными суммами; отразить такие изменения отдельно в итоговой проверке.

Для архивирования использовать [scripts/archive_cleanup.py](scripts/archive_cleanup.py):

```powershell
python -B archive_cleanup.py --plan cleanup-plan.json --archive 'Архивы_движка/История_проекта_ДАТА.zip'
```

План имеет вид `{"root":"абсолютная папка проекта","files":["относительный/файл"]}`.
Без `--apply` создаётся и проверяется архив, исходные файлы остаются на месте.
`--apply` после проверки архива повторно сверяет SHA256 всех входных файлов,
затем удаляет только перечисленные файлы. Применять удаление только в пределах
порученной пользователем очистки либо к собственным временным файлам задачи.
Не расширять список после проверки. Скрипт отклоняет выход за корень, ссылки
файловой системы и защищённые конфигурационные каталоги; существующий архив
не перезаписывает. При сбое сохранять архив и журнал удалённых файлов.

При восстановлении читать `_CLEANUP_MANIFEST.json` в архиве, выбирать конкретные
нужные файлы, проверять их пути и SHA256; не перезаписывать текущую работу.

## Разделять снимок прогона и поздний отзыв

Исходный экспорт пользователя и входной снимок завершённого прогона сохранять
неизменными. Позднее решение по отдельной отметке добавлять отдельной записью
с UUID, источником решения, SHA исходного отзыва и явным набором изменяемых
полей. Изменение только статуса не должно копировать старые комментарии,
координаты, автора и происхождение поверх более поздних локальных правок.
Проверять эффективное состояние после выполнения JS и слияния локальных
данных, включая более позднее решение, удаление и повторное открытие страницы;
сырые initial_errors могут намеренно содержать исторические статусы.
Технический PASS переноса геометрии сам по себе не закрывает отметку пользователя.


Отдельные часы статуса проверять через полный рабочий JS и публичный обработчик
импорта, а не только извлечённые функции. Время изменения комментария не должно
подменять экспортированное время решения о статусе. Проверять несколько
циклов экспорта/импорта, более позднее решение между датами статуса и комментария,
равные часы, импорт старого комментария с новым статусом, legacy без часов и
удалённую отметку. Исправление просмотра выпускать отдельным postrun-патчем:
old/new SHA, неизменный initial config, защищённые GZ/CAD и recognition snapshot.
Успех нового теста не переписывает исторический FAIL; повторный независимый QA
связывать с новым SHA реального ресурса.

Обновление просмотра после завершения расчёта оформлять отдельным протоколом
и манифестом viewer assets. Сверять неизменность GZ/CAD/топологии и исходного
recognition snapshot; не перепечатывать исторические SHA для удобства проверки.
При независимой сверке старого baseline разрешать только перечисленные файлы
просмотра с проверенным old/new SHA и основанием изменения.

Численный след проверки границы может содержать исходный query buffer, который
не является экспортируемым ребром. При таком расхождении отдельно сравнить
native polygon, реальные выводимые интервалы и неизменный исходный trace.
Допуск арифметики доказательства не должен расширять физическое тело или
ослаблять пороги распознавания. Разные UUID замечаний сохранять даже при общем
source owner; совпадение одного компонента не доказывает совпадение всей отметки.

Для независимой проверки замечаний к коду без исходных чертежей читать
[references/code-review.md](references/code-review.md). Там же описаны точная проверка патча, source-first QA, физический inventory и границы диагностики.

## Проверять карточку замечания в реальном браузере

Использовать локальный Chromium с отдельным временным профилем и тестовыми
отметками. Не открывать пользовательский профиль для проверки. Для узкого окна
проверять фактический innerWidth в CSS px: мобильный эмулятор без meta viewport
может вернуть 980 вместо заданных 390. Для SVG определять начало выделения по
видимой части области чертежа через getScreenCTM и проверять elementFromPoint.
Один только прямоугольник getBoundingClientRect SVG включает поля letterbox.

Сначала проверять синтетический стенд, затем копию фактического HTML с новым
JS/CSS, после публикации повторять на действующей ссылке. Проверять отмену,
редактирование без смещения рамки, перезагрузку, импорт и экспорт JSON. Для
изменения интерфейса отдельно прогонять перенос часов статуса. Сохранять URL
отчёта и ключ локального хранилища. Архивировать исходные байты ресурсов по
относительным путям с SHA256, позднюю публикацию фиксировать отдельной записью.

## Разделять native shape, ink и query evidence

Хранить отдельно точную заливку PDF, реальные centerline-штрихи и интервалы
поискового доказательства с учётом печатной ширины. Граница заливки и общий
стык не являются командой нарисовать чёрное ребро. Параллельная пара границ
в пределах исходного float32 quantum сохраняет свой фактический gap/overlap;
не snap, не bridge и не объявлять положительный gap точным контактом.

Ссылка на source part является контекстом, а не владением всей полилинией.
Для физического ink проверять source segment, направленные t и aliases;
segment t и full-part normalized arclength t не взаимозаменяемы. При разбиении
общего ink сохранять все роли и один display owner. Малый реальный интервал
не должен исчезать из доказательства из-за порога удобства отображения.
Отдельно помечать только query-интервалы, которые запрещено экспортировать.

Неподтверждённый свежий fit не подменяет прежний provisional scale. Сначала
сравнивать native PDF points и параметры сегментов; для диагностического mm
использовать явно связанный с видом factor и сохранять его needs_review.
Не объявлять этим метрологическую приёмку или номинал изделия.

После адаптации общего метода воспроизвести proof установленной копией на
полном source context: локальная unit fixture может не содержать удалённый
штрих зависимости. Сопоставлять JSON-представление tuple/list как протокол,
не расширяя численные допуски для расхождений координат. Для общего interval
adapter отдельно проверять поворот, отражение и ULP-смещение по нормали,
включая spatial-index broad phase до collinearity predicate. Исправление
обнаруженного общего случая не смешивать с уже запечатанным узким прогоном.

## Сохранить приобретённый опыт

Проверенный повторяемый метод заносить в подходящий skill. Добавлять только
то, что влияет на решения следующего исполнителя: входы, условия применения,
обнаруженную причину ошибки, проверенный способ и границы достоверности.
Скрипты сохранять, если они переиспользуемы и реально проверены. Не копировать
в skills результаты прогонов, локальные библиотеки и историю всех попыток.
Для нового skill использовать skill-creator; валидировать `SKILL.md`.

## Проверить пакет движка для интеграции

Начинать с фактического маршрута загруженного PDF. Проследить локальные
импорты, включая отложенные, и ресурсы, которые открываются при экспорте.
Выделить привязки к контрольной базе, реестру, сетевым путям, рамкам
и замечаниям. В проверочной копии подставить синтетические служебные
данные. Для каждого изменённого файла сохранить исходный и включённый SHA.

Зафиксировать версии прямых и транзитивных зависимостей из реально
использованного окружения. Указать проверенную платформу и отдельно
пометить состояние сборки и допуска зависимостей в целевом сервисе.
Проверить извлечённый ZIP через штатный воркер с синтетическим PDF,
построенным тестом. Подтвердить масштаб независимыми размерными цепями,
перечитать DXF, проверить его аудит и локальные ссылки отчёта. Сверить
отказ на ошибочном входе и сохранение статуса проверки при неподтверждённом
масштабе. Случай с заливками без штрихов в области распознавания проверять
отдельно от плана с линиями. Сохранять результат каждого случая в протоколе.

Для сквозной проверки на Linux держать окружения API и движка раздельно.
Проверять хеши колёс в чистом окружении и запускать API-тесты с собственной
одноразовой базой на loopback. Использовать фактический маршрут загрузки,
очередь, отдельный процесс и скачивание DXF с проверкой SHA. Явно фиксировать
тестовые замены хранилища. При повторе изолировать ключи объектов по попытке
и перепроверять аренду под блокировкой перед публикацией. Проверять отмену
на дереве дочерних процессов и сохранять первый FAIL отдельно от результата
на исправленном SHA.

## Внешнее ревью кода по явному запросу

Для запрошенного пользователем анализа другой моделью собирать отдельный
санитизированный пакет: исходники движка, синтетические тесты, журналы и сводки
без PDF, рендеров, SVG планов, CAD, raw native/project geometry и реальных рамок
замечаний. Замены проектных конфигураций и fixtures отмечать явно, с original и
included SHA. Разделять frozen recognition, поздний viewer и текущий код;
проверять тесты именно распакованной копии с уже установленными зависимостями.

При явно запрошенной передаче через SSH/CLI сверять SHA на обоих концах и
неизменность payload после чтения. Фактическую модель проверять по runtime
metadata/result, а не по ответу модели о себе. Для анализа ограничить инструменты
чтением пакета; сохранять запрос, ответ и протокол в проекте. Если клиент
не поддерживает требуемую модель, предпочитать отдельную официальную установку
в папке задачи, сохранив существующую установку. Не считать мнение ревьюера
подтверждением проектной геометрии или инженерной приёмкой; конкретные находки
проверять независимо на небольших примерах перед изменением движка.

При отказе автопроверки на отправку кода подготовить отдельно разрешённый
текстовый запрос. По прямому поручению пользователя передавать проверенные
факты реальной задачи, достаточные для конкретной проверки, в согласованном
объёме. Хранить квитанцию запуска, неизменяемый
ответ с подтверждённым modelUsage и отдельный локальный протокол. Переносить
примеры через публичные функции и проверять, что вход представим до вызова.
Сравнивать геометрическое равенство по значениям, включая знак нуля.
Раздельно проверять точный оракул и действующий ULP-допуск, а совместимость
режима по умолчанию сверять по байтам с baseline в той же среде. В отчёте
различать синтетический результат и выполнение критерия внешнего ревью кода.

Для сквозного числового аудита окон и профильных панелей читать [references/window-output-audit.md](references/window-output-audit.md).

Для отдельного native-семейства с одной реальной связью между сложными профильными опорами читать [references/native-profile-connections.md](references/native-profile-connections.md).

После передачи артефакта с SHA в QA его байты неизменны. Дополнения и итоги писать отдельным протоколом; перед объявлением готовности проверить запись, exit code, реальный ресурс и его SHA. Правила семантического fallback, Windows byte-copy и postrun-просмотра приведены в [references/window-output-audit.md](references/window-output-audit.md).

## Проверить итог

Сверить сохранность исходников и актуального результата. Проверить локальные
ссылки после очистки и необходимые тесты движка. Не создавать новый расчёт
только для проверки уборки. Сообщить пользователю точку входа, что свёрнуто
в архив, сколько файлов убрано и какие зависимости оставлены.

## Контроль исполнения без CAD-прогона

Вести задачи в существующем плане проекта. Отчёты исполнителей принимать отдельными неизменяемыми событиями со стабильными ID. Перед заменой плана проверять исходный SHA и пользоваться общей блокировкой писателя. Запоздалый отзыв сохранять в истории, не отбрасывая более позднее решение. Отличать дату получения от фактической даты завершения; неизвестную дату оставлять пустой. Проверять ссылки и критерий конкретной стадии. Проекция для локального HTML производна от JSON. На неизменившемся индексе достаточно проверки меток файлов и ближайшего срока. Для временных путей Windows нормализовать обе стороны проверки вложенности через resolve().

Для изолированного engine-ready port читать [references/profile-runtime-port.md](references/profile-runtime-port.md).

Для actual configured Scene, сертификатов display-proxy и переносимых QA-скриптов применять также раздел «Фактический Scene вместо декларативных полей» в том же reference.

До coalescing native aliases проверять eligibility каждого исходного alias и сохранять его owner/role/actual entity provenance; подробности в profile-runtime-port reference.

Для aliases с разными поддерживаемыми формами source refs применять также проверку канонизации в profile-runtime-port reference.

При исправлении эквивалентных reference forms сохранять raw binding каждого alias и точные segment/subspan ограничения; проверенный способ описан в том же profile-runtime-port reference.

Для сравнения частичного target coverage с уже разбитым canonical ledger применять раздел «Квалификация current-canonical проверки» в references/code-review.md; исходный FAIL и границы точности сохранять.

Для канонизации source refs сохранять ограничения каждого объявления отдельно; проверенный порядок разбора описан в profile-runtime-port reference.

Для фактического output-only DXF/Scene QA применять также раздел
«Output-only DXF QA перед фактической проверкой» в
[profile-runtime-port reference](references/profile-runtime-port.md): реальные
INSERT transforms/visibility, физическая кратность и разделение pre-run freeze
от postrun source-order/output receipts.

Для native CAD identity и child owner/source provenance применять уточнение
«Точная идентичность native CAD и child provenance» в том же reference:
общий world-ULP допуск не заменяет точную local+INSERT-chain сертификацию.

## Ожидаемый отказ отрицательного QA-контроля

Проверять тип исключения публичного контракта: его require может отклонять
отрицательный контроль через ValueError, а не RuntimeError. Перехватывать
только ожидаемые типы отказа; неожиданный сбой harness считать незавершённой
проверкой. Исправление harness сохранять отдельной версией вместе с исходной
диагностикой и SHA. Успех отрицательного контроля не подменяет остальные
проверки совместимости и фактического configured Scene/CAD.

Разные формы полевых QA-доказательств сначала проверять по фактическим
записям: presence/operation, ID/count/order, полные record/field SHA и все
имеющиеся type/count/keys/value, флаги неизменности и добавочные field proofs.
Только после этой проверки нормализовать форму представления для сравнения.
Различие state допускать лишь как явно разрешённую пару при точном совпадении
всех остальных полей и сохранении запрета запуска. Для повторного использования
физических PASS связывать прежний протокол и секции SHA; прошлый FAIL сохранять.
При диагностике field_values_or_digests не выводить сами value: они могут
содержать исходную геометрию. Выводить только имена/типы, счётчики и SHA.

При связывании отдельно принятого внешнего scope в общий component freeze
сохранять прежние правила, код и package manifest. Связать точные SHA scope,
независимого QA и подтверждения текущего оркестратора; при передаче роли
проверить predecessor/successor lineage. Старый packaged scope оставить явно
историческим, а effective scope указать одной отдельной ссылкой. Для сравнения
формы доказательств использовать только уже проверенную нормализацию,
связанную с неизменными QA/input SHA; сами данные и sidecars не переписывать.
До эксклюзивной записи нового freeze проверить его в памяти настоящим
read-only verifier принятого driver, затем сверить байты, ссылки и точный
состав нового package manifest. Component PASS сохраняет отдельный запрет
пилота/расчёта/публикации до соответствующего разрешения оркестратора.

Для свежего регрессионного пилота область распознавания брать из уже
зафиксированной source-registration/calibration metadata записи с точными
source SHA, page/view, config и certificate SHA. Сохранённая геометрия может
содержать такой же crop, но совпадение значений не заменяет происхождение
входа. Чтение control JSON и geometry oracle откладывать до завершения полного
распознавания/topology/assemblies; порядок подтвердить фактическими open
событиями и отдельным receipt. Дополнительные проверки выполнять над тем же
возвращённым результатом без повторного распознавания; approved/semantic
флаги метаданных не превращать в инженерную приёмку.

При отказе создания stdout до вызова runner сохранять отдельный immutable
startup-протокол. Marker намерения запуска сам по себе не доказывает вызов
runner или распознавания. До повторной подготовки сверить реальные границы
исполнения и оставшуюся авторизацию; сохранить прежние wrapper/SHA и не
повторять уже выполненное распознавание. Исправление доступа к своей TEMP
не должно менять входы, алгоритмы или ACL других задач.

Для held preseal сохранять неизменяемое body и отдельный comparison contract:
перечислить лишь разрешённые поля будущего root receipt/authorization flags,
а canonical digest вычислять после удаления только этих полей. Будущий
execution envelope обязан сохранить все остальные поля, включая дату body.
Не подставлять фиктивные SHA ещё не созданных actual/QA-файлов: закрепить
известные input refs и точные правила их последующей фактической привязки.

Перед фиксацией source-binding input ref проверить точные байты сериализации
будущего writer. Другой gzip/JSON encoding при том же canonical JSON меняет
file SHA и может сломать postrun source-order binding. При необходимости
сохранить отдельный immutable writer-encoded snapshot с доказательством
равенства canonical JSON и ссылкой на прежний файл. Это не новый source QA,
не разрешение читать saved geometry при распознавании и не допуск изменения
координат; фактический retained-file SHA всё равно проверить после исполнения.


## Проверка навигации фактического выпуска

Численный checker с полным source alias proof запускать отдельно от массового
Chromium-обхода: совместная нагрузка может завершить checker с MemoryError.
Сохранять технический результат отдельно от проверки публикации. Для всех
страниц проверять разобранные узлы HTML, локальные ссылки и байты ресурсов без
загрузки чертежей; отсутствие узла body в libxml2 при допустимом неявном HTML5
body само по себе не дефект. Живым локальным браузером отдельно выполнять
публичный импорт/экспорт и ключевые переходы. Не выдавать неполный браузерный
обход за PASS всех поверхностей. Сверять назначение ссылок корневой сводки,
включая страницы замечаний, возврат в пайплайн и индекс прогона: число ссылок
на виды не доказывает сохранение маршрутов. Все журналы без значений геометрии.


Для отдельной исправленной сводки вне дерева выпуска сверять в браузере
точный file-base и фактические назначения всех ссылок. Обратной заменой
разрешённых href и удалением вставленных base и nav подтверждать совпадение
остальных исходных байтов. Ранее проверенные страницы связывать SHA.
Живой переход на один вид и возврат через историю браузера проверять отдельно
от встроенной ссылки самого вида, которая может вести в исходную сводку.


Перед свежим bounded-прогоном с ограждением записи проверить отдельно
существование родительской папки и отсутствие каталога самого прогона.
Родитель должен разрешаться в ожидаемую папку результата внутри проекта.
При необходимости создать только родителя заранее. Иначе copytree попытается
создать его за пределами разрешённого каталога уже после распознавания.
Если распознавание успело выполниться, считать запуск использованным, даже
когда результат на диске отсутствует. Сохранить протокол ошибки; новый запуск
выполнять только в пределах оставшегося разрешения.

При публикации обновлять JSON-указатель и Данные_пайплайна.js одной проекцией.
Для каждой готовой строки использовать поддерживаемый review_navigation.review_target:
кнопка «Открыть» зависит от review_target.review_ready, а не от наличия готового HTML.
Быстрый переход к виду брать из той же проекции. Проверять рендер строк и реальный
путь текущего выпуска; для исправления проекции исходный CAD-прогон не повторять.

Для правки интерфейса поверх замороженного CAD-выпуска собрать отдельную
редакцию HTML и версионированных JS/CSS. Зафиксировать исходный и итоговый SHA
для каждой страницы. Относительную базу брать из папки исходного отчёта;
динамические ссылки строить от document.baseURI. Обратным удалением разрешённых
вставок сверить неизменность разметки чертежа. Проверять в локальном Chrome
file:// точный файл, ресурсы, существующее хранилище отметок и реальный переход
из пайплайна. Выводить только безопасные счётчики и контрольные суммы.

При жалобе «ничего не изменилось» проверять отдельно пользовательский маршрут,
видимое изменение и изменение состава распознанных объектов. Для отметки о
пропущенной стене привязать исходные UUID и готовые доказательства к точной
версии выпуска. Принятые исходные тела переносить самостоятельными полигонами
и сравнивать их с площадью существующего материала. В области просмотра
показывать заполнение без штриха по границе, отдельно от реальных штрихов
источника. В локальном браузере переходить по каждой отметке и измерять
разницу переключения слоёв, сохраняя только счётчики. Сверять геометрию JSON
и SVG с исходной, а после публикации проверять фактический маршрут и архив.
Различать видимое исправление, классификацию и решение пользователя.

Для уточнения «по обе стороны двери» проверять соседние исходные компоненты
за пределами рамки. Привязывать их к двери по нативным символам и проверять
положительный зазор до них. Ось существующей двери допустима для сравнения
после отбора исходных компонентов. При неполной классификации показывать
точные заполнения в режиме проверки без присвоения нового материала.
Один переход просмотра должен показывать оба края. Датированные решения
по другим рамкам вносить отдельно от геометрии и сверять эффективный архив.

Переход из пайплайна сначала сверяет свежий указатель распознавания, затем
применяет отдельную редакцию интерфейса только для того же run_id и исходной
страницы. При недоступной или устаревшей редакции сохранять путь текущего
исходного отчёта. Ширину холста измерять отдельно от начального масштаба плана,
учитывая отступы родительских секций. После проверки новой редакции архивировать
заменённые копии с исходными путями и SHA, затем повторно проверить живую ссылку.

## Проверять квоту внешнего Claude перед аудитом

Для авторизованного Claude Code получить /usage через --print --output-format stream-json --verbose с пустым stdin, в нейтральном каталоге без доступа к проекту. Из result брать только счётчики применимых окон и подтвердить нулевые токены служебной команды. Сверять аккаунт отдельно. Токены отдельной сессии и денежный бюджет CLI не являются процентом подписки.

Фильтровать сводку до передачи, оставлять запас до пользовательского предела и читать /usage до и после каждого ограниченного пакета. --max-turns 1 и CLAUDE_CODE_MAX_OUTPUT_TOKENS не гарантируют один фрагмент ответа или жёсткий суммарный предел токенов. Сохранять все текстовые блоки assistant в порядке выдачи, проверять начало и конец ответа, фактическую модель и exit code. При неизвестной квоте, недостаточном запасе или неопределённой доставке не запускать и не повторять вызов автоматически.

Для генерации универсального обработчика достаточно вымышленной схемы и
синтетического примера. В таком пакете не передавать сведения о проекте,
включая его идентификаторы и внутренние агрегаты. Привязку реальных данных
выполнить локальным адаптером. Перед запуском проверить полный возвращённый
код и его операции ввода-вывода. Запускать в изолированной папке и сверять
фактический выход отдельным методом. Хранить оригинальный ответ, изменения
локальной версии, подтверждённую модель и хеши входов и выпуска.

## Проверять локальный монитор отдельно от CAD-прогона

Подключать страницу к фактическим файлам событий движка. Для каждой попытки
использовать отдельную папку и ограничивать скачивание объявленными файлами,
которые уже существуют в ней. SHA загруженного PDF связывать с реестром
нужной редакции до обработки. Проверять очередь, отмену, повтор и изоляцию
результатов с тестовым обработчиком через localhost. Если запуск CAD пока
закрыт, проверить реальную загрузку в режиме паузы и честно оставить
сквозной прогон открытым. В Windows отказ песочницы на loopback отличается
от отказа сервера и проверяется отдельным разрешённым локальным вызовом.

При прямом разрешении на разовый контроль ограничить допуск точным SHA,
страницей, каталогом задания и сроком. Потреблять допуск эксклюзивной
записью после проверки входа. Проверить отказ повторного использования.
После успешного HTTP-прогона сверить скачанные байты с CAD на диске,
повторно открыть DXF и проверить единицы. Перезапустить обычный монитор
на той же очереди и повторно скачать результат. Ссылки «назад» из
изолированных отчётов вести на сводку попытки без записи глобального
указателя. Отдельно зафиксировать доработки после прогона.

Для изменений интерфейса монитора сначала убедиться, что сервер и
очередь не обрабатывают CAD. Обновить шаблон отдельно от API. После
перезапуска проверить реальную страницу в Chromium на обычной и узкой
ширине, отсутствие горизонтального переполнения, сохранение раскрытых
деталей при опросе, дедупликацию загрузки и SHA скачанного артефакта.
Снимки экрана и профиль браузера держать только в папке задачи.

Для нового PDF сохранять отдельный перечень по SHA документа. Обнаружение
планов по нативным заголовкам служит предварительным выбором страниц,
а печатный масштаб только подсказкой. Метрическую обработку открывать по
независимым размерным цепочкам текущего PDF. Проекцию событий очереди
публиковать атомарно отдельно от R32. На файловой странице проверять
переключение двух документов, прогресс активного вида, фактический путь
проверки и доступность старого результата.

При проверке повтора PDF сопоставлять SHA источника, точный набор страниц
и версию движка. Параллельные одинаковые загрузки должны разделять активную
попытку. Проверять, что сбой нового вида оставляет доступным предыдущий
DXF того же вида и сохраняет текущую ошибку. На сводной странице проверять,
что выборочная обработка не скрывает полное задание с тем же SHA.

В сквозном тесте использовать нативные листы с разными исходами. Сверять
автоматический выбор с исходными страницами и открывать скачанный DXF.
Проверять число объектов modelspace, единицы и аудит: корректный формат
пустого DXF не подтверждает наличие результата. В очереди вне проекта
проверять формирование пути и файлов страницы замечаний, чтобы ошибка
в отчёте не маскировалась под отказ распознавания.

## Разделять проверку масштаба и межэтажных осей

Привязку спорного числа проверять по его точному исходному текстовому блоку. Дублирующая строка с префиксом «Кв» может доказать номер квартиры даже при числовом спане без префикса. Отдельно проверять конфликты выбора размера, конфликт нескольких подписей на один отрезок и недостаток отложенных контролей. Снятие ложной ассоциации в аудите не меняет статус выпуска до повторной проверки независимых цепочек.

Для прямой оси связывать подпись с укороченным начальным штрихом и проверять продолжение по повторяемым штрихам. Калиброванные планы сравнивать жёстким переносом или документированным поворотом, оставляя проверяемую ось вне подбора переноса. Не подгонять масштаб по соседнему этажу. Отдельно отмечать сравнения на предварительном масштабе, неподтверждённые марки и кандидаты монолита со сдвигом центра: метрики контуров не доказывают тождество конструкции.

Для числового дубля в PDF требовать совпадение значения, текстового блока,
направления и базовой линии с явной строкой «Кв …», а также вложенность bbox
числа в bbox метки с малым допуском координат. Это позволяет сохранить
одноимённые размеры в соседних строках или блоках. Исключать подпись до
ассоциации с рисками и сохранять её исходный текстовый контекст. Если задача
касается только допустимости подписей, сохранять прежние геометрические
допуски для поиска цепочек. При сравнении отчётов сверять число и исходный
bbox подписи. Раздельно считать исключённые метки, восстановленные настоящие
размеры и остающиеся конфликты. Прирост независимых цепочек на виде без
исключений связывать с текущим методом разбиения, если прежний отчёт старее.

При разборе малых конфликтов масштаба сохранять строгий относительный консенсус
как способ найти начальный коэффициент. Допуск абсолютной невязки применить
также при отборе правильно привязанных размеров, затем повторно проверить все
невязки при итоговом коэффициенте. Воспроизводить прежние позиции рисок,
независимость цепочек и раздельные причины остаточного HOLD. При разноцветной
разметке локально сверять, к какой линии относится число: чёрный интервал
и короткая цветная размерная линия могут проходить в одной полосе текста.

Для решения пользователя по локальному конфликту показать опубликованные риски
и подписанный размер на одном фрагменте. При необходимости повернуть и увеличить
исходный PDF-фрагмент, а отметки рисок наложить отдельным слоем в координатах
рендера. Перекрытую подпись процитировать по точному текстовому спану. Невязку
для действующего выпуска считать с его коэффициентом, отдельно от значения
пробного fit. В вопросе явно разделить исключение из контроля масштаба и
подтверждение проектного размера. Сохранить HOLD до ответа пользователя.

После подтверждения локального исключения сначала воспроизвести исходный HOLD.
Исключить до ассоциации один исходный спан по листу, тексту и точному bbox,
затем повторить проверку на исходном коэффициенте и действующих допусках.
Для единичного конфликта сверить прежние координаты рисок, роли и разбиение
остальных размеров. Решение, исключённый спан и новый сертификат связать
с неизменённым протоколом. Выход за исходный допуск сохранить как замечание
к листу даже при PASS остальных контролей масштаба.

После снятия HOLD строгая ветка распознавания может завершиться раньше и
вернуть меньше контролей, чем предыдущая ветка с допустимым вылетом текста.
Зафиксировать результат штатного вызова и отдельно повторить прежнюю ветку
на её неизменённых параметрах. Сопоставить полный прежний набор размеров,
координаты рисок и независимость цепочек. Цветную подпись, исключённую
из сопоставления с чёрными линиями, проверить по её собственным рискам.

Для проверенных пар сохранять направление преобразования B → A, номера четверть-оборотов,
перенос, совпавшие марки и знаковые невязки. PASS требует единственного подходящего
поворота при подтверждённых исходных коэффициентах обоих видов. Проверять коэффициент
по сертификату конкретного вида и выпуску, а не по округлённому номиналу масштаба.

Для общей локальной сетки строить связные компоненты только по прямым PASS. Сохранять
опорный вид, выбранное дерево и путь каждого вида до опоры. Для каждого ребра вне
дерева сравнить его преобразование с путём по дереву: проверить ориентацию и обе
координаты замыкания в опорном кадре. Отдельным верификатором пересчитать пары,
компоненты и замыкания. Путь через соседние виды не подтверждает прямую пару.
Локальные XY-преобразования в координатах PDF не удостоверяют общие координаты
Revit, отметки Z или тождество элементов. Отдельно считать UNKNOWN в проверенном
наборе, пары вне охвата и этажи с одним общим типовым чертежом.

## Проверять сбои масштаба и координат в загруженных видах

Жёлтый статус всего вида сверять со статусом этапа масштаба, исходным
сертификатом и фактическим DXF. Для ложной ассоциации размерного текста
проверять сторону по направлению чтения глифа. Применять поправку, только
если прежние контрольные пары согласованы на одной стороне, конфликтующие
привязки на противоположной и после перепроверки сохранена каждая прежняя
пара исходных рисок. Подтверждённый размер по той же стороне остаётся конфликтом.

Общий размер на общей цепи может перекрывать промежуточные риски. Требовать
один непрерывный исходный штрих размера, риски с выносными линиями на обоих
концах и одинаковые исходные вылеты штриха. При расширении области чтения
линий сохранять область чтения подписей. Проверять повторное совпадение
всех прежних пар рисок до публикации. Исключение, разрешённое пользователем,
применять к точному исходному спану и двум рискам, связанным с SHA PDF
и видом. Фиксировать невязку, сохранять независимое разбиение цепей.

Если исходный полигон валиден, а после преобразования в миллиметры становится
невалидным, отделять рабочую геометрию от исходных тел. Проверить, что разница
площади ремонта ограничена точностью координат, и применить общий перевод
и к проёмам, и к границам помещений. Проверить фактический выход и не менять
исходное полигональное представление. При временной блокировке Windows
повторять атомарную замену файла прогресса, сохраняя старый целый снимок
до успешной записи. Проверять временную блокировку отдельным тестом.

## Публиковать ограниченное профильное дополнение к принятой базе

Если подтверждены только отдельные виды, хранить дополнение отдельным отчётом
с DXF, исходными доказательствами и SHA прогона. Для замороженного базового
корпуса сначала получить свежие данные выбранного семейства из исходного PDF,
затем привязать их к настроенному Scene базового вида. Сравнить фактические
старый и новый DXF после чтения с диска: геометрия, кратность, слой, INSERT,
дочерние сущности и XDATA должны совпасть за пределами добавленного слоя.
Игнорировать только служебные handles сериализации. При положительном
доказательстве видимости проверить каждый скрытый интервал на существующем
объекте и сохранить его исходного владельца.

Если версия панели замечаний привязана к идентификатору базового прогона,
отразить дополнение отдельным полем указателя и JS-проекции. Добавить ссылку
в пользовательскую точку входа и проверить сохранённые маршруты базовых видов.
Упакованные выходы и протоколы сверять по SHA до удаления собственной TEMP-папки.
