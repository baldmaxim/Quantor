# Изолированный перенос native-алгоритма в runtime

Применять, когда source-only прототип уже численно проверен, но общий движок
пока изменяет другой писатель. Передавать отдельный SHA-снимок кода и patch;
исследовательский пакет и ранее переданные артефакты не переписывать.

1. Сохранить SHA исходного модуля, конфигурации, зависимостей и защищённых
   пакетов. Переносить проверенный алгоритм без изменения условий; подтвердить
   эквивалентность AST либо явно проверить различия.
2. Разделить fresh source detection и привязку к итоговому core. Первую фазу
   вызвать до распознавания core, из самого file-bound PDF с проверкой SHA,
   crop и масштаба. Готовые CAD/GZ использовать только после этой фазы для
   сравнения выхода и владельцев. Нельзя принимать внешние drawing-кэши за
   доказательство свежего источника.
3. Оригинальные PDF-операторы должны поддерживать каждый выдаваемый интервал.
   Доказательства хранить через source/part/item/t и SHA ребра, без копирования
   исходной геометрии в handoff. Арифметический ULP-бюджет не закрывает реальные
   разрывы. Неподтверждённые кривые и implicit close не заменять хордами.
4. Привязывать новые интервалы после последнего изменения core/topology;
   существующим владельцам оставлять ссылки. Не экспортировать их повторно.
   Проверять отсутствие положительного пересечения и неизменность core.
5. Для экспериментального семейства требовать явных возможностей прогона и
   конкретного вида. По умолчанию выключено: без извлечения, новых полей и
   лишнего CAD-слоя. Выбор QA-страниц принадлежит внешнему сценарию; номера
   страниц и source IDs не являются правилами распознавания.
6. Не превращать неизвестные связи в стекло, оконные изделия или ведомость.
   Дать отдельный диагностический CAD-слой без HATCH и сверить прочие слои.
   Не терять реальные малые интервалы из-за общего display-length threshold.
7. Проверить pipeline control flow на синтетическом file-bound PDF с реальным
   новым детектором, binder и CAD-exporter. Добавить no-op, source binding,
   stale core, idempotency, реальные разрывы, aliases, поворот и единицы.
8. Проверять patch на точной базе в собственной TEMP-папке и сверять байты
   всех полученных файлов. На Windows явно зафиксировать core.autocrlf:
   LF patch и CRLF исходники требуют проверенного режима git apply.
   Не применять patch к изменившейся общей базе без пересмотра SHA.
9. Сохранить код, тесты, patch/baseSHA, зависимости и числовые протоколы.
   Независимый QA и внедрение имеют отдельные критерии. Удалить собственные
   CAD/GZ и пробы из TEMP после переноса необходимых протоколов; проверить
   неизменность действующего выпуска и ранее переданных SHA-снимков.

## Полный физический инвентарь и отображение

После source detection брать владельцев из фактического Scene/CAD-контракта:
семантические native-линии, исходные hatch_lines материалов, части собранных
дверных/воротных систем и их реальные line-fallback. Unbound QA-линия при
участии должна блокировать привязку, а не получать выдуманную source-ссылку.
Не ставить exact GEOS intersection filter перед публичным interval adapter:
его собственная ULP-политика поиска и положительной коллинеарности важна.

Производные HATCH/материальные границы принадлежат другой namespace. Они не
получают native-владение. Если часть доказанного native-интервала уже видна
в этой границе, после native-привязки разделить только маршрутизацию вывода.
Сохранить полный native-ledger, владельца и aliases; для скрытой повторной
прорисовки оставить отдельную запись с причиной и t-параметрами. Проверить
source-union до/после, фактические линии Scene и CAD polygon boundaries,
не только счётчик атомов. Старые числа сохранить как исторический протокол.

## Фактический Scene вместо декларативных полей

В post-detection reconciliation передавать тот самый настроенный Scene, который
получит экспорт, после последних изменений core/topology. Авторитет — реальные
линии и отдельные полигоны активных слоёв вместе с фактической таблицей styles.
Метаданные render=False, role и списки полей не определяют видимость, если
существующий renderer их игнорирует. Provenance pool даёт source-ссылки, а
физическое присутствие подтверждает фактическое членство в Scene. Не стирать
границы отдельных тел предварительным unary_union.

Подавлять новый native-интервал только при строго положительном точном
пересечении с существующим выводимым объектом. Сертификат связывать с
layer/kind/index и SHA исходной WKB-геометрии target, SHA настроенного Scene,
точным положительным subspan и направленными параметрами оригинального source
segment. Для полигона SHA относится к самому полигону, пересечение — к его
границе. Сохранять исходного native display owner, полный ledger, aliases и
реальные gaps; representation proxy не становится владельцем native source.
Query/context/clip buffer не подтверждает физический вывод. Проверять удалённый
или сдвинутый target, смену styles, paused layer, отдельную границу соседних тел,
игнорируемые renderer метафлаги, касание в точке и малый положительный gap.

Повторная привязка и установка QA-слоя должны отвергать устаревший Scene,
изменённые routed rows и несовпадающую фактическую таблицу styles. Проверять
caller с реальным exporter, а не только helper. Изменение только metadata либо
упаковки после fresh replay связывать с отдельным ограниченным протоколом и
проверкой сохранённого source-only prepared; тяжёлое распознавание без изменения
геометрического кода не повторять.

Portable QA-скриптам требовать явные project/engine/output; все результаты и
байткод писать только в отдельную собственную системную TEMP-папку, никогда
рядом с immutable package. На Windows проверять patch на точной базе в режиме
core.autocrlf=false и core.whitespace=cr-at-eol, если diff сохраняет исходные
CRLF/LF байты. Решает побайтное совпадение всех применённых файлов, а не один
успешный git apply. Отличать неопубликованный staging manifest selfcheck от
финального readback manifest. После передачи SHA не менять пакет; дополнения
и результат независимого QA оформлять отдельно, сохраняя прошлый FAIL.

### Порядок eligibility и aliases

Не объединять одинаковые geometry/source записи глобально до проверки
фактического активного слоя: первый неактивный logical alias может поглотить
активный и оставить прежний native owner только как строковый путь. Проверять
каждый оригинальный alias на точное членство в реальном активном Scene прежде,
чем coalescing выбирает общую физическую запись. Неактивные aliases не дают
владения. Для активных сохранять logical layer, source provenance, путь,
родительскую запись, owners, роли/ID и actual entity references. Объединение
не должно терять owner-role association; ledger получает активные owners и
роли, а отдельный provenance record сохраняет их соответствия.

Проверять оба варианта отключения дублирующих слоёв, обратный порядок
перечисления полей и ключей input, все слои неактивны, несколько активных
aliases с разными owner/role и обратное направление линии. При уже видимом
OLD ink сохранять old native reference, не новый owner с display proxy.
Новый generic FAIL оформлять отдельным versioned кандидатом; прежний FAIL и
source/ledger доказательства оставлять неизменными историческими
зависимостями. Авторский replay независимо написанных fixtures не заменяет
новую независимую проверку изменённого кандидата.


### Эквивалентные формы source refs перед coalescing

Если adapter поддерживает `source_path/part`, `source_references` и `source_parts`,
сначала подтвердить каждую форму отдельно через реальный Scene и публичный attach.
Затем сравнить одинаковые и смешанные пары aliases одной физической линии в обоих
порядках. JSON исходного представления не является каноническим source identity:
разные token могут оставить два legacy claims и вызвать ownership conflict даже
при эквивалентных целочисленных source IDs. Проверять один физический интервал,
все owners, направленные refs и role associations, а также отсутствие proxy вместо
старого native owner. Не канонизировать source segment или directed t потерей данных.

Отделять доказанный отказ поддерживаемых форм от malformed metadata (`roles=None`,
scalar `roles`, смешанные типы owners) и от фактического дефекта исходного чертежа.
Консервативный отказ attachment не доказывает выдачу дублирующей геометрии.
Окончательное исправление требует отдельного immutable кандидата; прежний FAIL
и положительные source/actual доказательства сохраняются.

#### Проверенный способ канонизации supported bindings

Сохранять реальный eligibility до coalescing. Для identity брать supported
reference declarations через уже одобренный adapter parser, а не сравнивать JSON
контейнеров source_path/part, source_references и source_parts. Стабильный набор
канонических references устраняет только различие формы, порядка и точных
повторов. Source/part/source_segment и объявленные interval/directed-t ограничения
остаются точными значениями: не округлять и не выводить из них whole-part claim.
Если parser сам дедуплицирует по source ID до учёта ограничений, разбирать
исходные declarations независимо для identity, чтобы не потерять разные
подынтервалы одного ID. Не вводить ради этого новый геометрический normalizer.

В provenance каждого активного alias хранить raw source binding вместе с
owner/role/ID, parent и actual entity associations. Представительная запись
остаётся одной; исходные формы не переписываются и не исчезают. Используемую
версию adapter связывать SHA и проверять установленный код.

Проверять все смешанные supported forms, обратный порядок, direction и active
layer selection, standalone/same-form controls. Отрицательные source/part/segment
или subspan claims не должны coalesce. На реально частичном legacy-интервале
подтверждать сохранение old ownership только внутри него и нового остатка
снаружи, без proxy вместо old owner. Malformed metadata остаётся отдельным
scope; supported-schema исправление не требует ослаблять проверки типов.

Канонизировать только поддерживаемую форму refs, а не её физические ограничения.
Если approved parser удаляет повторяющиеся source IDs, вызывать его отдельно для
каждого объявления до построения точного множества identity: разбор целого ряда
может отбросить второй ref того же ID с иным source_segment или subspan. Сохранять
исходное schema binding каждого активного alias вместе с owner/role/ID/parent/entity
association. Проверять одиночные и same-form controls, mixed forms в обоих порядках,
различные ref sets, явный segment, направленные t и наличие/значение ограничения.
Для реальной частичной старой линии сверять точную длину old reference, оставшийся
новый ink и directed source t; metadata сама по себе не расширяет физическую линию.
Рабочую реализацию оставлять в движке; QA не разрешает применять старый полный
patch поверх параллельно обновлённого движка. Для изолированной проверки брать
каждый прежний модуль из сохранённой копии только при точном SHA, фиксировать его
origin и дальнейший drift live-кода; hooks позже перебазировать отдельно без отката.

### Output-only DXF QA перед фактической проверкой

Проверенный reader должен раскрывать BLOCK/INSERT с реальными матрицами,
base point, вложением, отражением и MINSERT; сохранять мировой инвентарь,
кратность, root block/layer, XDATA и фактическую видимость сущностей/слоёв.
Границы HATCH учитывать отдельно, bulge и кривые не подменять хордами.
Неподдержанную геометрию отклонять явно. ULP-бюджет равенства концов после
local subtraction/INSERT addition не является допуском расширения gap или
положительного пересечения. Для прямого ink отдельно проверять строго
положительное пересечение точных мировых float-координат и endpoint-only contact.

Configured Scene сверять после реальной настройки styles и присвоений
transfer-слоёв. Проверять физическое членство и кратность линий, полигонов и
неизменённых namespace; декларация target или display map сама по себе не
доказывает выдачу. Freeze связывает checker и точную установленную копию;
postrun source-order/output receipts появляются после прогона и не должны
выдаваться за уже известные SHA в pre-run preseal. Проверять frozen-копию
на синтетических transform/visibility/gap случаях и на запечатанном старом
output-only CAD после source-proof. HOLD CLI должен завершаться до импорта
engine и чтения CAD при отсутствии финальных gates. Это подготовка QA, не
actual PASS и не инженерная приёмка.

### Точная идентичность native CAD и child provenance

Общий мировой ULP-бюджет не доказывает тождество native LINE: даже при
identity INSERT он может принять независимый сдвиг обоих концов по нормали.
Для exporter с PDF-to-world, local anchor subtraction и INSERT addition
сохранять в reader исходные локальные концы и реальную матрицу/параметры
каждого INSERT, включая block base point. Подтверждать точную направленную
локальную геометрию, ожидаемую цепочку exporter и воспроизводимый мировой
результат. Положительный контроль с длинным anchor обязан проходить даже
при roundtrip-отличии от прямой source-world формулы; независимый normal-ULP
сдвиг локальной LINE обязан отвергаться публичным CAD audit и target binding.
Это проверка выхода, не сужение допусков распознавания или source kernel.

Для неизменяемых CAD entities одной геометрии/styles и INSERT XDATA мало.
Сверять полный child AR_PLAN_PASS owner/role/source binding с мировой
геометрией, root/immediate block namespace и кратностью. Отдельно проверять
child-only owner, role, source и part mutations, а также обмен source bindings
между совпадающими геометрически root blocks. Корректная геометрия не должна
скрывать потерю происхождения.
