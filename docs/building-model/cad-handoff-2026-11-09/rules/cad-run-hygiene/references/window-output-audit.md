# Аудит видимости окон и профильных панелей

Сначала зафиксировать опубликованный указатель, dataset/source/engine для каждого вида. Считать отдельно исходные свидетельства, семантические кандидаты, физические штрихи HTML и сущности CAD. Пустой выход не доказывает отсутствие окон; количество полилиний не является количеством оконных блоков.

## Проверять фактический вывод

Программно разобрать HTML/SVG и сравнить физические линии с window_profiles, ground_floor_glazing_profiles и stepped_glazing_profiles. profiles — поле до классификации: его повторный вывод рядом с window_profiles удваивает штрихи и может вернуть подсистему в оконный цвет. Для shared после классификации использовать display_shared, включая намеренно пустой список. Не подменять пустую семантику исходным полем через логическое or.

Проверить checkbox, source-only/recognized-only, CSS display/visibility/opacity, порядок заливок и исходника, clip/mask/transform, crop и координатную систему. Headless DOM-проверка допустима без снимков экрана. Состояние слоя в браузере пользователя не выводить из одного HTML: отдельно указывать проверенные значения по умолчанию и возможное временное переключение. Хранение отметок localStorage не означает хранение видимости архитектурных слоёв.

CAD читать после независимого исходного распознавания только для аудита экспорта. Проверять actual entity/layer, flags/color, SHA, origin, scale и инверсию Y. Сравнивать исходные интервалы с реальными полилиниями HTML и CAD; явно учитывать только арифметику преобразования и округление координат, не расширяя физическую геометрию.

## Не смешивать топологию с исходным свидетельством

Фильтр facade_two_sided может скрыть реально найденную профильную панель при утечке inside/outside. exterior_both_sides и unresolved сами по себе не дают права назвать её окном. Отдельно проверить генерацию кандидатов: например, тонкая реальная полоса может не входить в семейство обычных параллельных профилей. Применять самостоятельный строгий вариант с двумя независимыми сложными исходными сечениями, настоящими продольными гранями/полосой и проверкой непрозрачного заполнения, штриховки, повторяющихся ламелей и дверного владения. Не ослаблять глобальные пороги.

Совпадение торца рельса с bbox ступенчатого профиля не доказывает контакт внутри выемки. Проверять контакт с настоящим native ink с ограниченной численной точностью источника. Напечатанные штриховые footprints служат только свидетельством контакта; не экспортировать их как материал или достроенное тело.

Белая полоса и сложные профили доказывают графическое семейство, но не материал стекла, фиксированную/открывающуюся роль, изделие, номинал или высоту. Неизвестную панель выводить отдельным диагностическим классом, сохраняя неизвестность. Камерные bookmarks строить по реальным штрихам; bbox для фокуса не превращать в контур окна.

## Завершать проверкой реального результата

Source-кэш использовать лишь после SHA исходного PDF и самого кэша, crop/rotation/scale/clip binding. Как минимум один независимый жилой этаж проверять свежим native извлечением, без пилота и CAD. В отчёте разделять уже выводимые штрихи, отсутствующую семантику и честный unknown.

Новые части распределять по native-интервалам. Legacy-конфликт положительной длины блокирует интеграцию; ссылка на существующего владельца не является второй физической линией. Проверять положительные/отрицательные примеры, поворот, перенос, изменение единиц координат, source-ID и порядок входа. Смена отображения не закрывает пользовательскую отметку и не даёт инженерной приёмки.

## Семантическая схема и неизменяемая передача в QA

Legacy raw fallback разрешать только при отсутствии всех поддерживаемых
семантических полей. Наличие любого такого поля, включая пустой список,
подавляет raw fallback. Независимо проверять каждую отдельную семантическую
схему, её пустой вариант и legacy raw-only; одного привычного dataset мало.

При postrun-исправлении просмотра сохранять распознанные данные и исходный SVG.
Менять только нужные группы/контролы, а новые camera-only bookmarks добавлять
без сдвига прежних индексов. Сверять все координаты выводимых полилиний, другие
распознанные группы и initial config; новую версию viewer связывать отдельно
от recognition snapshot. Полные отчёты могут иметь маршрут назад через список
планов: проверить реальный переход, не навязывая всем страницам один selector.

Проверенные code/HTML переносить с контролем фактических байтов. В Windows
учитывать Git autocrlf и перевод строк при текстовой записи. Для уже проверенного
HTML применять атомарное копирование bytes и повторно сверять published SHA.

Артефакт, переданный в QA с SHA, замораживать. Свои последующие тесты и пояснения
писать в отдельный addendum; не добавлять их в уже проверяемый deployment receipt.
При обнаруженном drift сравнить структурную дельту, сохранить доступные версии,
сверить actual HTML/resources и заново связать итоговый QA. Восстановленные байты
называть исходными только после точного совпадения с ранее записанным SHA;
явно указать способ восстановления. Если прежняя служебная версия недоступна,
сохранить это ограничение и воспроизводимые исходные FAIL, не приписывая им
побайтную сохранность. Ошибку test harness отделять от ошибки продукта через
baseline и целевой повтор, сохраняя первоначальный результат.
