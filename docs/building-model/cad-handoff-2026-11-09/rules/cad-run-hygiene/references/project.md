# Проект «Чертеж_CAD»

Проверено 06.11.2026 при разборе существующей папки.

- Поддерживаемый код: `АР_Обработка/90_Пайплайн`; основной PDF:
  `АР_Обработка/00_Исходники/МЛДГВ-КАМ0925-П-АР1.1_ver5.pdf`.
- Указатель полного результата: `АР_Обработка/16_Все_планы/Последний_прогон.json`.
  На дату проверки он указывает на прогон `20261106_154210` в
  `29_Оконные_интервалы_и_навигация`; не фиксировать это имя как вечный latest.
- В актуальном результате 80 видов. У 77 `source_geometry_folder` ссылается
  на прогон 27, у двух на прогон 28. Результат 29 содержит свои копии видов,
  но исходные папки сохранены для происхождения и сверки.
- `pipeline.py` и `inspect_pdf.py` загружают библиотеки из `_work/.deps`.
  `architecture_retry.py` без явного retry_plan читает
  `_work/audit80/template_preflight.json` и `inventory.json`.
  `door_room_retry.py` читает `_work/openings39/retry_plan.json`.
- Два тестовых модуля используют `_work/doors28/swing` как родительский
  временный каталог. При очистке его содержимое можно убрать, сам каталог
  должен существовать для текущей версии тестов.
- Локальные исходники CAD-сверки: `_work/network_cad_audit/local_input` и
  `local_archives`; опубликованные справочники:
  `АР_Обработка/Справочники_CAD_сверка`. Конвертированные DXF в рабочей папке
  не заменяют оригиналы DWG.
- Фиксированный пилот и контрольный снимок находятся в ранних разделах
  `АР_Обработка`, особенно 10–13. Их SHA256 и сертификаты нужны проверкам.
  Не удалять ранние разделы, просто сравнив номера с последним прогоном.
- `recognition_only()` запрещает распознавателю читать DWG/DXF и результаты
  пилота. Этот барьер нельзя обходить ради очистки или упрощения вычислений.
- Во время прогона код и конфигурация фиксируются манифестом; не менять их
  параллельно. `completed_requires_review` означает необходимость проверки,
  а не подтверждённую полноту и не разрешение выпуска объёмов.

## Учёт задач в пайплайне

Канонический реестр — `АР_Обработка/План_развития.json`; существующая страница
`АР_Обработка/Пайплайн_проекта.html` показывает его производную JS-проекцию.
Контракт регистрации, updater, inbox и настройки контролёра находятся в
`АР_Обработка/Рабочий_контекст/Контроль_плана_Astra.json`.

Перед новой работой опубликовать immutable JSON события и выполнить единый
updater; по завершении или блокере записать датированный исход, основание,
фактический scope и ссылки. Прототип не закрывает задачу внедрения. Неизвестные
исторические даты сохранять неизвестными. Контролёр читает только дельты;
обычное применение отчёта не требует отдельного вызова модели.

Файл плана, inbox, проекция и связанные доказательства — рабочие зависимости.
При очистке учитывать их ссылки, а не удалять материалы по одному имени _work.
Свою временную тестовую копию удалять после проверки. Числа и старые номера
прогонов выше описывают исторический снимок, актуальность определять заново
по указателю последнего проверенного результата.
