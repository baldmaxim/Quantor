# Проверка замечаний к коду без исходных чертежей

Когда поручено проверить замечания к движку, зафиксировать SHA256 заданного
среза. Распаковывать в системный TEMP только требуемый код и шаблоны; не
подключать live-модули вместо проверяемого среза. Не называть вспомогательные
скрипты `inspect.py`, чтобы они не затеняли стандартную библиотеку.

Разделять свежую детекцию, отбор предложений по scope и сверку с сохранённым
core. Если исправление удаляет уже сохранённый ложный компонент, проверить
одинаковые исходные доказательства на старой базе и на базе после исправления.
Зависимость коррекции старой базы от open/resolved не доказывает возвращение
компонента в уже исправленную базу. Проверить фактический canonical latest по
указателю; подпись происхождения предыдущего core не означает, что используется
его старая геометрия. Когда прочитаны лишь метаданные публикации, так и указать.

Метаморфные сравнения статусов сопровождать положительным fixture: равенство
трёх пустых результатов даёт слабую проверку. Для переименования заголовка можно
исполнить исходные AST-ветви диспетчера с настоящими детекторами и синтетическими
входами. Отмечать границу: такой тест проверяет диспетчер, но не полный прогон,
CAD-экспорт или наличие дефекта на реальном листе.

Проверять разные исходные представления символа отдельно, например одно ребро
и замкнутое полотно. Для downstream-подавления допускается явно помеченный
seed принятого legacy-объекта; он не доказывает, что upstream-детектор сам примет
этот fixture. Не смешивать ограничения представления и ошибку title-dispatch.

В handoff сохранять VERIFIED/CONDITIONAL/DESIGN_LIMIT/NOT_REPRODUCED,
точные пути и строки внутри среза, минимальное воспроизведение, хеши результатов
и нужную дополнительную проверку. Отдельно перечислять уже работающие guards,
чтобы исправление не повторяло upstream-защиту и не расширяло acceptance.
После проверки удалить свою TEMP-распаковку; исходный архив и compact handoff
сохранить. Не переносить в skill движок, данные проекта или журнал результатов.

## Точность патча и границы диагностики

Проверять не только apply --check, но и применение в собственной TEMP с точным
байтовым SHA целевого файла. На Windows учитывать core.autocrlf: для проверки
LF-патча использовать локальный параметр git -c core.autocrlf=false, если он
нужен для сохранения проверенных байтов; глобальную конфигурацию не менять.
SHA нормализованного текста отличать от SHA фактических байтов файла.

В title-invariance fingerprint сравнивать фактическую геометрию, источники,
ownership и suppression. Разницу пустых диагностических контейнеров отдельно
нормализовать или описывать как метаданные; не объявлять её геометрическим дефектом.

Если закрытое полотно проверяется через выделение существующего сегмента,
считать это диагностикой membership. Перед включением в детектор нужны владение
и экспорт полного исходного контура, отдельное segment/t-доказательство и
однозначный родитель. Проекция сегмента не заменяет source-part-геометрию.

## Source-first QA и физический inventory

При наличии независимого sealed native cache сначала проверить producer,
байтовый SHA cache, SHA распакованного payload, исходный PDF SHA, crop, display
rotation, систему координат и provisional scale. Сначала исполнить общий detect
на полном source context; ROI/ID использовать только затем для выбора scope.
Старый core читать отдельной фазой сравнения. Чужой sealed cache не переписывать
и не удалять. Отсутствующие spans/поля отмечать как границу независимой проверки.

Для physical ownership выводить inventory из фактического renderer/CAD-кода,
включая вложенные material.hatch_lines и source-lines вне assembled blocks.
Наличие блока само по себе не отменяет Scene line collection. Evidence-only
context не становится физическим владельцем. Derived material/frame/room
boundaries учитывать отдельным rendered-geometry namespace, не выдавать их за
native black ink. Пустой результат неполного inventory не доказывает отсутствие
прежнего владельца; исправление inventory фиксировать отдельной новой версией.

ULP-aware adapter не исправит внешний exact-GEOS prefilter, отбросивший legacy
ещё до adapter. Проверять весь caller/helper, каждое исходное ребро полилинии,
tiny certified interval и его направление по полному original segment, а не по
округлённому короткому вектору. Не менять общий normalizer под видом адаптера;
изменение его default-поведения явно выделять в контракт и отдельное ревью.

Метаморфные негативы проверять вместе с положительным fixture при произвольных
поворотах и отражениях. Для crossed texture сравнивать относительные направления
modulo pi; абсолютный page dx/dy может отключить защиту после поворота. Начальный
FAIL сохранять неизменным, исправленный вариант связывать с новым SHA.

В overlap-check отличать общий endpoint от положительного интервала без
epsilon-отсечения tiny ink. Для сертифицированных коллинеарных float endpoints
точное сравнение доминирующей координаты (например Fraction(float)) исключает
ложный положительный остаток от проекционного вычитания; normal ULP predicate
проверяется отдельно. Не переносить такую арифметическую диагностику в изменение
физических координат, границ или приёмки.

## Alias-only контекст после физической нормализации

Проверяя требование нового interval kernel, сначала воспроизвести реальные
owned claims на одобренном публичном normalize_view без reference-only строк.
ImportError нового символа сам по себе не является геометрическим доказательством.
Неизменность physical ledger сравнивать полностью, сохраняя owners, roles и gaps.

Source aliases хранить отдельными render=False annotations после нормализатора.
Partial alias требует atom reference, atom subspan и directed t конкретного native
segment для фактических концов subspan. Не прикреплять частичную ссылку ко всему
атому и не путать segment t с normalized arclength целой source part. У metadata
нет physical owner и права приобретать whole part. Проверять все source segments
независимым enumerator, как пропущенные, так и ложные aliases; реальные малые
нормальные и концевые разрывы не должны закрываться. Контракт QA не заменяет
проверку готового production caller и не одобряет общий kernel.

## Сверять coverage с фактическим Scene

Display proxy выводить из фактически сконфигурированного Scene: активные styles,
union-per-material либо отдельные тела, реальные правила render/role-флагов.
Нельзя подавлять native-интервал границей отключённого слоя. Union отдельных
тел может убрать внутреннее ребро, которое renderer/CAD всё ещё выводит.
Inventory также не должен исключать flagged row, если фактический renderer
её рисует. Проверять эти отрицательные случаи через attach и реальный Scene,
а не только helper. Исправлять общий контракт представления, не перечень кейсов.

При сверке полноты native inventory сначала сопоставлять точную нормализованную
геометрию строк. Boolean union нодирует наклонные hatches и может дать ложную
ненулевую difference даже при наличии идентичной строки. Такой остаток требует
разбора арифметики, а не ослабления геометрического допуска. Провал общего
контракта не доказывает дефект конкретного реального proxy: каждый фактический
покрытый интервал отдельно связать с существующим rendered target и точным
положительным overlap, сохранив native owner, aliases и направленные source t.

## Положительный интервал после reference-axis нормализации

Для optional API проверять default-режим отдельным golden corpus по фактическому
результату и исключениям; совпадение старых helper AST само по себе недостаточно.
Сертифицированный положительный source t-span проверять и на выходном ledger:
различные входные float endpoints могут схлопнуться при обратной интерполяции
по длинному native segment. Добавлять ULP-интервалы, меняющие только
недоминирующую координату, при нескольких углах и больших сдвигах. Сверять
выходные точки, directed source t, положительность span и coverage между собой.
Положительный вход и нулевой covered-атом требуют исправления либо явного
fail-closed результата, даже если прежняя физическая линия остаётся нарисованной.
Не лечить это snap, epsilon-удалением или изменением default semantics.

## Не терять active-layer aliases до Scene eligibility

Для одинаковых geometry/source refs в нескольких коллекциях проверить два
зеркальных случая: первая logical layer отключена, вторая реально выводится,
и наоборот. Глобальный provenance dedup до проверки фактического Scene может
сохранить только неактивный путь и потерять существующего owner/alias активной
линии. Строки alias path недостаточно: до разрешения eligibility сохранять
logical layer, owners/roles и actual entity references каждого представления,
либо дедуплицировать после выбора фактически выводимых вариантов. Нулевое
новое display overlap не доказывает сохранения прежнего source owner: новый
native owner с proxy на старую линию тоже может дать ноль дублей.

## Квалификация current-canonical проверки

Если частичное coverage меняет разбиение ledger, сначала исполнить прежний и
новый normalizer на одних и тех же фактических входах. Сравнить полный physical
fingerprint и aliases. Затем связать каждый реально выдаваемый Scene/CAD
интервал с текущим canonical атомом, его подынтервалом и настоящим native claim
целевого вывода. Сравнение с прежней неразбитой линией может обнаружить иной
численный факт и не заменяет эту проверку.

Сохранять исходный FAIL с SHA. Разрешающий протокол писать отдельно: указать,
что именно доказано новым сравнением, какие прежние утверждения остаются
ложными и какое source-t свидетельство унаследовано. Точное совпадение с
canonical ledger не доказывает строгую рациональную коллинеарность с raw source.
Если унаследованная арифметика даёт ULP residual, явно сохранить его и границу
достоверности; не менять координаты, snap или допуски ради PASS.

В протоколе отдельно считать все проверенные атомы, реально исполненные
missing-target ветви и направленные source-сертификаты. Full/partial CAD-only
и Scene-only проверять симметрично, включая независимые maps других объектов
и явно пустой CAD override. Qualified preinstall PASS остаётся отдельной стадией:
он не заменяет установленные тесты, freeze, пилот и проверку фактического выхода.
