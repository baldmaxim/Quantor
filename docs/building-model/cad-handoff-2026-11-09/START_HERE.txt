5. Критические инварианты
   Движок читает исходный PDF ревизии. Проверки масштаба используют размерные
   цепи и независимый holdout. Печатный масштаб сам по себе даёт диагностику
   без DXF. Пилот, готовый CAD, отделка и выпуск объёмов исключены из входа.
   У CAD-задания собственные каталоги и ключи для каждой попытки. Результат
   связывается с revision/job/attempt/page/view и SHA. Проверять права доступа
   к заданию и файлам. Потеря аренды останавливает процесс и закрывает выпуск
   этой попытки. Статус completed_requires_review требует инженерной проверки.
   no_cad_review_required означает, что есть диагностика без DXF. Известный
   случай PDFContext: подтверждённый масштаб и одни заливки в области
   распознавания могут дать ошибку без CAD.
   Пайплайн показывает серверные события, длительности и ошибки. Семь стадий:
   исходный PDF, область, масштаб, элементы, узлы и помещения, контроль,
   выпуск и отчёт. Часы замечаний, ревизию и историю результатов хранить
   раздельно. Порядок проверки и неизменность SHA описаны в rules/.

6. Проверка и границы выпуска
   CAD_QA_ENABLED доступен в local/test. Python API и CAD раздельны. Для QA
   использовать синтетические файлы, отдельную временную базу на loopback
   и разрешённое хранилище. Сначала повторить работающий backend, затем
   проверить весь браузерный сценарий и реальный скачанный DXF с SHA.
   ADR-0016/0034/0035 и матрица зависимостей определяют допуск в production.
   Отчёт об исполнении передавать по ID задачи с веткой, SHA, командами,
   кодами выхода, фактическими артефактами и оставшимися ограничениями.
