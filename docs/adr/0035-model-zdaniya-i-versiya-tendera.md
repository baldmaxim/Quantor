# ADR-0035. Версия тендера и контур модели здания

Дата: 2026-11-02
Статус: принято командой владельца; условия боевого включения — ниже

## Контекст

Нужно привязать работу к тендеру и конкретной версии документации и строить модель Revit из PDF. Разбор и
обоснование — [docs/building-model/00-plan.md](../building-model/00-plan.md). Владелец утвердил план
2026-11-02 («надо реализовать»), в том числе рекомендации его раздела 11.

В HUBTender версия тендера — отдельная строка `tenders` с новым UUID. Quantor хранит этот UUID в
`Project.external_id` и номер версии не сохраняет. Какие ревизии составляли комплект, тоже нигде не записано.

## Решение

**1. Версия тендера — замороженный комплект ревизий.** `TenderVersion` принадлежит проекту, содержит по одной
ревизии на документ и необязательно ссылается на строку HUBTender. Несколько комплектов могут ссылаться на одну
строку, если документы менялись без клонирования тендера. Заморозка фиксирует `manifest_sha256`; изменения запрещает
триггер базы. Возможность закрыта пилотным флагом `tender.versions`.

**2. Уточнение ADR-0011.** Один номер тендера — один проект. Другая версия того же номера добавляется в проект как
версия, а не создаёт новый проект. Запись в HUBTender по-прежнему запрещена. Остальные решения ADR-0011 в силе.

**3. Контур модели здания.** Отдельный контур за пилотным флагом `model.auto`. Цепочка: сырой JSON разбора →
нормализатор → кандидат → проверка человеком → утверждённая версия → пакет JSON для Revit → квитанция сборки. Запись в
Revit выполняется вне портала. Модель не пишет в таблицы обмера, MEP и `Region`, не выдаёт данные в расчёт calc и не
является ProjectGraph.

**4. Исключения из запретов — только внутри контура модели:**

- масштаб и размерные значения разбора — кандидат с основанием, подтверждает человек. Измерительное ядро и калибровка
  не меняются;
- разрешена выгрузка JSON для Revit из утверждённой модели;
- роли стен и типы помещений живут в контуре модели и не попадают в измерительное ядро.

**5. Тяжёлые зависимости.** OpenCV, Shapely и pypdfium2 по-прежнему запрещены в `apps/api` и основном образе. `plangeom`
работает только в отдельном образе и отдельном исполнителе.

## Условия

До их выполнения флаг `model.auto` не включается, а `plangeom` не попадает в боевой образ:

1. письменное разрешение автора `plangeom` на использование: сейчас лицензии нет;
2. образец целевого JSON для Revit: без него адаптер не пишется;
3. PASS гейта G1 на трёх объектах по порогам, утверждённым владельцем до прогона.

Сравнение версий модели (этап M8) и флаг `drawing.compare` этим решением не открываются: перед M8 нужно отдельное решение.

## Последствия

- Версия тендера не зависит от `plangeom` и пригодна сама по себе.
- Если сменится библиотека или формат Revit, меняется один адаптер: канонический формат модели принадлежит Quantor.
- Существующие проекты версий не получают автоматически: подставлять несуществующую историю нельзя.
