# ADR-0036. Пилот CAD PDF→DXF в бою, 3D DXF для AutoCAD и трассы механики

Дата: 2026-11-09
Статус: принято владельцем 2026-11-09; уточняет ADR-0035 и ADR-0034

## Контекст

CAD-инструмент PDF→DXF (маршрут `projects/[id]/cad`, исполнитель `app.cad_worker`, движок
[CAD_engine](https://github.com/baldmaxim/CAD_engine), замечания `cad_remarks`) слит в main и выложен в бой
закрытым: маршруты подключаются только при `CAD_QA_ENABLED`, который запрещён вне local/test, флаг `cad.export`
выключен и не редактируется из админки. Контракт — [cad-engine-integration-contract](../building-model/cad-engine-integration-contract.md).

Владелец хочет пилот на одном объекте — TENDER 342 «ЖК Знаки», документ `МЛДГВ-КАМ0925-П-АР1.1_ver5`, лист 32 по
проекту (стр. 81 PDF): корпус 9, секция 3, план 14 этажа на отм. +47,600. Затем по одобренной разметке — трассы
отопления и пожаротушения в 3D DXF для AutoCAD.

Условия флага `model.auto` (ADR-0035) не выполнены: лицензии `plangeom` не будет, образца Revit нет, G1 не
проводился. CAD-движок от `plangeom` не зависит, поэтому пилот CAD на `model.auto` не опирается.

## Решение

**1. Пилот CAD — отдельный контур за флагом `cad.export`.** `model.auto` остаётся закрытым.

- `cad.export` — пилотный флаг пространства: выключен по умолчанию, включается в админке на одно пространство,
  проверяется и интерфейсом, и сервером (ADR-0023).
- Боевой гейт — сам флаг: маршруты CAD подключены всегда и закрыты `require_feature("cad.export")`. `CAD_QA_ENABLED`
  остаётся только для QA-режима local/test.
- Пространство пилота — отдельное («ЖК Знаки — пилот CAD»), не `default`.

**2. Исполнитель CAD — отдельный сервис и образ.** `quantor-cad-worker` в `deploy/docker-compose.yml`, образ
`quantor-cad-worker` собирает `publish.yml` из закреплённого коммита репозитория движка. Одно задание за раз,
`cpus: 1.0`, лимит памяти по замеру; рабочая папка удаляется после задания. Основной образ `apps/api` движок, его
зависимости и `tools/` не получает. Вход и выход — только БД и MinIO портала.

**3. Лицензии — только в образе CAD-исполнителя.** PyMuPDF (AGPL-3.0), Shapely/GEOS и Pillow разрешены в образе
CAD-исполнителя. Основание — решение владельца 2026-11-09: CAD пользуется только владелец, образ закрытый (GHCR) и
никому не передаётся. В `apps/api`, основном исполнителе и контуре `calc` запреты ADR-0016, ADR-0030 и ADR-0034
действуют без изменений. Пересмотр — до появления любого стороннего пользователя или передачи Quantor заказчику:
замена PyMuPDF либо коммерческая лицензия.

**4. Масштаб калибрует человек.** Движок не выбирает масштаб сам: масштаб листа — калибровка человеком (ADR-0018),
передаётся движку параметром. Размерные цепочки (fit/holdout) и площади экспликации — автопроверка этой калибровки.
Расхождение — DXF со статусом «требует проверки», грубое — отказ с причиной «проверьте калибровку». Надпись
«М 1:200» — только для сверки.

**5. Лист выбирает человек.** Классификатор листов движка — подсказка, а не блок.

**6. Выход — 3D DXF для AutoCAD вместо Revit.** DXF R2018. Стены и плиты — с Z от отметок уровней, трассы —
3D-полилинии по слоям систем. Цель ADR-0035 «пакет JSON для Revit» заменяется: модули `revit*` в
`tools/building_model` заморожены как история. Генерация Revit/IFC по-прежнему запрещена; 3D DXF здания и трасс —
только в контуре CAD за `cad.export`.

**7. Отметки — из АР, с происхождением.** Отметка этажа — из заголовка плана и разрезов (`observed`), высота этажа —
по шагу отметок (`derived`), толщина плиты — из раздела КР; до его появления — допущение (`assumed`), подтверждает
владелец.

**8. Трассы механики — кандидат, не измерение.** Порядок: отопление, затем пожаротушение. Генератор — тип задания в
CAD-исполнителе (уточняет ADR-0034 для этого контура: вход — DXF, а не PDF). Вход — одобренный вид: запись
одобрения (задание, попытка, лист, вид, `dxf_sha256`, кто, когда), открытых замечаний нет. Выход — неизменяемый
кандидат с происхождением: хеши входа, версия алгоритма, параметры. Принимает человек, этаж целиком; 3D DXF трасс —
только из принятого кандидата. Длины — детерминированно, из геометрии и калибровки. Без диаметров, отводов и фитингов.
Константы алгоритма и высоты трасс — версионированные параметры с источником, не числа в коде.

## Последствия

- Пилот открывается без `plangeom` и без `model.auto`.
- Боевой сервер (2 vCPU, 4 ГБ) — узкое место: лимит памяти исполнителя ставится по замеру на пилотном листе, swap
  увеличен до 6 ГБ как временная мера; при нехватке — увеличение VDS.
- Движку нужны правки: внешний масштаб (п. 4) и выбор листа человеком (п. 5).
- Для трасс разметки движка мало: в DXF нет помещений с назначением, окон, шахт «ПТ»/«ВК». Источник этих данных —
  отдельное решение перед генератором (п. 8).
