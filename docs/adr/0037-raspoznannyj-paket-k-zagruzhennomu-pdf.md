# ADR-0037. Распознанный пакет прикрепляется к ранее загруженному PDF

Дата: 2026-11-10
Статус: принято; уточняет ADR-0007

## Контекст

ЖК Знаки: PDF листов загрузили в проект раньше, распознанный пакет `legacy-v1` (тот же PDF +
`*_blocks.json` + `*_results.md/html`) пришёл позже. Импортёр (ADR-0007) всегда создавал второй
`Document` с копией того же PDF, и в проекте получался дубль: геометрия, калибровки и обмеры лежали на
одной ревизии, распознанные области — на другой.

## Решение

**1. Поиск.** После извлечения PDF из архива импортёр считает его SHA-256 (потоково) и ищет в проекте
ревизию с тем же `source_sha256` (не ZIP-ревизию и не собственную производную ревизию пакета). Не нашлась —
прежнее поведение без изменений.

**2. Прикрепление.** Нашлась — новых `Document` и `DocumentRevision` нет, PDF в хранилище повторно не
кладётся, `source_metadata` ревизии не меняется (ADR-0003):

- листы: берутся существующие `Sheet` по `page_index`, недостающие создаются с тем же детерминированным
  идентификатором; пустые `width_px`/`height_px` заполняются размером растра распознавалки, заданные не
  трогаются. Число страниц пакета не равно числу листов ревизии (когда листы есть) — ошибка
  `PDF_PAGE_COUNT_MISMATCH`, ничего не записывается;
- `Region` и артефакты пакета создаются на существующей ревизии;
- геометрия заново не планируется, если `geometry_status` уже не `PENDING`;
- ZIP-ревизия переводится в `READY`.

**3. Повтор.** Если у ревизии уже есть области (или артефакты распознавания), ничего не пишется:
возвращается `already_imported=True` с текущими счётчиками. Второе распознавание того же PDF с первым не
сливается.

**4. Итог импорта** и payload задания получают поле `attached_to_existing`.

## Последствия

- Связь «пакет → PDF» видна по `Region` и `RecognitionArtifact` на ревизии PDF и по payload задания
  (`imported_revision_id` — ревизия PDF, `attached_to_existing=true`); в `source_metadata` ревизии PDF
  ссылки на пакет нет — ревизия неизменна.
- Дубля документа нет; обмеры и калибровки остаются на той же ревизии, что и области.
- Второй пакет для уже распознанного PDF не принимается молча: он получает `already_imported` и ничего не
  меняет. Замена распознавания — отдельное решение (новая ревизия PDF или явная операция).
- Пакет с PDF, которого в проекте нет, импортируется как раньше (ADR-0007).

## Отвергнутые альтернативы

- **Слить второй пакет с первым.** Нужны правила разрешения конфликтов областей; не нужно для MVP.
- **Записать ссылку на пакет в `source_metadata` ревизии PDF.** Нарушает ADR-0003.

## Поправка 2026-11-11: статус PDF-ревизии

При прикреплении пакета PDF-ревизия получает `processing_status = ready` (как и ZIP-ревизия): у неё уже
есть листы, области и артефакты, а подпись «Не распознан» в портале была неверной. Меняется только ход
обработки, содержимое ревизии не трогается (ADR-0003). Ранее прикреплённые ревизии исправлены миграцией
`0024_pdf_status_attached`: `unprocessed` → `ready` для ревизий, указанных в `imported_revision_id` успешных
заданий `legacy_import` с `attached_to_existing = true`.

## Поправка 2026-11-13: пакет без PDF

Распознавание часто приходит отдельно от PDF: PDF загружен раньше, папка распознавания
(`*_blocks.json`, `*_results.md`, `*_results.html`) — позже. ZIP без PDF теперь принимается и
прикрепляется к PDF проекта по имени файла: stem `*_blocks.json`, запасной вариант — `document_name` из
blocks; сравнение без учёта регистра, Unicode NFC, без `.pdf`, берётся последняя ревизия документа.
Нужен ровно один подходящий PDF-документ: ноль или несколько — `LEGACY_PDF_MISSING`, ничего не
создаётся и не пишется. Страхует имя проверка числа страниц (`PDF_PAGE_COUNT_MISMATCH`, п. 2). Собственный
документ для пакета без PDF не создаётся никогда. Поиск по SHA-256 для пакета с PDF не меняется. В payload
задания добавлено `attached_by`: `sha256` или `filename`. Веб собирает такой ZIP без PDF, когда в проекте уже
есть PDF с тем же именем.
