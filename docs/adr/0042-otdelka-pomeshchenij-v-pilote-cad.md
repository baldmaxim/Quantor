# ADR-0042. Отделка помещений по зонам в пилоте CAD

Дата: 2026-11-11
Статус: принято владельцем 2026-11-11; дополняет ADR-0036 и ADR-0038

## Контекст

Отделка в пилоте CAD стояла на паузе, чтобы сосредоточиться на конструкциях и трассах. Владелец снял паузу
2026-11-11: по зонам помещений (квартиры и МОП — лифтовые холлы, тамбуры, коридоры, лестницы) нужно быстро
назначать черновую отделку параметрами — грунтовка, штукатурка, шпаклёвка, окраска, обеспыливание, стяжка,
потолки — и получать количества по слоям.

Сейчас зона имеет только вид (`room_apartment` / `room_mop` / `door`), подтип МОП — свободное название;
сервер считает площадь и периметр зоны; высоты этажа есть в уровнях контура «Конструкции» (`effective_levels`).

## Решение

**1. Тип помещения у зоны.** Новое поле `room_type` — код из закрытого справочника (МОП: `lift_hall`,
`vestibule`, `airlock`, `corridor`, `stair`, `entrance_hall`, `pui`, `garbage`, `tech`, `mop_other`;
квартира: `living`, `kitchen`, `bath`, `wc`, `hall`, `storage`, `balcony`, `apt_other`). Если тип не передан,
сервер выводит его из названия по словарю; человек может исправить. У двери типа нет.

**2. Шаблон отделки — параметры проекта.** Шаблон: название, типы помещений для автоназначения, высота стен
под отделку (необязательно — до подвесного потолка), три поверхности (пол, стены, потолок), на каждой —
упорядоченные слои: работа, материал, число слоёв (раз), толщина мм, расход на м² (или на м² · мм) и его
единица. Шаблон назначается зоне явно; без явного назначения действует шаблон, в чьих типах есть тип
помещения зоны.

**3. Количества — детерминированно, из геометрии зоны и уровней.**
- пол и потолок — площадь зоны;
- стены — периметр × высота. Высота: из шаблона, иначе `wall_height_mm` уровней листа минус толщина слоёв
  пола шаблона; без высоты — `null` с причиной, не 0;
- материал слоя = площадь × расход (× толщина, если расход на мм) × число слоёв.

Проёмы и основание стены (монолит / кладка / ГКЛ) на шаге 1 не учитываются: ведомость помечает стены
«проёмы не вычтены». Шаг 2 — привязка рёбер зоны к конструкциям: вычет проёмов, откосы, основание по
материалу конструкции.

**4. Границы.** Контур «Отделка CAD» за флагом `cad.export`, как «Конструкции CAD»: не `Measurement`, не
`ExpectedQuantity`, в итоги обмера, calc и MEP не входит. Стоимости, цен и валюты нет. Ведомость — рабочая
таблица пилота, не ВОР Quantor и не смета. Параметр движка CAD `finishes` (отделка самого движка) остаётся
выключенным: отделку считает Quantor по зонам.

**5. Деление МОП.** Помещения МОП размечаются отдельными зонами со своим типом; в интерфейсе — разрез зоны
линией на две и правка вершин. Автоматическая разметка МОП по экспликации — следующий шаг `tools/cad_mep`.

**6. Шаг 2: рёбра зоны ↔ конструкции (решение 2026-11-11).** Контур зоны переводится в мм кадра листа (как в
3D-виде) и сопоставляется с контурами конструкций `walls.json` с допуском. Каждый участок ребра — один из видов:
- стена с основанием `monolith` (монолитные стены, пилоны, колонны), `masonry` (кладка), `gkl` (каркасные
  перегородки) — площадь = длина × высота;
- дверной проём (`door`, по контуру перемычки) — только надпроёмная часть: длина × (высота − высота двери);
- проём без двери (`gap`) — высота неизвестна, участок не отделывается, предупреждение;
- без стены (граница с соседней зоной, линия разреза) — не отделывается.
Откосы дверей — справочно: погонные метры и площадь на половину толщины стены каждой из смежных зон; в слои
стен — только если шаблон это включает. Слой стен может ограничиваться основаниями (например, обеспыливание —
только монолит, штукатурка — не по ГКЛ). Окон в результате конструкций нет — наружные стены считаются без
вычета окон, ведомость это помечает. Без результата конструкций или кадра — поведение шага 1 (периметр ×
высота) с предупреждением.

## Последствия

- Миграция: колонки `cad_zones.room_type`, `cad_zones.finish_template_id` и таблица `cad_finish_templates`.
- Пауза отделки в `docs/building-model/cad-handoff-2026-11-09/rules/CAD_PROJECT_RULES.md` снята этим ADR.
- После правки зоны или уровней ведомость пересчитывается при чтении: количества не хранятся.
