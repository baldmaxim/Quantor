# ADR-0052. Ручная привязка корпуса к площадке по двум парам точек

Дата: 2026-11-16
Статус: принято по указанию владельца Quantor (2026-11-16); дополняет ADR-0039 (общий вид здания) и
постановку зданий на объект по осям и ядрам (`cad_building3d.place_site`)

## Контекст

Вид «Весь объект» (ADR-0039) ставит здания на общую площадку автоматически: по общим маркам осей, затем по
совпадению монолита (ядер) с подземной частью, затем по резерву ядер. Часть корпусов автоматика не ставит
вовсе. В ЖК Знаки это корпуса 5 и 9: у их листов нет общих с подземной частью марок осей, лист нарисован с
поворотом, ядер одной башни мало, чтобы выбрать одно место из многих. Такой корпус остаётся отдельным блоком
(`placement = none`). Подбирать место эвристиками дальше значит выдавать догадку за результат; а человек
показывает место за минуту: две одинаковые точки на листе корпуса и на листе площадки.

## Решение

**1. Привязка по двум парам точек.** Человек указывает две точки на листе корпуса (источник) и те же две
точки на листе уже поставленного здания, обычно подземной части (цель). Точки — числа в мм кадра вида своего
листа (система DXF листа, как контуры этажей в `/cad/building3d`). Сервер выводит перевод «вид источника →
вид цели»: поворот `θ = угол(q2 − q1) − угол(p2 − p1)` и сдвиг по серединам отрезков
`t = (q1 + q2)/2 − R(θ)·(p1 + p2)/2`. Масштаба и зеркала нет.

**2. Хранение.** Таблица `cad_site_pins` (миграция 0045): лист-источник и лист-цель по тройке «ревизия
документа, страница, вид» (так в сборке 3D опознаётся этаж), по две точки на каждом, выведенные `rotation_deg`,
`offset_x_mm`, `offset_y_mm`, `baseline_mm` (расстояние между точками источника), `residual_mm` (разность длин
двух отрезков), `note`, автор и время. Запись неизменяема, кроме отзыва (`revoked_at`, `revoked_by`,
`revoke_reason`, как у `CadDecision`); изменение — отзыв и новая запись. Действующая привязка на лист-источник
одна (частичный уникальный индекс по неотозванным).

**3. Проверки при создании (422, `CAD_SITE_PIN_INVALID`).** Расстояние между точками меньше
`SITE_PIN_MIN_BASELINE_MM = 5000` — короткая база даёт плохой угол. Относительная разность длин двух отрезков
больше `SITE_PIN_MAX_LENGTH_MISMATCH = 0.01` — указаны не те точки или у листов разный масштаб; масштаб
привязка не подгоняет. Источник и цель — один и тот же лист. Ревизия не из этого проекта — 404.

**4. Применение при посадке.** Действующие привязки проекта сервис сборки читает из базы и передаёт в
`place_site_report`; сама `place_site` остаётся чистой функцией, привязки — её аргумент (по умолчанию нет).
Здание источника встаёт, когда здание цели уже поставлено: `G = S_цели ∘ T_пина ∘ A_источника⁻¹`, где
`A_источника` — совмещение листа внутри своей группы, `S_цели` — перевод вида листа цели в систему площадки,
`T_пина` — перевод привязки. Такое здание кладётся в посадку до резерва по ядрам и до присоединения по осям:
соседи по осям встают за ним, а привязка сильнее автоматики для своего здания. Пока цель не поставлена, здание
ждёт и автоматикой не ставится; цель, поставленная другой привязкой, допустима. Способ посадки —
`placement = manual`, у группы `site_pin_id`, сообщение «привязано вручную: невязка N мм, база M м». Способ
`manual` в «на проверку» не попадает.

**5. Не применилась — сказано.** Предупреждение `site_pin_ignored` с причиной по-русски: лист-источник входит в
базовую группу (основа площадки); листа нет среди этажей сборки (другая ревизия, лист не построен); оба листа в
одном здании; здание цели не поставлено; привязки одного здания по разным листам расходятся больше
`AGREE_SHIFT_MM`/`AGREE_ROTATION_DEG` (`cad_site_cores`). Согласные привязки одного здания — берётся созданная
позже. Если основы по ядрам нет и постановка запасная, привязка ставит только здания, которые автоматика не
поставила.

**6. API.** `GET /projects/{id}/cad/building3d/site-pins` (действующие, `DOCUMENT_READ`),
`POST …/site-pins` (создание, `DOCUMENT_UPLOAD`; прежняя привязка листа-источника отзывается тем же запросом
с причиной «заменён»), `DELETE …/site-pins/{pin_id}` (отзыв, `DOCUMENT_UPLOAD`; повторный — 409
`CAD_ALREADY_REVOKED`). Роутер за флагом `cad.export`; доступ по пространству и проекту, чужое — 404.

## Что не делаем

- масштаб и зеркало: масштаб листа задаёт калибровка, привязка — только поворот и сдвиг;
- автоматический подбор точек: точки указывает человек;
- перенос привязки на новую ревизию: привязка относится к ревизии листа, при новой ревизии перестаёт
  применяться (предупреждение `site_pin_ignored`), человек привязывает заново;
- пересчёт соседей, поставленных автоматикой до привязки в запасной постановке (без основы по ядрам).

## Последствия

- Корпус, который автоматика не ставит, встаёт на место за две пары точек; ошибка точки видна по невязке и
  по предупреждению, привязку отзывают и делают заново.
- Привязка не входит в итоги обмера, calc и MEP: вид только показывает.
- Откат миграции 0045 удаляет таблицу вместе с привязками.
