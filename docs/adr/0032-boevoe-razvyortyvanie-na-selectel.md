# ADR-0032. Боевое развёртывание на Selectel

Статус: принято, 2026-09-29.

## Контекст

До этого решения в репозитории не было ничего для боевого запуска: только dev-compose с базой и
MinIO. Владелец решил выложить портал для тестового пилота на Selectel под `quantor.meridianai.ru`.

Ограничения: существующий сервер `selectel` (1 vCPU / 2 ГБ, полтора десятка чужих контейнеров)
стек не вмещает; официальные образы MinIO сняты с публикации; внешнего провайдера входа нет
(решение — ADR-0031).

## Решение

1. **Отдельный VDS 2-4-50** (2 vCPU / 4 ГБ / 50 ГБ, 650 ₽/мес) — только Quantor. Соседей нет,
   выкладка не может их задеть. Рост — сменой тарифа без переезда.
2. **DNS прямо на сервер**, свой nginx и Let's Encrypt. Фронт-прокси зоны не участвует: загрузки
   до гигабайта не должны проходить два прокси с двумя лимитами тела.
3. **Одно имя для портала, API и файлов.** `quantor.meridianai.ru` отдаёт портал, `/api/` и
   `/health/` — API, `/quantor-files/` — MinIO. Браузер работает с API и файлами как с тем же
   origin: CORS для хранилища не нужен, service worker `/api/` не кэширует. Контур управления — на
   `admin.quantor.meridianai.ru`; cookie сеанса с доменом `quantor.meridianai.ru` видна обоим
   (ADR-0013 §4).
4. **Подписанные ссылки — под публичный адрес.** Новая настройка `S3_PUBLIC_ENDPOINT_URL`: API и
   воркер ходят в MinIO по внутренней сети, ссылки для pdf.js подписываются под
   `https://quantor.meridianai.ru`. nginx передаёт Host как есть — подпись SigV4 сходится; снаружи
   разрешены только GET и HEAD.
5. **MinIO на том же сервере — тестовый режим.** Цель ADR-0002 (управляемое S3) не отменяется:
   перед работой с реальными документами — Selectel Object Storage, меняются только адрес и ключи.
   Образ — сборка MinIO от Chainguard, закреплённая по digest: официальный `minio/minio` снят с
   Docker Hub. Реестр Chainguard с сервера недоступен (403), поэтому `publish.yml` копирует этот
   digest в закрытый пакет GHCR `quantor-minio`. MinIO (AGPL-3.0) — отдельный неизменённый
   сервис, в код портала не входит; пакеты GHCR закрыты, сервер входит в реестр по токену.
6. **Образы собирает CI**, сервер только скачивает: `publish.yml` по ручному запуску публикует
   `ghcr.io/baldmaxim/quantor-{api,web,admin}` с тегом git-sha. Next.js — автономный сервер
   (`output: standalone` при `QUANTOR_STANDALONE=1`). Один образ API — три роли: API, воркер,
   разовые команды (ADR-0014).
7. **Выкладка — `deploy/update.sh <sha>`**: образы → бакет → миграции отдельным контейнером →
   перезапуск → сверка образов → ожидание `/health/ready`. `docker-compose.yml` берётся из образа
   того же коммита. Откат — предыдущий sha. Выпуск записывается в файл `RELEASE`, ручные команды
   идут через `deploy/compose.sh`; `.env` заполняет владелец, и скрипты его не меняют.
8. **Ни одного порта наружу, кроме 80/443 nginx.** База, MinIO, API — во внутренних сетях; консоль
   MinIO — на петле, через SSH-туннель. Swagger и схема API в бою отдают 404. Пределы памяти на
   каждом контейнере.
9. **Резервная копия базы** — ежедневный `pg_dump` на сервере, 7 дней. Файлы MinIO в тестовом
   режиме не копируются — риск принят владельцем.

## Последствия

- Потеря диска сервера — потеря загруженных документов. Приемлемо для пилота, неприемлемо для
  работы: переход на управляемое хранилище — условие реальной эксплуатации.
- Образы web и admin собираются под конкретный домен (`NEXT_PUBLIC_*` вшиваются при сборке).
- Одна реплика API и один воркер: для пилота достаточно, масштабирование — отдельным решением.

## Отклонённые варианты

- **Апгрейд существующего `selectel`.** Дешевле на 250 ₽/мес, но выкладка Quantor делила бы
  память и ingress с чужими сервисами.
- **Вход через фронт-прокси зоны.** Второй TLS и второй лимит тела на каждом гигабайтном файле.
- **Сборка на сервере.** Сборка Next.js съедает два-три гигабайта — весь сервер.
