# ADR-0049. Профиль оформления проектировщика в пилоте CAD: образцы на листе вместо подстройки движка

Дата: 2026-11-16
Статус: принято владельцем 2026-11-16
Дополняет: [ADR-0036](0036-pilot-cad-v-boyu-i-3d-dxf.md), [ADR-0038](0038-podschyot-kladki-i-monolita-v-pilote-cad.md),
[ADR-0040](0040-material-konstrukcij-iz-uslovnyh-oboznachenij.md), [ADR-0044](0044-cad-dvizhok-otdelnym-repozitoriem.md),
[ADR-0045](0045-avtomasshtab-cad-po-razmernym-cepochkam.md)

## Контекст

Чертежи приходят от разных проектировщиков, и у каждого своё оформление: цвет заливки монолита, перо и шаг
штриховки кладки, толщины линий дверей, вид засечек размерных линий. Движок PDF → DXF уже различает оформление,
но только внутренним механизмом: профили `templates/material-profiles-v1.json` (два профиля: «серый 0,753» по
умолчанию и «тёмный монолит, шахты 0,754» под «Остров 14»). Профиль выбирает эвристика по листу. Новый
проектировщик — это разбор листа разработчиком, новый профиль, новая версия движка, пин и выкатка. Эффект
подтверждён: профиль «Острова 14» поднял число дверей на листе с 0 до 45 (коммит движка `59c9d25`).

Аудит 2026-11-16: 23 листа планов АР пяти проектировщиков (комплекты 339, 341, 342, 343, 314), затем прогон
боевого образа `quantor-cad-worker` (архив движка `1afeca5f32b7`, совпадает с пином) на восьми листах.

| Комплект | Монолит на листе | Заливка монолита в слое `02_МОНОЛИТ` | Двери / окна |
|---|---|---|---|
| 342 АР1.1 | серый 0,753 + штриховки 0,408 / 0,306 | 100% | 40 / есть |
| 342 АР1.2 | серый 0,754, штриховки другие | 93% | 25 / есть |
| 339 | тёмно-серый 0,422 | 0%: 52% ушло в «кладку 200», 46% ни в одну конструкцию; парковка — 83% мимо | 0 / 0 |
| 343 | сплошной чёрный | 0–4%: 96–99% ни в одну конструкцию | 0 / 0 |
| 314 | серый 0,5, шахты 0,754 | автомасштаб не узнал засечки; с ручным масштабом движок падает | — |
| 341 | не установлен: 0,753 у трёх крупных площадей, не стен | автомасштаб не узнал засечки; с ручным масштабом движок падает | — |

Выводы аудита:

- Один и тот же цвет у разных проектировщиков значит разное: серый 0,753–0,754 — монолит в 342, шахты в 314,
  крупные площади в 341. Общего правила для всех чертежей быть не может.
- Слоёв PDF (Optional Content Groups) нет ни в одном комплекте, метаданные `creator`/`producer` пустые или
  «Acrobat». Проектировщика по файлу не узнать, шаблон «слой → класс» невозможен — только по графике.
- Внутри тома оформление устойчиво по листам, но меняется между томами одного комплекта (342 АР1.1 и АР1.2) и
  на подземных этажах (314).
- Условные обозначения с материалом есть не на всех листах (нет на 339 и 343): подсказка ADR-0040 профиль не
  заменяет.
- Автомасштаб ADR-0045 тоже зависит от оформления: у 314 и 341 движок не узнал засечки размерных линий.

Доля «монолита» по 339 и 343 определена по форме заливок (полосы и колонны шириной 150–200 мм), визуально и по
легенде не сверена. Падения на 314 и 341 — отдельный дефект устойчивости движка (`AttributeError: NoneType` в
`plan_layers.py`, `source_hatched_strips.py`); его исправление идёт в CAD_engine независимо от этого ADR.

## Решение

**1. Профиль оформления — данные человека, а не код движка.** В контуре CAD за флагом `cad.export` появляется
сущность «профиль оформления» (`CadStyleProfile`): набор графических подписей классов, снятых с образцов на листе.
Профиль хранится как версионированный JSON с sha256; утверждённая версия неизменна, правка — новая версия. В базе
профиль занимает килобайты (это не бинарный файл, ADR-0002 не нарушается).

**2. Единица — том, не проектировщик.** Профиль привязывается к `Document` (том комплекта: АР1.1, АР1.2…) и
действует на все его ревизии. Для нового тома профиль того же проекта или пространства предлагается по совпадению
подписей, применяет его человек. Имя проектировщика ключом не служит.

**3. Образцы ставит человек на листе.** Человек щёлкает 1–3 образца класса, можно отметить и отрицательный
образец («это не монолит»). Классы первой версии:

- материалы: монолит, кладка (с типом по желанию), утеплитель, шахта;
- двери (перо и манера дуги);
- засечка размерной линии.

Окна, фасадные системы и оборудование — следующей версией: это сборки и узлы, а не только стиль линий.

**4. Подпись снимает детерминированный инструмент в исполнителе CAD.** Это скрипт движка без модели, OCR и растра:
он читает векторы PDF (PyMuPDF — только в образе `quantor-cad-worker`, ADR-0036). Подпись образца: цвет заливки,
цвет и толщина пера, угол и шаг штриховки, штрих-пунктир, для двери — перо и форма дуги, для засечки — форма и
длина. Инструмент возвращает предпросмотр «найдено N элементов, площадь S» по всему листу. Профиль сохраняется
только после принятия человеком. В процессе `apps/api` разбора PDF нет.

**5. Движок получает профиль входным файлом.** Новый необязательный вход преобразования
`style_profile.json` (схема `cad_engine.style_profile.v1`, расширение формата `material-profiles`). Приоритет:
профиль человека → автовыбор профиля движка → профиль по умолчанию. Движок остаётся встраиваемым (ADR-0044):
профиль для него — такой же файл, как `params.json`. Sha256 профиля входит в параметры задания и в ключ
идемпотентности, результат хранит id, версию и хеш профиля.

**6. Профиль подсказывает, но не решает молча.** Если профиль противоречит условным обозначениям листа
(ADR-0040) — у конструкции статус «проверить», легенда профилем не переписывается. Если подпись класса на листе не
нашлась или нашлась там, где профиль её не ждёт, — тоже «проверить», без молчаливого выбора.

**7. Покрытие листа — обязательная метрика.** Для каждого листа результат показывает долю заливок и штриховок
плана, не попавших ни в один класс профиля, и число элементов по каждому классу. Высокая доля неразобранного —
сигнал, что профиль неполон или лист из другого тома.

**8. Засечка в профиле помогает автомасштабу, но не заменяет проверку.** Подпись засечки расширяет поиск
размерных цепочек ADR-0045. Масштаб по-прежнему подтверждается только итогом `dimension_checks_passed`; надпись
«М 1:NN» масштабом не служит. Профиль не меняет порядок калибровки человеком.

**9. Гейт приёмки.** До включения профилей на боевом пространстве — замер на тех же листах аудита:

- 339 и 343 с профилем, снятым человеком: заливка монолита в `02_МОНОЛИТ` не ниже 90%, двери находятся;
- 342 АР1.1 и АР1.2 без профиля: без регресса (100% и 93%, двери 40 и 25);
- 314 и 341 — после исправления падений движка.

Итог замера — отчёт в `docs/` с честными `BLOCKED` там, где шаг невыполним.

## Что не входит

- Модель, OCR, растр страницы, распознавание по картинке; профиль не выдаёт физических величин — длины и
  площади считает только геометрия DXF и масштаб.
- Автоопределение масштаба по надписи и любые изменения правил калибровки (ADR-0018, ADR-0045).
- Перенос профиля между пространствами и любой обмен профилями вне пространства.
- Обучение моделей на образцах. Образцы могут позже стать ground truth для Stage 2B только отдельным решением
  владельца и по правилам `vision/`; клиентские листы в git не попадают.

## Последствия

- Подключение нового проектировщика становится работой пользователя на листе за минуты, без новой версии движка.
- Встроенные профили движка остаются запасным путём для листов без профиля человека.
- Порядок реализации — отдельными шагами, каждый со своей проверкой:
  1. CAD_engine: вход `style_profile.json` и его приоритет над автовыбором; синтетические тесты; новая версия
     движка и пин.
  2. CAD_engine: CLI снятия подписи по образцам и предпросмотра на листе.
  3. Quantor: сущность профиля и версии, привязка к тому, API за `cad.export`, контракт в OpenAPI.
  4. Quantor: интерфейс образцов на листе, предпросмотр, принятие; передача профиля в задание преобразования.
  5. Метрика покрытия в результате и интерфейсе; предложение профиля для нового тома.
  6. Замер гейта п. 9 и отчёт.
- Откат — выключить `cad.export` или не передавать профиль: движок вернётся к автовыбору.
