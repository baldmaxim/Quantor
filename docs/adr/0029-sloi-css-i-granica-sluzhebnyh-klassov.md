# ADR-0029. Служебные классы живут в слое `components` и всегда проигрывают разметке

Статус: принято, 2026-09-21

## Контекст

Общие стили `packages/ui/src/base.css` не были обёрнуты ни в один `@layer`, а Tailwind v4 первой же
строкой объявляет `@layer theme, base, components, utilities;` и складывает все утилиты в
`utilities`. По каскаду CSS безслойное правило выигрывает у правила в любом слое независимо от
специфичности и порядка. Поэтому служебные классы пакета молча перебивали утилиты, написанные в
разметке.

Дефект заметили с другой стороны: в окне создания проекта ряд кнопок лежал вплотную к нижней границе.
Причина — `.safe-bottom { padding-bottom: env(safe-area-inset-bottom) }` рядом с `p-[var(--s-6)]`.
На устройстве без выреза `env()` равен нулю, и нижний отступ окна обнулялся. Тем же способом были
испорчены ещё четыре места: тост обновления, `<main>` контура управления и два диалога.

Рядом нашлись однородные следствия: `@media (max-width:767px) button { min-height: 44px }` перебивал
`h-[26px]` и `h-[28px]`, превращая квадратные кнопки в овалы; `.scroll-area { overflow: auto }`
отменял `overflow-y-hidden` в ленте вкладок рабочей области; `:focus-visible { border-radius }`
скруглял по-своему даже круглую кнопку.

Общее у всех случаев одно: класс из общего пакета отменял решение, принятое в конкретном месте
разметки, и сделать это заметным было нечем.

## Решение

1. **Три зоны в `base.css`.** Вне слоёв остаются только токены (`:root`, обе тёмные палитры,
   `@theme inline`), регистрация `@property`, кадры `@keyframes`, правила `::view-transition-*` и
   блок `prefers-reduced-motion`. Базовые стили документа и мобильные правила — в `@layer base`.
   Служебные классы (`.press`, `.scroll-area`, `.skeleton`, `.safe-*`, `.spinner`, `.dialog-*`,
   `.tabular`, `.mono`, `.visually-hidden`, `.wrap-anywhere`) — в `@layer components`.
2. **Именно `components`, а не `utilities`.** Утилиты подставляются на месте `@import 'tailwindcss'`,
   то есть раньше нашего файла; попав с ними в один слой, служебный класс выиграл бы по порядку
   записи, и дефект бы остался. `components` объявлен раньше `utilities`, поэтому утилита из разметки
   выигрывает всегда.
3. **Блок `prefers-reduced-motion` остаётся вне слоёв намеренно.** У его правил `!important`, а важные
   объявления инвертируют порядок слоёв: важное вне слоя перебивает важное в любом из них. Этот
   предохранитель обязан выигрывать всегда.
4. **Безопасная зона складывается, а не подменяет.** Токены `--safe-t/r/b/l` хранят
   `env(safe-area-inset-*, 0px)`. Классы `.safe-*` применяются только к элементам без собственного
   padding по этой оси; там, где padding есть, вырез складывается явно в разметке:
   `pb-[calc(var(--s-5)+var(--safe-b))]`.
5. **Минимальная тап-цель — переменная.** `@property --tap-min` с `initial-value: 44px`,
   `inherits: false`; правило пишет `min-height: var(--tap-min, 44px)`. Запасное значение
   обязательно: без поддержки `@property` переменная дала бы невалидную длину и правило не
   применилось бы вовсе. Уменьшение цели пишется в разметке как `[--tap-min:26px]` и потому
   находится поиском.
6. **Квадратные кнопки задают обе стороны.** Для кнопок, видимых на телефоне, правильный ответ — не
   уменьшать цель, а вырасти до неё в обе стороны: `max-md:h-[44px] max-md:w-[44px]`.
7. **Метка `.ctl`** добавляется к классам кнопки: `<a>` без `role="button"` под правило тап-целей не
   попадал, и кнопка-ссылка оставалась мельче 44px.

## Последствия

- Разметка снова управляет своим оформлением: класс из пакета задаёт умолчание, утилита рядом его
  уточняет.
- Правка «включает» утилиты, которые раньше молча проигрывали. Три таких найдены и разобраны:
  `overflow-y-hidden` в ленте вкладок (возврат к намерению автора), `focus:outline-none` в поле
  поиска (класс убран — иначе поле осталось бы без кольца фокуса), `rounded-full` под
  `:focus-visible` (улучшение).
- `apps/admin/src/app/globals.css` с его `.admin-table` и `.table-scroll` завёрнут в
  `@layer components` по той же причине.
- Тёмная палитра сведена к одному набору значений: `--border-control` расходился между
  `@media (prefers-color-scheme: dark)` и `:root[data-theme='dark']`, и тема из системы выглядела
  иначе, чем выбранная вручную.
- Правило закреплено тестом `apps/web/src/lib/ui-css.test.ts`: он читает исходник и падает, если
  правило класса или тега окажется вне слоёв, если класс безопасной зоны снова начнёт писать `env()`
  напрямую или если тёмные палитры разойдутся.

## Отвергнутые альтернативы

- **Обернуть всё в `@layer utilities`.** Не чинит: внутри одного слоя при равной специфичности
  выигрывает более поздняя запись, а наш файл импортируется после Tailwind.
- **Перевести служебные классы на директиву `@utility`.** Даёт варианты вроде `md:scroll-area`, но
  кладёт класс в тот же слой, где живут утилиты, с которыми он конфликтует; победитель определялся бы
  внутренней сортировкой Tailwind — не тот контракт, на который стоит опираться. Ни один из этих
  классов сейчас не используется с вариантным префиксом.
- **Псевдоэлемент-распорка под вырез (`.safe-bottom::after`).** Действительно аддитивна, но вставляет
  ребёнка: во всех затронутых местах контейнер — `flex` или `grid`, и распорка стала бы элементом
  потока с собственным `gap`.
- **Считать безопасную зону внутри класса через `calc()`.** Невозможно: класс не знает базового
  отступа своего потребителя.
