# ADR-0005. Абстракция асинхронных заданий

Статус: принято, 2026-09-04

## Контекст

Импорт распознанного пакета — минуты работы: распаковка, проверка, создание сотен записей.
Дальше добавятся распознавание, извлечение векторов, расчёт объёмов. Пользователю нужно видеть
ход выполнения, а система должна переживать перезапуск.

Соблазн — сразу поставить Celery или Temporal. На Stage 1 реальная нагрузка одна
(`legacy_import`), и полноценный оркестратор станет инфраструктурой, которую надо
сопровождать без отдачи.

## Решение

Вводим сущность `Job` в базе данных как единственный источник правды о ходе работы:
тип, состояние (`queued → running → succeeded | failed | cancelled`), стадия, прогресс,
ключ идемпотентности, безопасный код ошибки, отметки времени.

Переходы состояний выполняются только через сервисный слой, который проверяет инварианты:
из завершённого состояния перейти нельзя, повтор с тем же ключом идемпотентности не создаёт
второе задание.

Исполнитель на Stage 1 — управляемое фоновое выполнение внутри процесса API. Очередь,
отдельные воркеры и durable-оркестратор добавляются, когда появится вторая-третья реальная
нагрузка. Redis по этой же причине сейчас не поднимается.

Интерфейс сервиса заданий не должен знать, кто исполнитель: замена внутреннего исполнителя
на очередь не должна затрагивать API и интерфейс.

## Последствия

- Состояние заданий переживает перезапуск, потому что живёт в базе, а не в памяти процесса.
- Долгое задание нагружает процесс API. Приемлемо для одной локальной установки, но это
  явная причина вынести исполнение в воркер при первой же многопользовательской нагрузке.
- Интерфейс опрашивает состояние с разумным интервалом; SSE/WebSocket добавляются позже.

## Отвергнутые альтернативы

- **Celery/RQ сразу.** Требует Redis и отдельного процесса ради одной операции.
- **Temporal.** Даёт durable-исполнение и повторы, но это отдельная платформа с собственной
  эксплуатацией. Разумный вариант на будущее, когда конвейер распознавания станет длинным.
- **Состояние задания в памяти процесса.** Теряется при перезапуске, не отображается честно.
