# ADR-0031. Локальная аутентификация с одобрением администратора

Статус: принято, 2026-09-29. Уточняет [ADR-0012](0012-granica-autentifikacii-i-avtorizacii.md) §1.

## Контекст

ADR-0012 отдал удостоверение личности внешнему OIDC-провайдеру и запретил хранить пароли. Боевой
запуск без провайдера невозможен: валидатор настроек отвергает `AUTH_MODE=dev` вне локальной среды,
а `oidc` требует издателя. Для тестового пилота на Selectel (ADR-0032) провайдера нет, и поднимать
Keycloak ради десятка пользователей — лишний сервис на сервере с четырьмя гигабайтами.

Решение владельца (2026-09-29): свой вход по почте и паролю, доступ — после одобрения в админке.

## Решение

1. **Третий режим `AUTH_MODE=local`.** Разрешён в любом окружении. `dev` по-прежнему только локально,
   `oidc` остаётся рабочим режимом на будущее — код провайдера не удаляется.
2. **Пароль — только хеш argon2id** (`argon2-cffi`, MIT) в отдельной таблице `local_credentials`.
   Параметры — минимальный профиль OWASP: 19 МиБ, 2 прохода, 1 поток; устаревший хеш пересчитывается
   при удачном входе. Хеширование — в потоке, не в цикле событий. Пароль в контракте API только во
   входных схемах, как `writeOnly`; тест контракта проверяет, что ни одна схема ответа его не содержит.
3. **Регистрация — заявка, а не доступ.** `user_identities.approval_status`: `pending` →
   `approved` | `rejected`. Одобрение администратором платформы сразу выдаёт пространство и роль:
   одобренный без членства вошёл бы в пустой портал. Ответ на регистрацию одинаков для нового и
   занятого адреса, хеш считается до поиска — форма не служит справочником пользователей.
4. **Вход.** Состояние заявки сообщается только знающему пароль. Неизвестный адрес проверяется
   хешем-пустышкой, чтобы время ответа не выдавало список пользователей. Пять неудач подряд —
   блокировка на 15 минут; счётчик в базе, а не в памяти процесса. Сверху — `limit_req` в nginx.
5. **Сеанс — прежний.** Та же непрозрачная cookie и тот же CSRF двойной отправкой (ADR-0012).
   Резолвер на каждом запросе проверяет «активен и одобрен»: отключение и отклонение действуют на
   уже выданные сеансы. Отключение и выдача временного пароля гасят все сеансы пользователя.
6. **Временный пароль вместо сброса по почте.** Почты портал не рассылает. Администратор задаёт
   временный пароль, пользователь обязан сменить его при входе (`must_change_password`); смена
   требует текущий пароль и гасит прочие сеансы.
7. **Первый администратор — командой на сервере**, а не подсказкой окружения:
   `python -m app.cli create-admin --email …`, пароль из терминала без эха. У локального входа нет
   провайдера, удостоверяющего почту, и `AUTH_BOOTSTRAP_PLATFORM_ADMINS` для него не действует:
   иначе администратором стал бы первый зарегистрировавшийся с «нужным» адресом. Повторный вызов —
   восстановление доступа.
8. **Аудит.** Регистрация, вход и отказ входа, смена пароля, одобрение, отклонение, роль,
   отключение и включение, выдача пароля. Значение пароля в журнал не попадает.

## Последствия

- Портал хранит пароли — появляется обязанность их беречь: хеш, лимиты, аудит, HTTPS. Утечка дампа
  базы даёт хеши argon2id, а не пароли.
- Второго фактора нет (ADR-0012 §9 относил его к провайдеру). Вне MVP; до него доступ к админке
  защищён паролем и правом `system.admin`.
- Переход на OIDC позже не требует миграции данных: личности провайдера — строки с другим `issuer`,
  локальные останутся рабочими до отключения.

## Отклонённые варианты

- **Keycloak на том же сервере.** Около гигабайта памяти и отдельная база ради пилота; остаётся
  целевым путём при росте числа пользователей.
- **Регистрация без одобрения.** Портал хранит чертежи Заказчика — открытый доступ по одной форме
  недопустим.
- **Сброс пароля по письму.** Требует почтового канала, которого у установки нет.
