# ADR-0055. ИИ-петля обводки и автозаполнение ВОР Заказчика в пилоте CAD

Статус: черновик, 2026-11-25; решение владельца 2026-11-25 (пилот на проекте «341. Капельский (СОЮЗ) (тест)»). Дополняет ADR-0006, ADR-0036, ADR-0038, ADR-0042, ADR-0051.

## Контекст

Пайплайн главной проекта: распознавание → паспорт листа → CAD (`cad_pdf_convert`) → конструкции (`cad_walls`) и зоны
(`cad_zones`) → одобрение человеком → трассы → 3D/«Здание» (сборка на чтении). Ошибки обводки правит человек
замечаниями. Проверка Codex (`cad_outline_review`, SSH на `kg_claude`, ручной запуск) даёт только отчёт.
Пересчёт `cad_walls` не читает ни замечаний, ни правок свойств; свойства конструкций (материал, толщина, высота,
учёт проёмов) применяются при чтении.

ВОР Заказчика: xlsx разбирается в позиции, есть связи позиций с группами конструкций (`cad_vor`, ADR-0038),
количества не сравниваются, в файл ВОР ничего не пишется.

Владелец хочет пайплайн: загрузка → движок и модель правят обводку в петле → независимая проверка моделью →
ручная приёмка с петлёй замечаний → автоматическое заполнение ВОР Заказчика и дополнение отсутствующим. Объём —
конструктив, двери, отделка МОП.

## Решение

1. **Петля вида.** Движок строит → ИИ-правщик (Claude Opus, `claude-opus-5-5`) смотрит пакет вида (вырезка листа
   PNG, наложение PNG, `walls.json`, исходная страница, документы проекта в Markdown) и выдаёт находки и правки
   свойств → пересчёт обводки → ИИ-проверщик в чистом контексте (видит только пакет и результат, не рассуждения
   правщика). Нет существенных находок — вид уходит человеку; иначе следующий круг, не больше `max_iterations` (3).
2. **Модель геометрию не рисует и величин не выдаёт.** Находка = тип из перечня замечаний CAD + рамка на листе +
   id конструкций + доказательство. Правка свойства — материал, толщина, высота, учёт проёмов — с доказательством.
   Геометрию по находке строит движок из примитивов PDF внутри рамки: новый вход `cad_walls` — замечания вида как
   подсказки (`false_wall`, `wrong_class`, `missing_wall`, `missing_door`). Тот же вход использует человек: петля
   одна для модели и для человека.
3. **Результат петли — кандидат вида до одобрения человеком.** Свойства от модели помечаются происхождением и
   видны в приёмке. Принятие и одобрение — только человек.
4. **Исполнение.** Задание `cad_ai_review` в исполнителе CAD, вызов `claude -p` на `kg_claude` по SSH (как проверка
   Codex), без пользовательских настроек и MCP, ответ по JSON-схеме. Пилот — настройка `CAD_AI_LOOP` (проект,
   модель, лимит кругов, документы на `kg_claude`); вне пилота недоступно и в интерфейсе, и на сервере
   (ADR-0023). Codex на том же пакете — для сравнения.
5. **Происхождение каждого прогона:** модель, sha256 промта, пакета, входа, `walls.json`, DXF, источников; расход
   (стоимость вызова, время, токены).
6. **Внешняя модель.** Передача клиентских чертежей и документов внешней модели (Anthropic через Claude CLI) — по
   отдельному решению владельца, для пилотного проекта; для Codex (OpenAI) — уже действующая практика, фиксируется
   здесь. Остальные проекты и пространства — не передаются.
7. **ВОР.**
   - В начале петли позиции ВОР Заказчика (конструктив, двери, отделка МОП) — перечень того, что модель ищет на
     виде (`vor_check`).
   - В конце модель предлагает сопоставление позиций с группами конструкций, дверями и отделкой МОП; человек
     подтверждает. Количества — только от движка.
   - Выгрузка — **копия** xlsx Заказчика с колонкой «Quantor» и строками «нет в ВОР»; оригинал неизменен.
   - Это снимает для пилота запрет «ВОР, сформированный Quantor» в части заполнения формы Заказчика. Цен и
     стоимости по-прежнему нет; флаг `reports` не включается.
8. **Claude Code в продукте.** ADR-0006 и CLAUDE.md («Claude Code и Cursor — инструменты разработки, не часть
   продукта») для пилота уточняются: Claude CLI — исполнитель проверки вне процесса API; бизнес-логика от имени
   модели не зависит, модель — параметр пилота.

## Границы

- Модель не выдаёт метры, м² и м³; числа считает только детерминированный движок.
- Масштаб — только движок (ADR-0045); модель масштаб не определяет.
- `max_iterations` — жёсткий лимит; модель вызывается только по кнопке или в петле пилота.
- Цен, расценок и валюты нет; один пилотный проект.
- Кандидат модели — не факт и не итог: в выгрузку ВОР — только после одобрения человеком.
- Оригинал ВОР Заказчика не изменяется; клиентские данные в git не попадают.

## Последствия

- Срезы: **S1** — проверка с замечаниями; **S2** — правки свойств и подсказки `cad_walls` (правка движка и пин,
  ADR-0044); **S3** — петля и шаг «ИИ-проверка» в пайплайне главной; **S4** — ВОР; **S5** — сравнение с Codex.
- Риск: ключ конструкции — хеш геометрии; после пересчёта свойства и принятие переносятся только при однозначном
  совпадении. Замерить в пилоте.
- Зависимость боя от компьютера `kg_claude` и лимитов подписки приемлема для пилота; для боя — ключ API и
  отдельный хост (новое решение).
- Новые артефакты и таблицы (прогоны петли, находки, происхождение, расход) — уточнить в срезе S1.
