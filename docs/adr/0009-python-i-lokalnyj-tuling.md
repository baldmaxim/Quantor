# ADR-0009. Python 3.12 и локальный тулинг

Статус: принято, 2026-09-04

## Контекст

На машине разработки Python 3.14 стоит по умолчанию, рядом установлен 3.12. Драйверы базы
данных и S3 (`asyncpg`, `aiobotocore`) распространяются бинарными пакетами и отстают от
свежих версий интерпретатора. Разработка ведётся под Windows, а проверка — на другом
компьютере, поэтому окружение обязано разворачиваться одинаково в обоих местах.

## Решение

- Бэкенд работает на Python 3.12–3.13; в `pyproject.toml` зафиксировано
  `requires-python = ">=3.12,<3.14"`.
- `pnpm run setup` сам находит подходящий интерпретатор, создаёт `apps/api/.venv` и ставит
  зависимости. Ручных инструкций по venv в README нет.
- Прямые зависимости закреплены точными версиями. Инструмент с lock-файлом (`uv`/`poetry`)
  не вводится: он добавляет ещё одну обязательную установку на каждой машине, а точные
  пины дают воспроизводимость, достаточную на этом этапе.
- Проверки бэкенда: `ruff` (линт и формат) и `mypy` в строгом режиме. Правила `RUF001–RUF003`
  выключены — документация проекта на русском, и кириллица не является «подозрительным символом».
- Команды разработчика — npm-скрипты в корне; всё, что сложнее одной строки, вынесено в
  `scripts/*.mjs`, чтобы одинаково работать в PowerShell и в bash.

## Последствия

- Обновление зависимостей — осознанное действие с правкой `pyproject.toml`, а не побочный
  эффект установки.
- При появлении бинарных пакетов под 3.14 верхнюю границу можно поднять одной строкой.
- `# type: ignore` и подавление правил линтера запрещены: ошибка типов чинится кодом.

## Отвергнутые альтернативы

- **Системный Python 3.14.** Часть колёс собирается из исходников или отсутствует.
- **uv с lock-файлом.** Лучше по скорости и воспроизводимости, но требует установки ещё одного
  инструмента на обеих машинах. Кандидат на переход, когда список зависимостей вырастет.
- **Makefile для команд.** Требует установки make под Windows.
