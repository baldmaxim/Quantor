# ADR-0004. Архитектура просмотрщика: рендер и overlay разделены

Статус: принято, 2026-09-04. Пункт о реализации overlay уточнён
[ADR-0015](0015-sloi-nalozheniya-na-canvas2d.md): слои наложения остаются на Canvas2D,
WebGL — решение по измерению. Разделение слоёв и императивная камера в силе.

## Контекст

Рабочая область должна открывать PDF на 77 страниц и 50 МБ, плавно масштабироваться и
показывать поверх чертежа сотни распознанных областей. На следующих этапах поверх того же
чертежа появятся измерения — уже тысячи объектов на лист.

Типичная ошибка — рисовать и документ, и разметку одним компонентом: тогда любое изменение
разметки заставляет перерисовывать страницу, а панорамирование упирается в React.

## Решение

Три независимых слоя:

1. **Base render** — отрисовка страницы PDF. Интерфейс `RenderBackend` с единственной
   реализацией на `pdfjs-dist`. Тайловый бэкенд для патологически тяжёлых листов
   добавляется позже как вторая реализация, без переписывания рабочей области.
2. **Overlay** — отдельный слой поверх, рисует распознанные области из нормализованных
   координат (см. [ADR-0008](0008-koordinaty-i-proishozhdenie.md)). Реализация на WebGL,
   с прицелом на пространственный индекс и LOD при росте числа примитивов.
3. **Камера/viewport** — императивный контроллер трансформаций. События колеса и
   перетаскивания не проходят через состояние React: панели и элементы управления
   принадлежат React, высокочастотные преобразования — рендереру.

Тяжёлые библиотеки (`pdfjs-dist`, WebGL-слой) грузятся только на маршруте рабочей области
и не попадают в общий бандл.

Будущий слой измерений — отдельный тип слоя. Переиспользовать объекты `Region` для измерений
запрещено, см. [ADR-0008](0008-koordinaty-i-proishozhdenie.md).

## Последствия

- Просмотрщик сложнее «просто отрендерить компонентом», зато прокрутка и зум остаются
  плавными на реальных документах.
- Требуется явная отмена устаревших задач рендера при смене страницы или масштаба.
- Кэш отрисованных страниц ограничен по объёму — иначе браузер съест память на 77 страницах.

## Отвергнутые альтернативы

- **Готовый компонент-просмотрщик PDF.** Не даёт нужного контроля над кадрами, наложением
  и отменой рендера.
- **SVG/DOM для областей.** Тысячи узлов на лист — гарантированные лаги при панорамировании.
- **Тайловый сервер сразу.** Нет доказанной необходимости; это инфраструктура на будущее,
  которую нельзя обосновать данными сегодня.
