# Передача на Stage 2

Отчёт о состоянии портала на 2026-09-07. Пишется как вход для следующего пакета промтов:
что действительно работает и проверено, где расширять, и какие ловушки уже найдены —
чтобы не искать их заново.

Границы Stage 1 и запреты — в корневом `CLAUDE.md`. Архитектурные решения — в
[`docs/adr/`](../adr/), их одиннадцать, и ни одно не отменено.

---

## 1. Что работает и проверено на живом стенде

Сквозной сценарий прогнан 2026-09-07 на тестовой машине (Windows, Docker Desktop:
PostGIS 17 + MinIO) на эталонном архиве `01-03-00-01-12_ПД-00260560-АР.zip`, 47 МБ,
77 листов, 383 области (230 text / 90 image / 63 stamp).

| Шаг                                                | Результат                             |
| -------------------------------------------------- | ------------------------------------- |
| Создание проекта, загрузка ZIP                     | 0,62 с                                |
| Импорт пакета (фон, `legacy_import`)               | 1,49 с, `succeeded`, `sheet_count=77` |
| Открытие первого листа (HTML + API + PDF из MinIO) | ≈0,34 с                               |
| Отрисовка чертежа и слоя областей                  | подтверждена визуально                |
| `pnpm test:api` с эталоном                         | 246 passed                            |

Флаг `viewer` включён по итогам этого прогона. До него он стоял выключенным намеренно:
портал не должен объявлять готовым то, что ни разу не открывали на настоящем документе.

**Работают:** проекты (список, карточка, поиск, сортировка), загрузка файлов потоком,
импорт распознанного пакета, просмотрщик PDF с отладочным слоем областей, интеграция с
TenderHUB, установка как PWA, светлая и тёмная темы.

## 2. Дефекты, найденные только на живом документе

Каждый был невидим на моках и стоил отдельного разбора. Это лучший аргумент за то, чтобы
Stage 2 начинал с живого стенда, а не заканчивал им.

1. **Потоковое чтение из MinIO.** `async with response["Body"] as body` в aiobotocore
   возвращает не `StreamingBody`, а обёрнутый `aiohttp.ClientResponse`, у которого
   `read()` не принимает размер куска. Скачивание PDF падало целиком.
2. **Слой областей не совпадал с чертежом.** Размер листа брался из `width_px` пакета —
   это пиксели растра распознавалки (4,17 px/pt на A1, 3,16 на других листах того же
   документа), а pdf.js рисует в единицах документа. Слой оказывался в 4,17 раза крупнее.
   Плюс координаты поворачивались повторно: в пакете они уже относительно повёрнутой
   страницы. Разбор и доказательство — в [ADR-0008](../adr/0008-koordinaty-i-proishozhdenie.md).
3. **Зум колесом не работал.** Объект листа пересоздавался на каждый рендер родителя,
   эффект отрисовки видел новую зависимость и обрывал начатую задачу; рендер случался на
   каждый щелчок колеса — страница не дорисовывалась никогда.
4. **Порядок «последнего задания».** `server_default=func.now()` в PostgreSQL — время
   начала транзакции, поэтому два задания из одной транзакции получали одинаковый
   `created_at`, и `DISTINCT ON` выбирал произвольное.
5. **Повторный импорт оставлял пакет «в обработке»:** ранний выход не доводил ревизию до
   `READY`, хотя задание завершалось успешно.

## 3. Данные

Семь таблиц, две миграции (`0001_domain_stage1`, `0002_project_source`).

```text
Project ──< Document ──< DocumentRevision ──< Sheet ──< Region
   │                             └──< RecognitionArtifact
   └──< Job
```

- `Project` — `workspace_id` (граница арендатора, пока фиксированная), `source`
  (`manual` / `tenderhub`), `external_id`, `external_ref`.
- `DocumentRevision` неизменяема; повторная загрузка того же файла по SHA-256 возвращает
  прежнюю ревизию ([ADR-0003](../adr/0003-neizmenyaemye-revizii.md)).
- `Region` — свидетельство распознавания, **не** измерение и **не** объём. Три сущности
  разведены намеренно; переиспользовать `Region` под обмеры нельзя
  ([ADR-0008](../adr/0008-koordinaty-i-proishozhdenie.md)).
- Координаты — нормализованные от левого верхнего угла, `[x0,y0,x1,y1] ∈ [0,1]`,
  относительно **отрисованной** (повёрнутой) страницы.
- Бинарные файлы — только в объектном хранилище, в базе ключи и SHA-256
  ([ADR-0002](../adr/0002-hranenie-binarnyh-fajlov.md)).

## 4. Контракт API

OpenAPI — единственный источник; TypeScript-клиент генерируется, руками не правится
([ADR-0001](../adr/0001-granicy-monorepo.md)). Дрейф проверяется в CI.

```text
GET  /health/live                          процесс жив
GET  /health/ready                         база, схема миграций, хранилище
GET  /api/v1/meta                          версии и флаги возможностей
     /api/v1/projects                      список, создание, карточка, изменение
     /api/v1/projects/{id}/documents       документы проекта
     /api/v1/projects/{id}/uploads         приём файла потоком
     /api/v1/documents/{id}/revisions      ревизии
     /api/v1/revisions/{id}/sheets         листы
     /api/v1/revisions/{id}/content-url    временная ссылка на файл
     /api/v1/sheets/{id}/regions           области листа
     /api/v1/jobs/{id}                     состояние задания
     /api/v1/integrations/tenderhub/*      тендеры и создание проекта по тендеру
```

`/health/ready` отдельно различает недоступную базу и отставшую схему — устаревшая схема
после `git pull` иначе выглядит как отказ сервиса.

## 8. Что Stage 2 получает нерешённым

**Блокирует продуктив:**

- **Аутентификации нет.** `workspace_id` фиксирован, разграничения доступа нет. Выставлять
  наружу в таком виде нельзя. Колонка `workspace_id` заведена во всех запросах заранее,
  так что добавление арендаторов не потребует переписывать выборки.
- **Задания живут в процессе API.** Один пакет — 1,5 с; при нескольких одновременных
  займут рабочие потоки. Переход на воркер не меняет контракт.

**Требует решения владельца:**

- Формат пакета распознавалки v2 — сейчас разобран только `legacy-v1`.
- Нужна ли история ревизий чертежа в интерфейсе (`drawing.compare`).
- Что делать с двойным хранением PDF: он лежит и внутри архива, и отдельным документом.

**Мелкие долги** — в [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md), там же измеримые
компромиссы (uuid4 как тай-брейкер, часы приложения вместо БД, контраст рамок).

## 9. Правила, которые стоит перенести в следующий пакет

Они дали больше всего пользы и их легко потерять при смене контекста:

1. **Проверять на живом документе как можно раньше.** Все пять дефектов раздела 2
   невидимы на моках.
2. **Не показывать чужой расчёт как свой.** Из TenderHUB берутся только номер, название и
   заказчик; позиции и сметные строки не переносятся, пока портал не умеет считать сам.
3. **Флаг включается фактом готовности, а не намерением.**
4. **Отказ внешней системы — отдельный класс ошибок** со своим кодом и своим текстом:
   пользователю нужно понимать, чинить ключ, ждать или звать администратора.
5. **Диагностика важнее общего сообщения.** «Не удалось загрузить» после `git pull` стоило
   отдельного разбирательства; `/health/ready` теперь называет команду.
6. **Числа в отчётах — только измеренные.** Если не мерили, так и писать.
