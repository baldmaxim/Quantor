# Производительность, безопасность, наблюдаемость — отчёт этапа

Документ отвечает на один вопрос: почему портал не должен «тормозить и глючить» на
реальном документе и что с ним будет, если его попробовать сломать.

Всё, что ниже помечено как проверенное, проверено запуском, а не рассуждением. Что не
проверено — названо прямо.

## 1. Производительность

### Что измерялось

| Свойство                                     | Как проверено                                                                                  | Результат                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------- |
| pdf.js не попадает в бандл списка проектов   | сценарий Playwright скачивает все загруженные скрипты `/projects` и ищет в них признаки pdf.js | ни одного совпадения      |
| Число запросов не растёт вместе с проектами  | счётчик SQL на списке из 3 и из 15 проектов                                                    | одинаковое число запросов |
| Число запросов не растёт вместе с листами    | счётчик SQL на 40 листах                                                                       | не больше 4 запросов      |
| Бинарные файлы не проходят через процесс API | ответ `content-url` не является файлом                                                         | отдаётся ссылка           |
| Предел выборки нельзя обойти                 | `limit=10000` на областях                                                                      | 422                       |

Счётчик запросов — не украшение: глазами разница между одним запросом и тридцатью не
видна, пока проектов мало, а на тридцати проектах список уже заметно тормозит.

### Что сделано, чтобы не тормозило

**Фронтенд.**

- pdf.js и слой областей загружаются динамически и только на маршруте рабочей области;
- страница и слой областей — два разных холста: подсветка прямоугольника не перерисовывает
  пятидесятимегабайтную страницу;
- панорамирование и зум не проходят через состояние React: камера двигает холсты стилями,
  а уведомления подписчиков объединяются в кадр (50 движений мыши → одно обновление);
- ширина панелей во время перетаскивания идёт в CSS-переменную мимо состояния;
- открытыми держатся не более двенадцати страниц PDF, выселяются самые далёкие от текущей;
- устаревшая отрисовка отменяется при смене листа и масштаба;
- перерисовка по зуму отложена на 180 мс — щелчки колеса не ставят задачу на каждый шаг;
- список листов не рисует миниатюры всех 77 страниц;
- ключи запросов TanStack Query собраны в одном месте, поэтому одни и те же данные
  не запрашиваются дважды;
- ручной мемоизации нет: её делает компилятор React, а `useCallback` с зависимостью-ссылкой
  он отказывается оптимизировать.

**Бэкенд.**

- приём файла потоковый, память не зависит от размера: содержимое переливается кусками
  по 1 МБ через временный файл;
- архив читается по оглавлению и кусками, `extractall` не используется;
- счётчики документов, листов и последнее задание берутся подзапросами и `DISTINCT ON`;
- у всех списков обязательная пагинация с верхним пределом 500;
- индексы заведены под фактические выборки: `(workspace_id, updated_at)`,
  `(project_id, created_at)`, `(revision_id, page_index)`, `(sheet_id, block_type)`;
- на запрос к базе стоит предел времени — зависший запрос иначе держит соединение
  и рабочий поток бесконечно;
- у обращений к хранилищу ограничены попытки (3) и таймауты (5 с на соединение, 60 с
  на чтение);
- бинарные файлы отдаются временной ссылкой прямо из хранилища.

## 2. Безопасность

### Модель угроз и что им противопоставлено

| Угроза                          | Мера                                                                                   | Проверено тестом |
| ------------------------------- | -------------------------------------------------------------------------------------- | ---------------- |
| Выход за каталог при распаковке | отвергаются `..`, абсолютные пути, пути с буквой диска                                 | да, 5 вариантов  |
| Символические ссылки в архиве   | пропускаются только обычные файлы                                                      | да               |
| Бомба сжатия                    | пределы степени сжатия, суммарного и поштучного размера                                | да               |
| Слишком много файлов в архиве   | предел числа записей                                                                   | да               |
| Посторонние типы внутри архива  | белый список расширений                                                                | да               |
| Ложный размер в оглавлении      | чтение с жёстким пределом, а не по заявленному                                         | да               |
| Подмена типа переименованием    | сигнатура содержимого важнее расширения                                                | да               |

| Доступ к чужому проекту         | каждый запрос ограничен рабочим пространством                                          | да, 4 маршрута   |
| Утечка в сообщении об ошибке    | наружу только код и короткий текст                                                     | да               |
| Секреты в логах                 | пароли и ключи в `SecretStr`                                                           | —                |
| Обход пагинации                 | верхний предел на `limit`                                                              | да               |

### Ограничения, о которых нужно знать

**Аутентификации нет.** Работает временный dev-контекст рабочего пространства: все запросы
идут от фиксированного `workspace_id`. Портал в таком виде нельзя выставлять за пределы
доверенной сети — любой, кто дотянется до API, увидит все проекты. Колонка `workspace_id`
заведена в схеме именно для того, чтобы добавление арендаторов не потребовало переписывать
таблицы и запросы.

**CORS** ограничен списком источников из окружения; звёздочка не используется. При
подключении настоящей аутентификации к этому добавится защита от CSRF — сейчас её
отсутствие не создаёт риска, потому что нет ни сессий, ни куки.

**Ссылки на файлы** временные, время жизни настраивается и ограничено сверху сутками.
Тот, кто получил ссылку, может скачивать файл до её истечения — это свойство подписанных
ссылок, а не упущение.

**Зависимости.** Тест падает, если в проект попадёт SDK модели, библиотека компьютерного
зрения, Celery или Temporal. Регулярной проверки уязвимостей в зависимостях пока нет —
это работа этапа развёртывания.

## 3. Наблюдаемость

- сквозной `X-Request-ID`: принимается от клиента или генерируется, возвращается в ответе
  и попадает в каждую запись журнала;
- журнал структурный, в не-локальных окружениях — JSON;
- у импорта в журнале есть идентификатор задания, число листов и областей, признак
  повторного запуска и код отказа;
- причина отказа проверки готовности пишется в журнал, но не уходит в ответ;
- `/health/live` не трогает зависимости, `/health/ready` проверяет базу и хранилище
  с ограничением по времени и отвечает 503 при недоступности;
- на фронтенде есть границы ошибок маршрута и корневого макета, а вывод ошибок клиента
  собран в одну функцию — это и есть точка подключения внешнего сборщика, когда он
  понадобится.

Трассировки (OpenTelemetry) нет намеренно: без нескольких сервисов она даёт стек
сопровождения без отдачи. Граница описана в ADR-0010.

## 4. Коды ошибок

Стабильные коды — часть контракта, интерфейс опирается на них, а не на текст:

```text
NOT_FOUND · VALIDATION_FAILED
UNSUPPORTED_FILE_TYPE · MIME_MISMATCH · UPLOAD_TOO_LARGE · EMPTY_FILE · CORRUPT_ARCHIVE
ARCHIVE_UNSAFE_PATH · ARCHIVE_LIMIT_EXCEEDED
LEGACY_PDF_MISSING · LEGACY_BLOCKS_INVALID · LEGACY_SCHEMA_UNSUPPORTED · IMPORT_FAILED
STORAGE_UNAVAILABLE · DATABASE_UNAVAILABLE · CONTENT_NOT_AVAILABLE
JOB_TRANSITION_INVALID
PDF_LOAD_FAILED · PDF_RENDER_FAILED · PDF_URL_EXPIRED
```

Каждому соответствует формулировка на русском; тест проверяет, что перевод есть у всех
и что в нём нет технических подробностей.

## 5. Что отложено к развёртыванию

- аутентификация и разграничение доступа;
- ограничение частоты запросов;
- проверка зависимостей на уязвимости в CI;
- политика хранения загруженных архивов;
- вынос импорта в отдельный воркер (пороги — в [ADR-0010](../adr/0010-orkestrator-buduschego-konvejera.md));
- измерения на реальном пакете с записью чисел в этот документ.
