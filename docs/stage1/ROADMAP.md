## Переработка дизайна UX/UI-агентом

Вставляется между промтами 03 и 04: домен к тому моменту готов и известно, какими данными
реально оперирует интерфейс, а код оболочки ещё не написан — переделывать нечего.

### Вход

- `design-reference.html` — текущий образец: список проектов, карточка проекта, рабочая область,
  токены и правила;
- `_prompts/stage1/reference/ROUTES_AND_UI.md` — обязательный состав экранов;
- `_prompts/stage1/reference/KREO_WORKFLOW_NOTES_2026-09.md` — рабочие сценарии как ориентир;
- фактические поля API из промта 03: что интерфейс может показать на самом деле.

### Задача агента

Отдельный агент с ролью UX/UI-дизайнера перерабатывает образец, а не пишет код приложения.
От него нужно:

1. **Ревизия информационной архитектуры.** Проверить, что путь «проект → документ → лист →
   область» проходится без лишних шагов, и предложить исправления, если нет.
2. **Визуальный язык.** Уточнить палитру, типографику, ритм отступов, состояния (обычное,
   наведение, фокус, выбрано, выключено, загрузка, ошибка, пусто). Результат — набор токенов,
   пригодный к переносу в `globals.css` один в один.
3. **Плотность и иерархия.** Инженерный инструмент, а не лендинг: проверить размеры строк,
   панелей, шрифтов на 1440 и 1920 px, найти лишний воздух и недостающие разделители.
4. **Рабочая область.** Проработать три панели, панель инструментов, статусную строку и
   поведение выделенной области. Это самый нагруженный экран — ему больше всего внимания.
5. **Доступность.** Контраст ≥ 4.5:1 в обеих темах, видимый фокус, тап-цели ≥ 44 px там, где
   интерфейс используется с сенсорного экрана, работа с клавиатуры.
6. **Узкий экран.** Список проектов остаётся пригодным, рабочая область показывает внятное
   сообщение вместо сломанной вёрстки.

### Ограничения

- Бренд, оформление и тексты Kreo не копировать — только принципы работы.
- Не рисовать функциональность, запрещённую на Stage 1: обмеры, расчёт объёмов, вызовы моделей,
  отчёты. Выключенное должно выглядеть выключенным и подписанным этапом.
- Не выдумывать данные, которых нет в API: показатели, проценты, деньги.
- Цвета только токенами; хардкод недопустим, иначе тёмная тема разъедется.

### Выход

- обновлённый `design-reference.html` (или несколько файлов-макетов рядом с ним);
- перечень изменений с обоснованием;
- итоговый набор токенов и размеров, готовый к переносу в код.

Результат утверждается владельцем, и только после этого промт 04 реализует его в React.

## Что нельзя делать ни на одном шаге

Границы этапа перечислены в [CLAUDE.md](../../CLAUDE.md): никакого распознавания элементов,
Auto Measure/Count, расчёта объёмов, определения масштаба, инференса моделей, разбора BIM,
сметного движка и агентного runtime.
