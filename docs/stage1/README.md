## Промт 03 — домен, хранилище и API

### Модель данных

Семь таблиц в миграции `0001_domain_stage1`: `projects`, `documents`, `document_revisions`,
`sheets`, `recognition_artifacts`, `regions`, `jobs`.

Что в них заложено:

- ревизия документа неизменяема; меняется только состояние обработки ([ADR-0003](../adr/0003-neizmenyaemye-revizii.md));
- повторная загрузка того же файла в тот же документ запрещена уникальным индексом
  по `(document_id, source_sha256)`;
- координаты областей хранятся нормализованными от левого верхнего угла ([ADR-0008](../adr/0008-koordinaty-i-proishozhdenie.md));
- `Region` отделён от будущих `Measurement` и `Quantity` — это разные сущности;
- перечисления лежат в базе как значения (`active`, не `ACTIVE`) с CHECK-ограничением;
- бинарных данных в базе нет: только ключи объектов и контрольные суммы.

### Хранилище

Протокол `ObjectStorage` и реализация поверх S3: потоковая загрузка со счётом SHA-256 на лету,
чтение кусками, `stat`, удаление и presigned-ссылки. Файл при приёме переливается через
временный файл, поэтому память не зависит от размера документа.

Ключи объектов строятся из UUID; пользовательское имя файла хранится отдельным полем
и метаданными объекта, кириллица сохраняется.

### API v1

```text
GET    /api/v1/projects                        список, поиск, сортировка, пагинация
POST   /api/v1/projects
GET    /api/v1/projects/{id}                   со счётчиками документов и листов
PATCH  /api/v1/projects/{id}
GET    /api/v1/projects/{id}/documents
GET    /api/v1/projects/{id}/jobs
GET    /api/v1/documents/{id}
GET    /api/v1/documents/{id}/revisions
GET    /api/v1/revisions/{id}
GET    /api/v1/revisions/{id}/artifacts
GET    /api/v1/revisions/{id}/sheets
GET    /api/v1/revisions/{id}/content-url      временная ссылка прямо в хранилище
GET    /api/v1/sheets/{id}/regions             фильтры по типу и статусу
GET    /api/v1/jobs/{id}
```

Все списки с пагинацией. Каждый запрос ограничен рабочим пространством: обратиться к чужому
документу по прямому идентификатору нельзя — ответ 404.

### Задания

Переходы состояний живут в одном месте и проверяют инварианты: из завершённого состояния
выхода нет, прогресс принимается только у выполняющегося задания, повтор с тем же ключом
идемпотентности возвращает существующее задание, а не создаёт второе.

### Отказы

Стабильные коды вместо безликого 500: `DATABASE_UNAVAILABLE`, `STORAGE_UNAVAILABLE`,
`CONTENT_NOT_AVAILABLE`, `NOT_FOUND`, `JOB_TRANSITION_INVALID`. Строка подключения, трассировка
и креды в ответ не попадают — это проверяется тестом.

### Аутентификация

Её нет. Работает временный dev-контекст рабочего пространства: фиксированный `workspace_id`
в каждом запросе. Портал в таком виде наружу выставлять нельзя, но добавление арендаторов
позже не потребует переписывать таблицы и запросы.

## Промт 05 — приём файлов (серверная часть)

Интерфейс загрузки ждёт переработки дизайна и промта 04, поэтому пока сделана серверная
половина: она самодостаточна и проверяется тестами.

```text
POST /api/v1/projects/{id}/uploads               приём файла
GET  /api/v1/projects/{id}/upload-capabilities   что портал делает с каждым типом
```

Что заложено:

| Правило                                | Как сделано                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| Память не зависит от размера файла     | тело читается кусками по 1 МБ и сразу уходит в хранилище                              |
| Тип решает содержимое, а не расширение | сигнатуры PDF и ZIP проверяются по первым байтам                                      |
| Предел размера                         | считаются фактические байты, поток обрывается при превышении                          |
| Повтор не плодит копии                 | сравнение по SHA-256 в пределах проекта, лишний объект удаляется                      |
| Повтор не запускает второй импорт      | ключ идемпотентности задания из хэша пакета                                           |
| Кириллица в именах                     | имя сохраняется как есть, в ключ объекта не попадает                                  |
| Честные статусы                        | ZIP → задание импорта; PDF → `unprocessed`; RVT/NWD/NWC/IFC → `processor_unavailable` |

Ошибки отдаются кодами: `UNSUPPORTED_FILE_TYPE` (415), `MIME_MISMATCH` (415),
`UPLOAD_TOO_LARGE` (413), `EMPTY_FILE` (400), `CORRUPT_ARCHIVE` (400).

Распознавания здесь нет: ZIP-пакет только ставится в очередь. Сам импорт — промт 06.

## Промт 06 — импорт распознанного пакета

Единственная часть портала, которая понимает текущий формат распознавалки. Она ничего
не распознаёт заново: её задача — открыть уже распознанный проект.

### Что получается после импорта

```text
Document(recognized_package)      загруженный архив, неизменяемый источник
  └── DocumentRevision → ZIP
Document(pdf)                     то, что откроет просмотрщик
  └── DocumentRevision → PDF, извлечённый из архива
        ├── Sheet × числу страниц
        ├── Region × числу областей
        └── RecognitionArtifact: blocks.json, results.md, results.html
```

### Безопасность архива

Архив недоверенный, поэтому `extractall` не используется вовсе. Проверки идут по оглавлению,
до чтения хоть одного байта:

| Угроза                            | Что сделано                                                |
| --------------------------------- | ---------------------------------------------------------- |
| Выход за пределы каталога         | отвергаются `..`, абсолютные пути и пути с буквой диска    |
| Символические ссылки и устройства | пропускаются только обычные файлы                          |
| Бомба сжатия                      | предел степени сжатия, суммарного и поштучного размера     |
| Слишком много файлов              | предел числа записей                                       |
| Посторонние типы                  | белый список: pdf, json, md, html, txt                     |
| Ложный размер в оглавлении        | чтение с жёстким ограничением, а не по заявленному размеру |
| SSRF через `crop_url`             | сервер не обращается к внешним адресам никогда             |
| Активный HTML                     | `results.html` хранится как данные, а не как разметка      |
| Кириллица в именах                | UTF-8, с запасным вариантом cp866 для старых архиваторов   |

### Проверка пакета

Явные коды вместо неопределённой ошибки: `LEGACY_PDF_MISSING`, `LEGACY_BLOCKS_INVALID`,
`LEGACY_SCHEMA_UNSUPPORTED`, `ARCHIVE_UNSAFE_PATH`, `ARCHIVE_LIMIT_EXCEEDED`, `CORRUPT_ARCHIVE`.

Проверяются версия схемы, пространство координат, диапазон нормализованных координат,
корректность полигонов, повторы `block_id` и ссылки на несуществующие страницы.

`results.md` разбирается терпимо: нужен только указатель `block_id → сырой текст секции`.
Семантику Summary/Description на этом этапе не трогаем — формат ещё изменится. Файл без
заголовков не ломает импорт, а даёт пустой указатель.

### Исполнение и идемпотентность

Задание выполняется фоновой задачей внутри процесса API — очередь и воркеры появятся вместе
со второй реальной нагрузкой (ADR-0005). Состояние живёт в базе и переживает перезапуск.

Идентификаторы производных объектов детерминированно выводятся из идентификатора ревизии
пакета, поэтому повторный импорт не создаёт вторую копию, а сразу сообщает, что всё уже
импортировано. При сбое транзакция откатывается: наполовину видимого проекта не остаётся,
задание получает безопасный код, ревизия — статус `failed`.

### Тесты

Безопасность архива и разбор схемы проверяются без базы: попытки выхода за каталог, бомба
сжатия, ссылка, посторонний тип файла, ложный размер, битый JSON, чужая версия схемы,
полигон без точек, повтор `block_id`.

Сквозной импорт требует PostgreSQL. Отдельный набор работает на эталонном архиве
(77 страниц, 383 области, 230/90/63, 320 секций Markdown) — он запускается только там,
где архив лежит в `_prompts/stage1/fixtures/legacy/`, и пропускается в остальных случаях.

## Промт 08 — контракты будущих сервисов

Задача шага — сделать так, чтобы Stage 2 подключался к готовым границам. Реализаций нет:
это типы, правила и точки расширения. Подробно — [docs/architecture/future-boundaries.md](../architecture/future-boundaries.md).

Что появилось:

- `app/contracts/models.py` — шлюз моделей: паспорт возможностей, требование модуля и выбор
  по возможностям, а не по имени поставщика. Ни одного SDK, ни одного вызова;
- `app/contracts/pipeline.py` — форма будущего конвейера из десяти шагов с требованиями
  к каждому: идемпотентность, повторяемость, отменяемость, возобновляемость, происхождение;
- `app/contracts/quantities.py` — типы `Measurement`, `QuantityItem`, `ScaleCalibration`,
  `VerificationIssue`. Таблиц для них нет намеренно;
- [ADR-0010](../adr/0010-orkestrator-buduschego-konvejera.md) — когда переходить с фоновой
  задачи на очередь и когда на durable-платформу;
- настраиваемые флаги возможностей: `/api/v1/meta` отдаёт их интерфейсу, переопределение —
  переменной `FEATURE_FLAGS`.

Границы этапа стали проверяемым свойством: тест падает, если в зависимости попадёт SDK
модели, библиотека компьютерного зрения, Celery или Temporal, если появится второй реальный
тип задания или если у `Region` заведутся поля величины.
