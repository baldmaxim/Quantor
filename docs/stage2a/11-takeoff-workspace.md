# Промт 11 — рабочая область обмера

Дата: 2026-09-09.

## 1. Что собралось

```text
┌──────────────────┬────────────────────────────────┬────────────────────┐
│ Обмеры           │  PDF · области · масштаб ·     │ Свойства измерения │
│  Двери      3 шт │  измерения                     │ строка, тип        │
│  Стены      2 м  │                                │ величина, масштаб  │
│  + Новая строка  │                                │ лист, версия       │
└──────────────────┴────────────────────────────────┴────────────────────┘
Выбор · Панорама · Масштаб · Счёт · Линия · Ломаная · Площадь
```

| Часть             | Где                                             |
| ----------------- | ----------------------------------------------- |
| Список строк      | `components/workspace/TakeoffPanel.tsx`         |
| Инспектор         | `components/workspace/MeasurementInspector.tsx` |
| Запросы и мутации | `lib/queries.ts`                                |
| Сборка            | `workspace/page.tsx`                            |

Вкладка «Обмеры» включена: заглушка «Обмеры появятся на этапе 2» убрана.

## 2. Решения

**Строки называет пользователь.** Строительные категории портал не придумывает: «Двери»,
«Перегородка ПГ-1» — это его язык, а не наш классификатор (ADR-0019).

**Единица не выбирается.** При создании строки видно, что даёт каждый тип — «Количество
шт», «Линия м», «Площадь м²», — но выбрать «площадь в метрах» нельзя: единица следует
из типа.

**Инструмент включается только под свою строку.** Кнопка «Площадь» недоступна, пока
активна строка «Двери»: рисовать площадь там нечем, там считают штуки. Смена строки
сбрасывает инструмент в «Выбор» — тип новой строки может не совпасть.

**Архивация вместо удаления** и в интерфейсе: у строки кнопка «в архив», а не «удалить».

**Величина показана прочерком.** Правило подсчёта с версией появляется в промте 12, и до
него в инспекторе честный `—`, а не выдуманное число: «примерно столько» в смете хуже,
чем «пока неизвестно».

**«Масштаб не задан» — это отдельное состояние**, а не ноль. У счёта вместо него «не
требуется»: штуки не зависят от размера страницы.

## 3. Архитектура состояния

| Что                                          | Где живёт                          |
| -------------------------------------------- | ---------------------------------- |
| камера, черновик масштаба, черновик обмера   | императивные контроллеры вне React |
| серверные данные                             | TanStack Query                     |
| активная строка, выбранное измерение, ошибка | состояние React                    |

В React попадают только события, которых единицы за сеанс: выбор строки, выбор измерения,
смена инструмента. Поток координат туда не доходит — этим занимаются контроллеры с
подпиской и склейкой в кадр (ADR-0004).

Сохранение идёт по завершению фигуры и по отпусканию вершины, а не по движению указателя.

## 4. Ошибки показываются по причине

| Код                            | Что видит пользователь                                              |
| ------------------------------ | ------------------------------------------------------------------- |
| `MEASUREMENT_VERSION_CONFLICT` | «Измерение изменил кто-то другой. Обновите лист и повторите правку» |
| `VALIDATION_FAILED`            | «Геометрия не подходит выбранной строке обмера»                     |
| `PERMISSION_DENIED`            | «Недостаточно прав для обмера»                                      |

Сообщение выводится в строке состояния. Линтер, кстати, и поймал момент, когда ошибка
вычислялась, но никуда не показывалась.

## 5. Что сломалось справедливо

Два e2e требовали, чтобы вкладка «Обмеры» была **выключена** и подписана «Этап 2». Это
было верно до Stage 2A и перестало быть верным сейчас.

Тест переписан осознанно, а не подогнан: теперь он проверяет, что вкладка включена,
открывается и показывает пустой список. Ломаться он будет снова, если обмер выключат.

Поломка была предсказана в [аудите промта 00](00-preflight-audit.md) — приятно, что список
ловушек оказался полным.

## 6. Узкий экран

Рабочая область по-прежнему не рендерится ниже 1024 px и честно пишет «Нужен экран шире».
Полноценный CAD-редактор на 360 px делать не пробовали: это не тот случай, где мобильная
версия лучше отсутствия.

Существующий PWA-каркас не тронут.

состояний и слой. Здесь собрана сборка из проверенных частей, и её проверяет Playwright.

### Чего здесь не проверено

Скриншотов нет. Сквозной сценарий на живых данных — создать строку, поставить метки,
перезагрузить, отредактировать вершину — относится к промту 15, где есть настоящий PDF
и поднятый стенд.

## 8. Остаток

- выбор действующей калибровки из нескольких и подтверждение проверяющим — API готово,
  кнопок нет;
- флаг `takeoff.manual` остаётся выключенным.
