Дата: 2026-09-09. Архитектурное решение — [ADR-0016](../adr/0016-kanonicheskaya-geometriya-stranicy-pdf.md).

Парсера нет. `JobType.PDF_GEOMETRY_EXTRACT`, обработчик и эндпоинт чтения — промт 03.

### Почему статус проставляется уже сейчас

Миграция переводит существующие ревизии PDF в `pending`. Если бы новые загрузки при этом
получали умолчание `not_applicable`, backfill обесценился бы в тот же день. Поэтому
начальное состояние проставляется там, где ревизия рождается, — это часть схемы, а не
поведения задания.

`not_applicable` означает «извлекать нечего» (ZIP-пакет, BIM), `pending` — «применимо, не
сделано». Разница не косметическая: первое не должно попадать ни в какие очереди и отчёты
об отказах.

## 2. Контракт API

### Чтение геометрии листа

```text
GET /api/v1/sheets/{sheet_id}/geometry     →  200 PageGeometryRead
                                              404 NOT_FOUND
                                              409 GEOMETRY_NOT_READY
```

Отдельный ресурс, а не поле в `SheetRead`. Причины:

- `SheetRead` возвращается списком на 77 листов; геометрия нужна открытому листу, и
  раздувать список ради одного из них — это N+1 наоборот;
- у геометрии своё состояние и своя причина отсутствия. Поле `geometry: null` в листе не
  различает «не извлекали», «в работе» и «не удалось», а различать надо: интерфейс обязан
  показать разное.

Авторизация — существующей цепочкой `Sheet → DocumentRevision → Document → Project.workspace_id`,
по образцу `documents_service.get_sheet`. Чужой лист — **404**, не 403: 403 подтвердил бы, что
такой лист существует.

```jsonc
// PageGeometryRead
{
  "sheet_id": "…",
  "coordinate_space": "pdf_display_points_top_left",
  "display_width_pt": "2383.9370", // строка: точное десятичное, без потерь в JSON
  "display_height_pt": "1683.7795",
  "pdf_rotation": 90,
  "media_box": [0, 0, 1683.7795, 2383.937],
  "crop_box": [0, 0, 1683.7795, 2383.937],
  "parser_name": "pypdf",
  "parser_version": "6.1.3",
  "source_sha256": "…",
  "geometry_fingerprint": "…",
  "extracted_at": "2026-09-09T…Z",
}
```

Десятичные передаются **строками**. `JSON.parse` в браузере превращает число в `float64`, и
канонический вид, на котором построен отпечаток, теряется. Строка сохраняет ровно то, что
лежит в базе.

### Состояние извлечения

`geometry_status` и `geometry_error_code` добавляются в существующий `RevisionRead`. Это
аддитивное расширение: удалённых полей нет, старый клиент их игнорирует.

Так интерфейс получает ответ на «почему у листа нет геометрии» одним запросом, который он и
так делает при открытии документа, — без обращения к журналу заданий.

### Что НЕ появляется

- эндпоинта запуска извлечения по кнопке. Задание ставится сервером при появлении ревизии
  PDF; ручной перезапуск — существующая операция «повторить задание» в админке;
- геометрии в `SheetRead` — см. выше;
- записи геометрии клиентом. Единственный источник — задание.

## 3. Задание `pdf_geometry_extract`

Новый `JobType` в существующем реестре (`app/domain.py::JobType` + `app/worker/registry.py`).
Второго механизма очередей не заводится: захват, аренда, пульс и повторы уже работают.

### Область видимости

Задание проектное: `workspace_id` = пространство проекта, `project_id` = проект ревизии.
Общесистемным оно быть не может — у него всегда есть владелец (промт 01).

### Поток

```text
DocumentRevision(PDF)
  → потоковая выгрузка в ограниченный временный файл
  → провайдер геометрии читает страницы
  → проверка: число страниц, положительные размеры, допустимый поворот
  → одна транзакция:
        листы созданы или найдены (uuid5 от {revision_id}:sheet:{page_index})
        геометрия записана для всех страниц
        revision.geometry_status = ready
  → succeeded
```

Временный файл удаляется даже при исключении — по образцу импортёра
(`tempfile.TemporaryDirectory` + `_download` через `storage.iter_stream`). PDF в память
целиком не читается: 500 МБ там делать нечего.

### Идемпотентность

Ключ идемпотентности: `pdf_geometry:{revision_id}:{parser_name}:{parser_version}`.

Повторный запуск с тем же парсером не создаёт второе задание. Смена версии парсера —
**новое** задание: геометрия могла измениться, и это должно быть видно, а не скрыто
идемпотентностью. Существующие строки при этом заменяются, а не дублируются — на это стоит
`uq_page_geometries_sheet_id`.

### Два сценария, одна операция

| Сценарий             | Что происходит                                   |
| -------------------- | ------------------------------------------------ |
| Прямая загрузка PDF  | Листов нет — задание создаёт их из страниц PDF   |
| Импорт legacy-пакета | Импортёр уже создал листы — задание их обогащает |

Идентификаторы листов детерминированы одной формулой в обоих случаях, поэтому это upsert, а
не две ветки. Импорт при этом не удлиняется: он ставит задание и завершается, а разбор PDF
идёт отдельно — полторы секунды импорта не должны превращаться в минуту.

### Согласованность с legacy-листами

- `page_index` обязан совпасть;
- число страниц PDF обязано совпасть с числом листов;
- `Sheet.rotation` из пакета сохраняется нетронутым как метаданные источника и **не**
  применяется к нормализованным координатам второй раз;
- `width_px` / `height_px` не трогаются;
- расхождение → отказ задания целиком, без частичного `ready`.

## 4. Коды ошибок

Добавляются в `app/errors.py` вместе с обработчиком (промт 03).

| Код                         | Когда                                             | HTTP | Повторяемо |
| --------------------------- | ------------------------------------------------- | ---- | ---------- |
| `GEOMETRY_NOT_READY`        | геометрия запрошена, но `geometry_status ≠ ready` | 409  | —          |
| `PDF_UNREADABLE`            | файл не открывается как PDF                       | 400  | нет        |
| `PDF_ENCRYPTED`             | PDF защищён паролем                               | 400  | нет        |
| `PDF_PAGE_COUNT_MISMATCH`   | страниц в PDF ≠ листов у ревизии                  | 409  | нет        |
| `PDF_PAGE_GEOMETRY_INVALID` | неположительный размер или недопустимый поворот   | 422  | нет        |
| `GEOMETRY_EXTRACT_FAILED`   | прочий отказ извлечения                           | 500  | нет        |

Повторяемыми (`RETRYABLE_ERROR_CODES`) ни один из них не становится: все они про содержимое
файла, а битый файл повтором не чинится. Повторяемыми остаются прежние
`STORAGE_UNAVAILABLE`, `DATABASE_UNAVAILABLE`, `JOB_LEASE_LOST`, `JOB_TIMEOUT` — они про
обстоятельства.

Содержимое PDF в сообщения об ошибках и в журнал не попадает: там чужая проектная
документация.

## 5. Провайдер геометрии

Узкий интерфейс — «дай страницы с отображаемым размером, поворотом и рамками»:

```python
class PageGeometryProvider(Protocol):
    name: str
    version: str
    def read(self, path: Path) -> list[RawPageGeometry]: ...
```

Реализация Stage 2A — **pypdf**, версия закрепляется точно в `pyproject.toml`, как и все
остальные зависимости ([ADR-0009](../adr/0009-python-i-lokalnyj-tuling.md)).

### Оценка вариантов

| Библиотека | Лицензия           | Даёт                                           | Вердикт         |
| ---------- | ------------------ | ---------------------------------------------- | --------------- |
| **pypdf**  | BSD-3              | MediaBox, CropBox, `/Rotate`, размеры страницы | **выбрана**     |
| pypdfium2  | Apache-2.0 / BSD-3 | то же плюс растр и текст                       | не нужна сейчас |
| PyMuPDF    | AGPL-3.0           | `page.rect` напрямую                           | отклонена       |

PyMuPDF отклонена не по технике: §13 AGPL обязывала бы предлагать исходный код
пользователям портала, который отдаётся по сети, либо покупать лицензию у Artifex. Ради
чтения четырёх чисел это несоразмерно.

pypdfium2 не добавляется, пока не понадобится серверный растр или извлечение вектора. Когда
понадобится — меняется реализация провайдера, а не всё, что на неё опирается. Именно для
этого `parser_name` и `parser_version` лежат в каждой строке.

### Отображаемый размер считает провайдер

pypdf не отдаёт «отображаемый прямоугольник» готовым, поэтому он выводится:

```text
box     = crop_box ∩ media_box        # CropBox может выходить за MediaBox — обрезаем
w, h    = box.width, box.height
если rotation ∈ (90, 270): поменять w и h местами
```

Это ровно то, что делает `pdf.js` в `getViewport({ scale: 1 })`, и именно поэтому результат
обязан совпасть с браузером. Совпадение проверяется тестом на эталоне, а не принимается на
веру: расхождение здесь означает, что разметка ляжет мимо чертежа.

## 6. Отпечаток геометрии

```text
geometry_fingerprint = sha256(
    "pdf_display_points_top_left|{w}|{h}|{rotation}|{media_box}|{crop_box}"
    "|{parser_name}|{parser_version}"
)
```

Числа — канонические десятичные строки с четырьмя знаками; рамки — списки таких же строк.
Отсюда и `Numeric(12, 4)` в схеме: у десятичного значения одна каноническая запись во всех
трёх средах, у двоичной дроби она зависит от форматирования.

Отпечаток отвечает на вопрос «та ли это геометрия, по которой посчитана величина» одним
сравнением. Величина, посчитанная по другой геометрии, обязана это показывать.

## 8. Найдено попутно: перечисления не защищены базой

Проверка миграции офлайн-рендером (`alembic upgrade … --sql`) показала расхождение между
кодом и его же документацией.

`app/models/mixins.py::str_enum` объявлен как «перечисление как VARCHAR **с CHECK**». CHECK он
не создаёт: у SQLAlchemy начиная с 1.4 параметр `create_constraint` по умолчанию выключен.
Проверено на метаданных — у `document_revisions` есть ровно два CHECK, и оба про SHA-256 и
размер, а не про статусы.

Следствия:

- состав значений `processing_status`, `geometry_status`, `document_kind` и прочих проверяет
  приложение, а не база. Запись мимо API может положить туда что угодно;
- расхождения между схемой и моделью **нет**: ни `create_all`, ни миграция CHECK не создают,
  поэтому `test_schema_matches_migrations` проходит. Это и подтвердилось.

На Stage 2A ничего не меняется: включение `create_constraint=True` затронуло бы все
перечисления проекта и потребовало бы отдельной миграции по каждому. Но докстрока хелпера
обещает то, чего нет, и это стоит либо исправить, либо выполнить — отдельным решением.

Проектным инвариантам Stage 2A это не угрожает: область видимости задания и размеры страницы
держат настоящие CHECK и внешние ключи, а не перечисления.
