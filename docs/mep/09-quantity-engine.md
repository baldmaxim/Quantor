# MEP: Quantity Engine — `MepNetworkGraph` → `MepBoq` (синтетика)

v3 PROMPT 09, 2026-09-15. Только синтетические графы v0.3: реального комплекта П нет, PROMPT 02–04 не
начинались. Цель — показать, что валидный граф детерминированно превращается в физические количества
без vision, LLM и цены.

## 2. Правила

| Правило                   | Что считает                                                               | Ед. |
| ------------------------- | ------------------------------------------------------------------------- | --- |
| `mep.segment_length.v0`   | участки класса `quantity=length`, группа по `quantity_group_keys` профиля | м   |
| `mep.node_count.v0`       | узлы класса `quantity=count`, та же группировка                           | шт  |
| `mep.path_turns.v0`       | промежуточные вершины посчитанных участков со сменой направления (план+z) | шт  |
| `mep.branch_nodes.v0`     | узлы, к которым подключено ≥ 3 участков, группа по степени                | шт  |
| `mep.parameter_change.v0` | узлы, где подключённые участки различаются значением ключа группы         | шт  |

- Длина: план — нормализованные → pt по снимку калибровки → мм; высота — `z_mm` или отметка уровня;
  наклонный участок — `hypot(план, подъём)`. Сумма копится без округления, округление до 0,001 — последним.
- Какие классы идут в ВОР и какими параметрами группируются — решает профиль (`ClassDef.quantity`,
  `quantity_group_keys`). Ядро не знает ни труб, ни приборов.
- Топологические строки — геометрические факты. Сопоставление с фасонными изделиями не делается:
  правил нет (Р-MEP-7) → предупреждение `FITTING_RULES_NOT_APPROVED`. Строк ESTIMATE нет.

## 3. Что не выводится, а блокируется

| Код                        | Когда                                                        | Последствие                |
| -------------------------- | ------------------------------------------------------------ | -------------------------- |
| `NETWORK_INVALID`          | граф не прошёл `validate_network_graph` (в т.ч. хеш профиля) | `refused`, строк нет       |
| `PARAMETER_UNRESOLVED`     | параметр группы есть, но `unresolved`                        | элемент не входит в строки |
| `PARAMETER_MISSING`        | параметра группы нет                                         | то же                      |
| `DECISION_BLOCKS_QUANTITY` | элемент в `UnresolvedDecision(blocks_quantity=true)`         | то же                      |
| `CLASS_UNRESOLVED`         | `class_key = null`                                           | то же                      |
| `NO_SCALE`                 | нет снимка калибровки листа                                  | длины нет, счёт остаётся   |
| `CROSS_SHEET_PLANAR`       | плановое звено между разными листами                         | длины нет                  |
| `ELEVATION_INCOMPLETE`     | отметка известна только у одного конца                       | длины нет                  |
| `LENGTH_UNDETERMINED`      | звено без плана и без разницы отметок, смешанное план/высота | длины нет                  |
| `NODE_SYSTEM_AMBIGUOUS`    | узел не отнесён ровно к одной системе                        | узел не считается          |

Есть хотя бы один блокер — статус `partial`; без блокеров — `complete`.

## 4. Результат на синтетике

`network_graph_resolved.v0.3.json` (лист 2383,937 × 1683,7795 pt, 35,277777777778 мм/pt) → `complete`:

| Строка                    | Группа               | Кол-во   | Источники      | Проверка |
| ------------------------- | -------------------- | -------- | -------------- | -------- |
| `mep.segment_length.v0`   | size 50, `syn.mat_a` | 21,025 м | seg-main       | да       |
| `mep.segment_length.v0`   | size 32, `syn.mat_a` | 48,990 м | seg-b1, seg-b2 | да       |
| `mep.node_count.v0`       | `syn.net.terminal`   | 2 шт     | n-t1, n-t2     | нет      |
| `mep.path_turns.v0`       | size 32, `syn.mat_a` | 2 шт     | seg-b1, seg-b2 | да       |
| `mep.branch_nodes.v0`     | degree 3             | 1 шт     | n-j1           | да       |
| `mep.parameter_change.v0` | size: 32 ↔ 50        | 1 шт     | n-j1           | да       |

Ручная проверка: seg-main = 0,25 × 2383,937 × 35,2778 = 21 024,9 мм; ветка = (0,2 × 1683,7795 +
0,15 × 2383,937) × 35,2778 = 24 494,97 мм × 2 = 48 989,9 мм.

«Проверка = да» — в строку вошло выведенное генератором (`rd_prior_inferred`, `retrieved_pattern`,
`deterministic_rule`); у каждой строки — счётчики происхождения и минимальная уверенность.

Исходный `network_graph.v0.3.json` (материал `unresolved`, решение `ud-1`) → `partial`: длин и поворотов
нет, блокеры `PARAMETER_UNRESOLVED` и `DECISION_BLOCKS_QUANTITY` по трём участкам; счёт приборов и
разветвление остаются.

## 5. Тесты (`test_mep_boq.py`)

- эталоны: оба графа дают ровно опубликованные `boq_*.v0.3.json`;
- повторяемость: одинаковый хеш ВОР; порядок узлов, участков, систем во входе не влияет;
- в модулях движка нет импортов модели, изображения, сети; в схеме ВОР нет полей цены;
- длина совпадает с независимой формулой; разбивка по размеру с источниками; без двойного счёта;
- повороты, разветвления, смена параметра; коллинеарная вершина не поворот и не меняет длину;
- класс без правила количества не считается; происхождение доходит до строки;
- без калибровки длин нет, счёт есть; отсутствующий параметр не выводится; невалидный граф и
  изменённый профиль — `refused`; предупреждение о фитингах;
- дельта графа → дельта ВОР: удлинение ветки меняет только её строку на ожидаемые мм; третий потребитель
  даёт +1 шт и степень 4;
- вертикаль между уровнями = 3000 мм; наклон = `hypot`; стояк + горизонталь = один поворот;
  неполные отметки, звено между листами и смешанное звено — блокеры.
