# MEP-эксперимент П → РД → ВОР — состояние

Живой документ эксперимента. Промт 00 пакета v1 выполнен 2026-09-15 на коммите `d570e83`;
в тот же день эксперимент переведён на пакет v3 — [квитанция миграции](MIGRATION_V1_TO_V3_RECEIPT.md).
Решения — [ADR-0027](../adr/0027-mep-gipoteza-p-rd-vor-izolirovannyj-eksperiment.md) и
[ADR-0028](../adr/0028-mep-semanticheskoe-raspoznavanie-v-scope.md), пакет — `_prompts/mep_p_to_rd_v3/`
(`_prompts/mep_hypothesis_v1/` — история). Номера промтов ниже — по v3.

## 1. Цель

Проверить три независимых утверждения и мерить каждое отдельно:

1. **Распознавание П.** Поверх замороженного base новый слой MEP semantic extraction даёт
   `MepEvidenceGraph`: стояки, приборы, оборудование, подписи и связи с принципиальных схем ВК стадии П
   и геометрию помещений, санузлов и шахт с архитектурных планов — только то, что реально показано на П
   (Р-MEP-18).
2. **Достройка РД.** Из evidence, выученного prior по РД и правил получается `MepNetworkGraph`:
   связность, трассы, параметры с происхождением.
3. **ВОР и цена.** Количества детерминированно выводятся из графа, цена — отдельной моделью по
   историческим ВОР.

Критерий успеха PoC: сеть топологически валидна, ВОР воспроизводим, ошибка количества и стоимости
приемлема на полностью отложенном проекте. Не «похоже на РД».

## 2. Scope

- Дисциплина — ВК, горизонтальная разводка одного типового жилого этажа.
- Вход П: принципиальные схемы ВК (не в масштабе) + архитектурный план этажа (геометрия). Выход РД: план этажа ВК с трассами (Р-MEP-18).
- ОВ, ЭОМ, СС не подключаются.
- Запись в Revit/IFC нет. Результат — overlay, JSON и количества.
- Флаг `mep_rd_hypothesis_v1`: пилот, по умолчанию выключен.

## 5. Что пакет предполагает и что есть на самом деле

Пакет написан под «AI-архив». Сверка с репозиторием на `d570e83`:

| Понятие пакета                       | В репозитории                                                                                                                 |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| EvidenceGraph, FloorGraph            | нет                                                                                                                           |
| typed POINT / LINE / AREA heads      | нет; ближайшее — геометрия `Measurement`: count / line / polyline / polygon                                                   |
| «монолит / кладка / двери»           | нет в портале; офлайн-цели slab/masonry в `vision/quantor_vision/slab/` и `tools/planswift_gt/`                               |
| PDF ingest, source transforms        | есть: `DocumentRevision`, `PageGeometry` на pypdf, нормализованные координаты (ADR-0008, ADR-0016)                            |
| распознавание страницы               | импорт пакета legacy-v1: `Region.block_type` ∈ text/image/stamp, `raw_content_md`; MEP-классов, этажа, стадии, confidence нет |
| векторный и текстовый канал PDF      | нет: провайдер читает размер, поворот и рамки                                                                                 |
| whole-sheet context + high-res views | в портале — растр pdf.js по видимой части (ADR-0025); в `vision/` — тайлы датасета                                            |
| raw / source-supported / unresolved  | нет как контракта; есть `Measurement.source` manual / ai / imported                                                           |
| масштаб                              | есть: `ScaleCalibration`, мм на точку PDF, неизменяема (ADR-0018); автоопределение запрещено                                  |
| project-heldout split                | есть в датасете Stage 2B (`docs/stage2b/08-dataset-build.md`)                                                                 |
| experiment/result storage            | объектное хранилище (ADR-0002) и записи прогонов `vision/quantor_vision/runrecord.py`                                         |
| флаги                                | есть: `apps/api/app/core/features.py`, `require_feature`, админка (ADR-0023)                                                  |

Вывод: MEP-сущностей в выходе base нет. Их даёт новый слой MEP semantic extraction; до него
генератор проверяется на `HUMAN_GT` (Track A). Таблица «сущность → источник → метод → GT» — в
[квитанции миграции, §3](MIGRATION_V1_TO_V3_RECEIPT.md#3-mep-сущности-что-есть-и-чего-нет).

Цепочка после миграции:

```text
legacy-v1 base recognition [FROZEN]
→ MEP semantic extraction (vision/, NEW)          — что показано на П
→ MepEvidenceGraph (input_mode: MODEL_EXTRACTED | HUMAN_GT | HYBRID_REVIEWED)
→ P→RD generator → MepNetworkGraph               — какая РД нужна
→ Quantity Engine → MepBoq → Pricing
```

## 8. Риски

| Риск                                                               | Что делаем                                                                    |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Парных П↔РД по ВК нет или мало (PoC — 20–30 проектов, 150–300 пар) | каркас на синтетике, `HOLD_DATA`, learning curve вместо веры в число альбомов |

## 10. Следующая веха: реальная стадия П → PROMPT 02

Начинается только после передачи реального комплекта П и по команде владельца. Первым шагом — только:

1. точный объём: листы, система, этаж;
2. разбор реальных условных обозначений: символы, линии, подписи;
3. минимальная схема разметки MEP по чертежам (реальный `MepSystemProfile`);
4. правила разметки и политика неоднозначности;
5. формат разметки `HUMAN_GT` на контрактах v0.3;
6. небольшой пилот ручной разметки;
7. STOP до обучения модели.

Готовая база: [05-contracts-v0.3](05-contracts-v0.3.md), [09-quantity-engine](09-quantity-engine.md),

## 11. Данные без пар П↔РД — последствия для плана

Решение владельца 2026-09-17 (Р-MEP-3): объекты будут, но в основном без пар П и РД. Из этого следует, не меняя
замороженных контрактов:

| Данные                       | Для чего годятся                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------- |
| только П                     | распознавание П (PROMPT 02–04): разметка HUMAN_GT, baseline, обучаемый экстрактор |
| только РД                    | prior РД и корпус retrieval для генератора (PROMPT 07–08); кандидат на псевдопары |
| П и РД одного объекта (13АВ) | **только отложенная проверка** генератора и сквозной слепой тест (PROMPT 12)      |

- **Псевдопары из РД** — гипотеза к PROMPT 06, не решение: из сети РД оставить то, что обычно показано на П
  (стояки, приборы, подписи систем), и учить достройку до полной РД. Правило «что видно на П» — только по
  реальной паре 13АВ и с источником; расхождение распределений псевдо-П и реальной П измеряется, а не
  предполагается.
- Единственная реальная пара не попадает в обучение и подбор порогов: иначе проверить генератор будет не на чем.
- Цели PoC «20–30 проектов с парами» заменяются на отдельные цели по П-разметке, по корпусу РД и по числу
  реальных пар для проверки; числа — после PROMPT 02 по оценке стоимости разметки.

## 12. Вход П без плана этажа ВК — последствия

Сведения владельца 2026-09-17 (Р-MEP-18): на стадии П по ВК обычно есть только принципиальные схемы, планы
этажей ВК — в РД.

```text
П:  схема ВК (системы, стояки, приборы по этажам, диаметры; без масштаба)
  + архитектурный план этажа (помещения, санузлы, шахты; в масштабе)
  → MepEvidenceGraph (листы разных видов в одном графе)
  → генератор: разводка по архитектурному плану с опорой на схему
РД: план этажа ВК → MepNetworkGraph (эталон)
```

- Контракты v0.3 это допускают без изменений: `MepEvidenceGraph` содержит несколько листов; схема —
  `scale_status: uncalibrated`, метрики на ней запрещены; помещения и шахты — вид `zone`; связь «стояк на
  схеме ↔ шахта на плане» — тип связи профиля. Ядро не меняется.
- Длины считаются только по планам в масштабе: на П — по архитектурному плану, на РД — по плану ВК.
- Архитектурных планов стадии П в полученных архивах нет (есть разделы 5.1–5.5 ПД и АР стадии РД). Для
  пилота нужен раздел АР стадии П корпуса 3; если его нет — архитектурный план РД как временная замена,
  с явной пометкой в происхождении и без использования в оценке генератора.
- Пилот PROMPT 02 на листе 3 ИОС 2.1 (схема) остаётся верным выбором.
