# Разметка легенды MEP в PlanSwift

Обновлено 2026-09-17 по списку владельца. Профиль v0.2.0: 27 классов, 10 систем,
6 атрибутов, 5 типов связей; `status: draft`. Полный профиль и источник лежат только в датасете.
Решения Р-MEP-3, 17, 18 берутся из main; самостоятельные записи решений здесь не создаются.
Весь переданный парный объект — только отложенная проверка, без обучения и настройки.

## Строки обмера

Создать **одну строку на класс**, имя `MEP|<class_id>|<подпись из таблицы>`.
Точка Count означает один символ или якорь текста; Linear — ломаную видимой трассы.
Новые классы по усмотрению аннотатора не создавать. Автоматический текст PDF не является HUMAN_GT.

для текста — ручной якорь, а не автоматически рассчитанный bbox. Для трубы — polyline.
Все классы из легенды допустимы в профиле; это не утверждение, что каждый есть на выбранном листе.

## Атрибуты без дополнительных строк на класс

Общие значения допускается дописать к **имени строки** после подписи:
`MEP|route|Трубопровод|system=b1.1`. Такое значение действует лишь если одинаково для всех
элементов строки. При разных системах оставить общую строку без system и задать его каждой секции.

Для малого пилота: одна секция Count с одной точкой на элемент; одна секция Linear на непрерывную
ломаную. Имя **секции** содержит идентификатор и атрибуты, например:

```text
e001|system=b1.1|diameter_label=DN20|review=CONFIRMED
e002|system=t3.1|valve_type=ball|actuated=true|review=CONFIRMED
e003|system=b1.1|riser_mark=Ст.В1|review=AMBIGUOUS
e004|review=IGNORE_FOR_TRAIN
```

Это предлагаемый протокол будущего конвертера, а не уже работающий импорт. Он читает `Name`
позиции и `Name` секции из их `Data.xml`: ключ класса — второй компонент имени строки;
последующие `key=value` — значения по умолчанию. Значения секции имеют приоритет. Поля review
и eNNN — метаданные проверки, не атрибуты профиля. Только перечисленные ключи разрешены.
Символы `%`, `|`, `=` внутри значения кодировать как `%25`, `%7C`, `%3D`; декодирование один раз.
Неполное имя или неизвестный ключ — отказ импорта с причиной, без угадывания.

Если редактирование имени секции неудобно, те же поля записать в `review.csv` рядом с проектом:
`annotation_key,page_guid,section_guid,point_index,class_id,system,diameter_label,riser_mark,valve_type,actuated,shower_head,review,raw_text,reason,annotator,reviewed_at`.
Ключ при одной точке — GUID секции, при нескольких — GUID плюс индекс с нуля; после перестановки
точек индексы сверить. GUID берётся из сохранённого `Data.xml`. Значение CSV имеет приоритет
над именем секции, но конфликт двух непустых источников требует review и не разрешается молча.
Не полагаться на цвет, итоговые количества или неописанные пользовательские свойства.

## Допустимые значения

Ключи систем: `b1`, `b1.1`, `b1.2`, `b1.3`, `t3.1`, `t3.2`, `t3.3`, `t4.1`, `t4.2`, `t4.3`.
Подписи B1/T3 и кириллические В1/Т3 нормализуются по явной таблице `annotation_policy.json`.
`Т3` или `Т4` без суффикса не доказывают зону: сохранить исходную подпись, system оставить
неустановленным и отметить неоднозначность. Для электрического полотенцесушителя не назначать
водяную систему без явного свидетельства.

`valve_type`: `ball` — шаровой кран; `gate` — задвижка; `globe` — вентиль;
`butterfly_position` — затвор с контролем положения. `actuated=true` — явно показан электропривод;
`false` — вручную проверено его отсутствие. Неизвестное значение не равно false.
`shower_head=true/false` — вручную проверенное наличие/отсутствие душевой сетки у смесителя.
`diameter_label` и `riser_mark` — буквальная запись, без вычисления диаметра или номера стояка.
Если признак неразборчив, не заполнять его догадкой.

## Спорное и исключённое

`CONFIRMED` — человек проверил класс, геометрию и введённые значения. `AMBIGUOUS` — геометрия
сохранена, в reason записаны причина и варианты; в подтверждённый HUMAN_GT не переносить.
`IGNORE_FOR_TRAIN` — элементы сохранены и учтены отдельно, не выброшены из исходной разметки.
Для pump, membrane_tank, sprinkler, flow_switch этот статус обязателен независимо от читаемости;
причину сомнения можно дополнительно записать в reason. На выбранном объекте **все** классы
запрещены для обучения, а четыре перечисленных также вне пилотного подтверждённого графа.
Бытовой пожарный кран `household_fire_tap` остаётся классом легенды; комплект пожаротушения
эталоном пилота не является.

`NOT_VISIBLE` — запись о недоступном наблюдении в журнале, без вымышленной точки. Дубликат
щелчка пометить IGNORE_FOR_TRAIN с причиной; одинаковые подписи в разных местах не сливать.
Неразмеченное не означает отсутствующее. Разрыв трассы не достраивать.

## Связи — отдельная ручная таблица

`relations.csv`: `id,from_annotation_key,to_annotation_key,relation_type,review,reason,annotator,reviewed_at`.

| relation_type             | Разрешённые классы источника → назначения |
| ------------------------- | ----------------------------------------- |
| `label_system_to_element` | label_system → route или riser            |
| `label_diameter_to_route` | label_diameter → route                    |
| `label_mark_to_symbol`    | label_mark → symbol                       |
| `route_touches_symbol`    | route → symbol                            |
| `riser_connects_route`    | riser → route                             |

Выноска, марка или ручное подтверждение — основание связи; ближайшее расстояние не основание.
Касание не превращается автоматически в гидравлическое соединение. Связи с исключёнными
элементами сохраняются в журнале, но не входят в подтверждённый пилотный граф.
Контракт v0.3 ограничивает связи по kind, а не class_id: точные ограничения классов записаны
в `annotation_policy.json`. Будущий адаптер обязан проверить их дополнительно. Ядро не изменено.

## Что сохранять и что будет читать адаптер

Сохранить полный локальный проект: Job/Pages/Takeoff с `Data.xml`, исходные страницы, журналы
и профиль с хешем. Сверить `PageGUID` с SHA-256 исходного PDF и номером страницы; название
страницы само по себе недостаточно. Таблица количеств CSV/Excel без проекта не заменяет геометрию.

Из XML: `Name`, GUID секции, `PageGUID`, `DigitizerData/Points/Point` (X/Y/PointType).
N точек Count дают N элементов; Linear сохраняет порядок вершин. Сохранить хеши XML и источников.
Исходная единица координат зависит от формата страницы: TIFF — пиксели, PDF — точки;
имя старого поля `points_source_px` само по себе единицы не устанавливает. Нормализация `x/W,y/H`
допустима после проверки начала координат, поворота, размеров и соответствия CropBox/MediaBox.
Неизвестная трансформация или точки за страницей — отказ, не автоматический ремонт.

Для схемы `scale_status: uncalibrated`. Длины, площади, объёмы и цены из PlanSwift не импортировать.
Разрешены только строковые подписи размеров. Числовые метрические атрибуты не создаются.
Ручной подтверждённый экспорт: `input_mode: HUMAN_GT`, `provenance: human_ground_truth`,
`status: human_confirmed`, `review: confirmed`, источник `human_annotation` с автором и временем.
Автоматический текст остаётся отдельным источником. Старый автоматический черновик сохранён
со своим профилем v0.1.0 в history; в новый HUMAN_GT не переносился.

Проверка будущего экспорта — `validate_profile`, `validate_evidence_graph` плюс правила sidecar.
Сейчас проверен профиль и **пустой** шаблон: ручная разметка ещё не выполнена, конвертер не написан.
Использовать только ручные Count/Linear, без Auto Count, Auto Takeoff, OCR и моделей.
[Официальное руководство инструментов](https://help.constructconnect.com/03-a-detailed-look-at-the-home-tab-and-drawing-takeoff-and-annotations-176/planswift-03-00-create-your-first-takeoff-in-planswift-in-under-5-minutes-2777).
