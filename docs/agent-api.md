# API портала для агентов и скриптов

Портал целиком работает через REST `/api/v1/…`: всё, что делает страница, можно сделать запросом. Агенту (ИИ,
скрипту, навыку TENDER) туда пускает **личный токен** `qtk_…` — его создаёт человек на странице «Доступ»
(«Для чего токен»), значение показывается один раз. Токен действует от имени владельца в одном рабочем
пространстве и не может больше, чем роль владельца.

## Области токена

| Область | Что можно | Для кого |
|---|---|---|
| `read` — только чтение | проекты, документы и их разбор (виды, оси, «Здание», модель здания), задания, выпуски базы и координационный файл, расчёты | агенты, которым нужно знать объект |
| `upload` — загрузка документов и модели | всё из `read` + новые ревизии документов и IFC, построение модели здания, задания разбора чертежей | агент проектировщика: «отправить в 3D» |
| `tender` — расчёты TENDER | читать выпуски базы, загружать и читать расчёты (`quantor-obmen`) | навыки `raschet-*` |

Областей у токена может быть несколько: права складываются. Создавать проекты, выпускать и отзывать базу,
менять расчёт портала и выпускать токены токен не может никогда — это делает человек. Отзыв действует сразу.

## Адреса, которые нужны чаще всего

```text
GET  /api/v1/projects?search=<часть названия>                      проекты (items, total)
GET  /api/v1/projects/{id}/tender/base/coordination.ifc            координационный файл последнего выпуска
GET  /api/v1/projects/{id}/tender/base/coordination.json           он же для программы (номер выпуска —
                                                                    заголовок X-Quantor-Base-Release)
GET  /api/v1/projects/{id}/tender/base/releases                    выпуски базы, новые сверху
GET  /api/v1/projects/{id}/tender/base/releases/{rid}/download     ZIP выпуска (sha256 — X-Content-SHA256)
GET  /api/v1/projects/{id}/documents                               документы проекта
POST /api/v1/projects/{id}/uploads                                 файл (multipart; document_id — новая ревизия)
POST /api/v1/projects/{id}/model/imports                           построить модель здания из IFC проекта
GET  /api/v1/projects/{id}/model/imports/latest                    ход последней сборки
GET  /api/v1/projects/{id}/model/versions                          версии модели
GET  /api/v1/jobs/{job_id}                                         задание
GET  /api/v1/meta/openapi.json                                     полное описание API (только с токеном/входом)
```

Заголовок запроса: `Authorization: Bearer qtk_…`. Ошибка — JSON `{"detail": {"code", "message"}}`;
401 — токен не тот или отозван, 403 — у токена нет нужной области (или права у роли владельца).

## Клиент `tools/quantor_agent/quantor_agent.py`

Один файл, только стандартная библиотека Python 3.9+. Адрес — `QUANTOR_URL`, токен — `QUANTOR_TOKEN` или файл
`~/.config/quantor/token` (права 600). Токен не передаётся аргументом и не печатается.

```bash
export QUANTOR_URL=https://quantor.meridianai.ru
python3 quantor_agent.py projects --search Капельский
python3 quantor_agent.py coordination --project "341. Капельский (СОЮЗ)" -o coordination.ifc
python3 quantor_agent.py base --project "341. Капельский (СОЮЗ)" --out Базы
python3 quantor_agent.py push --project "341. Капельский (СОЮЗ)" KR.ifc      # область upload
python3 quantor_agent.py status --project "341. Капельский (СОЮЗ)"
python3 quantor_agent.py --json coordination --project <id>                  # последняя строка — JSON
```

Коды выхода: 0 — готово; 1 — нет того, что просили (нет выпуска, сборка не удалась); 2 — неверный вызов или
файл; 3 — портал отказал или недоступен; 4 — не дождались задания.

Навык TENDER `quantor-obmen` берёт базу своей командой `base_pull.py` (та же логика, распаковка в
`Работа/Quantor/Базы/`).

## Правила для агента

- Перед работой с объектом брать координационный файл заново (`coordination`): оси и этажи — общие для всех
  разделов. Если его нет или выпуск старый — сказать человеку, что нужен выпуск базы; самому не выпускать.
- Полные IFC на портал не загружать: только облегчённые (`tools/light_ifc`), предел клиента — 100 МБ.
- Токен держать в файле 600 или переменной окружения, в чат, файлы проекта и командную строку не вставлять.
