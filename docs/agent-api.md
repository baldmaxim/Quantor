# API портала для агентов и скриптов

Портал целиком работает через REST `/api/v1/…`: всё, что делает страница, можно сделать запросом. Агенту (ИИ,
скрипту, навыку TENDER) туда пускает **личный токен** `qtk_…` — его создаёт человек на странице «Доступ»
(«Для чего токен»), значение показывается один раз. Токен действует от имени владельца в одном рабочем
пространстве и не может больше, чем роль владельца.

## Области токена

| Область                                 | Что можно                                                                                                                  | Для кого                               |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `read` — только чтение                  | проекты, документы и их разбор (виды, оси, «Здание», модель здания), задания, выпуски базы и координационный файл, расчёты | агенты, которым нужно знать объект     |
| `upload` — загрузка документов и модели | всё из `read` + новые ревизии документов и IFC, построение модели здания, задания разбора чертежей                         | агент проектировщика: «отправить в 3D» |
| `tender` — расчёты TENDER               | читать выпуски базы, загружать и читать расчёты (`quantor-obmen`)                                                          | навыки `raschet-*`                     |
| `tender_import` — объект по тендеру     | создать объект по тендеру TenderHUB при пакетном импорте (см. ниже); сама по себе загрузку не даёт — только вместе с `upload` | дашборд «Тендеры»                      |

Областей у токена может быть несколько: права складываются. Выпускать и отзывать базу, менять расчёт портала и
выпускать токены токен не может никогда — это делает человек. Создавать проекты токен тоже не может, кроме одного
случая: область `tender_import` позволяет при пакетном импорте создать объект по тендеру, и только если у владельца
токена есть право создавать проекты (роль «инженер» и выше), только в рабочем пространстве токена и только по
тендеру, который портал сам нашёл в TenderHUB (номер и название — из TenderHUB, не от клиента). Общие
`POST /projects` и `POST /integrations/tenderhub/projects` токену по-прежнему недоступны. Чату OAuth область
`tender_import` не выдаётся. Отзыв действует сразу.

## Адреса, которые нужны чаще всего

```text
GET  /api/v1/projects?search=<часть названия>                      проекты (items, total)
GET  /api/v1/projects/{id}/tender/base/coordination.ifc            координационный файл последнего выпуска
GET  /api/v1/projects/{id}/tender/base/coordination.json           он же для программы (номер выпуска —
                                                                    заголовок X-Quantor-Base-Release)
GET  /api/v1/projects/{id}/tender/base/releases                    выпуски базы, новые сверху
GET  /api/v1/projects/{id}/tender/base/releases/{rid}/download     ZIP выпуска (sha256 — X-Content-SHA256)
GET  /api/v1/projects/{id}/documents                               документы проекта
POST /api/v1/projects/{id}/uploads                                 файл (multipart; document_id — новая ревизия)
POST /api/v1/tender-imports                                        пакетный импорт: перечень ZIP с хешами
GET  /api/v1/tender-imports/{import_id}                            пакетный импорт: состояние позиций
POST /api/v1/projects/{id}/model/imports                           построить модель здания из IFC проекта
GET  /api/v1/projects/{id}/model/imports/latest                    ход последней сборки
GET  /api/v1/projects/{id}/model/versions                          версии модели
GET  /api/v1/jobs/{job_id}                                         задание
GET  /api/v1/meta/openapi.json                                     полное описание API (только с токеном/входом)
```

Заголовок запроса: `Authorization: Bearer qtk_…`. Ошибка — JSON `{"detail": {"code", "message"}}`;
401 — токен не тот или отозван, 403 — у токена нет нужной области (или права у роли владельца).

## Клиент `tools/quantor_agent/quantor_agent.py`

Один файл, только стандартная библиотека Python 3.9+. Адрес — `QUANTOR_URL`, токен — `QUANTOR_TOKEN` или файл
`~/.config/quantor/token` (права 600). Токен не передаётся аргументом и не печатается.

```bash
export QUANTOR_URL=https://quantor.meridianai.ru
python3 quantor_agent.py projects --search Капельский
python3 quantor_agent.py coordination --project "341. Капельский (СОЮЗ)" -o coordination.ifc
python3 quantor_agent.py base --project "341. Капельский (СОЮЗ)" --out Базы
python3 quantor_agent.py push --project "341. Капельский (СОЮЗ)" KR.ifc      # область upload
python3 quantor_agent.py status --project "341. Капельский (СОЮЗ)"
python3 quantor_agent.py --json coordination --project <id>                  # последняя строка — JSON
```

Коды выхода: 0 — готово; 1 — нет того, что просили (нет выпуска, сборка не удалась); 2 — неверный вызов или
файл; 3 — портал отказал или недоступен; 4 — не дождались задания.

Навык TENDER `quantor-obmen` берёт базу своей командой `base_pull.py` (та же логика, распаковка в
`Работа/Quantor/Базы/`).

## Правила для агента

- Перед работой с объектом брать координационный файл заново (`coordination`): оси и этажи — общие для всех
  разделов. Если его нет или выпуск старый — сказать человеку, что нужен выпуск базы; самому не выпускать.
- Полные IFC на портал не загружать: только облегчённые (`tools/light_ifc`), предел клиента — 100 МБ.
- Токен держать в файле 600 или переменной окружения, в чат, файлы проекта и командную строку не вставлять.

## MCP: портал как инструменты ИИ-чата

`POST /api/v1/mcp` — MCP-сервер портала (Model Context Protocol, транспорт Streamable HTTP, ответы JSON,
без сеансов). Чат или агент подключает его по адресу и получает инструменты:

| Инструмент           | Что делает                                                                                    | Область токена |
| -------------------- | --------------------------------------------------------------------------------------------- | -------------- |
| `find_projects`      | проекты пространства: название и id                                                           | `read`         |
| `get_coordination`   | координационный файл последнего выпуска базы (`json` — оси и этажи, `ifc` — файл)             | `read`         |
| `list_base_releases` | выпуски базы                                                                                  | `read`         |
| `model_status`       | последняя сборка модели и этажи новейшей версии                                               | `read`         |
| `list_documents`     | документы проекта                                                                             | `read`         |
| `send_ifc_to_3d`     | «отправить в 3D»: IFC своей дисциплины новой ревизией того же имени и сборка модели (до 3 МБ) | `upload`       |
| `build_model`        | пересобрать модель из IFC проекта                                                             | `upload`       |
| `start_tender_import`  | пакетный импорт: перечень ZIP с хешами; объект — `tenderhub_id` (создаётся при `tender_import`) или `project` | `upload` (+ `tender_import` для создания объекта) |
| `tender_import_status` | состояние позиций пакетного импорта по `import_id`                                           | `read`         |
| `job_status`         | состояние задания                                                                             | `read`         |

Вход — личный токен в заголовке `Authorization: Bearer qtk_…` или вход чата по OAuth (ниже); cookie портала
MCP не принимает. Права — как у токена или разрешения: роль владельца и выбранные области. Проект в
инструментах — id или точное название.

### Веб-чаты: Claude и ChatGPT (вход по OAuth, ADR-0054)

Токен вставлять не нужно: чат сам регистрируется на портале и открывает страницу входа.

- **Claude** (claude.ai, приложение): «Настройки» → «Коннекторы» → «Добавить свой коннектор» → адрес
  `https://quantor.meridianai.ru/api/v1/mcp` → «Подключить». Откроется портал: войти, проверить имя чата и
  что ответ уйдёт на `claude.ai`, нажать «Разрешить».
- **ChatGPT**: «Настройки» → «Приложения и коннекторы» → «Дополнительно» → включить режим разработчика;
  «Создать» → тот же адрес, вход OAuth → страница портала → «Разрешить».

Что разрешить: «читать» — всегда; «загружать IFC своего раздела и собирать модель» — галочка, её можно
снять. Права не шире роли человека. Подключённый чат виден в разделе «Доступ» строкой «Claude (чат)» —
там же «Отозвать»: доступ гаснет сразу. Доступ чата живёт час и обновляется сам; работает он только
для MCP, остальной API его не принимает.

Для служб (настройки `oauth_redirect_uris`, `oauth_allow_loopback`): метаданные —
`/.well-known/oauth-authorization-server` и `/.well-known/oauth-protected-resource/api/v1/mcp`,
регистрация `POST /api/v1/auth/oauth/register` (RFC 7591), выдача `POST /api/v1/auth/oauth/token`
(код с PKCE S256, обновление с заменой), страница согласия `/oauth/authorize`.

### Claude Code и другие программы

По токену:

```bash
claude mcp add --transport http quantor https://quantor.meridianai.ru/api/v1/mcp --header "Authorization: Bearer qtk_…"
```

Или без токена — тем же входом OAuth (адрес возврата на этом компьютере, `http://localhost`):

```bash
claude mcp add --transport http quantor https://quantor.meridianai.ru/api/v1/mcp
```

Любой другой MCP-клиент с транспортом Streamable HTTP подключается так же: адрес и заголовок с токеном
либо вход OAuth.

## Пакетный импорт документации (дашборд «Тендеры»)

Локальный процесс (Python) выгружает на портал папку тендера: каждый документ — ZIP пакета распознавалки
(`recognized-package/legacy-v1`). Файлы не идут через перечень: сначала клиент присылает **перечень с хешами**,
портал отвечает, что догрузить, затем клиент шлёт ZIP обычной загрузкой в проект с привязкой к позиции.

```text
POST /tender-imports  (перечень, хеши)  ->  import_id, to_upload
    для key из to_upload:  POST /projects/{project_id}/uploads  (ZIP + tender_import_id + tender_import_item)
GET  /tender-imports/{import_id}  каждые несколько секунд  ->  пока complete = false
```

Распознавание ZIP идёт заданием в фоне: «файл принят» и «импорт завершён» — разные моменты (см. состояния).

### Позиция перечня

Позиция — один ZIP legacy-v1: один оригинальный PDF, обязательный `*_blocks.json`, необязательные `*_results.md`
и `*_results.html`. До 500 позиций в перечне.

| Поле            | Что                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| `key`           | ключ позиции, 1–200 знаков, уникален в перечне; стабилен между запусками (например, путь PDF внутри папки тендера) |
| `filename`      | имя ZIP без пути, оканчивается на `.zip`, до 255 знаков                                               |
| `size`          | размер ZIP, байт (≥ 1; не больше предела загрузки портала, иначе 422)                                 |
| `sha256`        | SHA-256 **байт ZIP** — проверка передачи                                                              |
| `pdf_sha256`    | SHA-256 байт PDF внутри ZIP                                                                           |
| `blocks_sha256` | SHA-256 байт `*_blocks.json` внутри ZIP                                                               |

Хеши — 64 шестнадцатеричных знака (регистр не важен, портал приводит к нижнему). Ключ различает одинаковые
имена в разных папках: `корпус 1/План.pdf` и `корпус 2/План.pdf` — две позиции.

Отпечаток комплекта строится из `(key, pdf_sha256, blocks_sha256)`; `sha256`, `size` и `filename` в него не
входят. Поэтому ZIP, пересобранный с другими временными метками, — тот же комплект: повторный `start` вернёт
прежний импорт.

### Поиск объекта

Ровно одно из полей запроса: `project_id` или `tenderhub_id`.

| Порядок | Условие                                                                                   | `matched_by`   |
| ------- | ----------------------------------------------------------------------------------------- | -------------- |
| 1       | передан `project_id` — проект своего пространства (чужой и несуществующий — 404)          | `project_id`   |
| 2       | есть объект, привязанный к тендеру с этим `tenderhub_id`                                  | `tenderhub_id` |
| 3       | есть объект с тем же номером тендера (другая версия того же номера ведёт в существующий объект) | `tender_number` |
| 4       | объекта нет — создаётся по данным TenderHUB (нужна область `tender_import`, см. ошибки)   | `created`      |

`matched_by` в ответе — как найден объект при создании импорта. В TenderHUB портал обращается только в пунктах 3–4
и только для токена с областью `tender_import`: без неё после пункта 2 сразу `403 TENDER_IMPORT_CREATE_FORBIDDEN`
(объект другой версии того же номера такой токен не найдёт — передайте `project_id`).

### Запуск: `POST /api/v1/tender-imports`

(`created: false`).

{
  "tenderhub_id": "7c1e9a52-3b1d-4f6a-9e0b-5a2d8c4f1e77",
  "items": [
    {
      "key": "Корпус 1/АР/План 1 этажа.pdf",
      "filename": "plan-1-etazha.zip",
      "size": 18734211,
      "sha256": "9f2c1b7e4a6d3085c1e9b2f47a8d0c3e5b6a7f1d2c4e8091a3b5c7d9e0f12a34",
      "pdf_sha256": "3a7d5c9e1b2f4068a7c3e5d9b1f20486c8ae0d2f4b6a8c1e3057d9b1f3a5c7e9",

### Состояние: `GET /api/v1/tender-imports/{import_id}`

Требует `read`. Ответ — тот же объект, что у `start`, с `created: false`. Чужой и несуществующий импорт — 404.

### Загрузка позиции: `POST /api/v1/projects/{project_id}/uploads`

Требует `upload`. `multipart/form-data`; ZIP — потоком, base64 не нужен.

| Поле формы           | Что                                                                       |
| -------------------- | ------------------------------------------------------------------------- |
| `file`               | ZIP позиции; имя файла оканчивается на `.zip`                             |
| `tender_import_id`   | `import_id` из ответа `start`                                             |
| `tender_import_item` | `key` позиции из перечня                                                  |

Оба поля `tender_import_*` — только вместе; `document_id` с ними не сочетается (422). Проект в пути — тот же,
что `project_id` импорта, иначе 404 `TENDER_IMPORT_NOT_FOUND`.

```bash
curl -sS -X POST "$QUANTOR_URL/api/v1/projects/$PROJECT_ID/uploads" \
  -H "Authorization: Bearer $QUANTOR_TOKEN" \
  -F "file=@plan-1-etazha.zip;type=application/zip" \
  --form-string "tender_import_id=$IMPORT_ID" \
  --form-string "tender_import_item=Корпус 1/АР/План 1 этажа.pdf"
```

Ответ — обычный результат загрузки: `document`, `revision`, `job` (задание импорта, `queued`), `is_duplicate`.
**201** — файл принят впервые, **200** — позиция уже была принята: возвращается прежний результат без второй
ревизии (`is_duplicate: true`). После приёма портал сверяет размер и SHA-256 с перечнем; несовпадение — 422
`TENDER_IMPORT_HASH_MISMATCH`, файл не сохраняется.

### MCP

`POST /api/v1/mcp`, инструменты `start_tender_import` и `tender_import_status` (подключение — выше). Через MCP
передаются только перечень и статусы; файлы — только HTTP multipart, как в разделе выше.

| Инструмент             | Аргументы                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| `start_tender_import`  | `items` (обязательно, 1–500 позиций с теми же полями), и ровно одно из: `tenderhub_id` или `project` (id или точное название) |
| `tender_import_status` | `import_id` (uuid)                                                                                             |

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "start_tender_import",
            "arguments": {"tenderhub_id": "7c1e9a52-3b1d-4f6a-9e0b-5a2d8c4f1e77",
                          "items": [{"key": "Корпус 1/АР/План 1 этажа.pdf", "filename": "plan-1-etazha.zip",
                                     "size": 18734211, "sha256": "9f2c…", "pdf_sha256": "3a7d…",
                                     "blocks_sha256": "c4e8…"}]}}}

{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
 "params": {"name": "tender_import_status",
            "arguments": {"import_id": "0b6f3d1a-8c24-4e57-a9d3-61f2c8e5b704"}}}
```

Ответ `result`:

```json
{
  "content": [{"type": "text", "text": "Импорт 0b6f3d1a-…: объект «ТН-0042 · ЖК «Северный»» (created), https://…. Позиций 1: ждут загрузки 1, принято 0, импортировано 0, ошибок 0, конфликтов 0. Импорт не завершён."}],
  "isError": false,
  "structuredContent": { "import_id": "0b6f3d1a-8c24-4e57-a9d3-61f2c8e5b704", "…": "тот же объект, что в ответе HTTP" }
}
```

`structuredContent` — тот же объект, что возвращает HTTP; разница 200/201 через MCP не видна, смотреть `created`.
Ошибка портала приходит как `isError: true` с текстом сообщения (для 403 — с пометкой про область токена).

### Состояния позиции

Состояние не хранится, а вычисляется при каждом чтении по заданию импорта и ревизиям проекта.

| `state`    | Что значит                                                                                              | Что делать клиенту                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `pending`  | файла нет на портале (и этого PDF с распознаванием в проекте нет)                                       | загрузить; ключ — в `to_upload`                                     |
| `received` | **файл принят**, задание импорта в очереди или идёт (`job_status` — `queued`/`running`)                 | ждать, опрашивать статус; не загружать повторно                     |
| `imported` | **импорт завершён**: PDF и распознавание в проекте; заполнены `pdf_revision_id`, `document_id`          | ничего; позиция готова                                              |
| `failed`   | задание упало или отменено, либо PDF в архиве не совпал с `pdf_sha256`; `error_code`, `error_message` — причина (у отменённого задания могут быть пусты) | ключ в `to_upload` — дослать один раз за запуск; иначе показать причину человеку |
| `conflict` | этот PDF уже распознан другим результатом (`error_code` = `TENDER_IMPORT_OCR_CONFLICT`); данные портала не изменены | не загружать; решает человек в портале                              |

Поля позиции: `job_id`, `job_status` — задание импорта (после приёма); `package_revision_id` — ревизия
принятого ZIP; `pdf_revision_id`, `document_id` — ревизия и документ PDF (у `imported` и `conflict`);
`error_code`, `error_message` — у `failed` и `conflict`; `received_at` — когда принят ZIP. Позиция, чей PDF с тем
же `blocks.json` уже есть в проекте, сразу `imported` без загрузки.

На уровне импорта:

- `summary` — счётчики по состояниям и `total`;
- `to_upload` — ключи, которые клиенту надо (до)загрузить: все `pending`, `failed` с повторяемым отказом и
  `failed` с отменённым заданием (отказ по содержимому, например битый `blocks.json`, сюда не входит);
- `complete: true` — нет позиций `pending` и `received`. Это не «всё успешно»: в завершённом импорте могут быть
  `failed` и `conflict` — проверять `summary`.

### Ошибки

Формат — `{"detail": {"code", "message"}}`. Ошибки схемы тела запроса (лишние или пропущенные поля, неверный
хеш, пустой перечень, повтор `key`, одновременные `tenderhub_id` и `project_id` или ни одного из них, имя не
`.zip`) — 422 со стандартным списком в `detail`: элементы `{"type", "loc", "msg", "input", "ctx"}`; для повтора
`key` и для `tenderhub_id`/`project_id` `loc` — просто `["body"]`, причина — в `msg`. Опираться на статус.

| HTTP | Код                               | Когда                                                                        | Что делать                                                              |
| ---- | --------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 401  | —                                 | токен неверный или отозван                                                   | выпустить новый токен                                                   |
| 403  | —                                 | у токена нет области (`upload` для start/загрузки, `read` для статуса)       | выдать токену нужную область                                            |
| 403  | `TENDER_IMPORT_CREATE_FORBIDDEN`  | объекта с этим `tenderhub_id` нет, а токен без `tender_import` или у владельца роль ниже «инженера» | добавить область `tender_import` / роль, либо создать объект человеком и передать `project_id` |
| 404  | `NOT_FOUND`                       | `project_id` не найден в пространстве токена                                 | проверить проект и пространство токена                                  |
| 404  | `TENDERHUB_TENDER_NOT_FOUND`      | тендера с таким `tenderhub_id` нет в TenderHUB                               | исправить идентификатор                                                 |
| 404  | `TENDER_IMPORT_NOT_FOUND`         | импорт не найден, чужой, или проект в пути загрузки не тот                   | взять `import_id` и `upload.path` из ответа `start`                     |
| 404  | `TENDER_IMPORT_ITEM_NOT_FOUND`    | в импорте нет позиции с таким `tender_import_item`                           | передавать `key` как в перечне                                          |
| 409  | `TENDER_IMPORT_ITEM_DONE`         | позиция уже `imported` или `conflict` по данным проекта, а ZIP к ней не принимался | не загружать; позиция обработана                                        |
| 422  | `TENDER_IMPORT_HASH_MISMATCH`     | размер или SHA-256 загруженного ZIP не совпадают с перечнем                  | пересчитать хеши; при повторе `start` с новыми значениями — отправить заново; проверить обрыв передачи |
| 422  | `VALIDATION_FAILED`               | размер позиции больше предела загрузки; поля `tender_import_*` не парой; `document_id` вместе с ними; файл не `.zip`; нет имени файла | исправить запрос                                                        |
| 429  | `TENDERHUB_RATE_LIMITED`          | TenderHUB ограничил частоту (при создании объекта)                           | повторить `start` позже                                                 |
| 502  | `TENDERHUB_UNAVAILABLE`           | TenderHUB недоступен                                                         | повторить `start` позже                                                 |
| 503  | `TENDERHUB_DISABLED`              | на портале не настроена интеграция с TenderHUB (нужна для поиска объекта по тендеру, если объекта ещё нет) | передать `project_id` или обратиться к администратору                   |

Коды позиции (в `items[].error_code`, не HTTP-ошибки): `TENDER_IMPORT_OCR_CONFLICT` — состояние `conflict`;
`TENDER_IMPORT_PDF_MISMATCH` — `failed`: PDF внутри принятого ZIP не совпал с `pdf_sha256`; остальные коды
`failed` — причина задания разбора пакета. Те же байты ZIP повторно запускают задание, только если отказ
повторяемый (недоступность хранилища или базы, потеря аренды, превышение времени); пересобранный ZIP с другими
байтами — новый пакет и новое задание при любом отказе, в том числе после отмены задания.

### Как выгружать надёжно

1. Посчитать хеши, составить перечень, вызвать `start`. Обрыв или неизвестный исход — повторить `start` тем же
   перечнем: вернётся тот же `import_id` (200), параллельный `start` тоже безопасен — импорт один.
2. Перед повторной загрузкой позиции спросить статус: позиция могла быть принята, а ответ потерян. Грузить
   только ключи из `to_upload`.
3. Повторная загрузка уже принятой позиции безопасна: 200, `is_duplicate: true`, вторая ревизия не создаётся —
   даже если ZIP пересобран. Параллельные загрузки одной позиции встают в очередь на сервере.
4. Опрашивать `GET /tender-imports/{import_id}` с паузой в несколько секунд до `complete: true`. `received` —
   ещё не конец: идёт распознавание.
5. Упавшую позицию досылать, только если её ключ в `to_upload`, и один раз за запуск: загрузить тот же ZIP
   (повторяемый отказ) или пересобранный — тогда сначала повторить `start` тем же перечнем с новыми
   `sha256`/`size`. Снова `failed` или ключа нет в `to_upload` — показать `error_code` и `error_message`
   человеку, в цикле не повторять. При изменении самих PDF или `blocks.json` комплект станет
   другим — `start` создаст новый импорт.
6. `conflict`: данные портала не менялись; клиент ничего не делает, решение — за человеком в портале
   (`project_url`).
7. После `complete` итог — по `summary` (`imported` / `failed` / `conflict`), а не по самому признаку.

### Токен дашборда

Области: `upload`; для автосоздания объекта по `tenderhub_id` — ещё `tender_import` (владелец — инженер или
выше). Если объект создаёт человек, а клиент передаёт `project_id`, достаточно `upload`. Токен хранить в файле
с правами 600 или переменной окружения; не передавать аргументом командной строки и не печатать в журнал.
